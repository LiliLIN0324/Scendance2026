## 分组与命名规则

- 转换把每套模型拆成 `Preset_Structure`（固定场馆）与 `Preset_Objects`（可编辑物件）。后者的每个子节点命名 `Preset_Object_N`（N 从 0 起、不超过 4 位），中文名写在 `extras.displayName`，前端按 `node.userData.displayName` 读取（`three/scene-presets.ts`）。
- 同类构件重复出现时按顺序编号（`吧台凳 1`…`吧台凳 6`），只出现一次时用裸名（`茶歇台`、`舞台`）。
- 跨图层的零件会合并成一件：美术馆的画作由画框 + 画布组成，接待台由柜体 + 台面 + 内嵌件组成；市集的 12 个摊位、12 个遮阳棚本身就是成组节点。
- 天花板/屋面板与吊装灯具不进入编辑视图：`bar`、`office`、`studio` 整层剔除；`cafe` 只剔除 `RoofSlab`、`CeilingLight`（店面玻璃与门窗保留）；`conference` 只剔除天花板与吊装灯具（右墙、入口、吸音鳍保留）。
- **散件不会变成可编辑物件**：会议室家具层的 151 个零件、草坪家具层的 112 个单网格、市集的货箱与桶都留在固定结构，只有已成组的整件（椅子、人物、摊位、遮阳棚、已分组陈设）进入物件列表。
- **零厚度构件不能作为可编辑物件**：渲染器 `normalizeGlbInstance` 会把实例缩放到物件的实测尺寸，并拒绝零厚度包围盒（`模型包围盒无效`）。因此构建期就会检测并把它留在固定结构里，同时打印一行构建日志。cafe 的 `Cafe_BrandSign_001`（品牌标牌）是当前唯一一例。

## 数据与保存范围

预设使用前端 `RoomLayout.scenePreset` 指定固定场馆；每个物件用 `glbUrl + glbNode` 选取原模型中的节点，并保存米制尺寸、位置、旋转和离地高度。多个物件共享一次模型下载，但渲染实例分别拥有材质和几何资源，编辑/删除不会污染其他实例。

这些完整模型尚未注册为云端资产；场馆结构、离地高度及物件数量也超出现有云端场景协议。适配器明确阻止云保存和 AI 修改（`PRESET_LOCAL_ONLY`），界面显示「预设 · 本地保存」。云项目仍可通过原入口打开。

场地尺寸是概念方案：体育馆来自照片概念模型，70 × 76 m 的工作范围用于容纳周边布景；快闪 12 × 8 m、草坪 28 × 20 m、市集 30 × 22 m 等同属概念尺寸，人数不代表核定容量。

## 来源与构建

- 10 套源归档位于 `scene/templates/<key>/`，来自 `codex/gym-scene-template` 提交 `f2ec7ebd58094e51b868528b1ff499bcd8ea9b0d`，各目录保留 `template.json`、`ASSET-SOURCES.md` 与统一命名的总览图（详见该目录 [README](../../scene/templates/README.md)）。
- `npm run dev` / `npm run build` 触发 `scripts/package-scene-presets.mjs`：按各目录 `template.json` 声明的图层，把场景拆成 `Preset_Structure` / `Preset_Objects`，**只重写 GLB 的 JSON 块，二进制块（几何与贴图）逐字节保留**，输出到 `frontend/public/scene-presets/<key>/<key>.glb` 与 `preview.jpg`，生产产物在 `frontend/out/scene-presets/`。
- `gym`、`popup` 的物件分组按上游导出序号手工复刻；其余 8 套走脚本顶部的 `PRESET_SOURCES` 图层计划（`by: flag | grouped | names`，`groups` 可把多个零件合成一件）。三类归属必须覆盖根节点的全部图层，漏一个、找不到分组、图层带变换、零厚度判定都会让构建抛错，不静默丢资源。
- 新增一套预设要同时改三处：`lib/types.ts` 的 `ScenePresetKey` 联合、`lib/scene-presets.ts` 的 `SCENE_PRESETS` 表、`scripts/package-scene-presets.mjs` 的 `PRESET_SOURCES`。前两处由 `Record<ScenePresetKey, …>` + `satisfies` 互相约束，漏改会在 typecheck 期报错。
