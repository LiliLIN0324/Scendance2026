# 隔离试用：批量对话与工具检查

先启动**专用、独立端口**的本机试用。脚本只接受服务状态为 `ready` 且使用计数符合预期的试用，不读取密钥，不读取用户项目；登录的是该试用中的虚构演练账号和临时数据库。不要指向正在给用户使用的端口。

从 `frontend` 目录运行：

```powershell
node scripts/evaluate-live-dialogues.cjs 4331 --synthetic 5 5
```

将端口换为新启动的隔离真实模型试用端口、将 `--synthetic` 换成 `--live` 才会发生真实付费调用。数字分别是本次案例数（1–5）和本次模型请求上限。前 5 条均为固定虚构文本；每条请求前检查计数，出现无效输出、事实不符、超时或结果不明就停止，不自动重试。

需要附加一项单椅工具预览时，在**使用计数为 0 的新试用**运行：

```powershell
node scripts/evaluate-live-dialogues.cjs 4331 --synthetic 5 11 --include-tool
```

工具运行先执行，预留最多 6 次模型轮次；工具用例未取得可用候选时，后续对话不会继续。每个对话只调用需求提取，不会伪装为已测工具或场景结果。工具回执与最终候选分别列示，场景不自动应用。运行中的已发出请求不能撤回，上限不是服务商账户的硬性消费上限。

长驻试用可以用 `--expected-used=N --offset=N` 明确从当前请求计数和不同的固定案例位置继续；计数不匹配时会拒绝运行。同一请求仍受试用进程指纹保护。`--include-tool` 目前只支持计数为 0，避免误把旧运行当新结果。

输出为 JSON，只包含案例编号、固定结果代码、请求次数、耗时、脱敏工具记录及原场景是否改变，不包含模型原文、用户输入、工具参数、认证信息或 Key。样例断言不能证明回答语义、真实库存、场地安全或现场验收；`--synthetic` 结果也不代表真实模型能力。模型响应输出、流畅度与长期稳定性仍需人工和多次对照评估。

“每两人一桌”案例的对话提取接口只暴露总人数与布局类型，系统的每桌人数由另一链路处理。本批量脚本不会检查那条链路：即使提取字段正确，该项也标 `partial`，同时报告 `modelExtraction: passed` 和 `systemRatio: not_exercised`。`complete` 表示已完成指定批次，不表示所有案例的各层能力均已通过。
