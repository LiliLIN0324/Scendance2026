② 意图理解（LLM 只做分类）

understandOutdoorTurn · outdoor-agent-response-contract.ts
动作枚举：scope / zones / main-routes / objects / sub-routes / people / refine-3d / verify-access / adjust / connect / library-search / ask / cancel / simulate

③ 事实校验与合并

mergeOutdoorFacts（outdoor-agent-contract.ts）
本句溯源：新增/变化的 items·zones·people·guests·event 必须在「本句或上一句」原文里找得到
沿用已确认的数：数量与已确认完全一致时不再要求本句依据（用户补一句「放在摆摊区」不该抹掉上一句的 1000 张）
占位吸收：还没定分区的条目，在补上分区后被吸收，不重复铺一版
本想新增：用户这句既没数字也没数量词（「随便放」）时，模型给的清单视为编造，直接丢弃并记进设计过程 —— 本轮

④ 设计师模式（本轮主线）

lib/outdoor-draft-design.ts · draftDemand() 本轮
按用途反算：市集 8㎡/摊、展览 9㎡/位、座椅按面积、舞台 48㎡；用途未知的分区跳过并留说明
上限与诚实：单行 ≤200、条目 ≤20，超限写清「真实容量以现场为准」
追问预算：连续第二次追问且画布没推进 → 不再问第三句，直接出默认方案
「随便/看着办/都行」 → 第一句就出默认方案，不再追问清单
草案不自作主张：默认值只在内存里用，不写回 brief.items；用户下一句亲口说的数量仍然优先
放不下就缩：只缩放不下的那个分区（如演出区座位），卡上写清缩到多少，不硬塞、不报红卡

⑤ 阶段主链（8 站）

OUTDOOR_STAGE_LABELS 文案本轮改写
搜索目标地点→ 核对具体活动范围→ 分区用途与室内外依据→ 主要入口与通道→ 按分区摆放物料→ 物件间隙的子入口与支线→ 岗位、人数与活动路径→ 同规划3D深化
阶段顺序有闸：没分区不排物件；没有已核实主入口不排物料；没有设施不排子线
「按用途复用我的物料」→「按分区摆放物料」：没清单时用的是内置库，原话是假的 —— 本轮

⑥ 确定性与几何

lib/outdoor-agent-planning.ts · proposeInventoryObjects
真实库优先：个人库 → 内置库；同名候选优先 scale:（真实尺寸）而非 icon:
落位策略：行列 / 居中 / 沿边，卡上「换一种排法」循环预览
禁排区：建筑足迹、室内区域、已有设施、通道都要让开
容量粗筛：有人数才做 2㎡/人 保守粗筛；没有人数就跳过，并说明「没做粗筛」

⑦ 预览 → 确认 → 落盘

offer() / confirm() / apply()
预览不写画布：提案带 base 版本，画布变了就作废重算
确认才写：applyPlan(next, expected) 用期望版本兜住并发写
撤回留痕：撤回/替换进卡片历史，可点开看当时问了什么
默认方案自证：warnings 首条固定「这一版是默认方案：…不是你说的数字」

⑧ 失败、提示与恢复

status() / noticeFix / 错误卡 文案本轮改写
失败卡标题：由阶段名改成「这一步没做成 · <阶段>」——本轮
红卡的下一步：缺前置条件时给真能改变状态的动作；只有真正的重放才写「重试」
提示不自己消失：低风险提示不再 8 秒收起，留到下一句覆盖 + 手动「收起」——本轮
取消不动规划：AbortError 静默结束，真失败才亮原因

⑨ 入口核对（人证）

verify-access · outdoor-workflow-card.tsx 本轮改写
三个互斥方向：只能进 / 只能出 / 双向（入口不自动等于出口）——本轮
成组三选一：等宽选项 + 小字「记成什么」，窄屏单列，hover/focus 有反馈——本轮
仍需预览确认：核对结果先出预览，确认后才写 user-confirmed
不做安全背书：核对 ≠ 消防/疏散/合法容量

⑩ 红线（不可越）

本项目规范 硬约束
不编：数量、价格、库存、账号状态、云端资产 ID
不冒充：草稿 ≠ 已确认；本地保存 / mock / 云端验证分开汇报
不承诺安全：不以「排下了」当安全通过；无障碍与疏散需现场核验
不改契约：wire schema（outdoor-agent-response-contract.ts、site-plan.ts）需人 review
