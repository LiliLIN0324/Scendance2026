01研究目标与方法

目标：判定“6 天内做什么最能提高得分”，并把判断压到可核验的证据上，而不是复述课程内容。

方法：三条线交叉。

  • 一手规则线：直接解析赛事官网前端 bundle（holo-global-main-hackathon），拿到评分权重、奖项结构、提交表单字段与《参赛作品提交须知》原文；课程页只作为交叉验证。
  • 代码事实线：审计 Lux3D / Aholo 生成链路、资产追溯字段、分享快照与失败文案，全部对到具体文件与行号。
  • 可运行性线：实跑构建与类型检查，区分“真失败”和“本机 dev server 争用造成的假失败”。

说明：飞书答疑表已取得并逐条核对——导出 PDF 共 12 页、10 条问答，内容全部为产品相关，已摘入 §4.5。赛事类问答（报名与组队、选题命名、提交后能否修改）未出现在该导出文件中，报告中相关要求仍以官网 bundle 与《参赛作品提交须知》为准。

4.2 测试：146 个红条不能当结论

2026-11-13 14:58 的全量运行结果：54 failed | 520 passed (574) 文件，146 failed | 7776 passed 用例。但该次运行期间 3210 端口的 dev server 一直在跑，失败项含大量 Test timed out in 20000ms——属于资源争用放大，不等于 146 个真实缺陷。不要在这 6 天里清理测试；要的是“一条端到端演示链能跑通”。

4.3 追溯链：数据层有，界面层没有

上一轮曾判断“providerMode/providerModel 缺失”，此处更正：迁移 supabase/migrations/20261028120000_aholo_lux3d.sql 已把 assets.source 扩到含 'aholo'，并为 generation_jobs 增加 provider_mode='aholo'、provider_model='lux3d' 的约束。也就是说，“确实用了 Lux3D”在数据库里是可核验的；缺的是前端把来源显性展示给评委看。

4.4 分享与失败文案

  • frontend/lib/share-snapshot.ts 已有 droppedAssets 报告与 20 000 / 64 KiB 长度上限，说明“静默丢件”可能已改为显性提示——但尚未实机复验（docs/04 的 G2/G5 结论停留在 2026-11-04）。
  • material-generate.ts 的 cloudFailure() 只识别未配置、额度耗尽、鉴权三类错误；Lux3D 免费账号同时只允许一个生成任务，并发被拒会落到“结果暂时无法确认，可能已创建任务或产生费用”，演示现场连点两下就会吓人。

4.5 厂商口径：答疑表里已经写死的边界

以下摘自赛事官方答疑表（PDF 共 12 页、10 条，内容全部为产品类，2026-11-13 核对）。它最大的价值不是新功能，而是替我们已有的边界做官方背书，同时点出几处对外表述必须收口的地方。

主题厂商口径对我们的影响
3DGS 与碰撞 Viewer 提供 3DGS/Mesh 渲染、相机控制、拾取与碰撞查询；但3DGS 的视觉外观不会自动变成可碰撞实体，需要接触的区域必须另配碰撞网格或碰撞数据。 背书 与我们“3DGS 不当量尺、不当碰撞体”的边界完全一致，报告书可直接引用，把限制讲成方法论。
精确测量 世界重建用于还原拍摄空间，世界生成用于创作新场景；两者都不能直接当作精确测量结果。 背书 支撑我们“米制精度由 GLB / 矢量壳承担”的分工，避免对外承诺“扫完即量尺”。
重建输入 重建图片路径至少 20 张，也支持相应视频；提交后返回 worldId，还需查询状态与最终产物。 一致 与我们采集导引的 180 张 / 3 层 / 330° 不冲突；视频仍是主通道。
采集重叠度 相邻照片至少约 70% 内容重叠，并从不同位置与高度覆盖主体；COLMAP 建议同一物体至少出现在 3 张图中。 背书 与 frontend/lib/capture-guide/ 的阈值一致；西湖素材 49 分、覆盖 102.6° 的判定有了外部依据。
文件识别与单位 PLY 要看 header 的元素与属性区分网格 / 普通点云 / Gaussian；SPZ 需对应版本的读取器；单位、轴向不能靠后缀或文件名猜，要记录最终变换。 待补 venue-scans 目前只按 .spz/.ply 过滤，资产元数据应记录 upAxis / 单位 / 变换（现有实测 upAxis=Z）。
渲染链路 Editor 的 Hybrid Mix、Viewer、云端成片不是同一条渲染链路，不能用一个入口的效果推断另一个入口的能力。 注意 我们自己的 three.js splat 预览更不等于 Aholo 成片；对外只描述我们实际验证过的画面。
“穿模”归因 Fly / 自由观察模式允许镜头进入墙体，不能仅凭穿墙判定资产损坏；需要防穿墙应使用带碰撞数据的漫游模式。 话术 评委试用时若出现穿墙，要能当场解释相机模式，而不是被当成缺陷。
图纸 / 效果图 空间图纸与效果图只表达部分尺寸与外观，仅上传图纸或效果图难以保证精确还原门窗与家具位置。 改文案 “上传平面图”只能表述为布局参考，不能承诺自动还原三维尺寸。
世界生成 世界生成最多 1 张图；SpatialGen 不承诺固定高斯点数，也没有指定点数的参数。 别报数 报告中不要出现“多少万高斯点”这类未经核实的数字。
流体 / 动态 Viewer 未内置流体动力学求解，静态水面只能作带材质网格展示，真实流动需额外模拟系统。 不涉及 Demo 里不要承诺水面动效或流体交互。

怎么用：报告书里单开一小节“边界与取舍”，直接引用上面三条背书（3DGS 不碰撞、不用于精确测量、渲染链路不同），比反复解释“我们做不到”更有说服力——评委看到的是我们知道工具边界在哪。

能直接用在 Demo 里的三件事

  1. 世界生成有网页入口，不必等 API。Aholo Reality 网页可按官方教程上传图片生成世界；API 额度或并发卡住时，这是现成的兜底。
  2. Crop 可裁背景与边缘噪点。重建结果四周的漂浮噪点不必重采，Editor 里裁掉即可；先留副本，再从多个视角检查，被前景遮住的墙面仍需重采。
  3. 画质档位可调。Reality 自有项目支持 Original Quality (RAW)，独立 Viewer 也有质量配置；录屏用高画质，做对比时锁死同一资产、同一视角、同一分辨率。

另：采集建议是先拍小样确认多视角覆盖，再提交全量；物体重建与空间重建是两条路径，先按目标选对，再谈参数。
