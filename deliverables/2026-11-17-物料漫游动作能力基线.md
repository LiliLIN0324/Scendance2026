**目标**：在不改产品代码的前提下，把「物料能不能坐、能不能交谈、能不能挥手」的现状量清楚，给出一份可复查的数字与可照做的标注清单。

**复跑方式**

```bash
cd frontend
npx vitest run components/room-organizer/lib/prop-interaction-audit.test.ts
```

输出：`deliverables/material-interaction-audit.json`（逐条明细，可直接 diff）。

## 二、三个硬问题

### 问题 1：51 件动作是 slug 里"场景名"替道具决定的

125 件有动作的道具里，**51 件（40.8%）光看名称判不出来，只有把整条 slug 塞进去才命中**。slug 的构成是「所属场景名-道具名-哈希」，于是场景名参与了匹配。

根因是关键词用的是 `includes` 子串匹配，没有词边界：

| 物料 | 判成 | 实际是被谁误触 |
|---|---|---|
| 移动厕所（两格） | table → 交谈 | slug 里 `portable` 含 `table` |
| 双履带拖拉机 | display → 交谈 | slug 里 `tracked` 含 `rack` |
| 线阵列音箱 | stage → 挥手 | slug 前缀 `festival-stage` |
| 背景发光屏模块 | booth → 交谈 | slug 前缀 `dj-booth` |
| 打开的十四英寸笔记本电脑 | table → 交谈 | slug 前缀 `computers-and-desk` |
| 带绳礼宾隔离柱 | booth → 交谈 | slug 前缀 `dj-booth` |
| 发电机拖车 / 电源配电箱 / 电缆过线板 | stage → 挥手 | 同一条 `festival-stage` 前缀 |

前 20 条（全量 51 条见 JSON `actionFromSlugOnly`）：

### 问题 2：95 件承诺了动作，但人物根本播不出来

`talk` / `wave` 共 95 件（去重后），当前人物 GLB 默认只重定向 `Idle_Loop` 与 `Walk_Loop`。也就是说这 95 件的能力**全部无法兑现**：按 E 只会走到 `resolvePersonAction` 回退 idle，再弹一句"这个人暂时没有交谈片段"。

典型样例：品酒接待吧台（talk）、影院验票台（talk）、中世纪市集摊位（talk）、音乐会舞台与排练区（wave）、甲板舞台与背景板（wave）。

可用的 clip 其实已经在预设里：`Idle_Talking_Loop`、`Sitting_Idle_Loop`（`character-generate.ts`），只是人物生成链默认不产出。所以这不是"物料标签"单方面的问题，而是**物料能力 × 人物能力**的二维缺口。

### 问题 3：可坐判定的边界有 8 件错位

30 件 seat 里，8 件不在座椅桶：

| 物料 | 桶 | 说明 |
|---|---|---|
| 游艇会露台桌椅套装 | tables | 套装，落座点取设施中心＝桌面 |
| 绿色咖啡桌椅套装 | tables | 同上 |
| 圆桌与椅 | tables | 同上 |
| 户外圆桌椅（带伞） | tables | 同上 |
| 吧桌与长凳 | tables | 同上 |
| 旋转飞椅 | rides | 游乐设施，不是坐具 |
| 疏散椅 | logistics | 医疗器械，不是可坐设施 |
| 双沙发遮阳休息区 | structure | 整间休息区，中心点不在沙发上 |

桌椅套装按 seat 处理，坐下会落在桌子中心——这在漫游里是"人坐进桌子里"。需要单独一类 `seat-set`，给出多个座位锚点（朝向 + 坐面高），而不是一个中心点。

另外 `seatMiss = 0`：名称里带"椅/沙发/凳"的物件没有一件被判漏，说明坐具这一路的关键词目前是可靠的。

## 四、修复顺序（按性价比）

1. **匹配先止血**：slug 只取"物件段"（去掉场景名前缀与哈希），关键词改全词匹配。预计消掉 51 件里的绝大部分误判，改动集中在 `seat-placement.ts` 与 `prop-interactions.ts` 的 `haystack / matches`。
2. **能力改声明式**：物料库加 `capabilities: { actions, seat?, source }`，`propInteractables()` 把 tags/capabilities 传给 `propInteractionProfile`（现在这条线是空的）。人工标注优先，关键词只做兜底。
3. **动作可用性分级**：物料标了 talk/wave 但当前人物无对应 clip 时，属性卡与 E 键提示要说清"需要带 Talk 的人物"，而不是注册交互后再报错。
4. **桌椅套装单列**：`seat-set` 带多个座位锚点，解决"坐进桌子"的 4 件。
5. **重跑本审计**：每次库更新后跑一次，盯三个数——`actionFromSlugOnly` 降到 0、`clipMissing` 与服务端真实 clip 对齐、`seatMiss` 保持 0。

## 五、与"人物沿流线走 / 进分区自由活动 / 见椅坐下"的衔接

这份审计只解决"物料端说不说自己能坐/能谈"。Lili 提的那套行为还需要人物端补齐四件事，本报告不重复展开，但依赖关系是明确的：

- 「见到椅子就坐下」依赖本报告的 `seat` 准确率与座位锚点（套装类必须先修，否则人会坐到桌上）；
- 「分区内自由活动」依赖分区语义 + 可坐物标注，否则自由活动只能随机走，没有停留点；
- 「流线内固定行走」已有数据基础（`assignCrowdWalkRoutes`），但缺 route↔zone 切换；
- 「坐下」最终能否播出来，取决于 `Sitting_Idle_Loop` 是否随人物产出——与 `talk/wave` 是同一个缺口。

## 八、能力标签化与执行器接线（同日第二批）

第七节的「未接线」已补上；同时把「靠关键词猜」换成「生成一次、可审查、可覆盖」的能力表。

### 8.1 标签体系（借 smart object / affordance 的做法）

参考成熟做法：把「这个物体能提供什么交互」写进物体自己的能力，而不是每个使用方现猜（Sims 的 smart object、Unity/Unreal 的 interactable 组件都是这个分工）。落地成三层：

| 层 | 文件 | 作用 |
|---|---|---|
| 数据 | `lib/library-capabilities.ts`（生成，976 行） | 每个 slug 一条 `kind` + `actions` + `source` |
| 类型/查表 | `lib/prop-capabilities.ts` | `capabilityForSlug()`、覆盖率统计，不做关键词 |
| 使用方 | `prop-interactions` / `seat-placement` / `outdoor-interactables` / 属性卡 / 3D | 有标签按标签，表外新物料才回退旧规则 |

生成器：`node scripts/build-library-capabilities.mjs`，从 `assets/library/merged.json` 重算，产物可 diff；要改单件物料改脚本里的 `OVERRIDES` 再生成，不手改生成文件。人工定稿 17 件（售票/问询/ATM/车架/枪架/观景平台/桌椅套装）。

### 8.2 复测（标签版）

| 指标 | 上一版 | 标签版 | 说明 |
|---|---|---|---|
| 有标签的物料 | 0 | **514 / 514** | 表外 0 件 |
| 判不出类别（unknown） | 359 | **0** | `none` 是「判定为非交互」，不是「不知道」 |
| 动作只靠 slug 命中 | 19 | **0** | 表内不再跑关键词 |
| 人工定稿 / 规则生成 | 0 / 0 | 17 / 497 | 有争议的 17 件走人工 |
| 可坐（单件 / 套装） | 22 / 5 | 22 / 5 | 不再漏、不再坐桌面 |
| 可交谈 | 49 | 40 | 收回 9 件场景名/后缀误命中 |
| 可挥手 | 10 | 6 | 摄像/观景平台不再当舞台 |
| 有动作但缺 clip | 59 | 46 | 40 交谈 + 6 挥手 |

要点：`unknown` 归零不等于「都变成可交互」，而是把 436 件明确判成 `none`（纯陈设/车辆/绿植/围栏），把判断依据从「猜不出」变成「写明不可交互」。

### 8.3 人物剪辑链路

| 项 | 改动 |
|---|---|
| 生成默认剪辑 | `DEFAULT_CHARACTER_ANIMATIONS`：Idle / Walk / **Idle_Talking_Loop** / **Sitting_Idle_Loop**（挥手仍按需勾） |
| 物料侧默认可用集 | `DEFAULT_PERSON_CLIPS`：Idle / Walk / **Sitting_Idle_Loop**（现有 crowd GLB 三件套） |
| 属性卡提示 | 只有真缺片段才提示；坐姿不再对默认人物报缺 |

边界说明：仓库里没有可写入的动画二进制，本次完成的是**链路与默认集**；交谈片段仍取决于人物生成任务实际产出 `Idle_Talking_Loop`（46 件物料的提示会一直保留到那时）。

### 8.4 3D 执行器接线

新增 `lib/person-roam-runtime.ts`（`RoamRuntime`：座位占用、走位推进、坐/起时间线），并在 `outdoor-plan-3d.tsx` 接进人群层：

| 环节 | 接线 |
|---|---|
| 座位来源 | `seatFacilityTargets()` + 能力表 `seat/seat-set`，含套装四向锚点与坐面高 |
| 分区 | `plan.boundary` → `RoamZone`，执行器在区内采样落点 |
| 位移 | 每帧 `tick(dt)` → `enuToWorld()` 写 `group.position`，朝向 `atan2(dx, dz)` 与 `person-route` 同口径 |
| 坐/起 | `takePersonControl()` 的 `setSeated(true, 坐面高)` / `setSeated(false)` |
| A 段 | 不改：有流线的人仍由 `assignCrowdWalkRoutes` + `people-anim` 驱动 |

执行器 5 条单测：按步速推进、同椅不双占、坐够起身并释放、注销释放、无分区不乱走。

### 8.5 关于删减 / 新增物料

本次**没有**删改目录条目：`merged.json` 的每条都挂着 GLB/贴图，删一条会连带资源与已放置方案；而「判不出类别」的根因是判定层，不是目录冗余。当前用能力表把 436 件明确标成 `none`，等价于「不参与交互」，比删除可逆。若要做真正的目录瘦身，建议下一步按「近 90 天未被放置 + `none` + 无 GLB 引用」出候选清单，再由你确认后删。

| `能坐 木` | 先按能力筛，再按名字收窄 |

搜索框占位符已改成「搜索素材，或输入 能坐 / 能聊 / 可操作」，不靠猜。

### 9.2 防漂移守卫

新增 `lib/library-capabilities.test.ts`（9 条）：

- 目录 976 行逐条必须有标签，行数必须相等——新增物料忘了重跑生成器，测试直接红；
- `kind` 与 `actions` 自洽（seat 必带 sit，none/operate 必须无动作）；

### 9.3 顺手修掉的一个真问题

### 10.5 走查抓到并修掉的坐标系 bug

上一版执行器按**绝对 ENU** 接线（`enuToWorld` 只翻 z），但 3D 场地实际以边界包围盒中心为原点：`world = (x − cx, −(y − cy))`。实机一跑就会发现人物整体偏一个场地中心。

修复：新增 `lib/plan-scene-frame.ts`（`planPointToScene` / `scenePointToPlan` / `planPointToRoam`）并锁 4 条测试；执行器的座位与分区统一先换算到场景坐标。同时把接管条件收紧为「没有流线的人才进执行器」，保住 A 段（沿流线）原行为。

### 10.6 crowd 交谈与挥手：重定向接通（2026-11-17）

卡点不是标签，是骨架不同：16 个 crowd GLB 全是 Mixamo 骨架（`mixamorig:*`，52 骨），逐个体检只有 `Idle_Loop` / `Walk_Loop`；带交谈的是摆置人物 `people.glb`（Rigify 53 骨，`Idle_Talking_Loop`）。按成熟做法用 three 官方 `SkeletonUtils.retargetClip` 把片段搬过去，而不是再复制一套模型：

| 环节 | 做法 | 证据 |
|---|---|---|
| 骨名映射 | `mixamoNamesFor()`：部位表 + 指节正则（`LeftHandThumb1 → DEF-thumb.01.L`） | 6 条单测 |
| 交谈 | `retargetFromRigCached()` 把 `Idle_Talking_Loop` 搬到 crowd 骨架，同骨架只算一次 | 实机 `talk: true` |
| 挥手 | 无现成素材：`buildWaveClip()` 以静止姿态为基准叠加抬臂 + 摆小臂，生成 `Wave_Loop` | 实机 `wave: true` |

实机（同一份 16×12 方案，4 人）：`idle / talk / walk / sit / wave` 五项全为 `true`；2 人落座、2 人在走。复跑：`frontend/scripts/verify-crowd-clips.mjs`。

诚实边界：

1. 挥手是**程序化**片段，只保证动作成立、可循环，不是美术级挥手；已核对 CC0 的 Universal Animation Library（46 条）无 Wave，替换需另找素材（见第十一节）。
2. 本次没拿到「静止 NPC 单独挥手」的截图：注入的 4 人都被落座/流线接管，`setNearestPersonAction` 按设计跳过被接管的人；画质只做了片段级校验（关键帧中途姿态与静止姿态夹角 > 0）。

## 十一、材质快改与 Agent 排道具：还差多远

先把两件事分开，它们不是一条链：

| 需求 | 本质 | 现状 | 差距 |
|---|---|---|---|
| 「能坐」搜索 | 标签检索 | 已通，但它是调试探针，不是产品路径 | 产品侧应让 Agent 按需求直接排道具，搜索留作兜底 |
| 木质 → 其他材质 | 运行时材质替换 | 未做 | 需材质槽识别 + 预设库 + 写回方案 |
| 交谈 / 挥手 | 动作片段 | 已通（重定向 + 程序化） | 只剩美术级挥手素材 |

材质快改的实际工作量（按现有代码结构估）：

| 步骤 | 内容 | 量级 | 风险 |
|---|---|---|---|
| 1. 材质槽识别 | 遍历 GLB 的 mesh/material，按名称 + 面积归到「木/金属/布/玻璃/塑料」 | 0.5 天 | 多数资产是烘焙贴图，只有材质名，没有语义 |
| 2. 预设库 | 每类 2–3 套 PBR 参数（色/粗糙度/金属度） | 0.5 天 | 纯逻辑，可单测 |
| 3. 应用层 | 只换 material，不动几何；保留或去掉贴图 | 1 天 | 去贴图会丢木纹细节；保留贴图只能调色调 |
| 4. 写回方案 | `facility.materialPatch` 字段 + 撤销 | 0.5 天 | 与现有保存/回滚对齐 |
| 5. Agent 工具 | 「把这几把椅子改成金属」→ 选中 + 改槽 + 回执 | 0.5 天 | 需要先定「改质感」还是「换整套材质」 |

结论（2026-11-17 当天已落地，不再是计划）：

| 已实现 | 证据 |
|---|---|
| 7 档预设（原样/浅木/深木/黑金属/拉丝钢/布艺/玻璃） | `lib/material-presets.ts` + 单测 |
| 只改 PBR、保留贴图；逐实例 clone，不污染 GLB 缓存 | `three/material-preset-apply.ts` + 单测 |
| 方案字段 `facility.materialPreset`（旧数据缺字段照常解析） | `site-plan.ts` / `schema.ts` / `schema.test.ts` |
| 属性卡「材质」色块，即时生效、走同一条 undo | 实机点选深木椅 → 「深木」高亮 |
| 3D 实机三把椅子分别为拉丝钢 / 深木 / 原样 | `verify/31-material-3d-0.png` |

仍未做：贴图整体替换（去木纹换纯色金属后的 UV/细节）、Agent 语言入口（「把这几把椅子改成金属」）。

挥手素材核对结果：CC0 的 Universal Animation Library（46 条剪辑）**没有 Wave**（只有 Dance / Talk / Sitting / Walk_Formal 等）；Mixamo 有 Wave 但不是 CC0。当前保留程序化挥手，若要美术级素材，需要二选一：接受非 CC0（Mixamo），或由美术手 K 一版导进来走同一条重定向链路。
