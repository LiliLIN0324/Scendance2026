户外 Agent 交互流程图 — 从你说的一句话开始

这是一张流程图，不按代码分层：每行左边是你的原话，中间是系统确定性地做什么， 右边是你在屏幕上实际看到的卡片/预览，以及不会发生的事。带「本轮」的是这几轮刚改的。

1 你说话主输入框，一句话就够
2 判断你说了什么模型只做分类，不编数量
3 按规则算分区用途 + 真实面积 + 库内真实尺寸
4 只出预览画布不写，等你点头
5 你确认才写进画布

A. 说不清的时候（最常发生）

原来这里会反复追问「各区放什么、各多少」，现在改成先给你一版看。

你说
随便放 / 你看着办 / 做一版，我还没想好
本轮：设计师模式
  • 不再追问清单——这句话不是需求，是授权我先做。
  • 按每个分区的用途 + 真实面积反算：市集 8㎡/摊、展览 9㎡/位、舞台 48㎡。
  • 只从真实库取件；单行 ≤200 件、≤20 行，超了就说明容量。
  • 算出来的量排不下（演出区座位）→ 只缩那一个区，其余照旧。
    • 默认值只在内存里用，不会写进你的需求；你下一句说的数仍然优先。
你会看到
待你核对 · 按分区用途出的默认方案摆摊区 市集摊位×25、演出区 舞台×1 + 椅子×33…
首条说明固定是「这一版是默认方案：数量按分区用途与可用面积反算，不是你说的数字」
不会发生：直接写画布、假装你说过这些数、把「排下了」当安全通过。
你说（第二次）
嗯…（还是没给清单）
本轮：追问预算
  • 第一次追问照常问；第二次还问不出来、画布又没动 → 不再问第三句。
  • 直接按当前分区出默认方案（同上一行）。
  • 你问的是「你能做什么 / 为什么这么排」这类真提问时不抢话，正常回答。
你会看到
待你核对 · 按分区用途出的默认方案设计过程里写明「连续追问没有推进」
不会发生：第三、第四句追问；也不会「沉默地把阶段跳过去」。

B. 你给了清单或场地

你说得越具体，系统越只做核对和落位，不改你的数字。

你说
室外市集，摆摊区放 20 个摊位
明确清单
  • 先把数字对上你这句话的原文（没有依据的提取会被退回，不会默默用）。
  • 去真实库找件、按分区落位、让开通道/建筑/已核对入口。
  • 只出预览；确认后才写画布。
你会看到
待你核对 · 逐区复用库内真实设施20 件市集摊位；可「换一种排法」看行列/居中/沿边
不会发生：把你的 20 改成它算出来的 25；不会不确认就落盘。
你说
户外集市，做两个分区：摆摊区和演出区
只有分区
  • 先出分区预览：每个区的用途、室内外属性。
  • 确认后才知道「能摆什么」——没分区不排物料。
  • 分区确认后按「有没有已核实的出入口」决定下一站。
你会看到
待你核对 · 分区用途与室内外属性摆摊区（室外·市集）、演出区（室外·表演）
不会发生：跳过分区直接摆物料。

C. 你在改主意或回答问题

改口、二选一、核对入口，这三类是线上最容易「答了却像没答」的地方。

你说
把摊位改成 30 个
改口
  • 认成同一批设施的增减，不是又铺一版。
  • 数量必须对上这句原文；对不上就退回，不猜。
  • 仍然只出预览，等你确认。
你会看到
待你核对 · 30 件市集摊位位置按新数量重排，不叠加成 50 件
不会发生：重复铺一版；把旧数量一起算进去。
你说（回答上一轮二选一）
第一个方案
选选项
  • 先认出「这是在回答刚才那个（1）/（2）」，按选项确定性推进到原请求的预览。
  • 设计过程里留一句「按你选的『…』继续」。
  • 认不出就清空，不让上一轮的选项污染这一句。
你会看到
待你核对 · 对应阶段预览不会再问一遍同一道单选题
不会发生：把你选的答案再丢给模型猜一次。
你说（对着某个入口）
这个门能用
本轮：三选一
  • 入口不自动等于出口——问你是 只能进 / 只能出 / 双向。
  • 选完出预览，确认后才标记「已核实」。
  • 核对≠消防/疏散/合法容量的通过。
你会看到
“海滩门”能不能走？[ 只能进｜入口 ] [ 只能出｜出口 ] [ 双向｜入口+出口 ]
不会发生：只凭「能用」就替你认定双向；替你宣布安全合规。

D. 点头、回头、收手

你说
就按这版 / 没问题
确认
  • 先核对你确认的是不是当前这一版（画布变过就作废重算）。
  • 写画布用「期望版本」兜住并发，不会覆盖别人的改动。
  • 写完告诉你下一步是什么，或者可以直接说下一句。
你会看到
已应用「…」下一步：物件间隙的子入口与支线；也可直接补要求或回退
不会发生：确认到一半、画布已经变了还照写。
你说
不要这版 / 撤回
撤回
  • 丢弃预览，规划保持原样。
  • 在卡片历史里留一条「已撤回」，点开能看到当时问过什么。
你会看到
已撤回这条记录保留在「更早的引导」里
不会发生：撤回还悄悄留了半版在画布上。
你说
停下来 / 取消
取消
  • 静默结束在跑的请求，不动规划。
  • 真失败（例如缺前置条件）才亮原因，并给一个能改变状态的下一步。
你会看到
这一步没做成 · <阶段>红卡上写清原因，下一步是真能推进的那个动作
不会发生：一个点了还是同一句话的「重试」。

E. 任何一句都不会越过的线

下表对上面每一行都成立。

  • 不编数：数量、价格、库存、云端资产 ID 一律不猜；模型提取必须能对上你的原话。
  • 不冒充：预览 ≠ 已确认；本地保存、mock、云端验证分开说。
  • 不背书：排得下不等于合法容量，无障碍与疏散要现场核验。
  • 可回溯：每次预览、撤回、替换都留在卡片历史里，刷新还在。
