01选题卡：直接粘贴

选题卡决定评委对作品的第一印象，也决定 30% 那一项怎么被理解。团队名已定「幕景宇宙」；受众先按项目里冻结的定位写，后面要改只动第二段。

作品名

幕景 Scendance（团队：幕景宇宙）

一句话介绍（用于选题、表单、社媒首句）

一句话生成活动装置，摆进真实场地，交付一个客户能自己转着看的方案。

想做什么

把“活动方案”从几张效果图，变成一份能走进去看的 3D 交付：在真实场地里摆物料、改结构，用一句话生成缺的那件装置，再把同一份方案以只读链接发给客户、以物料清单和平面图交给执行团队。第一版只做一条路——小型品牌沙龙，从空场地到可交付方案，20 分钟内走完。

给谁用

小型活动策划执行工作室（2–10 人）的主案设计师与执行负责人。他们现在用平面图 + 效果图 + 微信群对齐方案，客户看不懂、执行易返工。第一个具体用户是一场 50–150 人的品牌沙龙，方案要在 3 天内定稿。

Lux3D 在其中如何发挥作用（30% 那一项就看这段）

不是“顺带用了 Lux3D”，而是三个关键节点：
① 补物料：场地定了以后，缺的展台、装置用一句话或一张参考图交给 Lux3D 生成 GLB，归一化后直接落到画布上，可整体移动、旋转、缩放；
② 补风格：同一场活动换主题色系时，用图生 3D 快速出一版新装置，保留旧版本做对比；
③ 进交付：生成物作为“概念道具”进物料表（标注实物待确认），随方案一起发布给客户。没有 Lux3D，这条“缺什么就生成什么”的链路就不成立，只能退回固定素材库。

第一版不做（写进选题卡，反而显得克制）

开放注册、支付、多人实时协作、自建采集端、复杂多层场地、流体或动态水面。这些都不进这次 Demo。

07评委可能问的 8 个问题

问题回答要点（别背，讲逻辑）
这跟酷家乐 / 传统 3D 软件有什么区别？他们做“装修完成后的效果”，我们做“活动还没发生时的方案”：场地是临时的、物料是租来的、交付对象是客户和执行队。所以核心不是渲染，而是“缺什么生成什么 + 一份方案两种看法 + 一个链接交付”。
Lux3D 具体做了哪一步？没有它行不行？做“补缺”这一步：场地定了以后缺的装置，用一句话或一张图生成 GLB 直接落地。没有它只能退回固定素材库，客户想要的特殊装置就做不出来——这是链路里的必要条件，不是装饰。
3DGS 能用来量尺寸吗？不能，官方答疑也明确重建/生成结果不能直接当精确测量。我们只把它当观感背景，米制精度由 GLB 和矢量壳承担，摆位和落地用它们算。
生成的道具能直接施工吗？不能，物料表里统一标“概念道具，实物待确认”。它解决的是“客户看得懂、方向对”，不是出施工图。
真实场地重建要多久？稳定吗？视频通道实测可用，室内一批大约十几分钟出结果；图片通道我们遇到过运行时失败。所以演示优先用“已有扫描场地”，重建作为能力展示而不是演示主路径。
如果现场网络 / 生成失败怎么办？生成失败不阻塞已有场景，可以继续用内置物料；演示有本地兜底场景和录屏，不把失败伪装成成功。
谁付费？工作室负责人。卖的是“少返工 + 客户一次看懂”，不是卖 3D 模型。首版不做支付，先验证一个工作室愿不愿意为交付效率付订阅。
数据与版权怎么处理？客户场地素材走私有存储，分享用只读令牌、可撤销；免费账号生成的资产默认公开，所以演示不用真实客户敏感素材。

08十个坑（都已踩过或有官方口径）

  1. 构建红着部署。dev server 和 build 抢 .next 会报 /_not-found 或 webpack-runtime 错误，先停 dev server 再构建。
  2. 用 ZIP 里的 MODEL.glb。贴图是占位图，进网页发黑；要用导出时选的 GLB（我们是直接取产物里的 textured.glb，没踩这个坑）。
  3. 把 3DGS 当碰撞体。官方明确视觉外观不会自动可碰撞，接触区域要另配碰撞网格。
  4. 拿重建结果量尺寸。官方明确不能当精确测量结果。
  5. 用 Fly 模式的穿墙当缺陷。自由观察本来就允许镜头进墙，需要防穿墙要用带碰撞的漫游模式。
  6. 以为上传平面图就能还原三维。官方说仅凭图纸/效果图难以保证精确还原，文案要写“布局参考”。
  7. 报高斯点数。SpatialGen 不承诺固定点数，也没有指定参数——别写“多少万点”。
  8. 连点生成。免费账号同时只允许一个任务，并发被拒要显示“排队”，不能显示“结果未知”。
  9. 分享链接过长。哈希快照有长度上限，客户链接优先走云端发布，别在微信里发超长 URL。
  10. 社媒忘了发。5% 白送分，且帖子要在结果公布前保持公开。

09今天就能做的三件事

  1. 把选题卡发出去。用 §01 的五段文字，团队确认后由队长提交，拿到“选题已提交”的状态。
  2. 停 dev server，跑一次干净构建。命令：$env:NEXT_DIST_DIR=".next-verify"; npm --prefix frontend run build；成功即部署，失败把“文件:行号 + 错误码”贴出来。
  3. 录 60 秒兜底视频。就用现在线上能打开的版本，先保证“有东西可交”。

完成的标准不是“做完了”，而是：评委点开链接 → 30 秒内看到一句话生成装置 → 拖进场地 → 手机能转着看 → 报告书能对上这个过程。
