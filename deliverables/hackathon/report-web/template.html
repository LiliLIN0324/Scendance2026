从一句话，到一座能搭的场地 幕景 Scendance ｜ 真实户外场地 → 可编辑 3D 空间 → 能直接搭建的方案

幕景把真实户外场地变成可编辑的 3D 空间：在地图上圈选区域、现场扫描重建真实环境，把场地导入画布后直接布置舞台、展台、灯光与活动物料——这条管线上现在坐着一个会做设计的 Agent：客户先问「杭州的园林婚礼，80 人 8 桌，能推荐几个场地」，它给候选并说清哪些已完成重建；人选定之后，七个分区与三条流线的方案初稿按阶段摆出来，人确认一步，场景才动一步。

生成模型给出「看起来对」，幕景补的是「量得准、摆得下、交得出」——真实尺寸、真实地面、执行团队能直接照着搭。

一、痛点：三份文件，三次返工

  • 选场地只能靠笔记和卫星图。园子看着都美，但哪块平地放得下 8 桌、通道够不够 1.5 米、下雨往哪儿躲，笔记里没人写。签约之后才发现仪式区是个斜坡。
  • 效果图、物料清单、平面图由三拨人做三遍。改一次桌数，三处不同步，现场执行照着图纸对不上。
  • 婚礼物料基本不能买标准件。花艺拱门、姓氏迎宾牌、签到台造型、灯笼串，每样都定制、只用一次，改一次颜色就重来。
  • 七分区婚礼真正难的是流线。新人入场、宾客入场、上菜撤场三条线一交叉，现场就乱了——而这三条线在平面图上看不出来。

二、方案与架构：七个业务环节 × 八个 Agent 阶段

  1. 选场地。客户说「杭州、园林、80 人、8 桌」，Agent 按容量、风格、能否 3D 预览给候选，人选定一个。
  2. 高德地图圈选。圈出目标区域，得到锚点、边界与真实地理尺度。
  3. 现场采集。手机端按采集导引拍摄，数量、层数、重叠、尺度基准都有硬阈值，不达标直接拦下。
  4. 场景重建。Aholo Reality 把照片/视频重建成 3DGS 场景（.spz），作为真实场地底。
  5. 空间布置。画布把场地当壳体，物料在 2D/3D 同源编辑；Agent 按阶段出方案卡片。
  6. 定制物料。对话框里直接起 Lux3D 任务，GLB 自动归一化（单位、朝向、尺寸上下限）后进物料库。
  7. 交付。机位图册、物料清单 CSV、DXF 平面、只读分享链接。

代码口径是「八个阶段」：place → scope → zones → main-routes → objects → sub-routes → people → refine-3d。环节是业务口径、阶段是代码口径，对应关系见下表。

业务环节对应 Agent 阶段说明
1 选场地place会话的第一步就是接地点 / 场地
2 高德圈选scope圈出的边界是后续所有尺寸的坐标系
3 现场采集不属于会话场地生产链的前置步骤，不计入八阶段
4 场景重建不属于会话由 Aholo Reality 完成后进画布
5 空间布置zones → main-routes → objects → sub-routes → people五个阶段、一个业务环节：从分区到流线到设施到人员

⚠ 不要为了整齐把八阶段说成七阶段：代码就是八个。也不要拿八阶段去画业务流程图，那会把采集与重建画丢。

一个人物不是一步生成的：先用一张参考图出四视图，确认造型、比例、服装细节都对，再拿四张视图去出 3D。四视图一共 2.6 MB，下载就能看；GLB 是 17 MB。先验形再出模，是本项目控制成本的主要手法——也是我们敢在一场 80 人的园林婚礼里批量用定制人物的原因。

⚠ 四视图任务的记录是「轮询时任务已完成」，所以本组不写生成耗时；报告书里不出现「几秒生成」。

七、两组硬证据：素材闸门与 Agent 在环

差素材进不了重建。这不是事后筛选，是采集端的硬闸：机位数量、三层高度、覆盖角、尺度基准任何一项不达标，评分这一步根本不放行。方案也不许直接落地。提案先预览（绿框标新位、虚线标原位），人点确认才落盘，确认与放弃都写进决策留痕——AI 出方案，人签字。

闸门判据不放行时发生什么
采集闸门六项检查：机位数量、三层高度、方位与重叠、后向补拍、暂光健康、定位覆盖评分 < 50 判重采，素材不进入重建；尺度基准未录入时评分按钮不开
提案闸门人在卡片上点「确认并应用这一版」场景不写入，可撤销，确认 / 放弃均入决策留痕

八、为什么非群核不可

  • 婚礼物料是最典型的长尾定制。花艺拱门、姓氏牌、签到台造型，每样只用一次、改一次就重来，自建生成能力不划算，必须调外部生成；Lux3D 能在同一条对话里被方案上下文驱动（说「生成一个 3 米宽的木质花艺拱门」就能起任务）。
  • 真实场地的门槛在采集质量，不在算法。Aholo Reality 的产物能直接进浏览器端渲染（.spz），不需要我们做重资产转换。
  • 园林场地多是半开放绿地。室内效果图的团队进不去、也量不准；重建出来的场景是唯一能把树冠遮挡、台阶、坡地一起交给客户看的形式。
  • 知道什么不该生成也是判断。座椅、圆桌、隔离带、音响全部用物料库现有 976 个 GLB，只把定制、低频、只用一次的五件交给生成。

九、完成度自证：能做 / 不能做

  • 能做：一句话需求 → 候选场地 → 圈选边界 → 七分区初稿 → 三条流线 → 定制物料 → 图册 / 清单 CSV / DXF / 只读分享链接。
  • 能做：Agent 按八个阶段推进，每步提案都要人确认，确认前不落盘、可撤销、有决策留痕。
  • 不能做：3DGS 只提供观感，不提供精确几何，不能当量尺或碰撞体；摆位精度由 GLB 与矢量壳承担。
  • 不能做：照片 / 视频不是点一下就出可编辑几何，达不到采集阈值就是不可用（49 分判重采）；人物模型只做静态摆放，自动绑骨实测返回 MODEL_NOT_RIGGABLE，不承诺行走与动作。
  • 不能做：分区与数量均为方案暂定值，不代替现场勘测；场地推荐给的是候选与口径，不是勘测结论。

下一步。目标用户是中小活动公司与婚礼策划工作室——10–50 万预算的户外单最痛，他们请不起专职效果图团队。路线是先把「户外 + 单场地 + 可交付」做透：把交付格式（CSV / DXF / 图册）变成和搭建队对接的标准件，再把「选场地」那一问往后接场地库与档期——那就从「做图工具」变成「接单入口」。
