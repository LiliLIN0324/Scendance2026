# tools/units-preview

单位闸门（图纸标注毫米/厘米/米 → 米）的可视化预览。给不跑真实识别的人看效果用。

```sh
npm run preview:units        # http://127.0.0.1:3031
```

端口可用 `SCENDANCE_PREVIEW_PORT` 覆盖。

## 为什么需要它

`_shared/units.ts` 是纯函数，但它的效果只有真实识别（需要 `DEEPSEEK_API_KEY`）才会体现；而"差 1000 倍"这种错误恰恰不看就不知道有多荒谬。这个预览把关键判定摊开：**哪一条测量排除了哪一种单位**。

## 它不复制逻辑

所有数字由 `serve.ts` 直接调用产品模块算出：

```
collectRecognizedSamples → detectPlanUnit → explainUnitFit → normalizeRecognizedUnits
```

`serve.ts` 只 import `supabase/functions/_shared/units.ts`，不做第二份实现；`index.html` 是纯展示层，不含任何换算规则。因此页面显示的东西和线路上跑的东西不可能分叉。

issue 的**文案**由 `reconstruction.ts` 生成，这里只显示字段与 code（`UNIT_CONVERTED` / `UNIT_AMBIGUOUS` / `SCALE_IMPLAUSIBLE`），不复制字符串，避免两处文案漂移。

## 五个场景

| 场景 | 图纸标注 | 期望 | 验证的是 |
| --- | --- | --- | --- |
| 毫米图纸 | 12000 × 8000、墙厚 200、层高 3000、门洞 1000 | 采用毫米 ×0.001 | 最常见的真实情况 |
| 厘米图纸 | 1200 × 800、20、300、100 | 采用厘米 ×0.01 | 单位不是只有毫米一种 |
| 米制图纸 | 12 × 8、0.2、3、1 | 不改动 | 闸门不能画蛇添足 |
| 只有外框 | 12000 × 8000 | 报歧义，不换算 | 毫米和厘米都合理时必须问人 |
| 确认值差 1000 倍 | 已识别 12 m、用户确认 12000 m | `SCALE_IMPLAUSIBLE`，不缩放 | 旧逻辑会把整个场地缩放 1000 倍 |

## 读法

- **① 表**：每个结构长度在三种单位下的米值和是否落进现实区间。绿色是唯一可行的组合。注意 `200 cm = 2 m`、`3000 cm = 30 m` 这类读数就是排除厘米的原因——区间比契约上限窄，否则根本判不出单位。
- **② 判定**：唯一才采用；多个候选报歧义；没有候选就不换算。
- **③**：会被加到核对清单的 issue code。
- **两块画布**：同一个米/像素比例。右侧是换算后的真实尺度（含 1.7 m 人形参照）；左侧是原始数值直接当米——12000 m ≈ 114 个足球场，人形在这一侧不足 1 像素。

## 已知边界

- 它验证的是**单位判定**，不是识别质量：输入是手工构造的"模型返回"，不是真实 DeepSeek 输出。
- 场景里的平面是合成矩形，不含门窗位置、柱子和多段墙的复杂性。
- 画布使用合成几何，只用于展示量级差，不是渲染器的效果预览。
