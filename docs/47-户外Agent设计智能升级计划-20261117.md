## 二、北极星与验收哲学

- **北极星**：用户说「在西湖边办一场 80 人的音乐会」，Agent 给出的布局能回答「为什么舞台朝东、签到为什么在入口内侧、后勤为什么绕开水域」——依据来自真实场地证据，而不是模板惯性。
- **衡量方式**：不追求「拒绝率归零」。允许的失败顺序是：给出有依据的布局 > 明确拒绝并说明缺什么 > 给出无依据的假布局。**第 3 项永远是 0 容忍。**
- 每张卡交付必须含：定向 vitest 套件 + 至少 1 个「修前红/修后绿」的生产函数反例（沿用 docs/44 的红测纪律）。

## 三、架构不变量（任何卡不得违反）

1. 模型不产生几何坐标；几何一律由确定性代码计算并过安全门。
2. `confirm` 走完整确认门（docs/44 §8067e42 第 1 条），不回到原文子串匹配。
3. strictObject 契约只加 optional 字段，不删不改名（`outdoorTurnSchema` 兼容旧 preview）。
4. epoch/ticket/引用 issued context 三套防竞态机制原样保留。
5. 拒绝话术保留：规则引擎判不可行时，说人话说明原因 + 给可操作出路（手画/换场地/缩规模）。
6. 地图像素继续不送模型（A 阶段送的是 OSM 结构化要素，不是瓦片）。
