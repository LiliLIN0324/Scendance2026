## 0. 结论先行

**大部分用不上；只有两处值得动手，一处不建议碰。**

| 结论 | 内容 | 依据 |
|---|---|---|
| **值得立项（唯一新增产能）** | 用 Aholo 单图/多图/文生 3D 补「529 件 CC0 库之外的道具」：20 credits/件、5 分钟级、一件一个 GLB | 本轮实跑成功：127k 面、单网格、PBR 贴图内嵌，8.2 MB |
| **维持现状（不要换）** | 真实场地 → 可编辑场景仍走现有 web-scan 重建 + 我们自己的 SPZ 编辑层；Aholo 不提供「可编辑」增量 | XH-02 双档 SPZ 已在库；本轮单图 3DGS 公开 API 2/2 失败；Aholo 部件拆分对模型 3/3 失败 |
| **不碰** | 把「拆分/3DGS 语义分割」当可编辑方案；公共 API 的 part-split 目前是坏的 | 3 次调用全部 `status=4`，任务详情不返回任何错误字段，0 扣分 |
| **可留作体验线** | 人物绑骨 + 动作重定向（15 + 6 credits）是 Aholo 唯一「我们自己短期做不出」的能力 | 库内 PEOPLE-03 已真跑：18.96 MB 原模 → 41.8 MB 带骨 GLB → 两条动作 GLB |

一句话：**Aholo 对我们是「道具工厂 + 人物动画外包」，不是「场景工厂」。** 场地这条路它替代不了我们已有的重建链路，也解决不了 3DGS「整块不可点」的老问题。

## 2. 能力盘点（按能力归类，不按菜单）

### A. 实景 → 3DGS 重建（web-scan，独立网关 `studio.aholo3d.cn`）

| 项 | 内容 |
|---|---|
| 输入 | 照片（可多张/可 URL）、普通视频（多条）、360° INSV/OSV；`mode=scene|model`、`quality=fast|low|normal`、`steps`、`max_gaussians`、`remove_people` |
| 产物 | PLY / SPZ（可双档 LOD，带 `lodMetaPath`）；可开 `public_access` 拿公开 URL（关闭后旧 URL 404） |
| 硬限制 | 12–1,000,000 张；同一场景必须同画幅同镜头；`quality: high` **只对 INSV/OSV 导入有效**，照片传 high 直接 422 |
| 耗时 | 分段十几分钟到 90 分钟量级（库内记录）；失败的常见形态是 **8 秒秒败** |
| 失败表现 | `Fewer than 12 photos have reliable camera positions`；混画幅 422 `Keep the same aspect ratio and lens within one scene`；World API 失败**无错误字段**（`status=FAILED`、产物 URL 全 null） |
| 证据级别 | **库内实跑**（XH-02 双档、29 张两次失败、130 张 12/130 登记）+ **接口读到**（openapi.json） |

### B. 单图 / 多图 / 文生 → 网格模型（公开 API，本轮实跑）

| 项 | 内容 |
|---|---|
| 输入 | 单图（PNG/JPG/WEBP ≤10 MB，dataURL 或 URL）；多图 ≤32 张；或纯文本 prompt |
| 参数 | `version=G1`、`faceCount`（档位 100k/200k/300k）、`style`（7 种：写实/卡通/二次元/手绘/赛博/奇幻/玻璃）、`outputFormat=[zip,glb]` |
| 产物 | 一个**单网格、单材质** GLB（PBR 贴图内嵌）+ 原始 PBR 滤镜图（diffuse/reflect/gloss/fresnel/refract） |
| 耗时 | 本轮 2048 宽单图 → **325 s（5.4 分钟）**；站点自称 Turbo 20–60 s、标准 3–5 min |
| 计费 | 20 credits/次（成功才扣；失败 0） |
| 失败表现 | 极少数直接 422；`outputType=3dgs` 走公开 API 时 **55–57 秒后 status=4，任务详情无 error 字段、0 扣分** |
| 证据级别 | **本轮实跑成功 1 次**（参数与产物见 §3）；失败 2 次 |

### C. Turbo 极速版（页面有，公开 API 不认）

页面配置 `generationEditionConfig` 明确：`fastEnabled=true`、`fastOutputTypes=["mesh","3dgs"]`、`defaultFastPbrEnabled=false`、单图可去背景。**但公开 API 传 `generationEdition:"fast"` 会被忽略**：本轮同一图走公开 API 拿到的是标准档结果（20 credits、5.5 分钟、PBR 图全出），不是 Turbo。要真正用 Turbo/3DGS，只能进工作台（页面操作），没有 API 口。
证据级别：**页面/接口读到** + 本轮反证。

### D. 人物绑骨 + 动作重定向（公开 API，库内实跑）

| 项 | 内容 |
|---|---|
| 输入 | 绑骨：一个 GLB（≤500 MB，ZIP 内也必须是 GLB）；重定向：已绑骨的 `rigModelUrl` + `animationIds`（**一次 1–10 条**） |
| 产物 | 绑骨 GLB（含 skin）；每条动作一个带动画 GLB；可导 GLB/FBX（保留骨骼动画），OBJ/STL/3MF/PLY（丢骨骼） |
| 限制 | **只支持标准人形**；必须 T-Pose/A-Pose、Y-up Z-front；不能带武器/飘带/尾巴（会绑错）；**3DGS 不能绑**；输入不能带关键帧 |
| 耗时/计费 | PEOPLE-03：18.96 MB 原模 → 220 s 内出 41.82 MB 带骨 GLB（15 credits）；两条动作 6 credits |
| 失败表现 | 参数错会明确报：`animationIds must contain 1 to 10 actions`；素材形态不对时 `status=4` 且无原因 |
| 证据级别 | **库内实跑**（`docs/evidence/aholo/people03b-hanfu-rig/`）+ 接口读到 |

### E. 图像侧（四视图 / 多模态生图 / 7 种风格）

- 四视图：24 credits，输入单图或 prompt，出 4 张固定视角图，喂给多图 3D 提高一致性。
- 多模态生图：12 credits，图或文 → 概念图。
- 证据级别：**库内实跑**（历史任务 4829906/4826419 四视图、4829794/4826379 多模态，均成功）+ 页面读到风格枚举。
- 对我们的用途：只够「给甲方的概念图」，不进入 3D 链路。

### F. 工作台 / 节点画布 / 资产库（Web UI）

浏览器实测（未登录）：`https://lux3d.aholo3d.cn/workspace` 可浏览「工作台模式」「节点画布模式」，右上角有「登录」，资产库提示「登录后查看资产库」。节点画布是任务编排（图生 3D → 四视图 → 材质 → 拆分 → 导出），**本质是把已有能力串起来，不产生新能力**。
证据级别：**页面实看**（本轮浏览器）。

### G. 材质重绘 / 格式转换 / 重拓扑 / 部件拆分

- 页面存在、计费存在（材质 7、格式转换 1、重拓扑 6、拆分 30 credits）。
- **公开 API 404**（`/lux3d/v1/material-edit|format-conversion|retopology|rigging` 全部 `No matching API found`）→ 只能在工作台里点。
- 部件拆分有公开端点，但**本轮 3/3 失败**（见 §3），不能作为方案依赖。
- 证据级别：页面/计费读到 + 本轮失败实跑。

### H. LuxReal 实时渲染（工作台节点）

页面与节点表里有，作为「预览/出图」用；本轮未实跑，且与我们的交付包无关。

## 4. 逐条对上我们的五步

| 我们的环节 | 具体麻烦 | Aholo 顶不顶得上 | 理由（一句话） |
|---|---|---|---|
| ① 场地采集 | 手机/无人机素材规格不齐，混画幅秒拒 | **顶不上** | 它只收素材，不做采集；且规则比我们更严（同画幅同镜头） |
| ② 场地重建 | 低纹理失败无原因、质量不可控、SPZ 整块不可点 | **顶不上（但可继续当供应商）** | 重建能出 SPZ，但「可编辑」它没有；部件拆分只对网格且 3/3 失败 |
| ③ 场景里摆东西 | 库外道具要人找/人做；31 件轴误判 | **有条件可用** | 单图/文生 3D 5 分钟出一件 PBR 道具，正好补库外缺口；但一件=一个融合网格，不能拆成多件摆 |
| ④ 摆完看得过去 | 效果图是截图级 | **有条件可用（低优先）** | 四视图/多模态能给提案概念图，不能替代我们的机位渲染 |
| ⑤ 交付 | 一键 zip 已打通 | **无关** | 它没有交付物概念，别接进来 |
| ⑥ 人物 | 古风人形要能走一圈 | **顶得上（唯一硬需求）** | 绑骨 15 + 动作 6，已出 41.8 MB 带骨 GLB 与两条动作；代价是必须 T-pose、无飘带、3DGS 不能绑 |

**明确顶不上的**：让 3DGS 场景变成「一件件可点选、可移动」的物体。Aholo 没有 3DGS 语义分割/拆件；我们 docs/22 的结论同样成立——这条路只能靠我们自己的 `SplatEdit`/`clipXyz` 做区域编辑，别指望外部。

## 5. 能用它做什么（立项口径）

**先做（建议立刻排期，1 张卡）**：`道具补件`。
- 动作：给「库外但客户要」的道具（如特定灯笼、定制舞台背景、地方特色器物）一张正面照 → 单图 3D → 归一化 → 入 529 件库。
- 素材准备：单张 ≥1024 像素、主体完整、背景干净（去背景在工作台可勾，API 没有）。
- 量级：**20 credits + 5.5 分钟/件**，产物 8 MB 级，可直接进现有归一化与摆放链路。
- 风险：单网格不可分件；面数档位不可控（本次要 200k 实出 127k）；纹理是烘焙 PBR，近看会糊；失败不退款以外的信息一概没有。

**第二步（体验线，等 W4 排到再做）**：`人物动画外包`。
- 动作：人形 T-pose GLB（≤500 MB）→ 绑骨（15 credits）→ 选 1–10 条动作（6 credits/条）→ 入场景。
- 风险：飘带/武器会绑歪；3DGS 不能绑；41.8 MB/条的体积对分享链接不友好；动作库是否覆盖「古风走一圈」还需逐条试。

**不做**：
- 不做「单图 3DGS 快速场地」——公开 API 2/2 失败，工作台参数不可自动化。
- 不做「部件拆分」——3/3 失败且无错误原因，不能写进任何流程。
- 不把四视图/多模态生图接进 3D 链路——它们只出 2D 图，和摆放无关。
