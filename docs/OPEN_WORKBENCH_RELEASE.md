# 默认开放工作台

访客可以直接进入工作台，首次 Agent 请求自动使用 Supabase 的真实匿名会话，在自己的工作室中创建当前场景副本并取得租约；已有登录和绑定项目直接复用。界面保留当前几何、需求资料和输入，同一次发送继续生成。后台仍逐用户隔离项目和素材，租约、修订、几何校验继续执行。取消或准备期间修改场景不会提交旧 AI 请求。

本次整合登录页的「访客进入」入口。访客凭据保留在当前浏览器，重新打开页面时必须经过服务端身份校验；自动准备会复用该访客拥有的已保存项目。同一访客的多个标签页使用 Web Locks 串行刷新凭据，旧请求失败不能删除新的备份。普通账号仍保留原有每标签页会话行为。退出或清除浏览器数据后，匿名身份无法通过邮箱找回。

账户面板的团队权限是演示状态，默认所有角色的选项全部开启；切换不会限制编辑、Agent 或交付。它不授予其他用户私有数据的访问权，也不改变真实工作室的删除或成员管理权限。

体育馆等十种打包场景通过已知预设和节点引用保存，预设场景最多 500 件，普通场景仍为 50 件。具体模型契约见 `contracts/PRESET_SCENES.md`。后台接受已验证匿名用户，不接受未签名身份或共享管理员身份。需要开启 Supabase Auth `external_anonymous_users_enabled`。

大型场景传给 DeepSeek 时使用无损的列/行编码，省去重复的场景副本。JEV 大型请求聚焦三个方案的全部差异物件、附近共享物件和相关校验结果，并明确标注其余共享几何未传入；完整场景仍由程序校验。存储的场景格式、完整数字精度、几何和预算检查不变。预览差异比较补齐可选默认字段并容忍浮点往返误差，增加一张桌子只计为一个新增，不会把原有预设误报为全部改动。

Agent 仍最多 6 轮、90 秒；第 6 轮必须调用候选提交工具，避免模型在校验后继续检索而不交付。提交仍经过原有校验，不会将中间校验结果直接应用。JEV 只评估通过检查的三个不同方案，显示相对推荐概率，由用户选择。

上线顺序：执行 `20261003210000_preset_scene_access.sql` → 部署 scene-api → 开启匿名会话 → 验证真实访客 Agent → 发布前端并完成无登录浏览器验收。不会重新部署两个 worker，也不会恢复 HY3。

实现依据：[Supabase 匿名登录](https://supabase.com/docs/guides/auth/auth-anonymous)、[Auth 配置 API](https://supabase.com/docs/reference/api/v1-update-auth-service-config)。本次修改默认进入、自动准备项目、演示权限与实际预设场景的 Agent 兼容。
