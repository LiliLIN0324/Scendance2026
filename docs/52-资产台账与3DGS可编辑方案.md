### 1.3 “椅子比桌子大”的根因

|---|---|---|---|
| 舞台顶棚 `live-music-venue...stage-roof-canopy` | 3.00 × 6.31 × 0.54 | 3.00 × 0.54 × 6.31 | +1064.8% |
| 教堂屋顶单元 `wedding-and-chapel-kit-chapel-roof-bay` | 2.00 × 8.04 × 1.71 | 2.00 × 1.71 × 8.04 | +370.4% |
| 游艇舱篷 `powerboat-racing...cabin-cruiser-canopy` | 2.70 × 8.15 × 2.72 | 2.70 × 2.72 × 8.15 | +199.2% |
| 轿车 `car-park-and-road-vehicle-fleet-saloon` | 2.00 × 4.82 × 1.40 | 2.00 × 1.40 × 4.82 | +243.7% |

## 二、高斯可编辑的可行路径

### 2.1 现状与可直接复用的能力

当前点云是“整块环境”：`SplatMesh` 只加载一个 `.spz`，整场只做整体缩放/旋转/平移；屋顶裁切是 GPU 侧的 world modifier 按 Y 丢弃（[splat-preview.ts:777-795](file:///c:/Users/13266/.dsh/bot/workspace/Scendance2026/frontend/components/room-organizer/three/splat-preview.ts#L777-L795)）。代码注释也明确写了“点云不参与拾取、一件都点不着”（同文件 329、376 行）。

Spark 2.4.0 已经具备下面这些编辑原材料，不需要换引擎：

| 能力 | API | 说明 |
|---|---|---|
| 逐颗遍历 | `SplatMesh.forEachSplat` / `PackedSplats.forEachSplat` | 拿到中心、尺度、四元数、不透明度、颜色 |
| 逐颗读写 | `PackedSplats.getSplat` / `setSplat` | 可原地改中心；SH 存在 `extra.sh1..3` 独立数组中 |
| 子集抽取 | `PackedSplats.extractSplats(indices, pageColoring)` | CPU 纯 JS，返回新的 `PackedSplats` |
| 点击射线 | `SplatMesh.raycast(raycaster, intersects)` | 返回 `{distance, point, object}`，**不返回 splat 索引** |
| GPU 区域编辑 | `SplatEdit` + `SplatEditSdf` | 支持 `plane/box/sphere/ellipsoid/cylinder/capsule/cone`，可 `invert`、`opacity`、`displace` |
| SPZ 转码 | `transcodeSpz({ inputs, clipXyz, transform, maxSh, fractionalBits })` | 文件字节进、SPZ 字节出；支持 PLY→SPZ |
| SPZ 写出 | `writeSpz(PackedSplats / ExtSplats)` | 内存对象进、SPZ 字节出 |
| PLY 写出 | 无 | Spark 2.4.0 只有 PLY 读取，没有 PLY writer |

实测（本机 Node，真实产物 `scendance-m3-mvp.spz`，262,991 splats / 4.39 MB）：

| 操作 | 结果 | 耗时 |
|---|---|---|
| SPZ 原样重编码 | 262,991 splats，字节完全一致：否；307,083 / 4,388,014 字节不同（7.0%），文件大小相同 | 297 ms |
| `clipXyz` 裁掉一半 | 131,820 splats（正好一半），2.20 MB | 144 ms |
| `transform.translate +1 m` | 262,991 splats，体积不变 | 232 ms |
| 17 MB PLY → SPZ | 262,991 splats，与源 SPZ 数量一致 | 324 ms |
| 294,615 splats / SH3 / v2 → v3 | 数量与 SH3 保留，18.85 → 19.15 MB | 309 ms |

原始采集里最大的一份是 1,327,712 splats / 22.1 MB SPZ（解压后 85.0 MB，SH3），这是后面所有内存估算的上限。

### 2.2 选中

**能不能点选“某一颗”高斯：不能精确。** `raycast` 只返回命中的世界坐标点，不返回索引；要精确到颗，需要自己写 GPU ID pass，Spark 没暴露这条管线，硬做会绑死内部实现。

**语义分割：不建议。** 没有 3DGS 语义标签，浏览器里要跑 SAM 类模型再做深度反投影，属于研究型任务；对“裁掉一块/移动一块”这个目标，收益远低于框选。

**可行且推荐的选中方式：**

1. 屏幕空间框选 / 套索：把每颗中心用当前相机投影到屏幕，落在多边形内且深度在给定区间的进入选择集。一次 O(n)，在 pointerup 时算一次，拖动过程只画框。
2. 点击拾取：`SplatMesh.raycast` 得到一个表面点，再用“点到中心距离 < 半径”补一个球形选区；这不是精确单颗，但符合“点一下选中附近一片”的直觉。
3. 可选的点云连通扩张：以点击点为种子，在体素网格上做相邻扩张，适合物体与背景分离清楚的场景；不建议默认开，容易漏选/串选。

实现落点（本轮不写）：新增 `lib/splat-edit/selection.ts`（投影、多边形测试、球形/平面谓词、索引位图），新增 `three/splat-edit-overlay.ts`（框选层与选中点高亮）；从现有 `useSplatPreview` 暴露 `mesh` 句柄即可，不改 `splat-preview.ts`。
工作量：中，约 250–400 行。风险：1.3M splats 的单次投影在低端机上约百毫秒级，必须把重计算放在 pointerup，不能每帧算。

### 2.3 裁剪

**渲染预览：可以做。** 复用现有 `SplatEdit`/`SplatEditSdf`：BOX 或 PLANE + `invert` + `opacity = 0`，与屋顶裁切同一类做法，GPU 即时生效、不改数据。
**烘焙导出：可以做。** 两种路径：

- 轴对齐盒裁切：直接 `transcodeSpz({ clipXyz })`，实测 144 ms 裁掉一半，且保留 SH；适合“整档裁一块”。
- 任意形状/框选裁切：用选择集取补集 → `packedSplats.extractSplats(remaining)` → `writeSpz`；适合“按选中的一片裁”。

工作量：小到中，约 150–250 行。风险：`extractSplats` 走 `getSplat/pushSplat`，只带 DC 颜色，**会丢 SH1–3**；对当前 shDegree=0 的生成场景无损，对 SH3 原始采集会改变观感（反射/视角色）。要保 SH，得自己按索引压缩 `extra.sh1/2/3`，不能直接用 `extractSplats`。

### 2.4 移动

**渲染预览：可以做，而且是现成的。** `SplatEditSdf` 有 `displace: Vector3`，给一个包住选区的 BOX SDF，就能把这片高斯整体平移；GPU 侧每帧生效，不改数据、可撤销。

**持久化：两条路。**

1. 分块对象化（推荐）：把选中的子集抽成独立 `SplatMesh`（“一块高斯”），给它自己的 position/quaternion；整块移动就是移动这个对象。导出时输出“原档 + 每块 SPZ + 场景 manifest”。原档字节不变，移动无重编码。
2. 单文件烘焙：在 `PackedSplats.packedArray` 上只改中心编码（或 `setSplat` 回写）；SH 数组按索引对齐，平移不影响 SH。适合必须交一个标准 `.spz` 的场合。

工作量：中，约 200–300 行。风险：SDF 的 `displace` 只影响渲染，`raycast`、`getBoundingBox`、CPU 选择仍按旧中心算；移动后再点击会打空/打偏，必须把对象变换带进拾取换算。

### 2.5 回写

| 目标 | 能不能 | 说明 |
|---|---|---|
| 导出 `.spz` | 能 | `writeSpz`（内存 `PackedSplats`）或 `transcodeSpz`（文件字节 + clip/transform） |
| 导出 `.ply` | **不能直接用** | Spark 2.4.0 无 PLY writer；需自己写标准 3DGS PLY（17 属性 DC 版或 62 属性 SH3 版），或引第三方库 |
| `.ply` / `.spz` 字节级往返 | **不能** | 原样重编码就有 7.0% 字节不同；PLY→SPZ→SPZ 同样不同。量化（位置 12 位、scale/rot/color 8 位）与压缩分块导致不可逆 |
| 视觉级还原 | 大概率可以，但未验证 | 位置量化误差约为场景尺度的 1/8192；颜色 8 位可能出色带。必须用固定机位渲染帧做 PSNR/SSIM 或并排目检后才能签字 |

**字节级不丢的唯一做法**：不重编码未编辑的数据。保留原始文件，另存一份 edit manifest（选择索引、裁剪谓词、每块变换、操作顺序）；只有被编辑的子块重新编码。这样未动过的 splats 字节完全不变，动过的部分视觉近似。

工作量：SPZ 路径小（约 80–120 行）；PLY writer 中（约 200–300 行）；manifest 小。风险：内存与 Blob 体积——1.3M splats 的 SH3 解压后 85 MB，带 SH3 的 PLY 约 300 MB，移动端浏览器会直接崩；PLY 导出应只对桌面开放，移动端只出 `.spz`。

### 2.6 建议的落地顺序

| 阶段 | 内容 | 依赖 | 工作量 |
|---|---|---|---|
| P0 | 框选/套索 + 点击种子选区 + 选中高亮；BOX/PLANE 裁剪预览；导出裁剪后的 `.spz` | Spark 现有 API | 中，约 400–600 行 |
| P1 | 选中子集成为独立“高斯块”，整块移动/旋转；导出 `原档 + 块.spz + manifest` | P0 的选择集 | 中，约 250–350 行 |
| P2 | 单文件烘焙（中心写回 + SPZ 导出）；SH 按索引压缩（保 SH3） | P1 的块模型 | 中，约 250–400 行 |
| P3 | 桌面端 PLY 导出 + 帧差验收 | P2 的烘焙结果 | 中，约 200–300 行 |

合计约 1,100–1,650 行新代码，全部放在新增文件里；现有 `three/splat-preview.ts` 只需在实现阶段暴露 `mesh`/`packedSplats` 句柄，不需要改它的渲染逻辑。

### 2.7 明确不做的

- 精确“点中某一颗高斯”：API 不返回索引，不做 GPU ID pass。
- 语义分割选物体：没有标签与现成模型，浏览器内不做。
- 浏览器内字节级往返：量化管线决定做不到，不承诺。
- 移动端 PLY 导出：内存上限不允许，不做。
