## 2. 侦察结论（2026-11-12 六线只读盘点，证据齐全）

**总表：现有程度**

| # | 能力线 | 程度 | 一句话 |
|---|--------|------|--------|
| 1 | 场地理解（chat 说地名） | 雏形 | 正则闸门+槽位填充分齐全，但**无地点/场地名槽位**；地名通路只有「调研X」一条动词门 + 两个按钮入口 |
| 2 | 地名检索与地理锚定 | 可用 | POI 检索/行政区边界/OSM POI 占地轮廓/GCJ-02 锚点全链路可用，但检索结果**只动视图不写 plan.anchor**，2D/3D 双锚点轨未打通 |
| 3 | 流线/道路/入口 | 可用（手画） | 三类动线（人行/车辆/后勤）+出入口节点数据模型成熟、编辑交互完整，但**全部手画**，无 OSM 路网矢量、无自动生成 |
| 4 | 区域/事件/物料自动排布 | 雏形 | zone 9 语义 + 目录 549 条 + 落位冲突检查可用；自动排布仅室内宴会规则引擎，outdoor 全手放、无「区域→事件」概念 |
| 5 | 人群流动模拟 | 雏形 | 静态人群散布、室内氛围 3 人巡走、室内 WalkRoute 行走三套并存，**outdoor 无流动模拟**且 2D 流线与行走引擎不互通 |
| 6 | 2D图标↔3D模型+生成/上传 | 可用 | 贴纸↔模型双向映射 + 每模板 3 候选自动挑选可用，Aholo 文生/图生/场景/重建四条通路全接 UI；缺手动候选切换（B1..B4）与上传入口 |

- 视图辅助不落库：`plan-place-search.tsx` + `outdoor-plan-overlay.tsx:373-407`（placePin/placeArea → `focusBounds`/`focusLngLat`，注释原话「定位钉只是视图辅助（不改 plan / anchor）」）
- 双轨暗雷：`plan.anchor`（site-plan.ts:24，source picker/lookup/manual/asset-geo/preset）与 `SceneAnchor`（scene-anchor.ts:15）**互不回写**

- zone 语义：`site-plan.ts:48` `planZoneSemantics=['stage','audience','parking','loading','checkin','queue','medical','vip','reserved']`；facility/worker 有 zoneId，**zone 无 event 概念**

- 模型候选：`plan-facility-models.ts` `resolveFacilityModels`（内置映射）+ `loadFacilityModelCandidates`（在线库打分 topN，MAX_CANDIDATES=3），`selectFacilityModel` 自动挑、**无手动切换 UI**；消费方 `three/plan-model-layer.ts:204`

## 4. 架构判断：一条脊柱 + 三个生成器 + 一个 UI 补层

```
「在潮乐之城去做设计」
   │ V-1 脊柱：抽地名 → 回显候选气泡 → 确认 → 轮廓/行政区/手画兜底
   │          → 写 plan.anchor + sceneAnchor（两轨一次写对）+ plan.boundary → 相机框选
   ├─ V-2 生成器A：路网矢量 → 等级映射 → 流线+入口草案 → 虚线预览 → 确认 commitPlan
   ├─ V-3 生成器B：区域划分(zone.event) → 物料选型落位 → 预览 → 确认 commitPlan
   ├─ V-4 增强：zone 子出入口 + 流动模拟（2D 流动动画 v1，3D 行走后置）
   └─ V-5 独立层：属性面板模型候选 B1..B4 手动切换 + 生成/上传入口
```

纪律不变：所有生成器**只出预览**，确认才写画布（「听懂了会回显，确认后才写进画布」是现有头部话术，不破坏）；undo 栈全覆盖。

## 6. 依赖与施工顺序

```
V-1（脊柱） ─→ V-2（流线，先于区域） ─→ V-3（区域物料） ─→ V-4（子入口+模拟）
   └──────────────── V-5 独立，可提前或穿插 ────────────────┘
```
