## 1. 环境与「断网手段」的定档（这一段决定本条能判到哪一档）

清单 §1 预检 0.4 要求「能切 DevTools offline（或系统断网）」。本环境逐条试过，结论是**只能做到页面级**：

| 尝试的路子 | 结果 |
| --- | --- |
| DevTools offline 开关 | ❌ 会话内置 Browser（Electron FilePanel）不暴露 DevTools |
| CDP `Network.emulateNetworkConditions` | ❌ 9222 端口是 Edge 的 `--no-startup-window` 后台进程，`/json/version` 为空，不是 CDP 端点；本机没有可连的 CDP |
| 系统级断网（hosts / 防火墙 / 改系统代理） | ❌ 本会话**不是管理员**（`IsInRole(Administrator)` = False），改 hosts 需要提权；且系统代理会影响同机其它会话 |
| **页面级请求失败注入** | ✅ 采用：覆写 `window.fetch`（reject `TypeError: Failed to fetch`）、`XMLHttpRequest.prototype.open`（抛 `NetworkError`）、`Navigator.prototype.onLine`（false），并派发 `offline` 事件 |

**因此：这不是系统级断网**。影响面如实登记：

- 覆盖：`fetch` / `XMLHttpRequest` 发出的全部请求 —— 包括检索（`/api/amap-place`）、地图证据（`/api/site-context`、`tiles.openfreemap.org`）、
  云端读写（`scene-api/*`、`conversation-api/assistant/chat/stream`）。
- **不覆盖**：底图瓦片走 `<img>`（同源 `/api/carto-tiles`），不经过 `fetch` → 瓦片仍能加载，
  所以「地图部分（瓦片）」这一维度的降级**本轮没验到**。
- **不覆盖**：应用自带的超时（`AbortSignal.timeout`）与真实网络抖动的区别 —— 注入是立即 reject，比真实超时更硬。

**结论：#5 这轮判成 `partial`（不构成通过）**，并登记两个缺陷：

### 缺陷 1：离线时地图检索没有降级文案，且本地缓存冒充检索结果

- 复现：断网 → 地图左上角「搜地点」输入任意词 → 下拉里仍出现「最近选过」的同名/同前缀条目，且没有任何离线提示。
- 危害：用户以为检索成功了，选中的其实是上次的缓存地点；后续「按这块地设计」会建在错的场地信息上。
- 归属：`frontend/components/room-organizer/components/plan-place-search.tsx` —— 检索失败被 `lib/place-search.ts` 的
  「失败一律回空数组」吞成「没建议」，界面无法区分「没搜到」与「搜不到」；`buildPlaceSearchOptions` 又把「最近选过」无条件并进候选列表。
- 备注：`lib/place-search.ts` 的注释自己写明了「检索失败一律回空数组——调用方只当作『没建议』，不弹错」。这是**已知取舍**，不是本轮新引入的回归。

### 缺陷 2：断网下点「确认并应用这一版」，写入进行态不收口

- 复现：断网 → 点「确认并应用这一版」→ 卡片停在「正在把「确认当前活动范围」写入画布…」约 1 分钟，不报失败也不提示「云端没写成」。
- 危害：用户无法判断这一版到底写没写进去；恢复网络后也不会自动补写（本轮实测不静默重放），草稿与云端可能长期不一致。
- 归属：户外工作流的应用写入分支（`hooks/use-outdoor-agent-workflow.ts` 的应用/提交链路）对「云端写失败」的收口没有落到终态提示。

## 4. 缺口（环境层，不是产品缺陷，但影响可判口径）

1. **无法做系统级断网**：本会话非管理员，内置浏览器无 DevTools/offline、9222 非 CDP 端点。
2. **无法导出 HAR**：内置浏览器不提供 DevTools HAR 导出；本轮的请求证据改用「内置浏览器网络查询 + 页面内注入拦截记录」两条代替（原始读数已写进本文件与 `../02/2026-11-18-case02-search-responses.json`）。
3. **底图瓦片（`<img>`）未被注入覆盖**，「地图部分」里瓦片那一格没验到。
4. **云端 revision 没有前后对照读数**：断网前没记下云端 revision，恢复后也没专门读一次；只拿得到「写请求未出网 + 本地几何未变」这一侧证据。
   因此 **#5 的云端键没有点**（记录本里 `#5` 只标了「不构成通过」，云端列仍为未看）。
