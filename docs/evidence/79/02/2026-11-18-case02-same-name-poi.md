## 2. 前置：同名对是怎么找到的（这一步此前卡了两轮）

清单 §2 要求「预先找一对**名称完全相同、坐标不同**的 POI」。实测过程：

1. 先用生产端点 `/api/amap-place` 扫了 17 个通用词（公园/广场/小区/体育馆/博物馆/医院/银行/人民公园/文化宫/客运站/步行街/人民医院/汽车站/实验小学/文化广场/中心广场/人民广场）——
   **一个同名对都没有**；其中大量请求返回 `place failed`（502，高德配额类 infocode，函数内部重试 3 次仍失败），
   `no place`（404）也很多。线上 `limit` 被 `functions/api/amap-place.ts` 夹到 **10**。
2. 换本机 3199 代理（天地图 + 高德双源），对 40 个词 × 2 源 × limit=6 扫描，找「同名且坐标相距 > 500 m」的条目：
   「人民公园」×5、「市民广场」×6、「文化广场」×5、「**街心公园**」×4（高德单源，id 全为 `B0…`/`B000…` 前缀）。
3. 选「街心公园」做本用例：4 条同名条目分布在**北京海淀 / 大兴 / 密云 / 房山**，最远相距约 **89.8 km**，坐标差异远大于任何合并阈值。
4. 复核生产端点：`GET /api/amap-place?keywords=街心公园` → 同样 5 条、**同样的 id 与坐标**（生产与本机用的是同一把高德 key）。

## 5. 缺口与没做的事（不掩盖）

1. **「选中后的 project 读取」没有单独证据**：正式站页面加载期的请求落在抓取窗口之前；本轮只抓到轮询类云端读与检索类读。
   写请求为 0 是硬证据，「project 读取」这一项按缺记处理。
2. **底图瓦片在正式站上呈灰色**：地图飞到北京大兴后瓦片未铺上（`<img>` 走同源 `/api/carto-tiles`），
   本轮未追查是否与本环境代理有关；不影响候选与归属读数（判定不依赖瓦片）。
3. **未在生产站点「确认并应用这一版」**：#2 是只读用例，云端列要求零写，点确认会触发写请求，故不在本用例内点。
   （#5 里点过一次，见 `../05/2026-11-18-case05-offline.md`。）
4. **对话侧只给了前 3 个同名标题**（卡上只列 1./2./3.）：这是产品既有设计（`plan-place-search.tsx` 注释：chat 卡只给前三个标题），
