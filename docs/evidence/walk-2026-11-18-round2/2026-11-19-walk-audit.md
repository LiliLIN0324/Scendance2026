# 漫游第三轮：通行体检 / 流线导航 / 观景位（2026-11-19 凌晨）

这一轮把漫游从「能走」往「能出结论」推：走一遍之后要能说清哪里走不到、哪条流线被挡、
站在这里能不能看见舞台，以及把这个机位存下来发给客户。四个新模块都是纯函数，带单测；
界面入口接在漫游 HUD 与角色卡上。

## 真机走查（本地 Chromium + swiftshader）

注入的草稿：30×20 m 红线、一道贯穿隔断（x=6）、主舞台（x=10）、侧面帐篷；走查只读
`data-testid` 文本与 `__scendancePlan3dDebug` 的相机位。

| 项 | 读数 |
| --- | --- |
| 「存观景位」按钮 | **存在**（`outdoor-walk-spot`） |
| 「体检」条 | 首版渲染过，但内容是 **「体检 · 可达 0% · 3 件设施走不到」**；已定位为探针草稿被归一（见下） |
| 相机动没动 | 动了：`(0, 1.6, 0)` → `(-4.78, 1.6, 8.71)`，约 10 m |
| 边界提示 | **已触发**（小场地复测）：8×6 m 场地从中心往南走，第 3 个采样出现「已到场地边界」，相机 z = 2.86（边 3.0 − 半径 0.28） |

### 已定位：0% 可达是探针草稿被归一，不是体检错

验收桥读出应用侧实际拿到的 plan：注入的「隔断」宽 0.6 m、深 21 m，到应用里变成 **21×21** 的方形占地（非模板块被归一成正方形），把进场点整个盖住。体检报 0% 对这份几何是对的。

换成仓库里的经典案例（Scotiabank replica，60 设施 / 4 条流线，尺寸由模板决定）后，真机读数为：

| 项 | 读数 |
| --- | --- |
| 体检行 | `可达 100% · 1 条流线被挡 · 最窄 0.50 m · 看「40×50 公共帐篷」被挡`（首版） |
| 可达面积 | 37667.9 m²，比例 1.0 |
| 流线 | 4 条，1 条被挡；位置 38.7 m，挡路设施 `Bus Parking 引导车 1` |
| 视线 | 「40×50 公共帐篷」在 4.8 m 处被挡（占视线 8%） |

首版「最窄 0.50 m」是误报：流线贴着红线走，场外被算成了障碍。已修为只按设施障碍算距离，
新增单测「贴红线的流线不报窄通道」，修正后同一套体检不再把贴边流线当窄通道。

## 这一轮明确没做

- 分享页（`app/view/page.tsx`）接漫游：分享快照里没有户外 plan，接进去要改分享契约，不在本轮。
- 相机俯仰遮挡：只做了水平后拉，抬头穿楼板不在范围内。
- 3D 里把成稿流线画成线：导航只有 HUD 文本。
- 边界提示的真机验证：已在 8×6 m 小场地上验证（见上）；大场地因无头帧率低没走到边。
