# SC-16 · 首单交付验收（B3）

本轮把「出包 → 下载 → 打开链接」整条链路跑成可复现的验收，按 `docs/24` 的 1-1～1-6 逐条给结论。
能自动验的写成测试并入 `npm run gate`；不能自动验的（人眼、甲方、30 天有效期）在这里标清楚还差什么。

## 结论（一句话）

四件套装得出来、装得对、同版一致；**效果图还没有水印和版号，清单还没有单价**，这两条是对外交付前的硬缺口。

## 复现

```bash
# 夹具批量验收（并把结果写回本目录）
cd frontend
DELIVERY_ACCEPTANCE_OUT=../docs/evidence/SC-16/acceptance-run.json \
  npx vitest run components/room-organizer/lib/delivery-acceptance.test.ts

# 整仓门禁（含这条测试）
cd .. && npm run gate
```

真机那两步是 `.temp/sc16-browser-probe.cjs`、`.temp/sc16-review-probe.cjs`（一次性脚本，不入库）：
起 `npm --prefix frontend run dev -- -p 3001`，探针用 Playwright 驱动本机 Chrome，点确认版、点出包、保存下载、
解包读 PNG 头 / DXF / CSV / manifest，再打开分享链接取页面身份节点。

## 本轮发现的环境事实（不是缺陷）

- 新项目会自动载入 World 高斯样场，样场校准会把场地尺寸改写成 23.8 × 16.1 米，并把物料 `provenance` 标成 `ai`。
  四件套仍按改写后的尺寸保持一致；夹具路径不受影响（夹具直接用给定布局出包）。
- 分享页 dev 冷启首屏约 68 s 全是 Next 编译，热启 7.2 s。上线测首屏要用生产静态导出。
