# Agent 工具循环与双交付形态——PetitMaker 对标收敛卡（2026-11-21）

> 定位：[47-户外Agent设计智能升级计划-20261117.md](47-户外Agent设计智能升级计划-20261117.md) 的 **Phase F**，由 [48-PetitMaker-Agent对标实测-20261121.md](48-PetitMaker-Agent对标实测-20261121.md) 四轮实机对标触发。docs/47 的 A–E 卡不废弃：A（证据扩展）与 B1（可布置域）是本卡的地基；C（意图偏好）与本卡并存过渡。
> 核心主张：把 design-event 从「一次性大 JSON」演进为**多步工具循环**——模型持画布工具逐步施工，思考逐步外显，监督按后果分级；「设计」与「执行」成为两种交付形态，由请求动词决定。

## 一、触发证据（详见 docs/48）

PetitMaker 四轮实测：114 步 / 1071 处改动全自动建婚礼场地；纯活动描述自创 9 分区画布提案 + 回滚待批 + 「按这个方案开工」；显式「先只做分区」被精确执行并显式交棒。四条机制：单循环 + 世界状态工具、思考逐步外显、监督按后果分级、设计/执行双交付形态。

## 二、对 docs/47 不变量的修订（本卡专属，需人 review）

| 不变量 | 原文 | Phase F 修订 |
| --- | --- | --- |
| 1 | 模型不产生几何坐标；几何一律由确定性代码计算并过安全门 | **设计任务内放开**：模型经画布工具产生格子级操作（放置/铺路/清场），每个操作仍过确定性安全门（边界钳制/容量粗筛/敏感输入）；「确定性代码计算几何」保留在引擎侧的自动排布路径（wedding-layout 等），两条路径并存 |
| 6 | 地图像素不送模型 | 不变。工具返回的是**结构化**读数（区域清单/平地格集合/物品清单），不是像素 |
| 2/3/4/5 | 确认门 / strictObject 兼容 / 防竞态 / 拒绝话术 | 不变。确认门演化为「按后果分级」（F2），strictObject 只加 optional |

修订理由（docs/48）：PetitMaker 实证模型在工具接地 + catalog 全文的条件下能产出坐标级、自检、自报偏差的高质量设计；我们当前「模型只分类不设计」的结构性差距（docs/47 自述）在单轮大 JSON 路线下无法收敛。

## 三、施工卡

### F1 — 画布工具集与执行循环（地基卡）

| 项 | 内容 |
| --- | --- |
| 工具集 | `query_area(rect)`：返回区域内分区/设施/地形/占用读数（结构化，复用 A1/A2 证据）；`find_flat(rect, need)`：可布置域内的平地候选（复用 B1）；`place_zone(name, polygon, purpose)`：放分区；`place_facility(templateId, position, rotationDeg)`：摆件（模板必须真实存在于物料库）；`lay_path(cells | line+width, material)`：铺路；`clear_area(rect, what)`：清场（破坏性，必走 F2 审批） |
| 循环 | 模型每轮产出「下一个工具调用 + 面向用户的思考段」；前端执行、把读数回灌；直到模型声明完成或触发审批/上限 |
| 上限 | 单任务步数上限（建议 150）+ 工具调用预算；超限走 docs/47 E1 的三级降级话术，绝不静默截断 |
| 留痕 | 每步：思考摘要 + 工具名 + 参数 + 读数摘要 + 结果，入 `conversation_turns` 的 `tool_summary`（契约已支持，需扩 tool 名长度校验） |
| 验收 | 凹形场地（v4.18.2 回归几何）上，一句婚礼任务能 ≥20 步连续施工，每步读数与画布一致；步数上限触发时 reply 如实声明 |

### F2 — 按后果分级的监督闸（替换「按阶段确认」）

| 项 | 内容 |
| --- | --- |
| 分级 | 建设性（放分区/摆件/铺路在空地）= 默认直落（自动档）/核对卡（严格档）；**破坏性**（清场、覆盖既有实体、改已确认边界）= 无论档位必停审批 |
| 审批卡 | 三键：批准 / 不用（跳过该步继续） / 取消任务 + 可文字回答（改参数重提）；审批与答复入留痕（outcome=applied/blocked + 用户原话） |
| 改造点 | `gateAction`/`outdoorActionRisk` 加「破坏既有实体」档位；工具循环内每步调用；不动 docs/44 确认门语义（F3 的提案确认仍走完整门） |
| 验收 | 114 步类任务：建设性步零打断；任意一步触及既有实体即审批卡；审批/拒绝各留痕一条 |

### F3 — 双交付形态：设计=提案预览，执行=施工

| 项 | 内容 |
| --- | --- |
| 判定 | 请求动词/语义分类进 understanding（「设计/出一版方案/画一下」→ deliverable=proposal；「摆上/开工/落地」→ deliverable=execution）；判不准时默认 execution + reply 说明理解 |
| proposal 形态 | 模型先在**草稿层**画分区/物件预览（画布可见、可拖改），任务收尾**回滚施工层**只留预览；composer 提示词切「按这个方案开工」 |
| 开工 | 用户确认后，草稿层转正式实体（一条 undo 票），模型继续按方案执行（回到 F1 循环） |
| 复用 | 草稿层 = 现有 proposal 预览机制（offer/apply/undo 票号）的扩展：把「整版 JSON 一次应用」改为「工具循环逐步画草稿」；`recordCard("replaced")` 语义沿用 |
| 验收 | 「先设计一套分区」任务结束时地图零净变更 + 预览可见 + composer 提示「按这个方案开工」；开工后实体落盘且可一条 undo |

### F4 — catalog 进上下文（模型自选物料与替代）

| 项 | 内容 |
| --- | --- |
| 内容 | 当前活动可用的物料清单（templateId/名称/尺寸/关键限制）以紧凑行式进系统上下文；缺货类目显式标注「catalog 无 X」，教模型给替代方案并在 notes 里如实声明 |
| 预算 | 清单随活动类型裁剪（D1 注册表先行则消费其清单）；超预算走 E1 降级 |
| 验收 | 「没有椅子」类场景：模型用替代物完成布置且 notes 声明「catalog 无椅，用 X 替代」；不放虚构 templateId（F1 工具校验拒绝） |

### F5 — 思考外显（过程透明）

| 项 | 内容 |
| --- | --- |
| 内容 | 每步思考段（1–3 句）入任务卡（可展开、带时长）；任务卡显示步数/改动数；步骤链逐条入卡历史（复用 outdoor-card-history） |
| 验收 | 用户在任务卡上能看到「为什么做分区」的原文级理由；卡片历史可整链回看 |

## 四、执行顺序与依赖

F1 → F2 →（F3 ∥ F4）→ F5。F1 依赖 docs/47 A1–A2（证据）与 B1（可布置域）先行或并行；F4 依赖 docs/47 D1（注册表）先行或并行。F2 独立可先做（gateAction 分级改造对现有 offer/confirm 也有收益）。

## 五、非目标

不做疏散认证与安全承诺（沿用免责话术）；不送地图像素；不做自动档全自主无人监督模式（破坏性永远人审）；不替换室内管线；PetitMaker 的游戏化表达（像素地图/卡通标记）不搬。

## 六、风险与回滚

- 工具循环步数失控 → 步数/预算上限 + E1 降级话术；
- 模型放置越界/压物 → 每个工具调用过 v4.18.2 钳制与 facilityPlacementIssues，拒绝即回灌错误让模型自纠（PetitMaker 同款「被拒→补铺」行为）；
- 多步中途失败 → 步进 undo 票回滚到任务起点（换场路径已有先例）；
- 成本 → 每步一次模型调用的费用显著高于单轮大 JSON；先在自动档小任务灰度，cost 记录进 provider 调用账本。
