# 前端 v0.2.0：后端支持需求

日期：2026-10-02。交接对象：后端负责人 B。

本次仅修改 `frontend/` 和文档。没有修改 `supabase/`、数据库、`client/scene-client.ts`、根目录依赖或部署配置。下列新增能力是待实现需求，不代表现有接口已经支持。

## 产品目标与界面位置

客户上传场地/风格参考图，描述活动类型、人数、必需内容；点击物料区的 **Generate**，得到能放进三维场地的完整布置方案。物料不限桌椅，也可能包含帐篷、舞台、串灯、拱门、互动装置。

右下角助手负责沟通需求和提出建议。创意建议必须与客户明确要求分开说明，**不能未经确认自动加入场景**。前端不增加额外灵感快捷按钮，需求入口沿用现有物料区；确认应用是写入提案的必要步骤。

## v0.2.0 已接入的现有协议

唯一真源仍为 `supabase/functions/_shared/domain.ts`、`client/scene-client.ts` 和现有 API 实现。

| 能力 | 当前前端处理 | 当前限制 |
| --- | --- | --- |
| Auth / 项目 / 租约 | 介绍页和工作台共用内存会话；沿用原云项目操作 | 未部署或未配置时明确显示本地模式 |
| `POST /projects/:id/proposals` | 发送文字、场景、所选物件与项目/租约/版本信息；先展示返回提案 | `layout` 仅允许空场景；前端人数输入限 1–40 人，现有模型输出只有 salon/networking，`modify` 仅支持现有指令 |
| `POST /projects/:id/proposals/apply` | 用户确认后调用，校验旧场景、版本、租约；云端接受后再同步画布 | 本地在请求期间改变时保留新草稿，不覆盖 |
| 灯光 | 渲染现有 `neutral / warm / cool`；未指定的本地画布显示暖光 | 不增加协议枚举或额外灯光按钮 |
| 私有 GLB | 通过现有授权接口加载真实资产，失败时不应用提案 | 不编造 assetId，不把桌椅冒充帐篷 |
| 图片 | PNG/JPEG/WebP，最多 3 张、每张 5 MB、长宽不超过 4096；浏览器临时预览 | **没有上传、没有传给模型、不做图片理解；刷新后需重选** |
| 对话 | 文字请求转为现有布置/修改提案 | 不是通用问答服务；没有伪造 AI 回复 |

`/jobs` 的文字单体资产任务已封装前端 service 方法，但本版没有新增单体生成按钮或自动付费调用。现有 `/assets/floorplan` 用于底图存储，不等于参考图片理解，前端未挪用它。

## 后端待补齐

### 1. 图文需求输入

提供项目范围内的参考图上传和授权读取能力，并让模型实际收到图像。返回稳定参考图 ID、处理状态、错误原因；确认 MIME、尺寸、权限和存储生命周期。接口明确接受参考图 ID，禁止使用前端 blob URL 作为云端地址。

B 确定新增接口/字段后更新共享契约，A 再接线。目前前端文字请求明确告知模型未收到图片，不能声称已识别图片或从图片测量场地。

### 2. 完整创意布局

扩展当前两类模板，让布局规划能表达：主题、功能分区、动线、必须满足的物料、可选创意、物料规格与放置位置，以及无法满足的需求。人数超出现有上限时返回明确限制，不能悄悄按 40 人生成。

建议按两阶段处理：先给文字建议，用户明确采纳后生成包含这些物件的候选 `Scene`。任何还没有真实物料的想法标记为待补资产，禁止返回成功但遗漏必需帐篷，或将 `table` 重命名为帐篷。

非空场景要区分局部调整和整体重规划；整体重规划也必须保留用户确认流程与锁定对象保护。目前前端对非空场景只请求 `modify`，不会清空场景骗过 `layout` 限制。

### 3. 扩展活动物料

优先通过现有 `materialId: asset`、稳定 `assetId` 与 GLB 提供帐篷/拱门/灯具；若扩展内置目录，由 B 更新共享 schema/catalog 后通知 A 实现对应渲染。

每个资产需要尺寸、地面原点、朝向、名称、授权/来源、加载状态。生成中的物料应返回 pending 状态；失败需可见，不能用临时占位物宣称生成完成。组合物料还需说明拆分/整体拖动方式，给布局留出真实占地范围。

### 4. 对话与提案关系

补充适合多轮需求沟通的问答入口，并区分“纯建议”与“修改提案”。支持会话上下文、当前需求、选中物件和场景版本。纯建议不写场景；只有经过前端明确确认的提案可应用。

保留现有租约 generation、expectedRevision、localRevision、base_hash、proposal expiry 和幂等 requestId 保护。扩展后的能力不能绕过这些检查。

### 5. 能力与失败信息

建议提供能力声明，供前端确定图片理解、创意规划、支持物料和人数限制是否已上线。具体 endpoint/schema 由 B 在共享契约中定义，本文件不建立第二份实现契约。

返回可解释的失败/部分完成状态：服务未配置、配额耗尽、图片无法处理、场地放不下、缺少物料、任务失败、租约或版本变化。确认所有前置条件之后再调用付费生成，避免无法应用的请求产生费用。

## 联调验收

1. 上传参考图后，模型输出能指出确实可见的相关特征；未上传/识别失败时不宣称识别成功。
2. 明确要求帐篷时，成功候选场景含真实可加载帐篷资产与合理尺寸；缺资产则明确失败/待补齐。
3. 新点子先作为建议出现，不自动加入；用户确认提案后才改变画布。
4. 修改需求、拖动物件、失去租约、切换项目后，旧提案不可覆盖最新场景。
5. 模型不可用、生成失败、GLB 授权失败时保留原草稿，能继续手工编辑。
6. 刷新重开后真实云端资产和氛围可复现；断网本地保存与云端保存标识保持准确。

实际 Supabase 云端、视觉模型和付费三维生成不属于本轮已验证范围。后续逐项记录部署环境、账号角色与验收结果，勿把 mock 或本地预览写作真实服务验收。
