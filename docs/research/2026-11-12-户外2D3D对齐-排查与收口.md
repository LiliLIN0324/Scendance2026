## 3. 链路核对结论（数据层无错位）

- 同一中心：`facilityFootprint`、`facilityProp`、`planModelTransform` 都用 `frame.toShell(facility.position)`；框角点与 prop.center/width/depth 同出 `facility.size` × `frame.scaleX/scaleZ`。

- 同组偏移：户外卡 footprint 组与模型层组外层 x/z 偏移一致（y 差贴地层 BASE_Y）。
- 归一化：`normalizeGlbRoot` / `normalizeGlbInstance` 均按包围盒 x/z 居中、y 贴地；uniform 分支只按高度等比缩放，width/depth 仅作目录元数据，不存在「height 漏乘 scale」。

## 7. 本质复盘（2026-11-12 晚，用户再次真机判定「没对齐」后）

> 触发：新截图里紫框只压在车轮/底盘一小段，2.59m 高的大货厢整体「罩」在紫框外。

### 7.1 离线 GLB 分层几何实证（box-truck，node + GLTFLoader 直接解析，52414 顶点）

| 底盘层 0.25–0.7m | 2.608 × 7.466 | 0.043 |
| 箱体层 >0.7m | 2.652 × 7.542 | 0.005 |
| 高箱体 >1.5m | 2.537 × 7.539 | 0.005 |

- 整车包围盒长 7.54m，但**真实贴地轮距仅 4.66m**：货厢尾（z -3.77→-1.73，约 2m）与车头/拖车梁前挑（z 2.93→3.78，约 0.85m）都是**悬空几何**，没有地面支撑点。
- **贴地中心比包围盒中心前移 0.60m（局部）**；按 0.744 缩放后世界偏移约 0.45m。

### 7.2 根因链（代码 + 几何双证）

1. 系统把「占地锚点」等同于**整体轴对齐包围盒**：`glb-normalize.ts` L98-104 / L170-174 按 full Box3 的 x/z 中心居中、y 贴地；`fitFacilityModel` 按 full bbox 的 width/depth 做 uniform contain。**代码里没有「贴地轮廓 / ground footprint」概念。**
2. full bbox（含悬空件）≠ 真实贴地轮廓，二者长度差 2.88m（38%）、中心差 0.6m。
3. 2D 紫框是用户**自由绘制的任意比例矩形**（本框 5.61×3.01，比例 1.86），与模型真实水平比例（7.54/2.65=2.84）脱钩；contain 只保证最长边入框，短轴方向留空约 35%。
4. 高位箱体（高 2.59m，接近框深 3.37m）在浅俯角斜透视下屏幕投影显著外扩，而紫框是贴地平面、二者投影深度不同，肉眼即「车压出框」。

### 7.3 成熟产品/引擎范式（公开资料）

- **渲染几何与占地/碰撞解耦**：Unity / Godot / le.codes 用独立 collider/footprint 决定占位与碰撞，不直接拿渲染 mesh 的包围盒当占地。
- **物件自带权威尺寸 + 锁宽高比**：Planner 5D、Live Home 3D、IMSI Architect、dika 的角点拖拽默认等比（Maintain / Lock aspect ratio），W/H/D 是物件声明属性；2D 矩形与 3D 模型共享同一水平尺寸，不允许「任意比例矩形硬套固定比例模型」。
- **建模规范**：模型原点落底面中心并贴地（TurboSquid《Centering at the Origin》、Sweet Home 3D 导入向导要求设定 size/elevation/底面朝向）。
- **OnePlan**：物件 to-scale 放置在 HD 地图，2D/3D 同源真实占地。

### 7.4 候选修复路线（产品语义分叉，待拍板）

- **方案甲（对标 Planner5D/OnePlan，根治）**：2D 框 = 模型真实水平外廓；拖入按真实宽深比初始化、缩放锁宽高比；3D pivot 取底面水平外廓中心。框与模型永远等比贴合，斜俯视也不失真。需改 2D 绘制/缩放交互与设施 size 语义。
- **方案乙（保留自由框，改动小）**：维持任意框，但 3D 居中基准改用 ground footprint 中心，并在地面叠加模型水平投影轮廓（半透明盘）表达「框=地面支撑、箱体可悬挑」；自由比例导致的留空/外扩仍会存在。
- **通用配套（P2 观感）**：3D 默认更陡俯角 / 提供顶视切换；选中态在地面画水平投影轮廓，消除高度投影错觉。
- **数据层 P0（两方案都要做）**：为每个可放置 GLB 增加权威 footprint 元数据（full 水平外廓 + ground 贴地轮廓 + 地面中心偏移），加载期按距地阈值自动计算或随资产登记。

### 8.7 二次真机反馈：朝向转反 90° + 模型不随框缩放（2026-11-12 晚，路线 A 恢复原始轴序）

- **现象**：箱货 3D 相对 2D 选框水平朝向转反约 90°（车头/货厢短边方向伸出框）；拖改 2D 框大小后模型水平外廓不跟随。
- **轴序根因（不是 Y 反）**：离线解析 GLB 包围盒 `X=2.652（窄）/Y=3.484（高）/Z=7.542（长）`，竖直 Y 正常，长轴在 Z。登记口径 `width↔X、depth↔Z`，内置 box-truck 一致。方案甲在 `facilityFootprintSpec` 把候选宽深重排成 `width=长边、depth=短边`，丢掉原始轴序；而 3D 共享模型层 `fitFacilityModel/selectFacilityModel/planModelTransform` 的 swap（转 90°）与 contain 系数都是按「候选原始轴序 ↔ 2D 框轴序」对齐设计的，字段被调包后 swap/scale 错配，模型长轴被横到框的短边上。
