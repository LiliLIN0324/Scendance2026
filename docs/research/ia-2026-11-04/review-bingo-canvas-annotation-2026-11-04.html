Bingo 回归审校本意：画面钉点 → 意见线程 → 标记解决 → 回流制作者台账。本板对标 Figma / Frame.io / Dropbox Replay / Google Docs / Pitch / Markup.io / Miro 的已核实交互，只回答「偷什么、避什么、幕景落在哪一行」。对标底稿见同目录 MD。

主题

Figma 评论（Design / FigJam）

需改造
resolve 即隐藏缩放聚类未读排序只看我的线程

画布上「点哪说哪」的钉点评审范式本身，及其「解决即归档」的状态语义。

交互骨架（已核实）

  • 钉在点或框选区域；低缩放时邻近钉点合并为 cluster，点击聚焦；钉可拖动换位。
  • 线程内回复、emoji、@提及；右侧栏可搜索 / 按未读排序 / 只看与我相关的线程。
  • Resolve 后评论同时从画布与列表隐藏；误解决可在「显示已解决」筛选里 Unresolve。
  • 点列表条目会跳回画布对应位置；邮件通知链接直达画布落点。

偷什么

  • open/resolved 不加第三态；解决即从画布隐藏，而不是变灰常驻。
  • 制作者侧补「未读排序 / 只看我的线程 / 显示已解决」三轴。
  • 点台账条目 → 相机飞回画布钉位；低缩放钉点聚类。

避什么

  • 不要「进入评论模式」开关——客户页天然纯审阅。
  • 不抄删除确认弹窗（评论上限 80 条策略已存在）。
幕景落点：lib/review-pins.ts:8,118-127（open/resolved · 筛选计数）· panels/review-pin-layer.tsx（钉层）· bingo-audit-card.tsx:22-25 → S2 收口。

Frame.io 锚点评审

新增
锚钉+框选public/internal批注附件@提及

意见精确锚在媒体的某个时空点上；内部团队与外部客户看到两套评论。

交互骨架（已核实）

  • 播放中直接点画面留锚钉（Anchored）；可框选区域；点卡视角跳回锚点。
  • 发送前切换 Public / Internal——Internal 带锁，分享链接评审者永远看不到。
  • 评论可挂附件（每帖上限 6）、@提及通知、#标签筛选；按角色锁定分享链接。

偷什么

  • internal / public 分层——本轮最重要新增：制作者内部备注对客户页不可见。
  • 点评论 → 视角飞到锚点坐标（与 Figma 跳转互证）。
  • 钉点支持「点 + 可选框选」，画线涂鸦后置。

避什么

  • 不引 hashtag 体系（评审包规模小）。
  • 附件、区间评论是视频语义，后置 / 不抄。
幕景落点：lib/review-share.ts:59,71,177（ReviewComment / BingoMark / parentId 线程）→ 预留 visibility: public|internal 形状；review-share-page.tsx:146-152 客户侧只渲染 public；D7 云端同步后置。

Dropbox Replay 分享评审

需改造
两档权限口令默认禁下载免账号

一条分享链接上「只看 vs 看并评论」的权限分档、口令与禁下载——客户只读页的权限模板。

交互骨架（已核实）

  • 分享链接两档：仅限查看 / 查看并评论；可加口令；默认禁止下载。
  • 评审者无需账号即可留评；意见锚在具体帧/像素上。
  • 评审以「最终核准」动作收束（产品页主张）。

偷什么

  • 权限枚举 view-only / comment 预留进分享形状。
  • 默认禁下载——方案是核心交付物，公开链接风险面先堵。
  • 页面诚实标注「本地演示链接、不上云端」（对齐 S2 local-demo 边界文案）。

避什么

  • 不抄同步放映室（幕景评审是异步的）。
  • 不做多资产文件夹体系；一个评审包 = 一个方案版本。
幕景落点：lib/review-share.ts:18（local-demo 边界）· 路由 app/review/[id]/ + review-link-client.tsx · bingo-audit-card.tsx:22-25（clientHref / pinCount / returned）。

Google Docs 建议模式（Suggesting）

需改造
待批编辑accept / rejectRESOLVE / REOPEN指派

把「修改」本身变成一条可批准 / 可拒绝的意见线程——审校侧「自动体检 → 一键修复」的正确形态。

交互骨架（已核实）

  • 建议 = 待批准的延迟编辑：改动不直接落盘，内嵌标注等待批准。
  • 接受需编辑权限；拒绝需编辑权限或建议作者；线程可 RESOLVE / REOPEN 重开。
  • 评论线程可指派给指定人（assignee）变成行动项。

偷什么

  • 体检 issue → 待确认建议 → 绿框预览 → 唯一确认落盘 / 拒绝丢弃——与三道门同构。
  • REOPEN 语义：resolved 可重开，open/resolved 两态足够，不加第三态。
  • 体检结果自动生成带坐标锚的钉点，与人工钉点共用同一状态机与计数。

避什么

  • 不把多人同时改稿的编辑协作引来——客户只留评，不改布置。
  • 不做批量接受/拒绝（一次一个决策）。
幕景落点：lib/layout-review.ts:26-27,240,583（6 类 issue/fix · reviewLayout · proposeReviewFix）→ 建议化包装，全程过 onApplyCreative 三道门；客户侧不见修复按钮。

Pitch 幻灯片评审

新增
三档访客权限对象级状态移动端只读

把评论、状态、指派挂在单个对象（幻灯片）上的工作流——评审包（方案版本）状态的参照。

交互骨架（已核实）

  • 访客三档：Can edit / Can comment（看 + 评论）/ Can view（看，连评论都不可见）。
  • 每张幻灯片可设状态、可指派、可收评论；移动端只能评审、不能创建编辑。

偷什么

  • 三档枚举预留 view / comment / edit：纯汇报档（给领导）真实存在。
  • 评审包级状态：待评审 / 意见回流中 / 已解决，落在只读台账卡上。
  • 客户页浏览器打开 = 移动端心智：只能看、只能留评。

避什么

  • reactions、邮件通知后置（云端依赖）。
  • 团队指派社交层后置（D5/D7）；本地版只能是自己的标记。
幕景落点：review-share-page.tsx:146-152（view 档不渲染输入条）· lib/bingo-feedback.ts + bingo-audit-card.tsx:22-25（评审包状态与计数）。

Markup.io 访客钉评

直接复用
免注册随处钉点线程钉在原地

证明「免注册、随处钉点、线程钉在原地」是最低门槛的客户评审形态——幕景 local-demo 分享页就是这个档。

交互骨架（已核实）

  • 「Drop a pin anywhere on the content and the conversation stays exactly where it belongs」。
  • 支持网站 / 图片 / PDF / 视频 30+ 类型；访客免注册留评。

偷什么

  • 现状即对：parentId 线程（review-share.ts:177）保证线程挂在钉点旁、不漂移。
  • 保留访客昵称输入条——零成本，意见可分辨是谁说的。

避什么

  • 不抄代理截图模式（幕景评审页就是本体）。
  • 不追 30+ 文件类型通用性——评审载体只有当前方案画布一种。
幕景落点：lib/review-share.ts:177（addReviewComment + parentId）· review-share-page.tsx:146-152 → 直接复用，不改造。

Miro 通知与线程

后置
@提及Feed 通知中心钉住线程

团队协作层的通知范式——也恰好标出幕景本轮的后置边界。

交互骨架（已核实）

  • @提及触发通知；线程可 Pin 在板上同时展开多条讨论。
  • Feed 为产品内通知中心，汇总各板更新。

偷什么

  • 唯一可本地化的：制作者台账「置顶未解决钉」视图（自己置顶自己的待办）。

避什么

  • @提及、Feed 中心、跨板汇总全部云端多用户能力，按 D7 后置，只留接口注释。
幕景落点：纯后置——lib/bingo-feedback.ts + bingo-audit-card.tsx:22-25（returned）本地先承接回流语义；云端通知进 Q4 接口形状备注。
