## 0. 一页结论（先看这个）

- 「活动」开场不是空白对话框，而是**画廊 + 冷启动卡**：卡选活动 → 进同一条生成管线（tuijian 模式 + Notion Templates 的「一键复制成自己的」）。
- 主对话是**refine 通道**，3D 画布是**结果本体**：学 Framer——agent 直接在主画布上改，没有第二预览窗；生成三道门（绿框预览→唯一确认→撤销）接线不动。
- 进度表达学 Linear：**分状态（进行中/已完成）自由流转**，不是 wizard n/4。台账暂无进度 UI 现成锚点，列为开放设计项。
- 成员条沉底=**真人 presence**（Slack 小点），不是 agent 人格；Linear agents 的「委派/@触发、与真人可区分」是我们的反向边界教材（D5/D6）。

## 1. tuijian（推鉴）— 卡片→管线冷启动的老板模式

- 官方地址：https://github.com/wustwyh/tuijian （开源仓库，含完整 README）
- 核实记录：2026-11-04 web.fetch 实际抓取，README 全文可读。备忘录（2026-10-29）曾记录「仓库页薄/403」，今日该情况已不存在；但界面截图未逐张逆向，以下交互事实全部来自 README 自述文字 + owner 口述「笨但好懂」，**不是逆向 UI 像素**。
- 一句话价值：**「不写一个字，点三张卡，拿到一篇能直接发出去的多平台软文」**。

### 交互骨架
- 输入全卡片化：产品卡（型号精确到版本）、41 张客户卡（每张带场景描述/核心问题/资料出处）、8 张平台卡（公众号/微博/小红书/知乎/新闻稿/朋友圈/门店长图/采购方案），组合数 README 自述 3280 种。
- AI 多轮追问：一次只问一个问题、全部是可点选项；最多 7 轮，问满 5 个维度即可结束；**追问收成一张「创作要求摘要」再生成**。
- 输出：按平台适配的结构化结果页（卡片流 HTML），标题/导语/正文/话题标签可就地微调，预览与下载共用同一份 HTML。
- 后置只读环节：核验回查（产品事实、图片型号、合规、平台适配四类逐条），正文引用编号由程序回填出处。

### 偷什么
1. **卡片点选代替空白输入框**：新手第一动作是「选」不是「写」。
2. **追问一次一题、全是选项**：不弹长表单；且追问必须先收成摘要卡才生成——与幕景「一句话目标→预览→确认」同构。
3. **结果页结构化、可直接交付**：对应幕景三盘（布置/物料/执行资料），不是一段聊天输出。
4. **核验是只读后置环节**：对应幕景 S2 审校闭环的位置感，不抢生成主路径。

### 避什么
- README 自述的组合数（3280）、平台套数是营销数字，**不上幕景界面**。
- 7 轮追问对活动筹备过重：幕景默认「1 张活动卡 + 场地/人数 chips」一步进管线，不做多轮问卷。

### 幕景落点
- S1 空态改造：`agent-panel.tsx:1944` 现「先说一句，我来分派」空态随假分派整块拆除后，换成活动卡行（酒会/发布会/工作坊/空白场地，备忘录第 4 节已定）。
- 生成主 chrome：`PlanHome:1947`、`ProposalCard:1967`、计划卡 `:1968-1979` 从 bingo 脸重挂到活动脸（台账 S1）。
- 引擎红线：`LayoutAgentProvider:264` 三道门不松。

### 待 owner 决策点
- 活动卡的「追问摘要」是否在幕景实现（chips 即可，还是学 tuijian 收成一张要求卡再生成）？建议 chips 先行，摘要卡后置。

## 2. Notion Templates — 模板一键变成「我的文档」

- 官方地址：https://www.notion.so/templates （操作说明见 Notion 官方帮助：template duplication 流程）
- 一句话价值：模板画廊里选一张卡 → 选目标工作区 → 一个 Duplicate 按钮 → 自动出现在你自己的工作区里。

### 交互骨架（已抓取核实）
- 按类目浏览模板卡（每张卡带缩略图+用途一句话）。
- 选定模板后：下拉选要复制进的 workspace → 蓝色 **Duplicate** 按钮 → 已登录则模板自动加入你的工作区；未登录先引导登录/注册。
- 复制完成后是**你的可编辑副本**，不再与「模板」概念绑定。

### 偷什么
- **选模板=唯一动作按钮**：没有「先填配置再生成」的中间表单；「变成我的」是用户唯一要做的决定。
- 对幕景 S1.1 的直接含义：画廊里点一张活动卡 → 直接进活动工作台进入生成中态，**不弹任何配置 wizard**。

### 避什么
- 上万张模板的「模板市场」体量与类目墙不上幕景；活动卡只做少量精选（备忘录：卡片行级别的数量），不是模板商店。

### 幕景落点
- S1.1 开场画廊 `panels/local-activities-panel.tsx`（台账：本机活动列表面板，改造为画廊卡片入口）。
- 与 tuijian 卡冷启动共用同一行为定义：选卡→进管线，无表单。

## 3. Airtable Gallery View — 画廊卡片解剖的标准件

- 官方地址：https://www.airtable.com （Gallery View 机制见 Airtable 官方博客与官方帮助口径）
- 一句话价值：**每条记录渲染成一张卡——顶部封面图，下方可配置的几个字段**；同一批数据换视图不换库。

### 交互骨架（已核实）
- 卡=封面图（Attachment 字段置顶）+ 标题 + 少量关键字段；「Customize cards」里用 **Cover Field** 指定哪张附件当封面。
- 同一批记录可以在 Grid / Kanban / Calendar / Timeline 视图间任意切换，**读写的是同一份数据**。
- 筛选按钮带可见计数（如「1 filter」）；Interface Designer 另有 gallery 元件，是给搭应用的人配的。

### 偷什么
1. 卡面只放**封面+标题+2~3 个关键字段**，不堆全字段。
2. 「一份数据、多视图」= 幕景三盘（布置/物料/执行资料）就是同一份方案的三张视图，不是三个产品——直接印证备忘录原则 1。
3. 封面字段可换（对幕景=活动卡封面可以是画布快照）。

### 避什么
- 「Customize cards / Cover Field」这类卡面配置器不上开场画廊——幕景用户不应该自己决定卡显示哪几个字段。

### 幕景落点
- S1.1 画廊卡片解剖：封面（本仓已有 `captureStageCover` 画布快照与 PlanThumb 机制，台账只锚定「升级为画廊卡片入口」）+ 活动名 + 状态短词。
- 三盘关系论证：布置/物料/执行=同方案多视图，不新增三套生成故事（呼应 D4）。

## 4. Figma File Browser — 最近网格 + 草稿箱

- 官方地址：https://help.figma.com/hc/en-us/articles/30926159906967 （文件浏览器官方指南；另 help.figma.com 14381406380183）
- 一句话价值：文件以缩略图网格陈列；**Recents=最近看过的文件**，**Drafts=只有你自己能看的草稿箱**，星标置顶。

### 交互骨架（已核实）
- Recents 页：展示你最近查看/处理过的文件，方便「接着上次干」。
- Drafts 空间：你创建但未移进项目的文件，默认仅自己可见；随时可分享或移入项目；内含 Deleted files 垃圾箱 tab。
- 星标文件进侧栏快捷区；team projects 是文件夹组织层；FigJam 看板与设计文件在同一浏览器里同库陈列。

### 偷什么
1. **Drafts「个人草稿箱」概念**：没做完/没归档的活动不混进正式画廊，分区陈列。
2. 垃圾箱 tab：删除动作可后悔。
3. 缩略图网格=最近项目网格的标准形态。

### 避什么
- team/projects 两层文件夹导航对幕景过重（本机本地活动库，无团队盘）。

### 幕景落点
- S1.1 画廊分区：最近项目网格 + 草稿/已归档分区（`local-activities-panel.tsx` 现有归档/恢复能力为底座，台账锚定改造）。

## 5. Miro Dashboard — 画廊工具栏的成熟形态

- 官方地址：https://help.miro.com/hc/en-us/articles/360017571294 （Dashboard 官方帮助页，已全文抓取）
- 一句话价值：仪表盘是团队与画板的导航中枢——Recent 区、Starred 独立视图、搜索、排序、过滤、每卡溢出菜单一应俱全。

### 交互骨架（已抓取核实）
- Recent 区在左上，展示跨团队最近打开的画板；Starred 单独成视图。
- 显示：grid / list 两种切换；排序：created / last opened / last modified；过滤：owned by anyone / you / not you。
- 搜索：Ctrl/Cmd+E；每卡「…」菜单=分享/重命名/移动/复制/删除/**换缩略图**/下载备份/复制链接——**卡面本身不堆按钮**。
- 团队切换在左上；模板入口（Miroverse）在右上。

### 偷什么
1. **每张卡的操作收进「…」溢出菜单**：归档、重命名、删除不堆在卡面上。
2. 「按最近打开排序」=「接着上次干」的默认排序。
3. 换缩略图作为溢出菜单动作（对应幕景活动封面重做）。

### 避什么
- Spaces/Projects 两层组织、团队切换器、Miroverse 模板市场——幕景单机、精选卡，都不上。

### 幕景落点
- S1.1 画廊工具栏：搜索框 + 默认按最近打开排序；网格/列表切换列为可选后置。

## 6. Framer AI — 主对话与画布同屏共生的最佳教材

- 官方地址：https://www.framer.com/ai/ （已抓取官方页全文）
- 一句话价值：agent 在编辑器里、**对你的真实项目直接动手**——描述要什么，它在项目里生成可编辑页面；你可以继续在对话里 refine，也可以随时接手画布。

### 交互骨架（已抓取核实）
- 生成即落到主画布：agent 产出的是真实可编辑图层，不是锁死图片或第二预览窗；生成后可在画布上微调、撤销、手改。
- 上下文机制：**在画布上选中图层即可加为 chat 上下文**（Contexts）；`@` 引用页面/CMS/样式/素材。
- 会话纪律：**「Chats：每个任务开一个新对话，保持 agent 专注」**。
- 高级（幕景不学）：模型选择器、Branches 分支迭代、连接 Claude/Cursor 等外部 agent（MCP）。

### 偷什么
1. **对话是 refine 通道，画布是结果本体**：没有「生成结果在一个弹窗里」的第二世界。
2. 选中即上下文：与幕景「点中一件物料/一块区域再说话」天然同构。
3. 每任务一新会话：对应台账会话历史/新建能力的 IA 用途。

### 避什么
- 模型选择、分支、外部 agent 连接全是高级玩法，一律不上幕景界面（对应备忘录「Agent/MCP/model pickers → Never for end user」）。

### 幕景落点
- S1：生成 chrome（`PlanHome:1947` 等）挂活动脸后，对话窗与 3D 画布的关系=Framer 式同屏；**三道门（绿框预览 `onPreview` → 唯一确认 `onApplyCreative` → 撤销）接线不动**（台账红线：`LayoutAgentProvider:264`）。
- 会话历史/新建 `agent-panel.tsx:1910-1930,1939`：IA 含义=「每任务一会话」。
- 默认脸 `:1827`（现为 bingo）与 `room-organizer.tsx:2017` 的 `activeAgent` 初始值同步改到活动脸。

## 7. Notion Agent — 空态不是空白框，是动作建议清单

- 官方地址：https://www.notion.com/en-gb/help/notion-agent （已抓取官方帮助全文）
- 一句话价值：友好的脸在页面右下角；打开先给你**一组基于当前页面你能做的动作**；结果以可交互表格直接长在对话里。

### 交互骨架（已抓取核实）
- 入口形态：右下角「友好脸」；chat 可切 Sidebar（右侧栏）或 Floating（浮窗）。
- 空态=动作建议：打开后先列出「基于你当前所在页面」可执行的动作（如「把本页生成待办」「精简本页内容」）。
- 上下文：当前页/选中块/@ 指定页/All sources/上传附件；结果（如数据查询）以**可交互表格内嵌对话**，不跳转另开数据库。
- 会话：历史按话题命名、可搜索、可 pin。
- 写操作先确认：如代你在 Slack 发消息，先问确认，且以你的名义发出。

### 偷什么
1. **空态不是空白输入框，而是动作短清单**——直接回答「活动脸打开第一屏长什么样」。
2. 结果块内嵌对话：预览卡（绿框）长在对话流里，不跳页。
3. 写动作前确认：与幕景「唯一确认」门同构，文案上可互相印证。

### 避什么
- 给 agent 起名/换配饰的拟人化玩法；跨应用代操作（Gmail/日历/Slack 代理）是高级集成，后置。

### 幕景落点
- S1 拆除 `:1944` 旧空态后：活动脸空态=「基于当前活动你能做的事」短清单 + 活动卡行，不是空白聊天框。
- 确认门文案对齐「写动作先确认」（`onApplyCreative` 已有，只调文案不调接线）。

## 8. Dora AI — 「一句提示→完整可交付物」的首屏承诺

- 官方地址：https://www.dora.run/ （产品页如 /ai、/projects）
- 核实口径（诚实备注）：dora.run 主站是 JS 重应用，自动抓取无法直接渲染，**未逐页抓取其主站**；域名身份经多个 2026 年独立第三方目录与评测交叉印证（曾有同名干扰：Google 的 DORA 软件工程研究项目占用另一相似域名，切勿混用）。机制描述以官方帮助站 help.doraverse.com 与独立评测交叉核实为准。
- 一句话价值：空白提示框描述网站 → AI 直接生成完整多区块落地页 → 再进可视化编辑器 refine。

### 交互骨架（已核实）
- 首屏=一个提示框：自然语言描述想要的网站，AI 生成含布局/文案/视觉的完整初稿，不是给半成品。
- 生成之后才出现无代码编辑器（拖放/3D 物体/滚动动画/关键帧）。
- 支持导入 Figma 设计当底子。

### 偷什么
- **「一句话/一张卡 → 完整可交付物」的首屏承诺感**：生成前没有工具坞，工具在结果之后才出现。

### 避什么
- 编辑器（3D widget/关键帧/动画面板）一旦成为首屏，「大气」立刻崩塌——备忘录已判此为反模式；幕景生成前绝不出物料/空间工具。

### 幕景落点
- S1 活动脸冷启动：卡片/一句话起步；生成中 chrome（`PlanHome:1947`、`GenProgress:1962`）只出进度与预览，不出工具。

## 9. Viggle PINOC — 世界充满画面，对话框小而安静

- 官方地址：https://viggle.ai （PINOC 与 Agent Mode 描述见官网及 2026-10 发布报道交叉核实）
- 一句话价值：描述一个场景或丢一张图，一两分钟后**在生成的世界里自由漫游**。

### 交互骨架（已核实）
- Agent Mode：一段文字一次生成「角色+动作+场景」；也可丢视频提取场景与角色。
- 手工侧：Scene / Character / Motion 三个编辑器分开，各管一件。
- 生成后状态=可漫游的世界，不是工具面板。

### 偷什么
1. **画布（世界）是情绪主体，对话框小而安静**——备忘录「World eats chrome」的活样板。
2. 模式数量克制：Agent 一个入口 + 手工编辑器后置。

### 避什么
- 角色/动捕/自动绑定/MCP 与主产品并列（备忘录已判反模式）；三编辑器对非专业用户=工具箱。

### 幕景落点
- 结果态：生成后 3D 画布充满画面；左轨空间/物料工具不进活动脸空态（呼应 S3 面板化方向）。

## 10. Linear Projects / Cycles — 非线性进度：分状态自由流转

- 官方地址：https://linear.app （项目/周期进度图机制见 Linear 官方 changelog）
- 一句话价值：项目与周期的进度**按状态分线计数（进行中/已完成）**，issue 在状态间自由流转，没有强制先后。

### 交互骨架（已核实）
- 项目/周期视图的图上，**Started 与 Completed 分两条线**展示；曾因「完成+部分进行中混算」造成困惑而改版——Linear 自己的教训：进度口径要分状态。
- cycle 分 current / upcoming / previous；issue 按状态（Todo/In progress/Done 类）自由流转，无 wizard 步骤。

### 偷什么
1. **进度=分状态计数（进行中/已完成），不是 n/4 步**。
2. 各板块自由流转、状态自己驱动——直接对应「活动筹备各板块状态驱动、不强制 wizard 顺序」。
3. 周期=时间盒容器：可对应「一场活动」本身是容器。

### 避什么
- Insights/Dashboards 管理向图表（时序、分位线）不上幕景。

### 幕景落点

## 11. Slack Presence — 沉底成员条的小点哲学

- 官方地址：https://slack.com/intl/zh-cn/help/articles/201864558 （另 docs.slack.dev 用户 presence 文档）
- 一句话价值：**在线状态=名字旁一个点**（实心绿=在线、空心=离开、灰=离线），自动切换，无需管理；点成员直达私聊/通话。

### 交互骨架（已核实）
- 实心绿点=Slack 打开即在线（自动，不可手动点亮）；10 分钟无操作自动转空心「离开」；登出=灰点。
- 自定义状态=一句短文案 + emoji。
- 频道成员列表里，每人名字旁带状态点；**点成员 → 弹出通话/私信选项**。

### 偷什么
1. presence 点极小、自动、零管理成本——沉底成员条的正确颗粒度。
2. 成员点击直达私聊：不做第二套成员目录。

### 避什么
- Slack 式侧栏频道列表/DM 列表不上幕景——成员区只是**沉底一条**，不是第二聊天产品。

### 幕景落点
- 底座复用（台账 A 组）：`panels/member-chat.tsx`、`lib/team-messages.ts`、`panels/account-team-panel.tsx`、`lib/team-data.ts`。
- **presence 点是新增小项**（现有底座是消息收发与未读同步，非在线状态；无云环境下的降级行为列入 S1 待核验，台账已注明）。

## 12. Linear Agents — 反向教材：agent 与真人是可区分的两类实体

- 官方地址：https://linear.app/docs/agents-in-linear （已抓取官方文档全文）
- 一句话价值：agent 与人类队友并肩，但交互靠**指派委派**和 **@mention** 两种显式触发；agent 活动像队友一样可追踪。

### 交互骨架（已抓取核实）
- 触发：把 issue 指派给 agent（委派）；或在评论/描述里 @mention。
- 追踪：agent 有 user 式活动页；委派给 agent 的 issue 仍留在「My issues」里，人始终可见可控；可按 Delegate 过滤视图、按 Delegate 切 Insights。
- agent 不计收费席位；与人重名时自动加数字后缀以区分。

### 偷什么（反向边界）
- **agent 与真人必须可区分**：触发机制不同、追踪方式不同、席位身份不同。幕景 D5/D6 正是这条原则——真人沉底成员条，agent 左轨切换，两边绝不混。

### 避什么
- 把 agent 做成常驻聊天人格房间；把真人成员做成可 @ 的任务节点。
- 真多智能体编排（委派队列、异步回执）本轮不做（D6 后置）。

### 幕景落点
- **处置=后置**：当前只守「左轨四形=agent 槽位、沉底=真人」的边界；`member-chat.tsx` 不接任何 agent 路由。
- 开放项 Q1（活动脸显示名与毛绒头像去留）的研究旁证：Figma/Miro/Framer 导航都用缩略图+文字，不用吉祥物；Notion 的拟人脸在右下角而不在导航轨。倾向：活动脸用简洁标识，毛绒头像如保留，仅作开场画廊的品牌氛围，不承担左轨导航语义——待 owner 拍板。
