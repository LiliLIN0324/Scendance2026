## 二、它为什么会做分区——引思考原文

轮 1 第一步「查看区域」的思考全文（原文节选，可在画布上展开）：

> 「'这片空地'指的是哪里？用户没有选中区域。上一轮我们在 (88-102, 7-12) 建了集市广场……主路西侧 (30-90, 15-55) 是完全空的草地，这是一个理想的大型婚礼场地。」
> 「没有椅子 catalog……可用装饰：prints、花、花坛。」（逐字引用物料目录，知道缺什么、用什么替代）
> 「仪式区（北）：x=64..80, y=16..30。圆形台：以 (72,23) 为中心 r=7……宴席区（南）：x=58..86, y=38..54……通道：横向步道 y=40..41 x=76..87（接主路）。」

**分区不是被问出来的，是模型读完地形、读完物料清单后，把活动语义直接翻译成带坐标的空间组织方案。** 仪式/宴席/通道三个分区与每件物料是同一次推理的输出。它考虑过「要不要问用户」，先尝试用上下文自答，只在真正无法消解歧义时才问。

轮 4 证明分区也可以**纯推理发明**：只给活动（三天动漫展销会：白天摊位展销+舞台表演，晚上灯光夜市+露天放映，日均三千人），不给任何分区词，它自创 9 个分区——摊位展销区 ×2、主题展区、舞台表演区、灯光夜市、露天放映区、服务区、休息区、广场。**昼夜双态给了独立分区**（夜市与展销分离），3000 人推出服务区+休息区。分区方案 = 活动语义 × 场地现状的函数。

## 三、它为什么会做 design——design 是循环本身，不是一个阶段

它的世界是：**读画布 → 思考 → 调一个工具 → 再读画布**。工具集（从步骤链可见）：`查看区域`、`寻找平地`、`列出物品`、`散布物品`、`铺设道路`、`清空区域`、`标注`。114 步每步一个小动作，思考里连铺路接主路的逐格坐标都算好（「y=39: (88,39),(89,39)……所以从 x=80..87, y=40..41 铺即可」）。**design 是一串接地小决策的积分，不是一张大 JSON。**

## 四、四条可复用的机制设计

1. **监督按后果，不按阶段**：114 步建设性操作全自动连跑；破坏性操作（清空区域 14 格）停下三键审批（批准 / 不用 / 取消任务 + 可文字回答）；修改自己刚建的东西也必停；「N 条已答复的询问」全程记账。运行中 composer 变「为下一步添加备注」（可插话引导下一步）+「在本步结束后暂停」按钮。
2. **双交付形态，动词决定**：「**设计**一套分区」→ 交付提案（分区画上画布供审阅 + 回滚施工痕迹 + composer 提示词变「按这个方案开工」）；「**布置**场地」「按这个方案开工」→ 直接施工。第三轮显式流程指令（「先只做分区……分好区停下来告诉我」）被精确执行并显式交棒（「分区工作到此结束，等你指示再摆桌椅」）。**工具循环架构下「流程指令」免费；阶段管线下每个新流程形状 = 新代码。**
3. **收尾卡 = 自检 + 偏差自报 + 非变更清单**：轮 3 收尾卡含「核验完成……8 格连续无断口」（自检）、「一棵漏清的灌木被拒，已清灌木补铺到位」「如实说明两点」（偏差自报）、「16 座长桌、凉亭、集市广场、湖与环湖小径全部保持原样」（非变更清单）。
4. **过程透明**：每步思考全文可展开（带时长）、步数/改动数常驻、步骤链（「铺设道路 锦花砖路 沿直线 (71,38)→(71,54) 宽 1」）逐条入账、面板可整链回看。

## 五、与 Scendance 的差距对照

| # | 维度 | PetitMaker | Scendance 现状 |
| --- | --- | --- | --- |
| 1 | 架构 | 单 agent 循环 + 世界状态工具，每步重读画布 | 阶段管线 place→scope→zones→main-routes→objects，每阶段窄 prompt 出 zod JSON |
| 2 | 为什么做分区 | 看到了地形与物料，语义→空间的自然翻译 | 流程走到了 zones 阶段，还需引导卡 |
| 3 | 数据接地 | 逐格坐标（真读网格），catalog 逐字进思考 | OutdoorMapContext 摘要快照；物料选择由 wedding-layout 硬编码引擎决定 |
| 4 | 守门 | 按后果：建设性连跑、破坏性必停 | 按阶段：每阶段一张确认卡（含全建设性操作） |
| 5 | 执行粒度 | 一步一小动作，可暂停/插话/回溯 | 一步整版大 JSON，错一处全盘返工 |
| 6 | 多轮 | 世界状态上直接继续 | memory/brief/proposal 生命周期缝合 |
| 7 | 透明 | 思考全文外显 | 进度条 + designStep 留痕 |

## 六、公平性：他们的域比我们便宜

网格世界（万格上限、有限 catalog）、画布即时反馈、无真实世界对价。我们的难度高一个量级：真实地理与授权、米制契约、真实物料库、多租户审计与留痕。**对标的是 agent 决策模式，不是他们的域。** 我们已具备的监督档（gateAction/outdoorActionRisk）、对话留痕（conversation_turns）、供应商路由是生产级地基，他们没有。

## 七、对 docs/47 的三条输入（供 Phase F 决策）

3. 按后果分级审批可直接复用我们的 gateAction/outdoorActionRisk 框架改分级，不需要新框架。
