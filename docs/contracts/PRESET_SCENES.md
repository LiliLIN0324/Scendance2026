# 已归档场景预设

`Scene.scenePreset` 可选，只接受 gym、popup、bar、cafe、conference、lawn、market、museum、office、studio。其固定场馆结构仍来自部署包内对应 GLB，不会因云保存或 Agent 应用被替换为普通房间。

预设内独立物件使用 `materialId: "asset"` 与整数 `presetNode`，对应打包 GLB 的 `Preset_Object_<序号>`。该引用不能与 `assetId` 并存，必须在该预设的 `preset-manifest.json` 名单内。服务器及数据库独立校验引用；不接收任意模型 URL，不伪造云资产 ID。普通云 GLB 继续校验资产授权。

普通场景仍最多 50 件；这些已知预设最多 500 件。归档预设原有的负高度及细小构件保留，新增普通物件仍遵守原尺寸、高度、边界及结构约束。Agent 接收服务端归档名称，可新增、移动、旋转、移除或替换物件。原有越界状态不阻止无关新增，但不能引入新的越界或穿墙。

大型预设的 JEV 请求超过 100KB 时，使用共享物件表和警告表传输相同数据。各方案引用完整物件顺序及各自差异；保留 UUID、尺寸、位置、说明和全部警告，不舍入或截断。普通请求维持原格式；压缩后仍超限则保留有效候选并说明评价不可用，不伪造概率。

DeepSeek 对超过 50 件的场景使用列式物件表作为首条消息的传输格式，保留全部原始字段和数值；存储与应用仍使用标准 Scene。`get_scene` 引用首条消息中的同一草稿，不重复发送模型、名称和资源表。真实 307 件体育馆的读取、物料清单、三次方案校验、三方案提交及 JEV 流程均有体积回归，220KB 与 100KB 的请求上限不变。

完整预设目前不支持独立云资产的材质改写；不能用颜色字段假装改写 GLB 材质。交付导出仍显式拒绝完整预设，避免漏导出固定结构。云保存与重开支持完整预设；这不等同于 GLB 交付导出。
