# 单轮简报请求防重与限频草案

状态：**未部署、未接入付费派发**。新增专用表与 RPC，不改既有表；默认关闭时旧接口行为保持兼容。设置 `BRIEF_REQUEST_GUARD` 为非空且不是 `off` 时，旧 `/brief/extract` 当前一律返回 `BRIEF_GUARD_NOT_READY`，不会转去模型或回退到无保护路径。这是故意的暂停，不是已经可用的保护模式。

受控事务草案按认证用户与持久请求编号唯一记录摘要：同编号不同摘要拒绝，同一请求最多发放一次 dispatch 权限；一个用户最多一个未决请求，每分钟最多创建五个新请求。发送后取消、断线或超时为未知，不能自动重发；状态更新失败时保留 dispatched，同样不自动重发。无自动释放或清账功能。服务角色外的直接 RPC 调用被拒绝。请求正文和凭证不写入表。

`brief-guard-draft.ts` 是仅供隔离测试的编排草案，调用者必须在服务端将已验证用户和实际准备发送的 URL、完整请求体、非敏感请求头、账户标识及凭证版本绑定；它不接现有 API。现有真实供应商账户标识与凭证版本无法由此草案独立核验，也没有持久化客户端请求 ID、返回结果查询、支付预算或全账户限流。旧路径和其他供应商入口未纳入防护，不能把这个草案视为全局防重或金额上限。

准备启用之前还需证明：可信账户与凭证绑定、浏览器提交前持久化 ID、重启后的同 ID 查询与冲突处理、源代码唯一派发入口、跨进程真实供应商调用不重试、所有付费路径的独立限流或隔离账户，以及现有场景/访客兼容性。费用上界须另行核验并实施。本草案不得在缺少这些前提时解除 `NOT_READY`。

本地验证：常规 PGlite 测试 `tests/brief-request-guard-draft.test.ts`；有本地镜像和 Docker 时，显式设置 `RUN_ISOLATED_POSTGRES_TESTS=1` 运行 `tests/brief-guard-postgres.prototype.test.ts`，它在无网络、无宿主挂载的临时 PostgreSQL 容器测试并发与事务中断，并在结束后停止该容器。测试不访问真实供应商。
