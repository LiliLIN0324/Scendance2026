## 0. 用户口径（2026-11-16 深夜追加，与下文冲突时以本段为准）

用户在真机上给出的判断：**交互不好用、地图不理解、每一步都卡住、不会做设计、不懂不同层级的指令**。本轮按下面五条验收，不按功能清单验收。

1. **不卡在第一步。** 空白活动里说一句完整需求就能开始，不要求先选地点、先登录、先等地图十几秒。缺地点时只给唯一下一步（去地图定地点），并把这句话原样留存；选完地点、确认范围后自动接着做，不要求用户复述。
2. **地图要听懂人话。** 「签到靠近入口」「入口那条留出通道」「把签到往东挪两米」要落到具体对象和具体位置，并在画布上给出能核对的预览。听不懂时必须问一个能消除歧义的问题；不许静默降级成通用建议，也不许自己换一套方案。
3. **每一步都有下一步。** 任何时刻界面上只有一个明确的下一动作。失败要说清停在哪一步、现在能做什么，不留要用户猜的空白。
4. **要会做设计，不是只会摆东西。** 「200 人市集，签到靠近入口，留出通道」要产出一版有依据的方案：分出签到、主活动、后勤三类区，区的位置和面积能对上入口关系和人数；主通道净宽、出口数量能用人数推出并标明假设；后勤动线不穿越主活动区。用户改一句（“签到往东移两米”）只动相关部分，其余约束保持。只堆设施不给依据、或给不出一版可看的布局，按未通过算。
5. **分层理解指令。** 同一句里通常有多层，要分层接住，不要当一整段自由文本。层级决定走哪个工具、给多大自由度：

   | 层级 | 例子 | 走什么 | 自由度 |
   | --- | --- | --- | --- |
   | 目标级 / 模糊 | 做个 200 人市集 | 设计规划器组合（分区 → 动线 → 设施），先出可改预览 | 高：可自行定布局，但必须写明假设、给可替换的做法 |
   | 任务级 | 先排入口和后勤动线 | 点名的规划器，按给定次序跑 | 中：只动被点名的部分，其余保持 |
   | 约束级 | 签到靠近入口、留出通道 | 规则/几何校验器，改完必须复验 | 低：不得放宽或静默忽略约束 |
   | 编辑级 | 签到往东挪 2 米 | 确定性编辑工具，零模型调用 | 无：只改目标对象及其依赖 |

   层级冲突时以更具体的一层为准（编辑级 > 约束级 > 任务级 > 目标级），并把被覆盖的旧约束显式列出来。分不清层级时问一个最短的问题，不要猜。
6. **一次对话，一口气做完。** 用户说完一句（最多补一句地点），就直接产出一整版设计：分区、动线、设施、岗位到位，画布上就是能看的东西。不得拆成“先确认分区 → 再确认动线 → 再确认设施”的多轮小确认，不得每步都要用户点一次。只在会改变几何或范围的真歧义上问一次，方案出来一次性确认。开发上按批次推进是工程顺序，不得变成用户可见的步骤。
7. **可回看、可取证。** 同一活动的对话要能保存，刷新、切活动、重新打开都能读回；每轮生成一个可复制的诊断编号，能分到浏览器 / 地图 / 后端 / 模型四段；能一键导出本轮证据（请求地址、状态码、耗时、错误码、编号、实际走了哪条路径），默认不含原话、地址、坐标和令牌，带原话需要用户显式选。拿不出证据链的一轮不算验收通过。

以上七条任一不满足，即该批次未通过，不得标已验收。

## 1. 本轮交付

从工作台的同一个输入框开始，用一条自然语言说明活动、地点和布置需求。Agent 保留整条需求，能用地图或当前方案已知的信息往前做。缺什么就问什么。需要调整方案时，在画布上给出能核对的预览。确认、等待、失败、取消和刷新都有明确去向。支持人员拿一个诊断编号，就能判断这一轮结束在浏览器、地图、后端、模型还是应用环节。

首条交付链路用官网上的真实案例：**杭州植物园菊展市集（玉泉鱼跃）**，依据 `assets/yuquan-market-proposal.html`（甲方评审稿 V0.4，2026-11-12）。该稿口径：两日、六个 2×2 m 摊位、24×18 m 假设画幅、主路按 4 m 演算、集章 A/B 两版（入口集章 / 区内集章）。首句：「在杭州植物园玉泉鱼跃周边做两日市集，六个摊位，签到集章放进摊区，园路留 4 米贯通。」再用「把签到队列往东挪 2 米」检验已有方案上的直接编辑。摊位数、间距和净宽属于评审稿假设，落位、用地与人数以园方确认和现场实测为准；几何和流程断言使用固定测试场地。

本轮覆盖可见的户外工作台、现有地图和物料能力、户外理解服务、方案预览和应用。室内、导出、配色、生成和旧云端 Agent Run 保留兼容回归。付费生成、云端区域规划、附件识别各自使用已存在的能力和限制。通过本轮不等于这些能力已经开放。

## 3. 产品行为和状态约定

- **按任务工作。** 阶段用来表示已掌握的事实和建议下一步。合法的直接编辑、查询和补充要求可以跨阶段发起。选中一个区时先用它解释「这块」「这里」。多个真实对象都匹配且会产生不同修改时，问一个能消除歧义的问题。
- **地点可以后补，原需求持续有效。** 先存当前目标、约束和待补字段。地图和对话共用候选确认及范围更新流程，已有精确候选优先携带它的身份、来源和边界。真实可用范围以用户确认的边界为准。确认地点或登录后在同一项目恢复原任务。
- **允许边做边核对。** 已有可信范围，可以先出一版分区、动线、设施和岗位预览，列出影响该版的假设与待核对处。路网或地图缺失时可以继续用画布已确认几何做适用的部分。没有可信依据的路段、疏散、容量、合规结论或可通行性应明确标注，禁止编造事实或声称通过核验。
- **明确能力和提交结果。** 本地规则处理明确命令。模型负责歧义和结构意图。已注册规划器算几何并校验，沿用现有素材 ID、版本比较和应用入口。预览显示增删改和影响范围。确认绑定具体预览、项目和基准版本，提交完成后读回真实状态。取消清当前预览，保留先前已确认的内容。
- **监督沿用现有三档。** 先固定三档的规则矩阵。严格档的场景写入需确认。关键点档可在一份预览内完成多个低风险步骤，提交时集中确认。自动档只执行经产品明确列入白名单、可撤销、版本校验通过的低风险写入。范围变更、破坏性或超现有阈值的批量动作、付费和发布保留各能力的明确授权要求。模型输出没有授权效力。
- **失败位置可读。** 任务显示正在做的步骤、当前阻塞和下一动作。区分登录、未启用、地图依据不足、模型失败、额度不足、取消、冲突和超时后结果未知。供应商是否已受理未知时，先查现有状态，避免定时重发付费请求。
- **用已有机制做恢复。** 在现有 scope 存储上加带版本的最小任务状态。记录任务 ID、显式事实、待补项、状态、基准版本、待确认预览引用及最后一次诊断编号。划定刷新后能恢复的内容。执行队列、瞬态对象和授权回执不能仅凭一段聊天气泡推断。跨项目、工作室或账号的结果隔离。已有草稿无新字段时正常读取。

## 4. 分批执行与验收

按下面的依赖挑最早能推进的批次。每次定时触发只完成一个可独立验证的切片，剩余工作更新进度文件。M1 前端与服务端可以分别推进。角色分工用 `frontend/AGENTS.md` 和 `COLLAB.md` 中现有的审批和独占区约定。角色 A 可先做前端和契约验证，服务端契约、迁移与部署由 B 主责，按仓库流程交接。当前工作树有正在进行的前端和共享契约修改，先确认本批使用哪个基线。

### M0 · 固定复现、记录基线

**依赖** 无。**产物** 复现记录、第一失败点、现有测试结果，以及至少一个从正常入口进入的测试场景。

1. 新建隔离活动，记录 commit、登录态、工作台入口及是否使用真实服务。优先复现「无地点输入 → 地图选址 → 确认范围 → 看是否自动接回原需求」。再发首条组合需求，并补一条已确认范围的「排主入口和后勤通道」。每个断点记录用户输出、画布状态、网络请求起止、HTTP 和结果分类。
2. 分别复测未登录、登录且模型已接通、无模型但可用本地动作、预览后切活动。仓库自带浏览器联调脚本先看参数和副作用，优先固定 provider 回执。用真实服务时用虚构数据和隔离项目，复用已有环境与权限。
3. 用现有 `frontend/scripts/evaluate-agent-baseline.cjs` 和 `frontend/lib/outdoor-agent-http-contract.test.ts` 作为回归起点。已有失败按首次发生位置记录，并写下最小复现，避免把工作树已有失败算成本批回归。

**通过** 至少有一条浏览器入口的复现和一条实际 HTTP 契约复现，能区分「没有发请求」「已发但未执行」「执行过但没应用」。若真实服务不可访问，写清环境和能证明的最后一步，离线覆盖继续推进，M7 保留该实测项。

### M1 · 从前端决策追到后端

**依赖** M0 先确认入口。**产物** 有测试的诊断编号、前端事件、服务端日志和查询说明。

1. M1a 在消息入口生成不含身份的 `turnId`。每次实际请求用独立 `attemptId`，重试关联原轮次。记录分流、地图、理解、规划、校验、预览、应用、结束，覆盖成功及早退出。每轮恰有一个终态，例如 `local_done`、`awaiting_place`、`awaiting_login`、`preview_ready`、`failed`、`cancelled`、`stale`。详情能复制编号、阶段、耗时和安全错误码，失败提示带能采取的动作。
2. M1b 由 B 选择能被两个 Edge 部署保留的最小传递方式。若加可选请求头，补 CORS 允许头及暴露头、UUID 校验和兼容测试。向日志写固定名称、环境或部署标识、调用种类、阶段、耗时、供应商槽位、安全错误码与编号。覆盖权限、开关、解析、发出、响应、超时及取消，沿用已有供应商分类。日志故障不改变业务结果。限定内容和访问，日志不包含原话、客户地址、精确坐标、请求体、资源链接、令牌或原始供应商输出。
3. M1c 记录查找操作。浏览器看该轮是 local / map / conversation / scene，确认实际部署后按 ID 查函数日志。只有真正建了云 Agent Run 才用 `runId` 查原事件流。已有 `agent_run_events` 继续用于真实 Run，浏览器或理解事件无需伪造 Run 或先建数据库表。

**通过** 本地动作核对到零 `/assistant/chat`。一次成功和一次服务失败能从 UI 关联到服务端事件。验证旧请求、普通聊天、预检、跨项目隔离及字段脱敏。在 B 接线前，前端仍可独立解释未发请求的原因。

### M2 · 选址与待办接续

**依赖** M0，使用 M1a 来验证。**产物** 同一任务跨地图、对话、登录和刷新恢复。

1. 从 `sendCore` 提取户外入口决策，复用 `place-first` 和现有 hook 状态。把「需要地点」记录成一个有目标和显式约束的待办，界面显示保存的目标和唯一下一步。取消、改需求或换项目明确更新任务状态。
2. 将地图选点、对话搜索候选、通过地图圈范围走同一个确认流程。沿用候选 ID 和来源；身份确实不足时才按名称查找，并列出多个匹配项。地图正在查询、手动圈选和登录弹层同时出现时，维持当前有效任务及清晰的动作入口。登录仅拦涉及模型的分支。
3. 恢复绑定 `scope`、用户身份和基准版本。同一回执只能消费一次。草稿或场地变动后重新核对或出预览，不能套用旧版本。显式替换场地触发受影响的后续计划失效，保留仍有效的需求。

**通过** 复现句只输入一次。选地点和确认范围后能接续原任务。地图选中的同名场馆不换位。刷新、登录回调重复以及项目切换不会丢需求、重复付费或修改别的活动。包含离线或未配置模型时可走的现有确定性入口。

### M3 · 改分流、上下文和提问方式

**依赖** M2、M1a。**产物** 单入口顺序、按需地图数据、可回归的分流和问答。

1. 先固定优先级：取消与明确确认 → 已有提案的修订 → 用户明确点选/定位或确定性能力 → 缺项和恢复 → 歧义交给模型。已有确定性物件、路网和通用能力继续走原有规则。组合需求原样保留，防止单个关键词吞掉后面的目标。只有一个地方决定本轮的下一动作，UI 从结果渲染。
2. 用当前选中对象、边界版本、事实和相关地图依据构造最小上下文，按任务读取路网、POI 或轮廓。问候、问当前有几条线、确认、取消和确定性编辑不等无关地图。需要外部地图的能力对等待、部分结果和失败分别出结果，版本变化时丢弃旧数据。沿用现有契约和限制。先记录截断发生位置，再调整数据来源或上下文优先级，保留用户约束和选中对象。
3. 歧义影响几何或范围时只问一个问题。低风险默认值写在预览中，用户可以改。模型只返回受校验的语义和事实引用，拒绝凭空生成坐标、素材 ID、通过现场核验或越权确认。保留普通聊天和旧版本契约覆盖。

**通过** 明确的局部编辑或已有范围内的查询直接出结果。阶段不会阻断无关操作。对话补答后继续原意图。复现「已登录还先等地图十几秒」时，能说明是否需要地图，并用固定慢地图断言本地动作无需等待。测坏 JSON、旧响应格式、超长上下文、取消和地图部分可用。

### M4 · 从真实上下文生成可用的组合预览

**依赖** M3。**产物** 一个任务能产出一版可检查、可修订的户外方案差异。

1. 用已有分区、入口/路线、物料、岗位规划器按实际依赖执行。可先产出有依据的分区和路线，标明缺位设施、库存和数据缺口。路线区分目的与当前通行属性。预览的设施使用真实物料 ID 和尺寸，走既有几何校验、锁定物件和边界规则。规则判定附来源或明确假设。
2. 用户说「入口留着，签到往东挪 2 米」时复用同一任务，只改相关对象并重新校验依赖。预览显示新增、移动、删除数量和具体目标。能在画布定位。几何版本或关键事实变动后重算受影响部分。
3. 基础用例走一个已建立的固定测试场地，引入真实地图时单独报告覆盖。复用现有 2D/3D 同源方案数据。人群、岗位和流线预览可用来做现场走查，动画回放不代表容量或合规核算。

**通过** 首条组合需求在范围确认后产出可见预览，无逐阶段重复提示。确认后回读实体数量、位置、通行属性和 2D/3D 状态。局部调整只改变预期对象，锁定物件、其他区和用户原有内容保留。无有效路线或缺素材时 UI 能说明具体原因并给接下来可做的动作。

### M5 · 应用、取消、重试和恢复

**依赖** 版本绑定的首次检查随 M2/M4 落地；本批完成完整生命周期验收。**产物** 有版本约束的提交、撤销路径和恢复说明。

1. 用现有 `applyPlan` 和候选版本检查完成一次原子应用。预览引用和操作 ID 绑定活动、用户、基础版本和事项。双击、刷新重放、迟到回执和并行编辑先检查状态。云端 Run 允许按既有 `requestId` 查状态，遵循原写入保证。不能证明云端未提交时显示未知，回读后再决定是否重试。
2. 现场验证三档权限矩阵，明确每类动作是直接执行、出预览、需要显式确认还是当前不可执行。成功后提供实际结果或撤销动作。取消停止可取消的工作，忽略旧响应；若供应商已可能受理，呈现真实状态。项目切换、退出登录和重新打开不会自动提交旧预览。
3. 兼容旧草稿、旧聊天和过去的方案 revision。刷新只恢复能证明一致的任务和待办。不能恢复的未应用预览提供重新生成入口。需要后端改动时以现有契约和迁移路径交由 B 处理。

**通过** 刷新前后各中断一次，另测提交成功但客户端未收到回执、双击确认、拖动之后确认、切工作室、取消后的迟到响应和撤销。断言不会产生重复实体、覆盖更新、串项目、未经授权计费或发布。

### M6 · 用户可见文案与工作台验收

**依赖** M2–M5。**产物** 统一的任务卡和工作台回归。

1. 收敛 `outdoor-workflow-card.tsx`、阶段建议和 `agent-panel.tsx` 上重复提示。同一时刻显示目标、当前进展、待核对内容和直接动作。建议仍可用，但不要要求懂阶段术语才能继续。画布和对话的候选、状态与按钮保持一致。
2. 桌面和窄屏各走首次选址、局部编辑、超时、取消、登录后返回、撤销。看焦点和输入草稿恢复，键盘可完成预览和确认。Agent 回执明确写实际做了什么，未应用的结果标预览。

**通过** 每个场景可以从产品入口完成，录下必要的步骤、画布结果和诊断编号。复测分享、导出、室内入口、配色等现有通用动作。

### M7 · 对照评测、发布准备和止损

**依赖** M1–M6。**产物** 同环境前后对照、发布状态、回退方式和未覆盖项。

1. 用下表逐个复跑，报告本地固定数据、真实浏览器、真实云端三类覆盖。分别记成功率、重复输入、澄清和确认次数、地图与模型调用次数、首个有用反馈耗时、预览耗时。写样本数和环境，区分 UI 反馈与实际完成。用已有预览、配置和发布流程验证。
2. 发版候选运行前端 `npm run typecheck`、`npm run build`、相关 Vitest 和浏览器。涉及后端时从根目录直接运行 `npx --no-install vitest run <所需测试文件> --maxWorkers=1`，再做 B 负责的 Edge 契约、权限和迁移检查。根目录 `npm test` 默认带 `tests/`，附文件参数也会扩大到全量。分批运行时记录漏跑项。发布到会自动部署的 `main` 前遵循既有 PR 和发布授权，运行进度里分别登记本地通过、预览待验证和生产验证。
3. 能按独立提交回退体验改动并继续读取已经保存的草稿。若分流无法定位、错误自动应用、实际变更与回执不一致或跨项目泄漏，阻断发布。服务端查询说明写明环境、编号字段和查询权限。未通过的项目保留精确下一步。

**通过** 必须通过下表的固定用例和主流程浏览器验收。真实云端仅凭真实请求与日志关联过后标已验。任何当批执行者都能根据进度从新会话重做最后一次验收。

## 5. 交付验收表

| 用例 | 合格结果 |
| --- | --- |
| 空白项目输入组合需求，地图确认地点及范围 | 原句一次，最终有组合预览或具体缺项。地图和 Agent 不各要求再选一遍。 |
| 两个同名地点，地图选中其中一个 | 确认的是同一候选及范围，重新搜索时能解释原身份缺什么。 |
| 有范围、已选设施，发明确小改 | 直接定位对象并出预览，或者按已授权白名单提交；确定性路径零模型请求。 |
| 无范围先发设计句，再改预算或人数 | 恢复最新约束，不按旧需求生成。不因闲聊丢掉活动待办。 |
| 地图部分、离线或无路网 | 适用工作继续，丢失的数据和缺项可见，无虚构位置。 |
| 未登录、功能关闭、额度不足、网络超时 | 四类阻塞分别可识别。已保存需求和适用本地操作可用。没有自动重复付费。 |
| 待预览时说「等等」或过时的「确认」 | 不应用过期预览。确认绑定当前预览及版本。 |
| 应用中刷新、双点确认、切项目 | 最多应用一次，无跨项目写入，结果可回读。 |
| 确认后撤销，重开旧草稿 | 撤销结果在同一版本链路可验证，旧草稿可读。 |
| 一条真实模型失败，一条纯本地成功 | 诊断编号对应准确事件。前者能对到 Edge，后者明确没有模型请求。 |
| 普通聊天、室内布局、导出与旧云 Agent Run | 原入口和权限可用，户外升级不破坏既有行为。 |

初始体验目标，M0 记录基线后只调整测量条件：代表任务的需求重复录入 **0 次**，确定性本地操作模型调用 **0 次**，一次确认导致重复写入 **0 次**。组合需求在已知事实充分时最多一个必要澄清，范围确认和方案应用单独计数。固定环境下，点发到首个有用反馈目标 **1 秒内**；涉及外部服务的总耗时用同样本对照，分别记地图和模型耗时。超时恢复和零越权写入是验收条件。

## 6. 定时执行与中断恢复

### 推送与版本（2026-11-16 用户授权，优先级高于提示词里的“不推 origin”）

- **每轮结束推 main。** 用户已明确授权。但只推通过验证的提交：定向测试绿、`npm run typecheck` 0 错、CHANGELOG 已加段、根与 `frontend` 两个 `package.json` 版本一致。不 force push，不推未验证提交。
- **版本号按改动量两级。** 跨模块或新增能力 → minor `+0.1.0`（如 4.14.0 → 4.15.0）；单点修复、文案、测试、样式 → patch `+0.0.1`（如 4.14.1）。版本写进两个 `package.json` 与 CHANGELOG，commit message 带版本号。
- **节奏 45 分钟一轮。** 距上一轮提交不足 40 分钟且无新证据时，本轮只核对状态后退出，不产生改动。
- 推送失败（冲突、网络、钩子拒绕）时**不** 用 force，保留本地提交并在进度里写清失败原因与下次重试命令。
- 回退：每个版本一个可独立回退的提交；体验改动与服务端改动不同时混在一个 commit 里。

以下为原定时执行约定。

- 定时任务执行者需要同一仓库的持久工作目录和进度文件读写权限。首次运行记录仓库根、工作目录、分支和 HEAD。分支优先使用同一已有任务 checkout；要隔离时按执行环境的工作树流程创建一次并持续复用。若基线依赖本地主工作区的未提交修改，先记录差异及归属，不能假定新的 checkout 已包含它们。
- 同一执行分支只运行一个写任务。优先用调度器的互斥能力。若调度器不支持，执行前用原子方式创建本机临时锁，包含运行 ID、机器、PID、时间与分支。只有确认前一执行已结束才能清理残留锁，再从实际 diff 复核中断位置。活跃任务存在时本轮退出。仅凭时间过去不抢锁。
- 每批按 `待开始 → 进行中 → 已验收` 更新进度，外部阻塞检查项标 `待核验` 或 `阻塞`。开始动手前写下当前切片、开工 HEAD、预期路径和下一条命令。完成一个切片马上更新证据、剩余项和准确续跑点。恢复先看 `git status`、本批文件 diff、最近提交和测试证据，保留已完成内容。进行中不等于成功，失去输出时重做最后一个可重现的验收。
- 每次只处理可验证的最小切片。默认每轮留出最后 5 分钟做验证和落盘；没有剩余时长信息时，优先办一项验收。可持久保存的定向修改按仓库规则逐批提交，明确暂存自己的文件。不能提交时保留差异并记清未提交文件和恢复命令。业务前进遇到外部依赖时先推进无依赖切片，已有权限下核对新证据。发布与真实付费沿用项目授权和环境规则。
- 失败后用同一最小复现重跑，记录第一失败步骤并作一次有针对性的修正。持续外部阻塞时记录所缺的角色、接口或环境和解除条件；后续轮次先看条件有无变化。对真实请求先查回执，以免重复计费。所有批次验收后写最终结果和 commit，后续触发发现完成直接退出，便于关闭定时任务。
