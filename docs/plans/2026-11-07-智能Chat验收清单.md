# 智能 Chat 连续对话与建造验收

配套主计划与 Terra 工程任务单。以下是验收要求，不是已通过清单。执行者填写实际证据与限制；代码、模拟模型、真实模型、真实场地分开记录。

## 1. 核心连续旅程

使用隔离本地活动，开始时无已确认人数/场地尺寸/门事实。下面的尺寸和库存是测试假设，不是真实案例事实。

| 轮次 | 用户输入/操作 | 需要观察的行为 |
|---|---|---|
| 1 | 你好，我想办一场社区讲座，资料还没齐 | 既回应又保留讲座意图，不把整句当问候；优先问一个关键问题 |
| 2 | 我们有80把椅子，大概30个人来 | 人数为约30，不是80；库存是否已保存必须说清 |
| 3 | 上次有签到，这次不需要，大家都坐着 | 本场不签到、全员入座；历史不污染当前；必要确认聚合展示 |
| 4 | 为什么讲座要考虑通道和排队？ | 回答问题，不改人数、不强制新增签到，不声称已检查真实场地 |
| 5 | 场地还没量，你先帮我看看可能怎么摆 | 提供可修改假设探索；缺尺寸/门/容量仍未知，不卡死对话 |
| 6 | 测试先按12×9米、30人、课桌椅，不要舞台 | 明确这是假设；预览展示对应参数与未核验项；不偷偷变为确认事实 |
| 7 | 生成时立即说“再加两把椅子” | 原话保留，顺序可见；候选落稳后继续处理，不丢句或改错基线 |
| 8 | 等待时说“停一下” | 不排在卡住请求之后；立即停止本地等待，旧响应不写回；费用状态如实 |
| 9 | 重开受控测试，补齐本场可核对数据并生成 | 实际本场数据/假设分开；只问尚缺关键项 |
| 10 | 在这版上把选中的桌子往左移1米 | 指定对象与方向明确；锁定对象不动；完整差异可见 |
| 11 | 填写某一候选物料可用总数为0 | 显示精确短缺、阻止确认；清空恢复未知，不当零 |
| 12 | 取消该短缺或调整方案，确认后撤销 | 最终独立复核；一次应用，一次撤销恢复完整基线 |
| 13 | 给搭建方清单和待确认事项 | 来自用户选择的候选/正式版本；完整交接含需求、来源、假设、未知 |

第9轮若无法获得真实事实，可继续用明确合成事实验证程序，但结果只能标合成测试。禁止把“用户点了确认”改写成专业人员验收。

## 2. 测试矩阵

类型：U=确定性/契约测试；C=组件集成；B=真实浏览器、可用模拟响应；M=真实模型/服务；F=真实人员/场地。

### 对话生命周期与普通问答

| ID | 场景 | 必须结果 | 证据 |
|---|---|---|---|
| A01 | 两句连续发送，第一句模型挂起 | 两句各显示一次、顺序可见、第二句不丢 | C+B |
| A02 | 本地生成→立刻加椅→再加一把 | 等前候选稳定后计算下一候选，全部追加保留 | C+B |
| A03 | 云请求永不返回或忽略 abort | 超时/停止释放等待，不暗中重试，晚回复不应用 | C+B |

| A05 | 活动/会话/账号/楼层 A→B→A | 旧队列、旧模型响应、旧预览不复活 | U+C+B |
| A06 | 结果未知后重复发送、双击发送/确认 | 无意外重复调用/写入，重试要求与费用提示明确 | C+B |
| A07 | 你好；你好，来30人 | 前者立即回应，后者人数不被吞 | U+C+M |
| A08 | 一般活动原理问题 | 直接回答，不追问无关人数、不改布局 | C+B+M |
| A09 | 问完问题再补人数/尺寸/否定需求 | 同会话上下文保留，问答不覆盖已确认字段 | C+B+M |
| A10 | 未配置、未登录、401/429/超时/格式错误 | 准确状态和可继续的下一步，不白屏、不假成功 | U+C+B |

## 3. 每项证据记录格式

记录 ID、执行时间、提交或源文件摘要、环境/服务、原始输入、实际输出、期望、通过/失败/未执行、失败原因、产物或日志路径、下一步。秘密不进入日志。第三方产品宣传或模型自评不能作为通过证据。

建议记录在同目录单独的验收结果文件，不改这份要求来适应已有实现。环境失败与产品失败分开，缺失关键证据为未完成；同一失败不重复刷测试次数。

## 4. 发布判断

- R1：A01–A13、A22–A25 必须有对应通过证据；尚未真实验证时可交内部演示版并明确缺口，但不标记 R1 全部完成，不能把模拟宣称真实智能。
- R2：A14–A30、A37–A40 对公开支持能力通过；事务未完成则相关混合写入不能放行。
- R3：A31–A39 和独立交接 A41；不能以只读导出代替可恢复备份。
- R4：A42–A46，场地方与专业人员参与。没有这些证据不能标长期目标全部完成。

不得以测试数量、代码行数、子代理数量或模型说“完成了”替代上述用户可观察结果。
