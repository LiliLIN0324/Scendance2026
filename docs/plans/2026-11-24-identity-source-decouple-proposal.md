## 0. 目标（本轮收口定义）

**目标一句话**：把前端身份判定从「看 id 格式」改成「看记录正源」，让六类现役槽位正确分进四态；回读失效的云卡不再冒充可打开。这是 **B1 卡片范围内**的判定层收口，不跨到 B2 迁移、B3 写守卫、B4 镜像退役。

### 0.1 完成定义（DoD，逐条可核对）

1. **四态分类**：`bound-cloud` / `local-draft` / `cache-copy` / `orphan`。判定源 = controller 挂载 + 后端可达性 + 本机信封是否存在；id 格式（UUID / `house-*`）只用于展示分组，不再单独决定身份。
2. **失效隔离**：列表侧对云项目先做可达性预检；`NOT_FOUND` / 无权 / 已软删的卡标「失效 · 无法访问」并禁用双击，不进活跃可打开列表；回读失败时不得把本机草稿冒充云端版本。
3. **分区与来源标注**：本机草稿、云项目、离线缓存副本在卡片墙分区呈现；缓存副本只读并标「本机缓存副本」，不参与写租约。
4. **状态回执一致**：卡面状态与后端回读结果一致；不再出现与实际回读结果不符的陈旧标记（如回读已失效却仍标「场景已保存 v0」）。
5. **测试与门禁**：四态判定定向单测覆盖 cloud / local / cache / orphan 及互斥；根 + 前端 `tsc --noEmit` exit 0；既有 vitest 套件无增量回归；`npm --prefix frontend run build` exit 0。
6. **真机复核**：原六卡逐一复核——5 张 NOT_FOUND 落失效态、`583dbff1` 只读云项目落只读可打开；`house-*` 草稿不被误判成云项目。

### 0.2 本轮不做（Out of scope）

- 不删 / 软删任何云端项目，不清本机裸槽，不动 IndexedDB / localStorage 存量。
- 不做历史裸槽向 `house-*` 的迁移（B2）；不做写守卫 plan 化（B3）；不退役回写镜像与旧键（B4）。
- 不做新建即时归属全链（后端即时发号 vs 本机草稿后换绑，归 B2/B3 定稿）。
- 不访问数据库、不绕过 UI 重放后端接口。

### 0.3 阻塞拍板项（到决策点停住，不代选）

- `orphan` 过渡态处置：降级只读保留 / 迁 `house-*` 草稿 / 标失效移出列表。
- 离线缓存副本在无网时的可见性档位。
- 新建即时归属方式；C1 无参刷新草稿索引档位；C2 旧 `activity:` 存量会话 / 偏好迁移。

### 0.4 前置风险与门禁

- 后端 list/get 的 HTTP 状态码与数据层根因尚未定性（行缺失 / 成员移除 / 场景损坏 / 部署版本）。根因复核前，前端可达性预检失败一律按「失效」保守降级，**不静默删数据**；删除动作等 DB 只读复核定性后另议。
- 本地攒批：tsc + 测试 + 真机走查全绿后再一次性推 main；只按明确路径 `git add`，不用 `-A` / `.` / `commit -a`；不碰 7 个独占 / 基线文件。

## 3. 终态身份模型（三态互斥 + 缓存副本）

一份方案只有一种身份，由**记录正源落在哪里**派生，id 格式只作展示分组，不作身份真值。

| 身份 | 判定（正源优先） | 通道 | 可写 |
| --- | --- | --- | --- |
| **云项目 `bound-cloud`** | controller 挂着服务端项目，单项目回读 200，可探写租约 | 云卡进入 / 写租约 / 回写 | 持租约可写，否则只读 |
| **本机草稿 `local-draft`** | plan / flow / session / bodies 信封在本机；`house-` / `default-outdoor` / `replica-` 前缀 | 本机活动切换 / 备份恢复 / 点验；不去云端查 | 本机可写，显式存为云项目后换绑 |
| **离线缓存副本 `cache-copy`** | 曾成功打开的云项目本地副本；当前未挂云项目、联网不可达 | 只读查看，可「联网重新拉取」；不建立云绑定、不参与写租约 | 否 |
| **第三身份 `orphan`（终态不允许作为可切换身份）** | 既非本机前缀、后端回读 NOT_FOUND、controller 未挂云项目 | 过渡态降级为「失效 / 待迁移」，不进可打开列表 | 否 |

**派生顺序**：先看 controller 挂载与后端可达性，再看本机信封是否存在，最后才用 id 格式兜底分组。现役反序——先用格式判 cloud，再决定是否关闭本机通道（walkthrough §8.2）。

## 4. 现役错位清单（证据挂账）

1. **纯格式判定**：`projectLinkKind`（project-identity.ts:22-30）看到标准 UUID 即判 `cloud`，不看本机信封、不看 controller 是否挂云项目。
2. **早返回关闭本机通道**：`hasRequestedCloudProject()`（geometry-workbench.ts:29-34）仅凭 URL 格式判 requestedCloud；`isLocalActivityWorkspace()`（:37-42）requestedCloud 时早返回 false，不再读 controller snapshot / 本机信封。
3. **失效卡仍可进入**：`canEnter`（cloud-panel.tsx:1390）不探单项目回读可达性；NOT_FOUND 在 `enterProject → getProject` 失败后才回执。
4. **清单分态不足**：云项目、离线缓存副本、裸 UUID 历史槽混在云卡区；本机草稿虽单列，历史裸槽仍按云号展示。
5. **发号保留裸 id**：`withHouseId`（ids.ts:25-28）仅在 layout 无 id 时补 `house-<后缀>`；layout 已带裸 UUID id 时原样保留，不重写前缀，历史裸槽得以留存。
6. **list / get 一致性未在前端隔离**：list 返回的失效项仍直接渲染；前端无「列表项可达性预检」层。

## 5. 解耦落点映射（归 B1–B4，不跳卡）

### B1 会话 / 身份解耦（身份正源单点派生）

- 身份判定从「id 格式」切到「controller 挂载 + 后端可达 + 本机信封」三源一致；格式仅用于分组展示。
- `isLocalActivityWorkspace` 不再凭 requestedCloud 早返回：controller 未挂云项目、且本机存在该 scope 信封时，按本机工作区处理（过渡态行为，见 §7 待拍板）。
- 会话槽、简报、库存、草稿围栏、归档键、偏好、评审链接同一 projectId scope；去掉 `layout.id ?? 'local'` 裸回退（去回退随 B2/B4 成套，台账 :48）。
- 补单测覆盖 `bound-cloud / local-draft / cache-copy / orphan` 四态判定与互斥。

### B2 历史快照 / 存量槽迁移

- 历史裸 UUID 本机槽识别为 `cache-copy` 或 `orphan`：能对应到云项目的走缓存副本口径；对不上的按待迁移处理，迁移到 `house-*` 草稿或解绑。
- 两份 brief 打通（例3 理解失败人数导出，台账 :49）。
- 列表侧失效项隔离：回读不可达的云卡不进活跃可打开列表。

### B3 导出与写守卫 plan 化

- 写守卫按 plan scope + 项目级 lease / revision，不靠 layout.id 判定身份；checkin / note scope 转 plan（台账 :50）。

### B4 回写镜像退役 / 旧键迁移

- 旧裸槽键、环境偏好键一次性迁移（C2）；缓存副本键归位；清残留镜像分支（台账 :51）。

### 过渡态前端兜底（2026-11-24 已拍板，云卡部分已落码）

- 回读失效的云卡标「已失效 / 无法访问」并禁用双击，不进活跃列表；可放入「最近删除 / 失效」区。
- 本机草稿与云项目在卡片墙分区明确；离线缓存副本只读并标来源。
- 以上不改变后端数据，属前端展示与可达性隔离；与 C4 终态的关系随 B2/B3 定稿。

2. **步 2（B2）**：存量裸槽识别与迁移口径；失效列表隔离。
3. **步 3（B3）**：写守卫 plan 化。
