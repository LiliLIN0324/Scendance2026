## 3. 必须保持的产品规则

1. **全部上云不等于全部公开。** 两位管理员的合法上传默认进入可靠私有云归档；发布是独立动作。普通用户也保留既有私有内容边界。
2. 官方内容归共同工作区或等效组织实体，两人均有相应管理权。平台管理权和单项目编辑租约分开，管理员不通过绕开版本检查实现协作。
3. 素材原文件、项目草稿、已发布版本、案例目录各有职责；浏览器缓存是副本，不是唯一存档。
4. 项目草稿可编辑；发布版本不可变；案例固定入口指向当前发布版。修改草稿不影响公众，显式发布更新才切换指针。
5. 普通用户只读查看官方案例；“使用此案例”创建独立副本。官方更新、再次打开都不覆盖个人副本。
6. 原有固定版本交付可继续使用；受控分享支持撤销。已导出文件及自带数据的旧链接不能承诺远程擦除。
7. “云端已保存”必须有服务器确认的版本和依赖完整性证据；不能把上传完成、场景 JSON 保存和完整项目归档混为一谈。

目标主链：上传 → 私有云素材 → 官方云项目草稿 → 完整性核对 → 发布不可变版本 → 案例入口指向该版本 → 普通用户只读查看/另存副本 → 管理员编辑草稿并发布更新。

## 5. 关键实现约束

### 5.1 身份与共同归属（C01/C02）

- 选定唯一可信的服务端权限来源，沿现有认证链做 capability 检查，UI 只消费结果。审计授权者、被授权者、时间与变更；撤权即时对后续请求生效。
- 普通个人 owner 不能管理官方案例；不得靠知道 asset/project/case ID 访问他人私有内容；签名下载也须校验当前访问范围。
- 明确个人上传与官方上传归属。管理员上传默认云存储，但不隐式公开、不自动挪走现有个人项目。
- 梳理现有户外 owner-only RPC 与工作室协作的差异，给出兼容迁移，不通过所有人可读写或客户端传 actor 解决。
- 同一个官方项目仍使用版本冲突/租约约束，两人不能因超级管理员身份相互静默覆盖。

### 5.2 归档与保存（C03–C07）

- 覆盖已支持的文件格式；先核对实际大小/格式限制。大扫描不可沿用当前小 GLB 上传限制强行塞入；若引入直传/分片，保留完成校验、授权、失败清理和幂等登记。
- 文件已到对象存储但元数据登记失败、元数据成功但项目引用失败，都要能恢复并对账；不要制造幽灵成功或无限重传。
- 队列按账号/工作区隔离。切换账号、撤权、退出时停止原账号操作，不继承另一账号的上传映射或成功状态。
- 可保持本机先编辑；云端失败不丢本机。待同步任务须在刷新/重新登录后恢复；需要重选原文件时明确列出，不能承诺浏览器关掉仍能读取不可持久文件句柄。
- 完整保存清单包括项目实际引用的原文件、扫描、模型、图纸/图片、附件，以及必要的变换、配准、比例、室内/户外结构；建立字段覆盖表，哪些原资料私有、哪些发布可见须明确。
- 原文件/依赖未归档完不显示“完整云端已保存”，也不能发布一个引用本机代理、blob URL 或已过期签名地址的案例。
- 云端存 asset ID/稳定对象引用，查看时按权限换取地址，不能把短时 URL 当长期主键。对可公开的打包内置素材保留现有兼容。
- 保存确认只确认本次提交版本。上传期间用户继续编辑时，新改动仍为待同步，不能被旧请求回执清空。
- 页面离开时 best-effort flush 不是可靠持久化证明；避免靠 beforeunload 或固定延时声称已保存。

### 5.3 案例与分享（C08–C13）

- 复用现有 publications/shares/library_assets 等能力；首先确认 publication 实际覆盖的室内/户外和资源范围，再补缺口。
- 案例逻辑至少涵盖稳定 case ID、元信息、草稿引用、当前发布版本、发布状态及历史。新名称/表结构由实际实现审查确定。
- 国内静态案例可作幂等种子和过渡来源。保留已有 ID、引用和来源授权；不得批量公开只有内部学习授权的参考图或素材。
- 发布在依赖核验后产生不可变版本，再原子切换案例当前版本；失败时公众继续看到上一版。
- 案例目录只返回公开字段；公开资源只给已发布版本所需集合，不能泄露私有源附件和无关资产。另存副本的资源使用范围需明确，不能直接赋予原项目编辑权。
- 下架从目录移除，并按定义处理案例入口；“下架案例”和“撤销一条分享”须有不同且明确的影响范围。
- 云端受控入口做访问/撤销检查；可保留自带数据的离线导出，但显式说明固定快照、不随项目更新、无法远程撤回已发副本。

### 5.4 存量迁移与恢复（C14/C15）

- 先盘点、预览迁移清单，再执行幂等补传；校验原件字节/哈希和关联，不编造丢失原件。
- 服务器无法直接访问另一台设备的 localStorage/IndexedDB/本机代理。应提供用户在原设备发起的补传入口，不假称已找齐全部历史数据。
- 不删除本机唯一副本；新旧案例切换、账号/归属迁移和失败恢复须有可执行回滚说明。关键发布/权限审计不能等 P2 才做。

真正阻塞时只停相关部分，其他可独立实现继续：

- 缺少两位管理员的可信 UUID：继续角色机制/测试，暂不授予线上身份。
- 缺少数据库/契约 review：完成具体补丁、兼容与回滚方案，暂不应用线上变更。
- 缺少原设备文件：提供盘点与补传入口，不编造已归档结果。
- 缺少真实测试登录：完成本地实现和可读检查，标记 V01–V14 对应云端项待验。

**终点：不是“增加了云存储按钮”，而是两个管理员的合法上传可跨设备找回完整原件与项目、共同维护官方案例，普通用户能稳定查看已发布完整版本，案例可更新且不破坏旧交付和个人副本。**
