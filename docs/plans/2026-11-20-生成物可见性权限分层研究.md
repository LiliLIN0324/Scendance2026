# 生成物可见性与权限分层研究（2026-11-20）

> 状态：现状调研 + 方案建议，**分层归属尚未拍板**。本文只盘点现有代码与迁移的真实规则，不另起并行 schema；涉及 migration / 契约的改动均标注为「需人 review」。
>
> 后续：成熟产品对照、目标模型与分期落地路线见 [权限体系建设方案](./2026-11-20-权限体系建设方案.md)；本文 §五 的 6 个开放问题在该文 §五 给出了对标建议答复。
>
> 触发问题：「各种生成物——包括每个新建项目——都要能分权限看到：作为开发者希望所有人看到的、开发者能看到的、以及一个团队内都能看到的，具体怎么分还不清楚，但这个很重要。」

## 一、结论先行

1. **现状已经是四层，但没有被显式命名**：本机草稿 → 物主私有 → 工作室（团队）内 → 对外公开（注册用户公共目录 / 匿名快照链接 / 静态随包库）。
2. **库里不存在「开发者 / 管理员」用户角色**。`members.role` 只有 `owner` / `editor`；策展目录只能由 `service_role` 跑离线脚本写入，注册用户侧没有任何 admin 标记。这是与「开发者能看到的」期望之间最大的缺口。
3. **「公开」目前实际分两档**，产品上还没区分：
   - **匿名可访问**：只能通过分享快照链接 / 评审短链拿到一份脱敏快照；没有公开的项目列表、物料列表接口。
   - **注册用户可访问**：公共目录物料（`published_assets`）、策展目录（`library_assets`）——但前提是该用户在任意工作室有会员行；匿名访客拿不到。
4. **团队可见性只覆盖项目/工作室这条线**：户外活动方案、户外卡片历史、个人偏好、生成任务记录、Agent 运行记录都只对本人；同一团队的其他成员当前看不到。是否要把这些纳入团队可见，需要拍板。
5. 建议复用现有三套机制（`published_assets` / `library_assets` / studio 成员 + `project_assets`）表达公开、团队、私有；「开发者内部」层先用 `catalog` / `metadata` 标记做轻量方案，是否升级为独立角色表再议。

### 2.2 云端 3D / 图片物料（`assets`）

取用授权函数 `scene_private.can_use_asset(actor, asset)`，当前四个分支（`20261119150000_published_assets.sql` 定稿）：

1. **物主本人**：`owner_id = actor`；
2. **项目内继承**：资产被某个未删除项目引用（`project_assets`），且 actor 是该项目所在工作室的成员；
3. **物主公开**：资产在 `published_assets` 中，且 actor 在任意工作室有会员行；
4. **策展目录**：资产在 `library_assets` 中，且 actor 在任意工作室有会员行。

列表可见性 `assets.list`（`20261119160000_published_assets_publish_flag.sql` 定稿）：**本人所有 + 已发布到公共目录的物料**；项目共享件不进列表，只在打开对应项目时经 `can_use_asset` 取用；策展目录件也不进这个列表。

| 档位 | 存储 | 写入主体 | 可见范围 | 匿名可达 | 约束 / 依据 |
| --- | --- | --- | --- | --- | --- |
| 物主私有 | `assets.owner_id` | 上传 / 生成物主登记 | 仅物主 | 否 | `20261002060304_scene_core.sql` |
| 项目内共享 | `project_assets` | 项目保存时自动挂引用（`save_scene`） | 同工作室成员 | 否 | `scene_core.sql` `save_scene` / `check_assets` |
| 物主公开 | `published_assets` | **仅物主**可发布/撤下；**仅 GLB** 可发布，平面图/参考图不可公开 | 任意有会员行的注册用户 | 否 | `20261119150000_published_assets.sql`、`20261119160000_*publish_flag.sql` |
| 策展 CC0 目录 | `library_assets` | `service_role` 离线批量脚本注册；强校验 CC0 / sourceUrl / catalog 四件套 | 任意有会员行的注册用户 | 否 | `20261002180000_shared_model_library.sql`、`scripts/import-model-library.ts` |

## 三、与「公开 / 团队 / 开发者私有」三层期望的对照

| 用户期望层 | 现状对应 | 缺口 |
| --- | --- | --- |
| **所有人可见** | 静态随包库 + 内置基础件（静态直链）；分享 / 评审快照（链接制匿名） | 云端公共目录目前要登录；没有「匿名可浏览的公开物料列表 / 项目列表」；评审短链无吊销 |
| **团队内可见** | 项目、项目共享物料、成员、消息、工作室设置、重建源图 | 户外方案、生成任务、历史记录、偏好仍只对本人；项目没有私有 / 团队公开开关 |
| **开发者能看到的** | 无对应角色；策展目录靠 service_role 离线写入 | 缺用户级 developer/admin 标记；缺「内部候选 / 未达标物料」分组；前端没有内部视图 |
| **开发者私有** | 物主私有物料、本人任务记录、本机草稿 | 语义上已存在，但没有「内部草稿」与「客户可见」之间的中间标记 |

## 四、建议的三层口径（待拍板）

### 4.1 建议命名与定义

- **L1 公开（所有人）**
  - L1a 匿名公开：静态随包库、内置基础件；以及凭链接访问的脱敏快照（分享链接 / 评审短链）。
  - L1b 注册用户公开：`published_assets` 物主发布件、`library_assets` 策展件。是否把 L1b 再放开给匿名，是单独的契约决策（见 §五 开放问题 3）。
- **L2 团队内**：同一工作室成员可见的项目、项目引用物料、消息、设置、重建源图与任务。
- **L3 私有 / 内部**：物主本人件；再细分 L3a 物主私有（默认）与 L3b 开发者内部候选（未达公开质量、仅团队/开发者可见）。

### 4.2 各类生成物归属建议

| 生成物 | 建议默认层 | 理由 / 备注 |
| --- | --- | --- |
| 内置基础件、静态随包成熟物料 | L1a 匿名公开 | 现状即随包发版；成熟 CC0 / 已验收件 |
| 物主上传 / 生成的 GLB | L3a 私有，物主可一键升 L1b | 沿用 `assets.publish` 现状；仅 GLB 可公开 |
| 项目方案 | L2 团队内；对外再走 L1a 快照链接 | 现状即此规则 |
| 户外活动方案 | 现状 L3a；**建议评估是否升 L2** | 团队协作时同组成员应能接续编辑 |
| 重建源图 / 重建任务 | L2 团队内 | 与项目绑定，现状即成员可见 |
| 生成任务记录 / Agent 运行记录 | L3a 物主私有 | 过程记录，不必进团队库；团队只看项目产物 |
| 户外卡片历史、个人偏好 | L3a 私有 | 个人工作习惯，不共享 |
| 开发者内部候选件（未验收 / 试验批次） | L3b 内部 | 新增标记层，见 §4.3 |

### 4.3 「开发者内部」层的落地选项

**选项 A（轻量，不改表结构，先做）**：复用现有 `catalog` 字段与 `metadata` 标记分组。
- `published_assets.catalog` 已有来源分组字段；内部候选件可写 `catalog = 'scendance-internal'`（或 metadata 加 `visibility: 'internal'`）。
- 读取时按当前用户身份（成员行 + 开发者白名单）过滤；前端在物料面板加「内部候选」分组。
- 不需要新 migration；白名单先用配置 / 环境变量维护。

**选项 B（正式，需人 review）**：给 `members.role` 增加 `admin`，或新建 developer 标记表。
- 只有在「内部视图要对特定团队成员开放、且要可管理」时再上；涉及 migration 与 RPC 契约，按项目规范必须人 review。
- 不建议第一步就上：当前没有第二个人需要管理员视角。

## 五、待拍板的开放问题

1. **「开发者能看到的」到底指哪一种**：(a) 管理员策展后台视角；(b) 开发团队内部预览件（未达公开质量）；(c) 账主自己的私有件？三种对应不同落点。
2. **户外方案 / 生成任务要不要团队可见**：现状是仅本人；协作场景下是否需要同工作室成员接续。
3. **公共目录是否对匿名开放**：现状必须有会员行才能取 `published_assets` / `library_assets`；若开放，`assets.list` 与签名 URL 策略都要改，属契约改动。
4. **本轮 14 个 Aholo 道具默认落哪层**：(a) 静态随包库（L1a，需缩略图与构建入库）；(b) 云端登记为 L3a 私有，物主后续自行发布；(c) 先挂 L3b 内部候选，验收后再升公开。
5. **评审短链要不要补吊销入口**：现状只靠 180 天过期。
6. **项目级私有开关是否需要**：现状工作室内所有项目对全体成员可见；若存在「一个团队内只有部分成员能看某个方案」的场景，需要项目级可见标记。

## 六、改动清单与风险边界

- 可直接在前端 / 本地脚本层做：物料面板分组标注（我的 / 团队项目引用 / 公共 / 内部候选）、`catalog` 分组展示、白名单配置。
- 需 migration / 契约改动（**必须人 review**，本仓不擅自动）：角色枚举、匿名公共目录、项目级可见开关、评审短链吊销、内部标记入表。
- 已确认不可行 / 不建议：另起一套并行的权限表或身份 schema；现状 `studio` + `project_assets` + `published_assets` + `library_assets` 已经能表达公开 / 团队 / 私有三态。
