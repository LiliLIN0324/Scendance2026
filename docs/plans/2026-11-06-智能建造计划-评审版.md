## 1. 我们在做什么（一句话）

一个活动策划的 Web 应用：用户用大白话说一场活动（多少人、室内外、什么类型），系统在真实场地平面上自动排出多版布置，做人体工学/消防/无障碍/动线检查，给出中文人话解释，并支持对话式修改。

不是通用家装工具，是**活动策划垂直**：签到排队、主舞台、圆桌/剧院座席、打卡区、休息区、撤场路线这些是一等公民。

## 2. 北极星（为什么现在的还不够）

当前系统能「把家具摆进场地并打分」，但离「可托付」差四件事：

1. **事实可信**：门在哪、尺寸多少、核定人数——现在没有「这条信息是图纸来的、还是模型猜的」的区分。猜的不能当安全结论。
2. **规则适用**：不能拿美国 ADA 数字当中国规范结论；要标注用了哪本规范、哪个版本、哪些项根本没查。
3. **活动真实**：现在是静态家具堆砌，没有「人和流程」（排队会不会堵）、「时间」（搭建/撤场）、「资源」（椅子库存、电源、装卸口）。
4. **责任可追**：没有版本冻结、场地方确认状态、改一笔会不会让旧结论失效。

**北极星**：在信息不完整、需求冲突、现场变化时，系统能说清自己知道什么、不知道什么，给出可执行方案，并让人能核验、修改、交接。

## 3. 设计原则（评审重点）

1. **三个大脑分层**：LLM 负责听懂和说人话（输出带 schema 校验的结构化意图，不直接给坐标）；确定性算法负责几何（组团、连通、修复）；硬阈值规则是安全底线，对 LLM 输出有一票否决权，模型挂了规则兜底、对话不白屏。
2. **只把物理/安全写成硬规则，不把「某类活动该怎么摆」写成 if-else**：「商务=圆桌」「老年=轮椅」是刻板印象，活动相关需求必须由 LLM 读这一场活动本身提取；拿不准就问主办方一句，而不是用最保守假设替用户断言（例如「老年」≠「坐轮椅」）。
3. **生成器与验证器职责独立**：生成器说「我找到方案」，验证器用同一套事实和规则逐项复核，不能生成过程自己给自己打通过。
4. **约束结果四值**：pass / violated / unknown / not_applicable。**不匹配的数据不能静默按 0 分（通过）处理**——这是 FlairGPT 补充材料里记录过的真实事故。关键安全项 unknown 时禁止进入「可交付」。
5. **研究系统学方法、商业产品学交付、现场反馈才算数**：论文能跑 ≠ 现场安全；功能宣传 ≠ 已验证能力。

## 4. 数据结构目标（可信事实模型）

每个关键事实（门、尺寸、人数、固定障碍、电源、核定容量）记录四元组：

- 值与单位（门宽 1.2m、位置与开启方向）；
- 来源（场地方图纸 / 现场测量 / 用户口述 / 模型推测）；
- 状态（confirmed / pending / inferred / unknown，附测量误差）；
- 版本与影响（谁改的、何时改的、会使哪些检查失效）。

方案四态：**探索草案**（缺信息但假设可见，仅内部讨论）→ **待核验**（有布局但关键事实/检查未完成）→ **已通过系统检查**（列出已过规则及版本 + 未覆盖项）→ **已由相关人员确认**（记录确认人和版本）。任何影响场地/安全/容量的修改，旧确认自动失效、回落到待核验。

## 5. 阶段路线（请评审判断优先级是否合理）

| 阶段 | 目标 | 通过门槛 |
|---|---|---|
| P0 可信底座 | 事实四元组、规则版本、约束四值、方案四态 | 缺出口/比例尺时不显示「安全通过」；推测门显著标注「门位置未确认」；未知规则不静默消失 |
| P1 一个真实场景做通 | 选「银发讲座」走完全程：对话→场地确认→分组排布→解释 | 真实场地+真实物料，需求到可审阅方案；假设与不足全部可见；允许只出 0/1/2 个方案，无解时解释冲突并给最小调整建议 |
| P2 可靠修改 | 对话修改、锁定对象、差异预览、撤销、独立复核 | 改动用户同意后才应用；改后相关检查自动重跑、旧确认失效 |
| P3 交付版 | 版本冻结、平面图、尺寸、物料表、风险与待确认清单 | 没参与建模的执行人员仅凭交付包能复述布置；场地方能对特定版本确认 |
| P4 活动流程 | 排队长度、人员路径、搭建/活动/撤场阶段、资源限制 | 能识别静态图看不到的排队或阶段冲突 |
| P5 优化与学习 | 求解性能、更多活动类型、偏好排序 | 偏好只影响排序，绝不覆盖硬规则；先证明数据质量与人工基线 |

**近期最优先**：不是上更复杂求解器或 DPO，而是拿一场有图纸、明确人数、有家具清单的真实活动做纵向切片，记录每处需要人工补充的信息——先搞清楚缺的是算法、数据还是交付流程。

## 6. 把「活动」放进模型（静态家具之外）

- **人和流程**：区分观众/轮椅使用者/工作人员/供应商；签到排队长度、队伍是否侵入通道、服务能力。初期用明确假设估算，不假装人流仿真。
- **时间**：搭建/彩排/入场/正式/撤场是不同状态和障碍物集合。
- **资源**：家具库存（尺寸/数量/价格/供电/替代品）、舞台屏灯电缆、装卸口、场地禁区。生成时就报「缺 12 把椅子」「需确认电源容量」。

## 7. 验收指标（防自我感动）

- 关键事实覆盖率：入口/出口/尺寸/固定障碍多少已确认，不完整方案是否正确标为待核验。
- 安全漏检率：专业人员标注的危险案例中漏多少，如实报样本量与置信区间（100% 拦截 ≠ 零风险）。
- 无解解释质量：冲突时指出冲突并给可选调整，而不是悄悄删椅子。
- 局部修改可靠性：锁定对象不动、差异真实、撤销可恢复、旧确认失效。
- 现场可执行性：执行人员读交付包能否找到物件/数量/尺寸/待确认项。
- 真实效果：与人工方案比完成时间、返工、问题发现率、满意度；**同时统计放弃率与人工接管率**——不能只奖励「少说话少移动」。
- 几何诚实：通行净宽、转弯空间、会车空间是不同几何问题，1.5m 是保守设计目标而非完整无障碍结论；0.3m 网格 BFS 要补「实体转弯能否通过」并标注网格误差。
