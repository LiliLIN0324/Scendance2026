## 1. 我实际走了哪条路

1. 打开首页 → 新手提示弹层（8 段视频步进 + 8 条文字提示）→ 点「跳过」（`_shots/01`）。
2. 左上模式组点「山体」→ 调色板与底部工具条同时换（`_shots/02`）。
3. 左侧猫头「智能体」→ 浮动卡展开（`_shots/03`）。
4. 右上「保存与分享」→ 三档 tab，逐档看（`_shots/04` 自己继续、`_shots/05` 给朋友）。
5. 右上「打开菜单」→ 换一颗星球 / 导入地图 / 设置 / 帮助 / 关于（`_shots/06`）。
6. 右轨「切换视图」→ 3D 透视（`_shots/07`）。

**第一手感结论：它的产品感不来自"功能多"，来自"画布是唯一的主角"。** 一屏之内只有四条轨：左上模式、左上资产、右上全局、右下视图；中间永远是画布。任何面板都是浮在画布上的一张小卡，不挤压、不换页。

## 2. 七条实感观察

| # | 我看到的 | 为什么值得抄 |
|---|---|---|
| N1 | **模式切换 = 调色板与底部上下文工具条同时换**。切「山体」后顶部五张素材换成山体系，底部出现三组工具：画笔（4 个变体，键 1–4）、画笔形状（自由/直线/曲线/矩形/圆形，键 5）、自动修剪（不修剪 + 三个转角）。每组都有文字标签，每个按钮带数字快捷键徽标 | 这是"异层范畴不要平级人格化"的**最省力实现**：不建新面板、不加新页签，只切一组上下文工具。幕景的空间/物料两脸完全可以用同一手法做成「模式条 + 上下文工具条」，比现有侧栏面板轻得多 |
| N2 | **智能体是一张锚定在左轨的浮动卡**（DOM 里 `shell-assistant-panel` + `dock-pin`「停靠面板」），展开时画布一点没被挤窄，只在卡片范围内滚动（`pw-scroll-stable`） | 幕景现在的助手是常驻侧栏，一开就吃掉画布宽度（10-10 那轮"561px 助手全屏盖住 map"就是这个老问题）。**改成可停靠浮动卡**，是比"压缩面板"更彻底也更便宜的路 |
| N3 | **保存与分享是"分节开关 + 每节字节数 + 总大小"**。自己继续档里每一节都能单独开关：地图 508B、规划标注 0B、备注 0B、生成配方 0B（不可用时写明"此地图不是由生成器完整创建的，因此不可用"）、**溯源记录 202B（记录每格 AI 辅助与程序生成的来源）**、操作历史 35B、编辑器会话 93B、统计信息 161B、目录信息 2B；底部"格式化输出"开关 + "总大小 841 B" | 第 9 批的 provenance 在 petitmaker 里的对应物就是这一节。**交付/导出包做成"可分节选 + 体积可见"，比"导出一个大 JSON"更像产品**；而且"某节不可用并写明原因"这个口径，幕景的"生成件不可用"也是同一套 |
| N4 | **「给朋友」= 预设表单 + 右侧实时预览**，含标题/描述/尺寸（小图/标准/高清/原生）/画风，以及一个开关「**允许他人从图片重建此地图**」；预览里带图层侧栏、坐标标尺、日期与尺寸、logo | 幕景的评审包/交付预览可以抄这个骨架：导出前有真实预览；"能否被对方重建"是一个显式开关，而不是隐含在格式里 |
| N5 | 菜单极简：换一颗星球 / 导入地图 / 设置 / 帮助 / 关于。没有任何"更多" | 幕景左轨与菜单的层级可以据此做减法 |
| N6 | 2D/3D 是**一个按钮**（`切换视图`），切过去后右轨内容重排（2D 按钮变 3D，撤销/重做下移），底部工具条与浮动助手卡**都不动** | 幕景 2D/3D 切换已有；可抄的是"切视图时上下文工具条与助手卡保持不动"这条不变量 |
| N7 | 图层是右上「1 层」芯片 + 添加/删除；AI 产物可以独立成层、整层删 | 与计划书 X7 一致（幕景用 provenance 做"逻辑图层"，不引入完整图层系统） |

## 3. 与计划书既有条目的复核

| 计划书条目 | 我的复核 |
|---|---|
| X1 配方是可点名的实体（编号按钮 + 换一批） | **确认存在**：智能体卡里的示例任务是"在海边建一座渔村 / 先平整地面，四间房、一座码头和一条路"这类**两行式**结构，且**每次打开会换一批**。编号化配方我在本次未触发（需 key），但"换一批"确实在 |
| X2 示例 prompt 随工具上下文换词 | **确认**：山体模式下示例是"在北侧堆一座梯田山丘 / 三层高度，侧面加一道坡道"；切模式确实换词 |
| X3 参数面极简（两根滑杆 + 两个开关） | **确认**：底部工具条就是极简分组的范式（画笔形状 5 个、自动修剪 3 个），没有参数墙 |
| X4 区域负荷常驻顶栏 | **确认**：右上常驻「区域负荷：F5，0 / 10,000」，切模式时数字实时变 |
| X5 智能建造与画笔平级 + 数字快捷键 | **确认**：智能建造是工具槽里的一个格子，键 1–4 印在按钮角上 |
| X8 未配置态诚实且有人味 | **确认且更强**：「Beta / 有密钥就能开始 / **还没有密钥，我先睡一会儿**。等连接好了，就能接这样的任务」——不藏入口、不弹错误页，直接给任务范式 |
| X11 新手引导是 8 段 10 秒视频步进 | **确认**：每段一个原子动作（堆山/挖河/种树/转视角），可跳过可翻页，视频片段按钮在下方 |
| 第 8 章未列的两条新证据 | **N2 浮动可停靠助手卡**、**N3 分节导出 + 溯源节**，建议补进计划书；另建议把 **N1 上下文工具条**补为第 8 章新条目（对应 11.4「物品分类 tab + 教练气泡」的更轻做法） |

## 4. 明确不抄

- 像素画风与其素材；「搬进游戏」档；`区域负荷 10000` 这类游戏数值上限。
- **浏览器 BYOK**：petitmaker 的 Agent 是浏览器端自带密钥的 runner；幕景保持服务端鉴权 + lease + 运行记录（计划书 §「不搬」已写明，此处复核同意）。
- 网格/格子语义与"喷涂"手感（幕景是米制道具摆位，不是地形涂抹）。

## 5. 对「下一刀」的三条建议（与 `docs/plans/smart-build-next-phase-2026-11-05.md` 五批路线对齐）

1. **空间/物料两脸的面板化，不必新建面板**：按 N1 改成"模式条 + 上下文工具条（带快捷键徽标 + 文字标签）"，代价远小于侧栏重构，且天然解决 S3 里"两脸现存聊天行为"与"入口砍留"两件事。
2. **活动助手改成可停靠浮动卡**（N2）：直接消掉"助手展开盖住画布"这条老账，且不碰三道门与引擎接线。
3. **交付/导出包按 N3 分节化并露出溯源节**：与第 9 批 provenance 同源，一次做两件事——审校/交付侧看得见"谁放的"，导出侧看得见"包里有什么、多大"。

## 6. 本轮没验到的（不写成结论）

- AI 智能体真跑一次任务（无 key）：因此**没有**验证其真实执行质量、步骤时间线与错误回灌。
- 画笔实涂：我用拖拽手势试了一次，画布无变化（可能未选中画笔或需要按住），**手感未验**，不据此判断其绘制体验好坏。
- 导出与分享文件的真实内容；移动端布局；7 语言切换。
