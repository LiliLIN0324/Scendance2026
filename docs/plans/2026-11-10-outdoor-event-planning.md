# Scendance 真实场地活动规划升级

2026-11-10 · 产品与技术评审稿

## 已确认的实施范围

本次交付集中在现有 3D 工作台之前的 2D 活动规划。前期操作尽量贴近 OnePlan，按「真实地图选址 → 圈边界 → 画区、摆设施、画流线 → 查看清单 → 保存与导出」组织。基础图纸叠加和标定、人员布点纳入 2D 首版。市集验收四连：导入旧图叠真实场地 → 摆帐篷护栏 → 标客流与装卸流线 → 交叉点布引导岗 → 同版本导出图与清单；进入现有 3D 时空间关系保留。规划信息面板只保留常用指标、清单与问题定位。

沿用现有 3D 工作台、资产库和布置能力。跨模块工作限于交接规划版本、对象 ID、米制位置、尺寸和朝向，并验证现有工作台可读取其支持的数据。边界、分区和流线随规划版本保留，按现有能力决定如何呈现。下文 P1/P2 中的 3D 扩展、AI 和体验分析是远期设计参考，本次实施及验收以 2D 可独立交付和进入现有 3D 工作台为界。

## 1. 产品决策

户外地图项目默认打开「2D 规划」。用户先确定真实场地和活动边界，再完成分区、设施和流线。2D 本身可以保存、编辑、评审和交付。3D 与 AI 都从同一份已标识版本的规划读取数据。旧室内、实景重建和原有云端项目继续使用现有入口，允许有条件地建立关联。

首个样板选一个真实的户外市集。目标是从地址开始，完成边界、舞台与观众区、摊位、签到与排队、停车与装卸、安保医疗卫生设施和三类动线，发现一处人车交叉，刷新恢复后交付平面图与清单，再在后续阶段从同一版本进入 3D。城市搜索优先验证杭州，另用一处有已知尺寸的独立场地做尺度验收。

## 4. 页面信息架构

**顶栏**保留返回项目、活动名、保存状态、2D / 3D、导出。新项目主入口为「从地图开始」，现有项目显示原入口。2D 中的「进入 3D」显示规划版本与定位状态。主工具为选择、边界、分区、放设施、画流线、测量、撤销和重做。

**左栏**为「规划图层 / 添加设施」。规划图层默认分为场地边界、功能分区、设施与通行点、流线、工作人员、测量。每层可隐藏、锁定和展开。添加设施按任务搜索，点击模板进入放置模式，地图显示预览占地，单击提交，Esc 取消，放置后自动选中。图层负责呈现，设施类型和区域归属各有独立字段。

**中央**为满幅北向上地图，支持平移缩放、街道/卫星、回到场地、比例尺和图源署名。地理位置变化与编辑手势分别处理。选中的对象保持对比度，路线用箭头和线型区分，区域用名称和颜色区分。第一次开图只提示完成选址与边界，完成后给出下一步工具。

**右栏「规划信息」默认常驻。** 顶部显示场地面积、区域数、设施数、各类流线长度和待处理问题。下方分为总览、清单、问题，选中对象时展开属性，摘要仍然可见。点清单行定位地图，点地图对象同步聚焦清单。支持按区、类型、未归属和问题筛选。全案与当前可见统计分开显示，隐藏图层不会改变全案数量或问题判定。

| 指标 | 口径 |
| --- | --- |
| 场地面积、分区面积 | 分别计算边界和各分区。重叠时注明，分区覆盖取场内分区并集，独立显示越界和未分配。 |
| 设施件数、占地 | 一个摆放实例计一件，分区汇总用明确的主归属。逐件面积和场内占地并集分开，点位面积未知时标注缺尺寸。 |
| 路线长度、出入口 | 以同一版本的米制路径计算，按步行、车辆、后勤汇总。出入口显示关联路线及未连接节点。 |
| 问题 | 显示规则、位置、对象、依据与处理状态。暂缺宽度或尺度时标出缺失，容量与安全状态保留待核实。 |

## 5. 统一规划数据与坐标

建议由后端 `domain.ts` 所在契约层新增版本化 `SitePlan`。同一项目可以有既有室内场景和户外规划，必须明确哪个模块拥有哪份几何。

| 实体 | 核心字段与约束 |
| --- | --- |
| SitePlan | `schemaVersion, projectId, revision, spatialFrame, layers, entities`。实体稳定 UUID，同一发布版本包含边界、对象和所有关系。视口中心、缩放、个人图层可见偏好另存。 |
| SpatialFrame | `frameId, transformVersion, origin, sourceCrs, provider, projection, scaleBasis, accuracyM?, controlPoints?`。保留采集坐标来源、校准方式与可选误差。原点在首次确认后固定。地图切换、修改边界和移动镜头都不改变原点。 |
| 规划实体 | 共享 `id, kind, typeKey, name, layerId, levelId, source, style`。判别类型为 boundary、zone、facility、accessNode、staff、route、measurement。地面层先用固定 ID。实体可关联所属区；分区可有父区 ID，禁止循环。 |
| 几何 | 边界与区域用多边形，路径用点序列，点位用局部坐标，矩形设施以中心、朝向、宽深高存储。任意设施占地用物件局部轮廓和同一变换生成。多边形顶点与位姿二选一作为编辑真值。确认的长度、面积、包围盒从该几何计算。 |
| 流线 | `mode, direction, purpose, widthM?, fromNodeId?, toNodeId?, waypoints, timeWindow?, levelId`。端点关联后以节点位置作为唯一端点来源，移动节点自动更新。删除被引用节点需明确解除关联并保留原端点，或连带删除，合成一条可撤销命令。 |
| 模板与模型 | 模板含类型、默认尺寸、样式和可选资产映射。实例保存放置时的默认值和用户更改。模型引用记录资产身份、来源、校准与视觉变换；短期下载 URL 不落入主数据。舞台区域可直接渲染占位，若再布置实体舞台，其自身有 ID 并引用区域，设施清单只计实例。 |
| 派生信息 | 统计、问题、3D 几何和导出使用同一 `planRevision`。问题记录 `ruleVersion, entityIds, geometry, evidence`。旧版结果变更后重新计算或标为过期。 |

**坐标约定。** 真值使用局部米制 `(e,n,u)`，东、北、上。北向上的 2D 平面使用 `(e,-n)`，再经地图适配器转换为屏幕像素。Three.js 使用 `(x,y,z)=(e,u,-n)`。模板本地正面统一为 `+X`，角度以东为零、顺时针为正，Three.js `rotation.y=-θ×π/180`。模板正面、居中/落地 pivot、模型原始单位由资产适配器校正一次。旧场景中心与角点坐标、角度符号及宽深转换仍由后端适配器负责，另设方向夹具，避免二次平移和旋转。

**地理转换。** WGS84 来源使用固定原点的 WGS84 → ECEF → ENU，投影时声明地面高度约定，平面距离与地形路径长度分开。高德输入标明 GCJ-02。首发可在高德原生地理域内，用固定锚点与版本化局部米制近似映射，局部尺度用已知基线核验，标注「地图估算」或校准状态。高德公开转换支持 WGS84→GCJ-02。跨基准输入或跨供应商切换须走已验证的正向映射及控制点方案，未建立对应时阻止混合编辑、WGS84 地理导出和高精度定位承诺。始终保留原始参考点。 [高德坐标说明](https://lbs.amap.com/api/javascript-api-v2/guide/transform/convertfrom) · [GeographicLib ENU 定义](https://geographiclib.sourceforge.io/2009-03/classGeographicLib_1_1LocalCartesian.html)

**验证尺度。** 技术探针建议覆盖 500 × 500 m 样板。局部投影正反往返和 2D/3D 内部尺寸误差目标 ≤ 1 cm，独立校准基线 20–200 m 的误差目标 ≤ max(0.5 m, 1%)，至少检查两个方向，独立地标另测图像配准误差。前者验证数学和渲染适配，后者判断现场数据能否给出可用尺度。记录测试实测值，再决定发布范围。超范围时给出分区预览或明确提示，几何始终保持原比例。

## 6. 存储、迁移和同步

1. **新增项目子资源。** 建议使用现有 Supabase 私有 schema 中一张以项目 ID 为外键的规划快照表，带 `plan_revision`。用现有认证及 API/RPC 风格提供规划读写，服务端验证项目成员、写租约、租约代数、期望规划版本、实体引用、坐标范围与负载上限。旧场景更新和新规划更新分开，V1/V2 场景契约保持可读写。浏览器没有直接访问私有表的权限。新增写入路径经后端负责人评审。
2. **本地优先恢复，云端明确确认。** 本地草稿建议按项目独立保存在 IndexedDB，保存最近成功状态、待提交快照、基础云端版本。相同操作 ID 的重试结果一致。云端比较并交换版本，冲突保留本地稿，用户可重新载入或另存。切活动、切账号、过期租约均检查写入身份与视图代次。状态明确区分「本机已保存」「云端已同步」「有冲突」。
3. **迁移先预览再复制。** 旧地图项目优先从原始经纬度和已知坐标基准恢复边界。对象使用经验证的 `sceneAnchor/mapGroundFrame`、单位与原始缩拟合参数转换。缺来源、方向、可信尺度或关联 ID 时列入待校准，矩形区域或路线草稿仅在明确选中后导入。原布局、已有分享和历史保持可读。用户确认后创建关联副本，保存迁移报告和恢复入口。
4. **3D 直接投影规划版本。** 规划对象的平面位置、朝向和尺寸由 SitePlan 持有。3D 首轮只读这些字段，场景中按实体 ID 增量更新，保留同 ID 的资产映射与灯光材质等视觉属性。3D 视觉设置使用既有设计能力，必须与同项目和规划对象 ID 建立关系。以后开放 3D 平面编辑时，走同一规划命令和版本检查。无法映射的设施保留占位并列在清单。旧云端场景的 50 件和壳体限制不用于裁切规划投影。
5. **交付绑定快照。** SVG / 打印 PDF 和 CSV 从同一不可变快照导出，含版本、比例尺、北箭头、图例、尺度来源和所选范围。底图带图源署名，是否可嵌入由供应商权限和浏览器验证决定。矢量图独立可用。后续只读分享绑定规划快照，控制备注和敏感点位可见性。涉及规划与视觉版本同时发布时，在单次事务记录两者的快照引用。

## 8. 开发顺序与发布门槛

1. **P0a 技术探针。** 从干净可构建基线开展。验证高德街道/卫星与定位、底图使用与导出条件、米制校准、真实场地尺寸及云端租约/版本契约。建立固定几何、旧项目和双标签页夹具。探针可做 3D 对位验证，正式的 3D 功能仍在 P1。
2. **P0b 垂直切片。** 在功能开关内落地「搜索 → 圈界 →（可选）导入旧图标定 → 放一件设施 / 人员点 → 面板实时更新 → 本地保存 → 重开」。实现共用命令、选择状态和派生统计。随后完成分区、三类路线、节点、冲突与基础编辑。
3. **P0c MVP 交付。** 上云版本保护、规划快照和图/清单导出，验证真实市集走查。新地图项目可独立完成 2D，旧室内、重建、原有云端保存和分享回归通过后扩大开关范围。验收包含前端相关测试、typecheck/build、后端契约和 Supabase 权限/并发测试、真实浏览器与测试云项目往返。
4. **P1 统一 3D。** 先边界、区域、路线与设施占位，再接 GLB、地面注册、视觉属性与只读交付。达到 ID、朝向、占地和版本一致的验收后，再逐步开放更多编辑。
5. **P2 AI 和体验。** 先用确定性规则提供证据，再加活动模板、分区与资产候选、可回放的预览与确认。体验从视角和可达性入手，人群物理仿真单列。

| 技术风险 | 发布门槛 |
| --- | --- |
| 高德与 WGS84 偏移、地图尺度或影像不准 | 已知基线与独立地标双检。显示估算或已校准状态。未通过的来源只做参考。 |
| 大场地被旧房间尺度压缩 | 大于 100 m 的真实样本尺寸与几何恒定。独立验证大型规划和 3D 局部视图。 |
| 数据丢失与旧客户端回写 | 旧 PUT 保留新子资源；带区域、地理来源、资产引用的计划往返一致。迁移演练覆盖取消、失败、回滚和旧版打开。 |
| 资产模型、地图版权及分享范围 | 用占位覆盖缺失或无授权资产。试验只在许可允许时嵌入底图。分享快照与草稿隔离，测试越权、撤销及敏感内容过滤。 |
| 性能与冲突误判 | 先以 500 个实体做交互探针，使用按需模板加载、可见范围裁剪和空间索引。用已知交叉、共线、共享节点、分层及缺数据夹具验证结果。 |

## 9. 已拍板决策（2026-11-10）

1. **首发聚焦国内户外单层地图项目。**
2. **规划作为现有项目下的独立版本化子资源**（不塞进旧 scene PUT）。
3. **首轮由 2D 单向驱动 3D 平面几何**（位置/朝向/尺寸按对象 ID；3D 视觉属性保留）。

对外定位（可当场验证）：从真实场地出发，把活动平面方案变成可编辑、可预览的 3D 空间；AI 按你确认的边界、尺寸和动线完成初步布置。国际上 OnePlan / Eventplot 已有地图→3D 先例；幕景差异化押在「AI 在已确认空间约束下工作」。本阶段验收仍以接近 OnePlan 的 2D 可独立交付为准，3D 只验必要数据交接。

下一动作：在本机干净分支做 P0a 技术探针（避开当前 main 未解决合并冲突），不推云端改仓。
