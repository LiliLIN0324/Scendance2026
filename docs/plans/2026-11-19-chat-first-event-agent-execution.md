## 0. 给接手 AI 的总指令

你要完成幕景活动设计 Agent 的真实产品闭环：用户仅通过 Chat、截图、图片和文档，从真实场地检索开始，完成场地选择、自动范围、分区、具体物料、流线、个人级宾客与执行交付。用户不需要手动画地图。地图和 3D 是 Agent 操作后的可视成果，也是用户查看结果的界面。

不能把任务缩成改几句提示词、换卡片、补演示数据，或只完成一个婚礼模板。**案例范围（2026-11-19 用户指令，覆盖原文）：只做婚礼一个完整主案例，不做公益案例、不做跨活动类型迁移。** 该案例必须落到真实场景对象、物料数量和具体人员安排。

本任务明确授权必要的本地检查、目标网站交互和过程截图。用户此前要求节省验证成本：只运行能解决当前问题或证明闭环的定向检查；不默认全量测试，不重复没有新信息的检查。当前制定计划不执行这些检查。

可使用 `codex/` 分支开发；最终实现和必要文档必须整合至 main。合并前后保留他人未提交修改；不使用 `git add -A`，不强推。部署仍遵守仓库授权边界；若目标网站需要发布新版本，先准备具体版本和发布方案，再取得用户明确发布授权，不能把本地实现当成线上已生效。

## 2. 不变的产品行为

1. 一个活动、一个连续对话、一份空间方案；2D、3D、名单和清单关联同一版本。
2. 模型负责理解需求、提出策略、调用工具与解释取舍；工具负责搜索、读资料、计算几何、分配座位和执行修改。不能继续用关键词分支覆盖复杂意图。
3. 用户可以随时跳阶段、补资料和修改；阶段是成果状态，不是强制闯关。
4. 普通可撤销操作直接执行并解释假设；重大覆盖、删除已有成果和付费任务保留明确确认。复用现有监督设置，不另建一套批准系统。
5. 信息不足时先完成有依据的草案，只追问影响下一步的关键问题；不能反复要求精确地址、完整问卷或手绘。
6. 场地事实、用户要求和 Agent 假设分别保留来源、时间与确认状态。精美画面不能把估计尺寸变成实测。
7. 无资料时可建立标注假设的概念草案；最终基于真实场地的交付必须取得足以定位和定尺的依据。不能把未知场地冒充准确落位。

## 3. 聊天卡片改造清单

先盘点实际渲染入口和重复状态；删除 UI 前核对它承载的业务能力，将必要能力迁到统一入口，不能删卡同时删掉恢复/取消功能。

### 删除或收起

| 当前问题 | 目标处理 |
| --- | --- |
| 常驻“搜索地点／手画范围／先确认分区”的闯关卡 | 从默认聊天流移除；搜索由对话触发，范围由 Agent 提案；手动工具只保留为可选高级入口 |
| 无实际成果的地图插画、素材图与占位图 | 删除；用本轮真实候选、真实平面预览或简洁状态替代 |
| 同一阶段在气泡、底部任务卡和步骤卡重复出现 | 合并成一个当前执行状态；历史成果折叠保留 |
| 每个普通动作都要求“批准计划” | 按监督档位与实际修改风险呈现，普通可撤销布置不逐步弹审批 |
| 只给“输入需调整”、要求用户换句话说的错误卡 | 展示真实失败环节、已保留内容、可行下一步；保留手动重试与取消 |
| 固定推荐几个酒店、固定活动分类或固定数量的按钮 | 改为当前需求与实际资料驱动；模板是起稿策略，不是能力边界 |

### 新增或整合的卡片

| 卡片 | 展示与动作 | 出现时机 |
| --- | --- | --- |
| 场地推荐 | 推荐首选、备选、适配理由、来源、缺项；“选这处／比较／换一批” | 实际检索完成后 |
| 资料理解 | 文件缩略图、处理状态、提取出的需求/尺寸/名单；可用聊天纠正 | 上传后，处理完成再展示实际结果 |
| 场地范围 | 实际边界候选、尺寸依据、未知位置；“就用这块／调整描述” | 有可定位依据时 |
| 方案预览 | 分区、主要物料、关键通路与理由；“采用／改这里／换方案” | 产生可用布局后 |
| 人员与座次 | 个人记录、家庭分组、仪式/宴席分配、未安排者和冲突 | 名单处理后 |
| 物料清单 | 按区分类、实际数量、尺寸、模型来源、待采购/待补模型 | 有物料布局后，随布局更新 |
| 待解决事项 | 只列当前阻塞或影响交付的具体缺项，点击可查看依据 | 确实存在问题时 |
| 成果与过程记录 | 当前版本、2D/3D、导出文件、阶段截图与变更摘要 | 阶段成果形成后 |

不是让八张卡同时常驻。聊天以自然回复为主，当前任务只展开与本轮有关的卡；旧结果折叠，可回看、引用和继续修改。选择项可以直接聊天回答，不依赖点击按钮。沿用 docs/05 的颜色、字体、间距和错误状态，不自造另一套视觉风格。

## 4. 数据与工具必须连通

### 4.1 活动事实与附件

先建立现有数据归属图，再扩展缺项：活动简报、场地事实、空间方案、名册、流程任务、商业资料各用原真源。新增项目级资料引用与约束记录，避免把所有事实重复塞进长聊天历史。

每条事实绑定来源文件/页码/表格行或用户消息、修订号、提取状态和确认状态；支持纠错、撤回来源与冲突处理。图片和文档中的文字是资料，不能变成工具执行授权。

支持 JPG/PNG/WebP、PDF、DOCX、XLSX/CSV；图片识别内容和文件正文提取必须实际执行，不能只上传附件名称给模型。名单重名和亲属称呼不强行合并；补充名单按稳定人员编号增量更新。

### 4.2 联网调研

实现产品自己的服务端网页搜索及受限正文读取工具，不借用开发者聊天中的搜索能力冒充产品已接入。真实服务不可用时保留本地资料路径，明确缺少哪类证据。

结合用户本地调研、场地方公开资料、案例和地图核对，保留来源链接、资料时间及可引用内容。候选实体去重，区分酒店整体与具体草坪。草坪、容纳能力、承租、价格、档期分别取证，不从地点名或照片推断为已确认。

推荐先按用户明确条件给出排序；缺预算、人数、日期时仍可推荐，但说明排序依据与待补条件；新资料改变条件后更新排序。不要给没有依据的“匹配率百分比”。

### 4.3 自动范围与布局

按带尺寸平面图、已定尺模型、航拍/地图与照片组合、文字尺寸逐级建立范围。保留图纸到局部米制坐标的变换与尺度依据。识别入口、建筑、水域、树木、不可用区，并允许用户用指代和文字修正。

Agent 自动提出边界并展示预览；用户说“用西边那块草坪，湖边小路留出来”即可修正。不把酒店建筑轮廓当成已授权草坪，不把 3DGS 外观直接当成可通行几何。

分区和主物料联合计算，先留通行，再摆主要设施，再补装饰，再检查可达与占地；考虑相邻、视线、拍摄、遮阴与后勤。多个环节分时复用区域时保留时段，不重复计算同时占用。

### 4.4 人员、物料和流线

个人记录包括稳定编号、姓名/称呼、家庭与同行关系、出席状态、用户提供的照顾需求、各环节角色和位置。名单总人数与声明人数不一致时显示差异，不能默默覆盖。

每个人可分别关联仪式座位、宴席桌位、合影位置和时段路径；相邻/同桌等硬要求与优化偏好分开。亲属关系不凭称谓臆测。现有工作人员/岗位模型不能代替具名宾客名册。

每件物料必须有稳定对象编号、实际或标注估计的尺寸、位置、朝向、区域、数量和来源。优先用户已有与真实库内物料；缺模型时允许明确标注的尺寸占位件，不伪造资产号。数字模型和实物库存/采购状态分开。

宾客增加会影响桌椅、区域容量和路径；修改分区会影响关联物料和人员；锁定对象优先保留。只调整受影响部分，不能每句话清空重做。冲突需指向具体对象并提供可行取舍。

流线至少区分普通来宾、婚礼主角/活动嘉宾、服务工作人员；个人可关联共享路线与时段，不必为每个人复制一条几何线。动画是计划展示，不冒充安全认证或真实人流预测。

## 6. 完整使用脚本（婚礼单一案例）

### A. 西湖草坪婚礼

1. 新建活动，发送：“我想在杭州西湖附近找一个婚礼场所，最好有露天草坪。联网搜索，推荐最适合我的场地。”
2. Agent 实际搜索、比较并给出首选；用户用聊天选定，不先手画。
3. 上传分区参考截图、场地图/照片和宾客名单；Agent 提取内容、给出范围及信息差异。用户的分区截图若当前任务拿不到，明确索取，不臆造截图内容。
4. 用户确认/修正范围，Agent 形成分区、关键物料和路线布局；解释假设与取舍。
5. 处理男方/女方父母、亲戚、朋友与同行关系，安排到具体人和物理座位。重名只澄清必要条目。
6. 用户说：“把三舅一家安排到男方父母附近”“仪式背景低一点，别挡湖景”；Agent 局部修改并联动物料和清单。
7. 刷新后继续同一方案；导出实际布置图、按区物料清单、人员桌席表和活动流程；查看 3D 与分享视图。

### B.（已取消）真实场地公益活动

2026-11-19 用户指令：「没有公益，公益去掉」。原 B 节六条脚本（服务分区、受助者/志愿者分表、岗位时段表等）与配套的演练名单、脱敏要求整体不执行，也不作为验收项。跨活动类型的通用性留给第 9 节后续升级，不在本任务内证明。

## 8. 最终交付与完成条件

以下全部满足，才可汇报“完整 Agent 已交付”：

- 从空白活动开始，婚礼脚本仅靠 Chat、截图和上传资料完成；不要求手画地图、手摆物件、数据库注入或隐藏的开发者代操作。
- 搜索是产品内实际工具调用；来源可追溯。本地资料、地图结果、网页正文、图片理解分别如实呈现。
- 有真实场地对应关系和足够的尺度依据；概念草案与可执行版本区分清楚。
- 分区、物料、个人安排、时段路线、2D/3D 与导出使用同一方案版本；数量和编号能对应。
- 局部修改、取消、撤销、刷新恢复可用；不会把旧活动的附件、宾客或迟到任务写进新活动。
- 原有失败卡/手画闯关被替换为可继续推进的交互，报告要求的阶段截图完整且可追溯。
- 最终代码与文档已整合到 main，准确记录提交号；未提交的其他工作仍完整保留。
- 目标网站实际使用的是包含本次改动的版本。网站发布未获授权、登录/额度/资料不足等阻塞时，交付代码和具体阻塞，不宣称网站已验收。

最终给用户：目标工作台链接、main 提交号、一条从头使用步骤（婚礼）、阶段截图包与过程说明、最终方案/物料/人员/流程导出，以及真实剩余限制。截图可直接用于 Agent 报告；不要只交开发日志。

## 9. 持续升级机制

完整首版交付后，持续收集真实任务里的失败环节和用户修改：每项写输入、预期、实际、影响范围、资料来源和修复状态。优先处理“卡住无法推进、结果错误、修改丢失”，再优化方案质量和视觉表现。

升级沿用同一条工具和数据链，新增资料、场地或活动策略；不得为每类活动复制一套 Agent。保存少量具有区分力的案例，按本次改动范围做定向核对；没有新证据不重复跑全套。

每轮收口更新版本和交接，保留历史方案可读性。需要长期自动运行或定时任务时另由用户明确要求，不自行创建常驻自动化。
