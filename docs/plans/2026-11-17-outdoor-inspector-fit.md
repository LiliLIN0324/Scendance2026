# 户外属性卡版式：「文字生成」点不动（2026-11-17）

## 一句话结论

不是层叠问题，是**宽度问题**：属性卡的宽度由内容决定，而「3D 模型候选」那一排是横向滚动条，
它的固有宽度 = 候选数 × 68px。素材库候选一多，整张卡被撑到 **1248px**（实测），
冲出宿主（3D 接管态的宿主是整块覆盖层 `inset:0`）也冲出视口，
「文字生成 / 图片生成 / 导入 GLB」三颗按钮落在可视区之外 —— 真鼠标点下去，命中的是底图 canvas。

上一版记的「canvas 排在 DOM 后面压住了属性卡」是**误判**：抬 z-index、把 canvas 设成 `pointer-events:none`
都试过，按钮仍然不在命中栈里。真因是它压根不在可视区里。

## 证据

| 观察 | 数值 |
| --- | --- |
| 属性卡（section）宽度 | 1637px（生产走查）/ 1248px（回归夹具，视口 1280） |
| 视口宽度 | 1231px（生产走查）/ 1280px（夹具） |
| 候选条固有宽度（24 个候选） | 1628px |
| 去掉候选条后的卡片宽度 | 174.8px |
| 按钮中心命中栈顶（修复前） | 底图 canvas / 别的层，不是按钮 |

## 修法

三处，都在 `frontend/components/room-organizer/components/outdoor-inspector-layout.ts`：

1. **候选条外面包一层 flex 行**，候选条自己 `contain: inline-size`。
   - `flex: 1 1 0` 不够：flex 规范 §9.9.3 里，flex-grow ≠ 0 的项，max-content 贡献取的是**内容尺寸**，
     基准宽度为 0 并不影响它对父容器固有宽度的贡献。真正能把「行内尺寸与内容无关」用上的规则是
     `contain: inline-size`（CSS Containment）。加上之后候选条自己横向滚动，固有宽度不再进卡片。
2. **卡片允许收缩**：`flex: 0 1 auto` + `min-width: 0` + `max-width: 100%`。
   原来 `flex: 0 0 auto` 是不许收缩的，卡片想多宽就多宽。
3. **外层浮条同时受宿主与视口约束**：`max-width: min(calc(100% - 32px), calc(100vw - 32px))`。
   3D 接管态的宿主是整块覆盖层，只按 `100%` 算的话卡片仍能冲出屏幕。

另外把「生成或导入模型」三颗按钮改成**贴在卡片体底部**（`position: sticky`）：
用户 2026-11-15 就说过「生成和导入模型不应该收在下方，因为这个很重要」，
而收在滚动区折叠线以下时，它既看不见也点不到。

## 回归（这类问题截图验不出来）

`frontend/scripts/inspector-fit/run.mjs`：真实 Chromium + 真实 `globals.css`，
用**组件同一份**版式常量渲染属性卡骨架（24 个候选），量三件事：

1. 候选条不撑宽卡片 —— 判据是「把候选条从 DOM 摘掉，卡片宽度不许变」；
2. 三颗按钮的矩形完整落在卡片矩形内；
3. 按钮中心的命中栈顶是按钮自己或它的子元素。

门禁：`frontend/lib/outdoor-inspector-fit.test.ts`（vitest 包一层，进 `npm --prefix frontend run test`）。

**门禁有效性已自证**：把 `contain: inline-size` 去掉（= 修复前），脚本输出
`INSPECTOR_FIT_FAIL：候选条的宽度漏进了卡片：有候选条 1248.0px，去掉后 174.8px（差 1073.2px）`；
还原后 `INSPECTOR_FIT_OK`，卡片 174.8px，三颗按钮命中栈顶都是自己。

## 没做的

- 没有部署前端：并行会话正在推正式站，本轮只进分支与 PR，别名不抢。
- 夹具没有渲染整个组件：组件太重（three.js + 全套上下文），但撑宽的根因只在版式常量里，
  所以夹具复用常量、复刻这段 DOM，量到的宽度与命中栈顶就是生产里的行为。
