# PetitMaker 全面学习与幕景改造

2026-10-10。用户明确：素材移到底部只是举例，其他能改善使用与执行的机制也可以改，包括后端 Agent。沿现有开发目标推进，以下状态区分源码研究、本机通过和正在开发。

## 依据和目标

参考 [PetitMaker 固定源码](https://github.com/Stry233/PetitMaker/tree/4e120e50c844198649454eec6069ac65a062a732)，版本 1.5.557。已核本机参考副本 HEAD 与该版本一致；GitHub 元数据最后推送时间为 2026-10-04。具体源码入口与行号见 [界面和编辑机制](petitmaker-code-study.md)、[Agent 链路](petitmaker-agent-adoption.md)、[文件与恢复](petitmaker-artifact-adoption.md)。

目标是让两个人能在同一活动中完成需求整理、场景预演、方案核对、委托和外包资料、任务分工及执行交接。改造取舍以三段讨论的明确需求为主，参考项目提供实现方法；游戏摆放规则不作为活动承办标准。专业资料沿 [已核专业 Skill](professional-skill-basis.md)，仍待讨论的 Figma 标签不自动变成业务模块。

PetitMaker 的 Agent 实际是浏览器 BYOK runner，并不是幕景式服务端。采用其任务与编辑机制，继续使用幕景现有服务端鉴权、lease、运行记录和 GET 恢复；不搬入浏览器密钥存储、另一套队列或全量事件平台。代码与美术许可分别核对，本轮没有移植其品牌、图标或模型素材。

## 当前分工

- **幕景 · 前端交付流程**：原活动安排入口中的摘要预览、任务建议、人工选择与保存读回，以及必要的 BackendSession 和本机提案持久化。商业候选先固定，后续修改另验收。
- **幕景 · 后端交付契约**：独立任务 API 与 `client/scene-client.ts` 的 typed transport 及独立测试已完成，保留旧 Scene 调用兼容。服务切片冻结交接。
- **幕景 · 本地备份与恢复**：两项恢复差距调查已完成，继续实施可信公共模型解析及渲染/交付两个消费入口；不抢写共享 UI、存储 hook 或任务提案。
- **导演**：复核接口、源码版本、真实导出和保存证据，管理需求与验收范围，决定可以进入批量版本更新的内容。

## 下一段的用户验收

以明确标注的 30 人演练活动为例：在原活动安排中选择资料 → 看清实际发送内容 → 请求任务建议 → 勾选建议 → 保存 → 刷新核对 → 导出执行表。原有任务和事实保留，新建议只是待办；未知负责人、时间、费用和现场情况不补猜。

发送前持久保存原请求编号；网络结果未知时查原运行。结果准备一次、任务编号保持稳定；保存未核实则保留原稿，不重复添加或宣称保存成功。取消、资料变化、身份或项目变化时停止确认。模型仅接收明确选择的摘要，不读取合同原件、私人图片链接或完整场景作为任务建议上下文。

本机演练、真实模型、正式云和真实现场效果分别记录。私人 Today、团队飞书资料继续分开。完成可用增量后批量更新开发分支；截至本文，最新已上传版本仍为 `3e65023`，本轮增量尚未推送。
