## 1. 当前真实水位（对照 12 卡诚实盘点）

| 卡 | 机制 | 幕景现状 | 评级 |
|---|---|---|---|
| 01 | 配方身份 seed/hash/版本闸 | `recipe.ts`、`recipe-proposal.ts` 纯函数在；**没有任何真实生成请求带 seed**，同一句话仍不可复现 | 🟡 半成品 |
| 02 | 纯计划 IR 六阶段 | `agent-proposal.ts` 有 VenuePlan/PlanProposal 雏形；无 zone→动线→锚点→软装的分区 IR | 🟡 雏形 |
| 03 | 单旋钮 richness + seed avalanche | 无风格旋钮；rng 混合手法未搬 | ⛔ 未学 |
| 04 | settle 定点收束 | placement-rules 有主通道/椅岛/越界/穿墙判据；**没有收敛器，判据不会在落地后自动重跑** | ⛔ 核心未学 |
| 05 | Command 两阶段校验单门 | `build-command.ts` 纯函数 16 测绿；**三个真实写路径（拖放/键盘/预览应用）没有一条走它，目前是悬空代码** | 🔴 假活 |
| 06 | reject-and-skip vs 整批回滚双容错 | onApplyCreative 只有几何硬闸 throw；没有装饰件跳过/结构件回滚的分层 | ⛔ 未学 |
| 07 | 落地顺序纪律 | 无；候选整体 applyLayout，无基座→结构→软装顺序 | ⛔ 未学 |
| 08 | Outcome 拒绝账本 | 应用时按 id 差分写 placed/skipped；**refused 永远是空数组**——placement-rules 真实拒绝事件没进账本 | 🟡 半真 |
| 09 | 候选池/指纹/命令重放/缓存 | 指纹门已活接（confirm 拦截旧盖新）；候选不是命令序列、无多候选、无缓存、无 worker | 🟡 单点开 |
| 10 | ToolSpec 单一真相 zod 契约 | 无统一工具契约层；agent 侧参数校验分散 | ⛔ 未学 |
| 11 | Agent 大宏 + governor/nudge/compaction | 无宏层、无重复拒绝阻尼、无轮数闸、无上下文压缩；agent 只会一次性回一大段 | ⛔ 整块未学 |
| 12 | provenance taint 逐件溯源 | 家具 item 无 createdBy/贡献权重，「谁放的」查不了 | ⛔ 未学 |

**一句话：骨架纯函数铺了 60%，但「数理逻辑真正管事」的三块——命令门收口、settle 收束、agent 自律回路——还没上线。**

## 2. 受众视角：策划师真正害怕的七个瞬间

幕景的受众不是游戏地图作者，是**活动策划/宴会排期/空间设计公司的执行人员**：她要对客户负责人数与动线、要在现场对着 handoff 单盯搭建、会被甲方临时改需求。PetitMaker 的机制不能按「游戏网格功能」搬，要按她的害怕瞬间翻译：

| # | 真实瞬间 | 她现在的感受 | 对应机制 | 落地后她看到的变化 |
|---|---|---|---|---|
| U1 | AI 说「布置好了」，她不知道敢不敢信 | 得自己一桌一桌数、沿着通道走一遍 | settle 收束 + Outcome | 报告卡直接写「24 桌全部可达主通道，0 堵点；要 200 座，实际 192 座，差 8 座」 |
| U2 | AI 出预览期间她手动挪了主桌，一点确认被冲掉 | 再也不敢在预览时碰任何东西 | 指纹门（已做，待换站内弹层） | 弹「你刚改过画布，要保留你的改动还是整版替换？」，两个按钮都安全 |
| U3 | 同一句话隔天再生成，布局完全变了，没法跟客户说「这是上次那版微调」 | 方案不可复现，口头讲不清 | seed/recipeHash + 版本号 | 每版带「方案编号 #A7F3」，同编号复算同结果，换编号才是新方案 |
| U4 | AI 静默少放了 5 把椅子，现场才发现 | 「成功」提示骗了她 | refused 真账本 | 「放了 19 件，2 件因压消防通道被拒（已标红），1 件素材缺失跳过」——拒绝不再隐身 |
| U5 | 甲方问「这排桌子是谁定的、AI 摆的还是你摆的」 | 答不上来，也不敢让 AI 背锅 | provenance taint | 点任意物件可见「AI 生成 · 方案 #A7F3 / 手动调整」，handoff 单附 AI 件占比 |
| U6 | AI 来回改话术后卡在同一个错误上反复试，她只能干等转圈 | 觉得它「又笨又固执」 | 三级阻尼 + governor | 它自己说「这个位置我已试过两次不行，换个摆法」，40 轮内必给结论，不空转 |
| U7 | 想要「再密一点/再松一点」却没有滑杆可拉，只能重新组织语言 | 人机对话成本高 | density 单旋钮 | 一根「布置密度」轴，拖完即重算，背后是同一个确定性引擎而非重新猜 |

**适配原则**：PetitMaker 的用户能容忍网格、规则 ID 和技术文案；幕景的所有数理结果必须在 UI 上翻译成**人数、件数、米数、红环/绿勾**，任何 code（BBOX_OVERLAP 之类）只进开发者日志，不进策划师视野。

## 3. 现存实现的四个具体问题（先还债再扩建）

1. **build-command 是死代码**：`validateCommandShape/Preconditions` 没有任何调用方。拖放走 placeDiscrete、键盘走 confirmPlacement、预览走 applyLayout，各写各的。规则升级会出现「纯函数测绿、线上不生效」的两张皮。
2. **Outcome.refused 恒为 []**：M5 现在只在 apply 瞬间做 id 差分，placement-rules 在生成过程中拒掉的件根本没被记账。用户仍可能看到「放了 3 件」而不知道原本要放 8 件。
3. **指纹门 UX 是 window.confirm**：功能正确但与产品视觉体系脱节，且 `aiPreview.base === layout` 引用相等门与指纹门职责重叠，需要统一成一个权威闸。
4. **M3 判据无运行时触发点**：MAIN_AISLE_BLOCKED/CHAIR_ISLAND 只被 build-command 纯函数引用，AI 候选落地后不会自动体检，Bingo pin 靠用户手动点。

## 4. 升级路线：四个批次，按依赖排序

> 每批都写两行验收：工程验收（可跑的断言）与受众验收（策划师能感知的变化，对应 U1–U7）。

### 第 6 批（P0）｜命令门真收口 —— 让 M2 从假活变真活

- **6.1** 三个写路径全部改为先构造 SceneCommand（place/move/update/remove/apply-layout），经 `executeSceneCommand()` 统一执行：resolve → preValidate → 写 store → 返回 `{success, errors[]}`，非法不抛异常、附物件 id 与违规 code。
- **6.2** 拒绝事件直接 append 进本次 Outcome.refused（修掉问题 2），Bingo 卡「被拒 N 件」第一次出现真实数字。
- **6.3** 删除各路径私有的几何校验分支，placement-rules 成为唯一判据来源；window.confirm 换成站内确认弹层组件，指纹门与引用门合并为 `decideOnApply` 单点。
- 验收：tsc=0；写路径相关测试全绿；人为构造穿墙拖放时 Outcome.refused 长度 +1 且画布零变更。
- 受众验收（U4）：被拒件在 Bingo 卡具名列出并在画布标红，不再有静默消失。
- 预估：2 天。这是后续所有 agent 机制的地基。

### 第 7 批（P0）｜settle 定点收束 —— 本仓数理含量最高的一件

- **7.1 合法布置图判据**（纯函数，可测）：
  - 可达性：从每个座位/椅组质心沿可通行掩码（膨胀后的 AABB 自由空间）BFS 到主通道带，不通 = 孤岛；
  - 断头：通道带端点必须抵达设施或外墙开口；
  - 振荡防护：常量成对咬合（PetitMaker 的 JOIN_REACH/JOIN_LEFT 教训），收敛器每遍输出 `moved[]/violations[]`，终止条件 = 一遍零变化且孤岛数为 0，遍数上界 `2N+4`。
- **7.2 `settlePlacement(layout)`**：对违规件做最小平移（沿主轴试探 0.3m 步长网格），修不动的留 violations，不静默删除。
- **7.3 触发点**：AI 候选 apply 后自动跑一遍，修复清单进 Bingo「体检回执」；手动拖放不自动改用户位置，只亮 pin。
- 验收：构造「椅子围死通道」夹具，断言收敛后通道带零侵占、孤岛=0、上界内终止；vitest 纯函数覆盖 ≥20 例。
- 受众验收（U1）：AI 应用后报告卡出现一句「体检通过/发现 N 处堵点已自动挪开，M 处挪不动已标红」，她不用自己巡场。
- 预估：3 天。

### 第 8 批（P1）｜Agent 自律回路（卡 10+11，性价比最高的软件工学件）

- **8.1 工具契约单源**：一份 zod strict schema 同时产出类型/校验/给模型的 description；数值拒绝字符串隐式转换；参数拒绝必附合法 example 文案。
- **8.2 只暴露宏工具，不暴露逐件原子操作**：首批 4 个宏——`layBanquet(zone,spec)`、`buildStage(...)`、`arrangeSeating(zone,count)`、`scatterDecor(zone,density,seed)`，一次宏调用 = 一次 undo 步，内部批量走第 6 批的命令门。
- **8.3 三级阻尼**：同（工具, 规范化参数）失败过即不重复执行，直接回灌「换参数再试」；回滚 4 次升级 STOP 提示；零写入交付/写了≥3 步未自检两种 nudge。
- **8.4 governor**：单 job 轮数上限 40、静默轮计数；上下文超限时机械账本兜底（最后订单 + 工具调用计数），不依赖摘要模型可用。
- 验收：mock provider 夹具里跑「死循环重试」「空转收工」两个场景，断言阻尼与 nudge 触发；全部中文回灌文案。
- 受众验收（U6）：聊天框里能看到 agent 自述「第 N 次尝试、换了思路」，且任务必然在轮数上限内结束，不再无限转圈。
- 预估：4 天。**不碰生成管线和大模型本身，纯本地编排层。**

### 第 9 批（P1）｜可复现、可归因、可多选

- **9.1 M1 活接**：agent 生成入口强制带 seed（缺省随机下发并回显），recipeHash 进预览上下文；同一 recipe + 同一画布指纹命中缓存直接重放，不重复调生成。
- **9.2 多候选**：同 recipe 换 seed+1/+2 出 3 版（recipe-proposal 已有 deriveVariants），预览卡横排切换，候选各自带独立指纹快照。
- **9.3 provenance taint（卡 12）**：FurnitureItem 增 `provenance?: {source: human|ai|procedural, opId, seed?}`（可选字段，不动既有 wire 必填面）；命令门统一发 opId；handoff 导出附「AI 放置件占比」。
- **9.4 单旋钮（卡 03）**：引入 density 0..1 单轴驱动桌椅间距/装饰密度/候选丰富度，rng 用 seed avalanche（mulberry32 前先 mix 常量）防相邻 seed 同构。
- 验收：同 seed 两次生成 deep-equal；切换候选不串指纹；导出文件 AI 占比数字可手工核对。
- 受众验收（U3/U5/U7）：方案有编号可复算、三版候选横滑对比、物件可查出身、密度一根轴可调。
- 预估：4 天。

## 5. 明确不搬 / 暂缓清单

- 地形/台地/水体围堰/stencil 图片转地形/maze：网格游戏语义，幕景无对应物。
- worker 池与 128MB LRU 字节预算：等场景数据与 three.js 渲染资源彻底分离后再评估，当前候选只缓存「布置指令」即可。
- 父/子代理审批门（gates strict/checkpoint/yolo）：幕景当前单 agent 形态，第 8 批之后有多子代理苗头再做。
- 一切素材/品牌/游戏专有 prompt 正文（ASSET_LICENSES class 2 边界）。

## 6. 红线不变

不绕 onApplyCreative（只会把它修得更硬）；不引新依赖、不增色系（冷石 #F4F5F7 + 品牌绿 #4A7C59）；中文简体；不动 3D/生成管线（Aholo/HY-3D/Lux3d/scene-script）；不新增必填 wire schema 字段（provenance 全部可选）；每个纯函数模块必须配 vitest 且先测后接。

## 7. 总排期与完成定义

| 批次 | 主题 | 工期 | 完成后策划师能说的一句话 |
|---|---|---|---|
| 第 6 批 | 命令门真收口 + 拒绝真记账 | 2 天 | 「它拒了什么我都看得见，画布不会被偷偷改坏」 |
| 第 7 批 | settle 定点收束体检 | 3 天 | 「AI 摆完自己先巡过场，堵点挪开了才交给我」 |
| 第 8 批 | agent 自律回路（宏/阻尼/轮闸） | 4 天 | 「它不再跟一个错误死磕，忙一会儿一定给结论」 |
| 第 9 批 | 可复现/多候选/溯源/密度轴 | 4 天 | 「方案有编号、能对比、查得到出处，疏密我自己说了算」 |

合计约 13 个工作日，纯前端数据层与编排层，全程不依赖生成管线改造。**「智能建造真正完成」的终验标准**：给定一场 200 人晚宴需求，从一句话到可交付 handoff 全程——每版方案可复算、每次拒绝有名字、每张椅子可达通道、每个物件查得到作者、agent 在轮限内自律收口。

## 8. 实操 Web 版补学：源码之外的 11 个交互层优势（2026-11-05 真机点击）

在 petitmaker.com.cn 真机走查（跳过 8 段引导→生成/智能体/山体/物品四个模式→点配方实跑一次），以下是 12 张源码卡覆盖不到、但受众感知极强的产品手法，按幕景可移植性排序：

| # | PetitMaker 实测做法 | 受众价值 | 幕景适配动作 | 归属批次 |
|---|---|---|---|---|
| X1 | **配方是可点名的实体**：生成面板一排「配方 90673~90677」五个编号按钮 + 「换一批」，点击即复跑 | 策划师直接用编号跟客户/同事沟通「就按 90673 那版」，不用描述 hash | recipeHash 取 4-5 位人话编号显示在预览卡，「换一批」= deriveVariants 换 seed，三候选横滑扩展为五宫格 | 第 9 批 |
| X2 | **示例 prompt 随当前工具上下文换词**：山体模式给「堆梯田山丘+坡道」、物品模式给「渔村四间房一码头一条路」，每条都是「目标一行+约束一行」两行结构 | 空白输入框不吓人，照抄就能开口 | agent-chat 在活动/空间物料/Bingo 三脸下各给 3 条两行式示例，点一下填入输入框 | 第 8 批随宏工具一起 |
| X3 | **参数面极简**：整组生成只有「通道宽」「最高层」两根滑杆 + 「出入口」「显示路线」两个开关 | 旋钮爆炸是新手头号退点；印证卡 03 单旋钮哲学 | 第 9 批 density 密度轴落地时，同期把高级参数收进「更多」折叠，默认外露不超过 2 个控件 | 第 9 批 |
| X4 | **区域负荷常驻顶栏「x / 10,000」**：任何模式下都看得见容量预算，生成前后数字实时变 | 还没出错就知道边界，Outcome 是事后账、负荷表是事前尺 | 顶栏加「本场上限 N 件 · 已放 M 件」容量计（按场地面积+通道规范推算 N），接近上限变品牌绿提示色 | 第 7 批（settle 已有全部几何数据，顺带产出容量数） |
| X5 | **智能建造是工具槽第 4 格，与画笔/橡皮/修剪平级，数字快捷键印在按钮上** | 智能功能不另开页面、不搞神秘，就是一件随手切的工具；快捷键零记忆成本 | 生成入口已在 agent-chat 双芯片（F5）；补快捷键提示与当前模式高亮，不新增独立「AI 模式页」 | 小改，随第 8 批 |
| X6 | **「清除生成内容」「整个星球（作用域）」是显式按钮**：生成内容可一键清、作用域先选定再生成 | 不靠连点撤销回退 AI 产物；作用域=硬边界（卡 06）的 UI 表达 | 预览卡上区分「仅撤这次 AI 放置」与「整版恢复」，作用域沿用现有选中区域，不新增 wire | 第 6 批命令门事务天然支持 |
| X7 | **图层概念**：添加/删除图层、生成内容独立成层可整层删 | AI 产物与手工作品物理隔离，删 AI 不碰手动 | 不引入完整图层系统（成本过高），用 provenance source 标记实现「逻辑图层」：筛选/清理时按 human/ai 来源过滤，效果等价 | 第 9 批 provenance 附带 |
| X8 | **未配置态诚实且有人味**：「Beta」「有密钥就能开始」「还没有密钥，我先睡一会儿」，入口不藏、给「连接服务商/了解更多」出路 | 能力边界透明，用户不会对着死按钮困惑 | 检查幕景生成能力位未开通时的空状态文案，统一成「现状+一句出路」，禁用而不是隐藏入口 | 文案小改，随第 8 批 |
| X9 | **情境教练气泡**：物品笔刷旁浮一句「需要连续摆放物品时，点这里选刷放」 | 在用户正需要的瞬间教一个进阶动作，不堆帮助中心 | F3 吸附落点首次触发时给一次气泡「拖近已有物件会自动留出通道间距」，localStorage 记已读 | 小改，独立小补丁 |
| X10 | **文字生成降维成预设字形点选**（M/🍎/🌊/⛰/@ + 材料：山体/水/物品/印花） | 不会写提示词的人用点选完成 80% 输入 | 幕景对应物=活动类型模板卡（晚宴/工作坊/发布会）+ 材料（桌椅/舞台/花艺）点选组合，自然语言只是高级入口不是唯一入口 | 纳入第 8 批宏工具的触发 UI |
| X11 | **新手引导是 8 段 10 秒视频片段步进**，每段一个原子动作（堆山/挖河/种树/转视角），可跳可翻页 | 首课成本压到最低，比静态图文有效 | 暂不做视频（成本高）；先用 3-4 张静态分步卡覆盖「说一句话→看预览→确认布置→看 Bingo 体检」主路径 | 排到四批之后 |

**总判断**：PetitMaker 的工程护城河（12 卡）我们已排进四批；它真正的产品护城河是**把复杂数理全部藏进傻瓜交互**——编号化的配方、两根滑杆、常驻容量计、上下文示例、诚实空状态。幕景的适配纪律不变：所有这些交互里出现的数字都必须是米/件/人/百分比，不允许出现规则 code 与技术 hash。

## 9. 连接 API 后真机实测：agent 运行态的 9 个产品细节（2026-11-05，MiniMax M3.1 Flash 实跑）

用户已接入自定义服务商（https://api.minimax.cn/v1，模型 MiniMax M3.1 Flash），下发真实任务「从友邻中心向北侧铺一条小路」并跟踪 19 步 / 3 分钟全程。连接态与运行态暴露出又一批源码层看不到的交互契约：

### 9.1 连接与监督设置（对应卡 11 gates 的 UI 表达）

- **Y1 BYOK 设置面板**：服务商选「自定义」→ 填服务器 endpoint → 模型下拉带「刷新」拉取可用列表；「清除密钥」与「清除历史任务（N）」是两个独立按钮，删 key 不删历史。幕景适配：后端会话设置沿用现有 backend-session，不新增依赖，但设置项要把「连接配置」和「任务历史」分开管理。
- **Y2 三档监督频率直接产品化**：严格 / 关键节点 / 自动，选中档下方一句中文解释（实测关键节点 =「在计划步骤和大范围改动前询问」）。幕景现有三道门可直接映射成三档——**严格 = 每条写入命令都确认；关键节点 = 现状（预览→确认）；自动 = 指纹门无冲突时直放、有冲突才弹**。第 8 批 governor 落地时同步做这个三档开关，默认保持「关键节点」不改变用户既有习惯。

### 9.2 运行态时间线（governor/loop 的前端呈现，第 8 批 UX 验收照抄）

- **Y3 头部状态行**：「正在思考 · N 条思考 · 已用时 0:37」持续跳动，agent 活着还是卡住一眼可知。幕景 agent-chat 生成中必须有等价的步骤计数与计时，不能只有一个不确定转圈。
- **Y4 步骤流默认折叠尾部**：「共 19 步，显示最后 3 步」可点开看全部；每一步显示中文工具名 + 单步耗时（「查看区域 · 思考了 0:19」），思考内容另有「查看思考内容」折叠条。防刷屏与可审计兼得。
- **Y5 写入动作翻译成人话宏描述**：实际写步渲染为「铺设道路 · 野趣沙土路 · 沿直线 (88,63)→(88,20) · 宽 1」——材料名 + 几何 + 宽度一行讲清，原始参数收进展开层。幕景的宏工具（layBanquet 等）在聊天时间线里也必须有这种「一句话 + 可展开参数」的双卡结构，禁止把 JSON 命令贴给策划师看。
- **Y6 先读后写节奏肉眼可见**：19 步中前 8 步全是只读勘察（列出物品→查看区域→查看地图→查询物品），第 9 步才出现第一条写入宏。这让「agent 先看懂现场再动手」成为可感知事实；幕景第 8 批宏编排也应保证勘察类只读工具先于写入工具，时间线顺序即信任来源。

### 9.3 运行中的人工接管（比 gates 更细的动态控制）

- **Y7 「在本步结束后暂停」常驻按钮**：不改变全局监督档位，运行中随时插入一个一次性 checkpoint，当前步跑完即停。这是比静态三档更灵活的第四种控制，幕景应在 agent 运行条上提供等价的「跑完这步停下」。
- **Y8 「为下一步添加备注」输入框**：运行中可直接注入 steer（自然语言纠偏），下一轮 agent 就能读到，不用停任务重开。幕景 agent-chat 生成进行中应允许追加一句备注而不是禁用输入框。
- **Y9 优雅停止 + 重试过程可见**：点「停止」后不硬切，等当前步在 turn 边界收尾；任务中连续出现同名步骤「寻找平地 ×3」时，重试过程完全暴露（卡 11 repeatRefusal 阻尼的 UI 面），用户可自主判断要不要停。幕景侧：同名工具连续失败达到阻尼阈值时，时间线上要出现中文自述（「这个位置试了两次不行，换个思路」），与第 8 批三级阻尼的回灌文案共用一套。

### 9.4 补充实测：刷新恢复

- **Y10 会话恢复弹层**：重新打开页面弹「欢迎回来。检测到上次的编辑进度。你可以继续编辑，也可以重新开始。」两个按钮。幕景已有本地活动自动持久化，补一个等价的「继续上次/重新开始」首屏选择即可，成本极低，排进第 9 批收尾。

### 对第 8 批的硬性 UX 增补

原第 8 批只规定了 governor/nudge 的后端逻辑，现追加三条前端验收：①生成中显示步骤数+计时+中文工具名时间线（Y3/Y4）；②运行条常驻「跑完这步停/停止/加备注」三控件（Y7/Y8）；③监督方式三档开关，默认关键节点（Y2）。这三条不引入新依赖，全部是 agent-chat 既有组件的增量。
