# 场地自主规划交互与设计提升计划

日期：2026-11-20。状态：P0 基线已建立，真实页面验收被阻塞（浏览器自动化通道不可用）；P1/P2 由交互与规划两位负责人在途实现。基线与验收记录见 [2026-11-20-venue-agent-baseline-and-acceptance.md](2026-11-20-venue-agent-baseline-and-acceptance.md)。

目标：用户在当前场地说出活动意图后，Agent 能给出有空间组织和视觉主次的方案；用户在画布上看懂理由、指出局部、继续调整，并随时回到上一版。首轮聚焦已有户外婚礼链路，通过后再扩展活动类型。

## 现有基础与提升重点

代码基线以本次读取的工作区为准。已有婚礼自主规划、真实物料检索、通道预留、几何检查、监督档位与恢复机制；当前场地的真实浏览器设计效果仍需验收。

| 现状依据 | 体验与设计问题 | 本轮目标 |
| --- | --- | --- |
| `frontend/components/room-organizer/lib/wedding-layout.ts` 的 `initialZones` 默认沿外接矩形比例分区，再裁剪到边界 | 不规则场地容易形成狭长或破碎分区；默认北侧焦点缺少景观依据 | 先理解可布置区域、入口与可确认景观方向，再决定分区和仪式轴线 |
| 同文件 `optimize` 比较仪式优先与宴席优先，评分主要按两类座位数 | 摆得多尚不足以体现观景、动线、组团和画面留白 | 先满足硬约束，再按可解释的设计目标比较候选 |
| `wedding-request.ts` 对明确的整场婚礼指令走本地规划，对方位、尺寸、局部修改转交既有理解路径 | “先出一版”和“再改这里”分属不同路径，需要验证上下文能连续传递 | 全局与局部操作共用当前场地、选中对象和方案版本 |
| `use-outdoor-agent-workflow.ts` 已接规划报告和 `applyPlan` | 已有执行基础，尚需把方案变化与画布中的对象一一对应 | 聊天、方案摘要、画布选中与版本恢复形成同一条操作链 |

以上为代码观察与产品判断，不代表已观察到所有界面缺陷。第一阶段用实际页面复现确定最终施工范围。

## 用户完整流程

1. 用户打开已有场地，说“在这里做一个 60 人婚礼，保留中央草坪”。Agent 直接沿用当前场地与已放物件。
2. 在现有 Agent 面板展示一条简报：“60 人 · 中央草坪保留 · 先按当前入口规划”。缺入口或景观依据时以可修改假设继续；只有会改变整个设计方向的歧义才追问。
3. 生成过程中展示真实阶段，如“判断可布置区域”“组织仪式与宴席”“核对通道与桌椅”。沿用单一当前状态，停止后保留原方案。
4. 第一版完成后，画布显示完整设计。摘要只讲推荐理由、实际容量和需要核对的关键点；点“仪式区”定位对应区域。
5. 用户点选一组桌椅，说“这里松一点”；系统明确显示本次操作对象，局部试排，保留其他区域及锁定对象。
6. 用户说“换个布局”，在相同视角下比较两种有明确取舍的方案，选中后沿用现有监督档位应用。
7. 用户撤销、刷新或继续聊天时，场地、当前方案和已确认约束保持一致；保存、恢复与分享各自按真实结果显示。

## 画布与面板交互

沿用现有画布和 Agent 面板，不新增顶层导航。方案摘要接在当前设计结果后，避免聊天内出现多张重复状态卡。

| 位置 | 拟定交互 | 行为约束 |
| --- | --- | --- |
| Agent 结果摘要 | 推荐理由最多 3 条；实际席位数；“查看变化”“比较方案”“恢复上一版”按状态出现 | 假设人数与实际摆下人数分开；不默认展开全部几何日志 |
| 画布 | 临时显示“分区 / 动线 / 本次变化”图层；文字条目与对象双向定位 | 定位不改坐标；用户拖动画布后不再自动抢镜头 |
| 对象选中处 | “调整这里”“保持不动”；选中区域或组团作为下一条消息的显式上下文 | 多选与取消选择可见；用户可清除消息中的目标引用 |
| 局部修改结果 | 展示新增、移动、删除的数量与范围；提供一次撤销 | 预览和已应用状态明确；重新生成期间不能误提交旧结果 |
| 方案比较 | 相同相机、比例和图层下切换 A/B；每版显示实际容量与取舍 | 候选预览不覆盖已采用方案，关闭后恢复进入比较前的视角与方案 |

建议状态流：读取当前场地 → 形成候选 → 几何检查 → 预览或自动应用 → 可调整。严格档在应用前一次确认；关键节点档及自动档复用现有风险判定，避免增加逐物件审批。

遵循 [现有设计规范](../05-设计规范.md)：白纸、墨字、发丝线，品牌绿用于规定的选中与发送位置。图层用细线、透明填充、文字和线型共同区分；不以颜色作为唯一提示。键盘可选对象、切换候选与关闭预览。减少动态效果设置下直接切换状态。

## 空间设计能力提升

### 场地依据

统一读取当前方案边界、米制尺寸、入口、建筑与禁放区、现有物件、锁定对象、已确认需求。优先复用现有可布置域计算，接入前核对其输入输出，避免另造几何真源。

景观朝向、高差、树木及地面承载等信息须区分用户确认、已有结构化数据和待核对假设。照片可提供设计线索，不能直接证明真实尺度或无障碍通行；扫描模型没有语义信息时，不自动声称理解了其中的障碍。

### 分区与组团

按可用连续区域、入口关系和仪式焦点安排主次，减少只沿外接矩形切条。保留用户已有分区；允许重排时才重新组织。无法形成可用分区时，给出缩减功能或分时使用的方案，说明未满足需求。

观礼座椅面向共同焦点；宴席按完整桌椅组落位。迎宾靠近已确认入口，后勤与宾客路径尽量减少冲突。主景与次景形成层次，重点区域留出可说明用途的空间。物料缺失时保留尺寸明确的占位，并在摘要和清单中标注。

### 两种有区别的候选

优先给一版推荐方案，需要时展开另一版：例如“仪式与观景优先”和“宴席与服务效率优先”。景观方向未知时，不使用“观景更好”作为推荐理由。

候选先检查边界、已知障碍、锁定对象、碰撞与通道占用；存在冲突的结果标为待调整，不能靠其他得分抵消。容量不足如实列出。随后比较入口到主要区域的路径、观礼朝向、组团完整性、路线冲突、对原方案的改动量。权重与阈值先核对现有判据和评测口径，再通过夹具校准，不在界面给出缺乏依据的“美学 95 分”。

### 局部调整

明确区分对象坐标、组团坐标和场地方向。“这里”优先指向当前显式选择；无选中且有多个合理目标时，只澄清目标。修改后重算受影响物件、区域和关联路线；涉及扩大范围或移动锁定对象时走现有权限机制，不静默全场重排。

## 分阶段实施与交付

| 阶段 | 工作与交付 | 完成标准 |
| --- | --- | --- |
| P0 真实场地基线 | 在用户当前场地复现一次“生成 → 点选 → 局部修改 → 撤销”；记录 URL、版本、画布、输入和首个失败点；补一份静态交互草图 | 区分入口问题、规划问题和渲染问题；明确 2D、3D 各自支持的操作，不用夹具代替当前场地 |
| P1 看懂与修改 | 摘要关联画布、选中上下文、本次变化、局部改动与恢复；串通严格档和默认档 | “这组桌椅向右移 2 米”作用范围准确；锁定件不动；撤销回到原始几何和引用 |
| P2 设计质量 | 接可布置域、入口及焦点约束；提升不规则分区、组团、物料匹配与候选比较 | 在矩形、凹形、含建筑场地中产生可解释方案；硬冲突不作为可直接采用的合格结果 |
| P3 立体检查与交付一致 | 同一方案在 2D/3D 定位对照；检查真实模型、占位尺寸和视角；复用现有保存分享链路 | 当前支持的模型在 2D/3D 位置、朝向、数量对应；刷新和分享无丢件或旧版混入 |
| P4 当前场地验收 | 用户实际场地跑完下述脚本，保留总览与局部证据 | 功能结果与设计效果分别记录；发现问题回到所属阶段修复 |

推荐先交付 P0 和 P1 的完整小闭环，再做 P2；P3 接现有模型与保存能力，不等待新的实景视觉识别研究。跨活动通用规划、个人级排座、完整预算与流程交付继续由原任务书管理。

## 施工边界与依赖

候选修改面为 `wedding-layout.ts`、`wedding-spatial.ts`、`wedding-request.ts`、`use-outdoor-agent-workflow.ts`，以及既有结果卡、画布选中与叠加层。实施前读目录规范并确认最小文件清单；可将展示逻辑拆成独立组件，保持方案数据真源不变。

本次工作区已有画布、叠加层、保存恢复等在途改动。P0 先核对这些最终实现，避免覆盖；保存与恢复直接接现有实现。先以现有 `SitePlanData` 和客户端契约承载设计；新增持久化字段确有必要时单独列出评审，不在 UI 任务中暗改契约。实施前另读文档索引中的 Agent 判据、评测集与阈值审计，复用既有评测。

## 验收脚本

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 当前场地起稿 | “这里做 60 人婚礼，先出一版” | 使用当前场地；目标与实际观礼、宴席席位分别显示；设计与摘要一致 |
| 真实景观方向 | 用户指定湖景侧，“背景低一点，别挡湖景” | 识别目标与方向；仅调整相关物件；高度和遮挡结论有模型或人工视角核对依据 |
| 点击与聊天 | 选中一组桌椅，“向右移 2 米” | 先明确“右”的坐标语义；不移动其他组；几何检查、变化摘要一致 |
| 保留约束 | 锁定背景，“其余重新排” | 背景的位置、角度、尺寸与身份保持；不可满足时说明约束冲突 |
| 不规则与不足容量 | 凹形、建筑阻挡、小场地各跑一次 | 不跨禁放区，不生成破碎不可用分区；席位不足不写“已满足” |
| 两版比较 | A/B 来回切换后采用 B | 视角一致；差异真实可见；采用前原方案保留，采用后可恢复 |
| 中断与并发修改 | 生成时手动移动物件，再尝试应用旧候选；另测停止和失败 | 拒绝覆盖较新方案；旧结果不误应用；停止或失败保留原方案 |
| 保存与立体核对 | 采用、刷新、切 3D、打开分享 | 数量、坐标、朝向与版本对应；本地、mock、真实云端结果分别记录 |

验证采用原始复现与聚焦回归。规划测试覆盖组团、越界、障碍和容量；交互测试覆盖选中目标、监督档位、版本过期和恢复。产品代码变更后运行 `npm --prefix frontend run typecheck`、相关 Vitest、lint 与 build；记录原始输出和存量失败。最终附真实页面截图与设计评审意见，不能以测试通过替代视觉验收。

## 本计划交付范围

本次仅形成实施计划与文档索引，不修改产品代码、不部署。计划完成后的用户体验目标是：能在自己的场地看到一版可解释设计，通过点选和一句话持续改进，并可靠保留每一步结果。
