# 标注候选应用边界（本地实验）

标注实验目前仅供预览，默认关闭。模拟工作台中，Agent 读取用户绘制的预留区后生成一个冲突物件，界面提示冲突，原场景保持不变。这使用固定模拟回复，不代表真实模型或现场验证。

## 已证实的限制

- API 侧仅凭候选警告识别预览限制；警告缺失时不能可靠判断来源。
- 未安装的本地事务原型可从 `agent_proposals` 关联的运行输入识别标注任务，并在同一事务中阻止应用；现有 `scene_rpc` 入口不经过该原型，仍可绕过。
- 运行记录删除会通过外键级联删除关联，而候选本身保留。此时没有警告的标注候选与普通未关联候选无法区分；本地回归测试已复现原型允许应用。该测试是故障注入，不表示线上已发生。
- 一律拒绝未关联的候选会影响原本合法的非 Agent 方案，不能在未验证兼容性时直接实施。

## 开启前需要证明

1. 方案创建时，以不可由客户端自行声明的方式持久记录受限来源；来源缺失、失效或不一致时明确拒绝，而非视为普通方案。
2. 所有可能应用候选的数据库入口在同一事务中执行授权、来源、版本和场景检查；覆盖旧入口、并发修改与重复应用。
3. 保留原有非标注方案的应用路径，验证旧数据兼容及异常回滚；不能修改现有表结构的前提下先验证可行方案。
4. 完成真实数据库角色和权限核查、部署兼容性检查及真实模型端到端测试后，才可考虑开启。当前未完成这些验证。

本地证据：`tests/annotation-preview-guard.prototype.test.ts`；该原型不是生产 RPC，也不是权限边界。

## 来源保留的后续实验

第二个本地原型将来源记录和候选生成放进同一事务，并把签章绑定到具体候选。测试覆盖运行记录删除、签章失败回滚、伪造及跨候选复制签章。当前假密钥和模拟数据库只用于实验；新协议可识别没有标注字段的受控请求，但不能证明历史无来源候选的真实来源，也不能将其自动判作安全。

证据：`tests/annotation-source-retention.prototype.test.ts`。真实旧入口仍可绕过未安装的原型；真实环境中的权限、密钥管理、多连接并发和旧数据兼容均尚未验证，不应部署或启用。

## 工具反馈循环

`agent-annotation-check.ts` 在 validate_candidate 和 submit_candidates 两个入口独立比较矩形预留区与物件占地。新增或加重占用返回 `RESERVED_AREA_OCCUPIED`，给模型同 get_scene 一致的临时标注编号和调整提示；保留已有占用、未知标注、离地物件及未覆盖检查的 unknown 语义。预留区是用户规划草稿，绝不是核实过的物理场地约束。

模拟模型回归覆盖两条路径：读取场景 → 校验或提交冲突候选 → 收到反馈后换位置 → 提交修正版；两例均完成，实际场景版本仍为 0。另有 4 项纯函数测试。真实模型行为仍未验证，原有只预览限制不变。

参考官方实现：[Vercel ToolLoopAgent](https://github.com/vercel/ai/blob/main/packages/ai/src/agent/tool-loop-agent.ts) 和 [LangGraph workflows/agents](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/workflows-agents.mdx)。采用工具结果回传并继续循环的结构，不增加框架依赖或复制外部代码；通用运行循环不能替代本项目场景验证及数据库提交一致性。

## 更小的数据库保护方案

后续方案已整理为 `supabase/migrations/20261109160000_annotation_preview_guard.sql`，不再要求生产 HMAC 密钥。数据库在运行与候选建立关联时写入固定预览限制；普通更新不能移除限制；实际应用代理读取权威候选行，仍依赖原有入口保护对旧内部函数的撤权。独立 SQL fixture 已移除，测试直接读取正式迁移，避免维护两份实现。

安装选择明确为：同一事务内令安装前所有尚未应用的候选过期，保留场景与候选内容，但用户需要重新生成旧预览。安装失败应一起回滚。安装后生成的普通方案继续按旧规则使用。不能宣称旧待确认方案无缝兼容，也不以此保护对抗拥有数据库所有者权限的任意修改。

`tests/annotation-preview-trigger.postgres.test.ts` 已在本机无网络、无宿主挂载的临时 PostgreSQL 容器实际通过：安装锁等待、旧候选过期、finish/get 与权威 warning 一致、任务删除与应用竞争时拒绝、普通候选并发应用只成功一次。容器已清理。签章实验保留为研究证据，不作为新增运行依赖。

API 仅在显式开启且请求携带标注时，通过当前项目授权探测 `annotations.readiness` 的能力和版本；缺失或不匹配会在创建任务及调用模型前拒绝。默认仍关闭，标注方案仅预览。生产权限、部署及真实模型均尚未验证。

整合回归：后台首次全量 1299 项通过、5 项超时、4 项跳过；将失败的 3 个测试文件单进程复跑，41 项全部通过。前端定向对话 144 项、标注 22 项及类型检查和构建已通过。不能把这些结果表述为生产或现场验收完成。
