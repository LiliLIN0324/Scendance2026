## 3. 按结果推进的三个阶段

| 阶段 | 用户获得什么 | 完成条件 |
| --- | --- | --- |
| S1：可信的整版设计 | 一句需求得到完整方案，直接小改有精确结果，应用/撤销/刷新可信 | A/B/C/D 的首批切片接合；F 对冻结版本完成 11 条用例及“一次整版确认”的专项验收。开发与浏览器各自有证据；真实服务未验不算完成 |
| S2：同版交付与资源可用 | 方案里的资产可恢复，平面、物料、路线、岗位/任务属于同一版本，执行人员知道缺什么 | E 完成资产恢复、版本一致性、导出回读；D 验真实云保存/权限；独立执行者试读可回答做什么、谁负责、何时完成、如何检查及找谁确认 |

沿用强化计划的既有体验目标：重复录入 0 次、确定性操作模型调用 0 次、一次确认重复写入 0 次，事实充分时最多一次必要澄清，固定环境首个有用反馈 1 秒内；范围确认与方案确认分开计数。采集实际耗时并如实报告是否达标，不凭空另定工期、成功率或预览延迟阈值。每阶段以验收结果结束，不能靠增加功能或测试条数冲抵失败项。

## 4. 可直接派发的长期任务

以下每张卡可连同 §5 的共同执行约定交给一个 agent。A–E 是开发职责，F 是唯一整合与验收责任。各任务的完成终点明确；不要求无限运行或自行建立定时任务。

A–F 是本计划的任务编号，不是仓库既有人员角色 A/B；任务 D 由既有后端负责人持有。各卡的“独占”是拟分派责任，不自动撤销 frontend/AGENTS.md 的角色 A 所有权：前端变更由现有前端负责人统一承接或明确转交文件；COLLAB 所列独占区仍按其登记流程交接。本计划目前只在本机保存，未提交 main：新工作树或远端 agent 必须先收到本文件全文或可访问的副本，再开始任务。

- 验收：窄缝不误杀、斜交不漏判、既有已确认内容不被无故覆盖；本体/未知/真实障碍分开处理。签到东移 2 m 只影响目标及明确依赖；其他锁定对象、入口与约束保持。
