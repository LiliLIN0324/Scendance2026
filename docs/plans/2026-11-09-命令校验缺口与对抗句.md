# 命令校验缺口与对抗句

日期：2026-11-09。对照当前 main 的 `agent-runner.ts` 工具声明、`ai.ts` 命令结构和房间里的确认 / 快捷键 / 撤销路径。这是源码对照和合成句，不是现场验收。

产品仍是一个活动 Agent。撤销、确认、打开物料库不是模型工具。本页不引入第二个 Agent，不改三维渲染，也不新加依赖。

## 已经守住

- 模型命令只有八种：`add`、`remove`、`move`、`rotate`、`recolor`、`replace`、`add_resource`、`replace_resource`。说明文字和结构声明一致。
- 活动 Agent 确认落盘走 `applyLayoutCommandWithRefusals`。形状或前置失败时整份不写入。
- 物料落点走 `executeSceneCommand`。这个函数在改布局前同时检查形状和前置条件。
- 对话面板发送的执行方式是 `preview`。源码里没有「服务端返回 direct 就自动落盘」的分支。
- 提交候选时，几何复核发生在接受之前。

## 仍开着的缺口

1. 方向键、删除、旋转、复制、粘贴、Ctrl+Z 和拖放结束，直接改布局或恢复快照，不经过 `executeSceneCommand`。快捷键撤销是 `history.undo`，不是模型工具，也不是案例里的内存撤销。
2. `submit_candidates` 运行时先接收未知数组，再逐项解析。模型看到的是更严的三种候选之一。单份候选没有先调用 `validate_candidate` 时，不会因为缺那张回执被拒绝；净距和覆盖范围因此可能没有先算过。多份候选排序时才会标 `validated:false`。几何复核仍然会跑。
3. `DEEPSEEK_AGENT_MODE=legacy` 不走 `validate_candidate` 工具。它会做候选复核，然后结束。
4. 纵向案例里的共享命令和撤销只活在案例内存里，没有替换房间撤销栈。案例拒绝 `bypass`，不能当成房间已经收口。
5. 调用方如果显式传入 `direct`，不含建议、疑问、否定的祈使句仍可能被标成 direct。当前面板不传这个值，也不据此自动落盘。

这些缺口被 `tests/command-validation-gaps.test.ts` 盯住。路径被收口或守住的检查被拿掉时，测试会失败。

## 对抗句

在 PR #90 的讲座案例上追加，不替换原来的五句：

- 80 把椅子、八十把椅子、够坐、坏椅子，都不是到场人数，也不是已核验库存。
- 「不是 80 个人，到场大概 30 人」保留 30。单独一句「不是 30 人」仍然未知。
- 「80 位老人」「八十位长者」是人数。长者、适老、别假设、不愿被当成，都不会变成轮椅需求。用户明确说不需要，才记否定；明确说轮椅使用者，才记需要。
- 建议可以记成建议。零缺口也不能在这个案例里确认。先别定会继续推迟座位形式。
- 同一句里的改人数、移动、清单都留下。一句里同时往左又往右，移动保持未决，人数和清单不丢。

## 下一步

- 不要把键盘和拖放直接塞进命令门。先定撤销步和墙面吸附还要不要保持现在的粒度。
- 若要关闭「未校验也能提交」，需要同时改截止时间那条「不要继续校验、直接交完整候选」的提示，并重跑 agent 运行测试。
- 案例编辑器仍不要接进面板。
