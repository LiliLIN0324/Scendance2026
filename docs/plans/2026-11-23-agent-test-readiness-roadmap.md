## 三、分阶段计划

### 阶段 0 · 测试通畅前置（基础设施，本轮已完成一半）

**目标**：让 R7-A 几何对抗用例能被稳定驱动、可离线复现守卫拒绝态。

- **0.1 已落地**：DOM 手柄层（`e15c2f02`），自动化按 `[data-vertex-index="i"]` 取顶点钮按住拖拽；复用既有 `dragVertexRef → moveRingVertex → checkBoundaryRing → commitPlan` 链路，不另起校验。
- **0.2 部署与验收环境口径**：本仓前端由 Cloudflare Pages 从 `main` 自动构建发布（见 `docs/64-部署与发布手册.md` §5、`docs/66-Cloudflare部署.md`），**没有独立 staging 分支预览**。因此"先部署再验"= 攒批推 main 触发 Pages 构建后在 `pages.dev` 验；若需隔离，只能本地 `npm --prefix frontend run dev`（带高德代理）。两条路径二选一，验收前再拍板。
- **0.3 离线对抗断言补齐（纯测试文件，不碰产品码）**：复用既有 `outdoor-plan-canvas.pointer-capture.react.test.tsx`、`write-gates.react.test.tsx` 先例，用手柄元素驱动 A1–A7 守卫分支；断言"非法拖动拒绝 + 原环保留 + 面积/点数回执"。
- **0.4 真机跑对抗用例**：按 Flo 提议优先级 P0 `A6→A1→A3→A2`（同一 `checkBoundaryRing` 分支），P1 `A5→A4`，P2 A7-G；逐条留回执、原环是否保留、面积点数。决策点停住，不代应用、不代换排法。

**验收**：手柄在测试脚本里可定位可拖拽；守卫拒绝/原环保留在离线测试与真机双留证；通过后按攒批约定一次性推 main（含本地领先的 4 个提交）。

**边界**：只做 2D，不扩 3D；不改独占五文件与几何基线两文件；手柄命中走拍板的纯像素复用，不读 `dataset` 做目标优先。

### 阶段 1 · 编排抽离 headless turn engine（断点 1，最大架构前置）

**目标**：把"一条消息进来该发生什么"从 React hook/panel 抽成纯函数/纯类，使编排可离线重放、可换端、可评测。

- **1.1 抽取**：`turn(message, snapshot, memory, issuedContext) → { reply, proposal, outcome, events }`；约束 `lib/agent-turn/**` 内禁止 `import react`；UI 只做渲染与副作用落地。
- **1.2 先行护栏（判据 #13，与抽取并行，成本最低）**：阶段状态机不变量纯函数测试；抽离前后各跑一遍，当行为等价裁判。第一刀从 scope 阶段切起（经 2026-11-21 流程简化后是链上最小、测试最全的一段）。
- **1.3 收口的 R7 卡点**：M3 六因细分回执、M4 失效影响范围列示、D1 原句单处渲染、S4→S5 瞬态卡不闪丢、S5 反问前先回读已有草稿。这些阶段推进与回执逻辑目前焊在 `agent-panel.tsx` / `use-outdoor-agent-workflow.ts` / `outdoor-agent-planning.ts`，抽离后才能单测、单换。

**验收**：Node 环境不启动浏览器能跑完 30 条固定 prompt；`grep -r "import .*react" lib/agent-turn` 为空；状态机不变量测试进 CI。

**风险**：此为最大结构改动，动前须按 AGENTS.md §六在 `HANDOFF.md` 登记协作区变更；`agent-panel.tsx` 工作区另有他人在途改动，抽取前先核对归属，不捎带。

### 阶段 2 · 命令 golden 应用层补全 + 需求/候选字段（断点 5 残留，可与阶段 1 并行）

**目标**：先补纯数据与规则层，零架构依赖；把"听懂了却做错"和"缺前提还硬答"的口子堵上。

- **2.1 应用层语义 golden**：`agent-proposal.ts:976-983` 两处——`bothSides` 无视 count 强制摆 2 件、锚点物件缺失时整 op 直接失败（0 件）；补进 `data/agent-corpus/command-golden.json` 正例 + 反例；解析/应用函数可被该表驱动。
- **2.2 K4 需求追问**：需求回执步先弹结构化追问（人数区间、时段、室内外）；可跳过，但回执须标注"规模未知·按默认估算"，检索/容量估算带该前提。
- **2.3 K6 候选字段**：候选卡补面积、容量、可办业态、开放与许可标签；缺数据显式标"待核验"，不留空让人猜。
- **2.4 K5 占位动态化**：占位与快捷词按当前草稿已理解的场地/活动类型生成；无上下文用通用示例，不残留别的城市地名。

**验收**：golden 每条正例通过、每条反例不通过；新增动词不得绕过该表；K4/K6 缺前提时回执带"待核验/未知"标注。

### 阶段 3 · 设计意图通道 C 段 + 类型/环节解析（断点 2，决定产品天花板）

**目标**：让模型能表达意图、能把活动环节解析成功能分区，而不是退回规则兜底矩形。

- **3.1 C 段 `layoutIntent`（全 optional）+ E2 路由收敛**：与一次对照实验合并，用 C4 30+ 条评估集量化前后；不变量 1 不动——模型仍不产生坐标/资产 ID/价格/容量结论。
- **3.2 类型判定（D4/M1）**：先读流程关键词（签到/集卡/瑜伽/冥想/合影/兑礼）；低置信或多类型走通用分区反问，不硬套婚礼模板；人工变更范围后重跑一次类型/用途校验；确认重画卡回显当前判定类型，提供一键改型。
- **3.3 环节→分区映射（M6）**：五环节（签到领手环驱蚊贴 / 5 个集卡点 / 瑜伽冥想静躺 / 大合影 / 兑礼品）解析成功能分区，再按分区落物料；人数未知时垫类/座位先占位并标注"待人数确认后调整"。
- **3.4 M5 默认件推算依据**：默认件标注推算依据（面积/分区数）；人数未知明确标"待人数确认后调整"。举证口径注意：现有文案是"可调整的布局假设"，缺的是面积/人数的量化来源，不要写成"已无依据话术"。

**前置**：阶段 1 的结构支撑；阶段 2.2 的人数追问先补上前提。

**验收**：C4 pass 率不降；带 `layoutIntent` 的布局在 notes 里能说清"为什么这么排"；无 evidence 的 intent 被剥离且 reply 如实声明；瑜伽/冥想类语料不再被判成婚礼。

### 阶段 4 · 代码抢路由归还模型 + 评测接 CI（断点 3 + 断点 4）

**目标**：归因不断裂；测试价值从"人记得跑"变成"机器裁决"。

- **4.1 抢答分支对账（断点 3）**：以 C4 评估集为基线，逐条评估 `explicitProposalApproval()`、`defaultZonesForEvent` 等模型之前先判意图的分支——能还的还给模型 + 保留代码兜底；接管分支在代码里留注释对账；M1 类型守卫绕过在此收口。当日流程简化新增的确定性逻辑必须以确认门/提案之上的门形式实现，不新增"模型之前的抢答"。
- **4.2 评测接 CI（断点 4）**：先接三个——`tsc --noEmit`、27 条 agent corpus、C4 路由评估集；规则"基线下降 >2% 即红"；保留对照样本防沉默刷分（判据 #8）；未实现判据不计分。故意删一条判据实现，CI 必须红。

**前置**：阶段 1 完成后 4.2 才有意义。

### 阶段 5 · 多轮事件溯源（断点 6，长会话质量，非阻塞）

**目标**：长会话里"确认"不串台。

- `BriefMemory` 增 `pendingEventId`（只加 optional）；确认必须携带事件 id 且与最高优先未决事件一致；不一致降级为重新询问。
- 收口 M2：候选态半透明 + 虚手柄，已确认态实线实手柄；未确认候选不显示实体顶点手柄，图例标注两套含义。

**验收**：两卡并存时，对第二张卡的确认不得作用于第一张。**前置**：阶段 1。

### 阶段 6 · 计费与失败口径（断点 7，独立处理）

**目标**：失败可区分、可退、不残留；账务口径一致。

- **6.1 失败分类与清理**：M7 区分"服务端 durable run 未完成 / 方案被拒 / 输入触发"；补需求轮失败后清掉上一版预览残留，不把旧预览留在画布；回执带可排查错误码。
- **6.2 计费口径统一**：先统一"失败不退"这一条（口径不一致是账务风险）；预算上限是产品决定，单独拍；`AI_BUSY` 全局锁按 owner 收敛。

**验收**：并发重放只结一次账；`committed_cents` 不为负、不超扣；扣钱但无 turn 证据的步逐行退。**前置**：无。
