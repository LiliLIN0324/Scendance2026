# 助手开关与对话状态检查

2026-10-08 用户试用反馈：展开后右下角开关消失、助手设置应靠近输入框、重开聊天后出现执行交付且无法输入。

## 已确认的原因

1. 展开样式隐藏了右下角入口，只剩标题栏关闭按钮。用户原来使用的开关位置不稳定。
2. 助手设置和模式摘要分散在标题、聊天标题、消息上方及输入框下方，占用对话空间，操作控制离输入较远。
3. 资料浏览和对话共用工作模式。打开执行资料会写入delivery，模板另有composer隐藏条件；再次展开沿用这个状态，表现为聊天不能输入。初次进入默认plan，并非初次默认交付。
4. 停靠后资料经portal进入左侧，Escape监听却只在右侧聊天容器；在需求输入中按Escape不会关闭资料或返回入口。旧测试覆盖浮窗，没有覆盖这条停靠路径。本轮需补处理和对应回归。
5. 修订中发现模式选择仍会自动打开物料面板，在窄屏触发聊天收起。模式选择应保持输入连续，物料工具由显式入口打开；此项在本轮发布前修正。

## 调整方向

- 固定保留右下角开关，展开后仍可用；为其预留空间，不覆盖输入和发送。
- 模式、设置和发送集中在输入区。设置由图标展开，当前修改策略仍可辨认，键盘可关闭并回到触发按钮。
- 对话模式只有场景策划和物料建模；需求、图纸、模板、执行资料是按需浏览的内容，不代替对话模式。
- 保留真实生成范围、独立草稿、任务状态、候选确认和过期保护，不增加未接通的模型选择或通用聊天能力。

布局参考：[GitHub Copilot 的会话说明](https://docs.github.com/en/copilot/how-tos/github-copilot-app/agent-sessions)把模式选择放在输入框下方。此处采用控制靠近输入的组织方式，沿用幕景现有业务和配色。

## 本轮对抗路径

- 场景草稿→物料草稿→图纸/执行/模板→返回：检查模式、两份草稿、选择和候选。
- 生成中/结果待确认→收起→打开资料→再打开：不重复提交、不丢任务、不提前应用。
- 恢复备份或换项目：资料导航可定位到结果，聊天可输入；不同项目不串草稿。
- 桌面、平板、手机：设置展开和右下角开关不遮挡关键操作，Escape关闭设置后焦点有去处。

## 后续顺序

先完成本轮交互修复与验证，再用明确标注为演练的30人工作坊走通“活动需求→尺寸核对→场地布置→物料规格→分工与交接”。逐步补齐阻碍真实使用的缺口。真实AI效果、真实客户反馈和双人云协作需要分别验收，不能以本地测试或演练代替。
