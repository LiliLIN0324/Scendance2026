# 幕景 Agent 能力、工具与验证盘点

盘点日期：2026-11-07，工具数量与真实调用状态更新至 2026-11-08。对象是 `chat-integration` 当前工作区；与原 main 工作区和 `intelligent-followup` 不完全相同。下文区分代码存在、产品入口、模型可调用与真实验证，不能以任何一项替代其他项。

## 1. 先回答核心问题

模型提供理解、规划和判断能力；产品能否完成任务还取决于可用工具、真实上下文、执行环境、失败恢复与独立验证。同一模型在不同工具和状态环境中可以有不同表现。更长的自主运行时间不是结果可靠的证明；Anthropic 2026 年的研究中从不足 25 分钟到超过 45 分钟是最长交互的 **99.9 分位数**，不是典型会话长度或完成率：[Measuring AI agent autonomy in practice](https://www.anthropic.com/research/measuring-agent-autonomy)。

讨论顺序：先做 B——如何知道做对了；同时补最小 A——能根据工具结果自主选择下一步。C——长期学习与跨任务迁移，等有足够真实案例、稳定评测和人工基线后再做，不把本场对话记忆称为模型已经学习。

## 2. 云端 Agent 工具

来源：`supabase/functions/_shared/agent-runner.ts` 的 schemas、descriptions 和工具分发。数量只代表当前代码声明，不代表所有环境都已配置或真实调用成功。

| 工具 | 代码意图 | 使用边界 |
|---|---|---|
| get_scene | 读取任务提交的场景与选中对象 | 是指定快照，不等于实时现场 |
| search_resources | 查询任务授权范围内的模型资源 | 模型与尺寸不等于实体库存、价格或档期 |
| inspect_zone | 查看场地局部结构/物件 | 输入范围与图纸/场地来源决定可靠程度 |
| find_free_areas | 几何搜索候选空位 | 只是候选位置，不证明规范合规；模型仍可能绕过此工具自行给坐标 |
| prepare_seating_candidate | 按明确数量、规格和间距试排一人一桌一椅，通过运行内句柄提交候选 | 保留现有物件；普通云场景最多 50 件物料，放不下须明确报告缺口和未知项 |
| prepare_shared_seating_candidate | 按已明确的每桌两人要求试排双人课桌及独立椅子，通过运行内句柄提交候选 | 数量、规格和门洞等以可核验证据为限；缺口、物件上限及未知安全事项需可见 |
| create_parametric_model | 生成受限类别的参数化资源 | 有资源写入副作用，不是纯查询 |
| inspect_materials | 读取模型材质槽 | 不代表实物颜色与现场材质 |
| customize_material | 产生材质变体 | 有资源写入副作用，涉及对象权限与版本 |
| validate_candidate | 用候选构建逻辑检查，并返回警告、局部净距和未覆盖项 | 与生成共用 build；不是完整独立复核，更不是消防/无障碍通过 |
| submit_candidates | 提交候选方案 | 当前工作区增加对完整候选和基线的独立几何复核；仍不是现场安全验收，预览不等于已应用或场地方确认 |
| get_bom | 汇总场景对象、数量与标称尺寸 | 不提供真实供应、价格、预订或库存保证 |
| start_lux3d_model | 可配置时提交 Aholo Lux3D 生成任务 | 可能收费，实际账户可用性待核验；结果为模型，不能假称现场已有实物 |
| search_places | 可配置时通过高德查询地点名称、地址与坐标 | 默认关闭，需显式启用和服务端 Key；地点查询不是通用网页搜索，也不证明可租、价格或档期 |

上述共 14 个声明工具，不表示每个都在所有环境开放。`agent-runner.ts` 包含最多六轮的工具选择、结果回传、错误提示和防重复陷阱；它属于云项目 actor/lease/RPC 路径。最新工作区代码已取消 MiniMax 专属工具限制，参数化创建、材质变体与已配置的 Aholo 模型生成按相同条件开放，但这些新增开放路径目前只经过模拟验证。地点查询需额外配置、默认关闭。隔离环境已真实观测 MiniMax 调用局部查看、找空位、双人桌试排、候选检查和提交，并得到单椅及一次 30 人预览；30 人方案中的桌椅配比、原物变动、安全与库存仍需核验。工具执行回执、有效候选、最终应用与现场验收须分开统计，不能把模拟或单次成功扩展为整体可靠性。

## 3. 用户界面与本地能力

- **活动/对话**：已有多轮简报、候选预览、确认/撤销、停止与部分会话隔离；MiniMax 已在隔离试用返回过真实候选，但需求理解仍可能格式或证据校验失败，也不能视为成熟通用 Chat。
- **场地/空间**：可选地点地图、标注与编辑布局；地图地点/手画范围不等于可租场馆、室内平面、核定人数或场地方确认。未知门和尺度需保留。
- **物料**：已有本地模型目录、筛选、GLB 导入、条件满足时可走 Aholo 生成入口；Chat 可按原话提出查询并显示模型标称尺寸。用户口述物料原话可记为待核验，但本工作区尚未将它映射为真实库存。
- **审校**：Bingo/几何检查和评审反馈入口存在；部分几何能力为粗检，规则版本、适用地区、覆盖项和现场复核不能省略。
- **交接/备份**：有清单、交接、活动资料和版本相关能力；当前分支与 followup 的事实清单/冻结草案尚未完全整合。普通备份当前不含所有对话需求与场地事实，用户需看到清楚范围。

## 4. 反馈、结果验证与质量

使用受控虚构例子：30 位参加者，用户口述只有 20 把同规格椅子。数字只为测试，不指向真实园区。

1. **工具反馈**：查询返回“用户登记 20 把”，同时带来源、记录时间、型号与可用性；若缺失则为 unknown。
2. **结果验证**：用户明确要求人人就座，独立计数确认候选是否至少有 30 个合格座位，并核库存映射、布局碰撞和已知场地约束；缺口为 10，但不把“模型 3D 椅子”当 10 把现实椅子。
3. **自主调整**：模型可以提出借用、租用、替代或重新安排等选择；没有可查报价或库存时明确未知，不能假装已订到，也不能静默减少参会者或降低硬要求。
4. **质量评价**：在可核验约束之上，比较视线、交流氛围、预算、便利性与执行成本；偏好用于排序，不能覆盖已知硬冲突。验证器未知时可探索，不可声称系统安全通过或可交付。
5. **现场验收**：上述只能证明系统与输入数据的关系；场地方/相应专业人员仍需核验场地和适用要求。

成功应由环境或最终候选状态验证，而不是工具“成功返回”或模型说“已完成”。Anthropic 将运行轨迹和结果状态分别纳入评测，说明可参考：[Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)。

## 5. 实际差距及下一步

1. **稳定现有模型工具链**：隔离环境已真实验证 MiniMax 的部分工具调用及候选返回；需继续覆盖明确人数、原物保留、后续修改及交付，不能以单次成功替代评测。实际派发白名单需在执行侧强制，不能仅从模型工具列表隐藏付费工具。
2. **先修工具语义**：已删除 prompt 将局部 `valid:true` 说成达标、将 1.2/0.9 米当作完整通行判定的表述；工具返回有限几何覆盖和门扇/通行/消防等 unknown。当前工作区已为候选提交增加基于完整候选及基线的独立几何复核，相关模拟测试通过；这不等于独立安全验收，界面完整呈现仍需核验。
3. **记录结果与失败**：同一运行的动作、结果、版本、取消/未知状态和人工确认应可追踪；推理内容/密钥不写日志。超时不自动重发付费请求。
4. **跑一条完整样本**：杭州养老社区创作活动，场地未定先采用标明的合成假设；材料、人数、门和库存分开。先固定响应测程序，再有限真实 MiniMax 样本，再邀请场地方核实；三类结果单列。
5. **持续评估**：比较任务完成、误判、危险漏检、未处理需求、调用次数/延迟、用户放弃和人工接管；用同样输入替换模型对比，而不是只看演示效果。

## 6. 不能夸大的地方

- 智能体不是“模型说得好听”或“工具返回 200”。也不意味着所有步骤都必须询问用户：只读查询和可撤销探索可在已授权范围自动进行；具有实际外部副作用或关键未知的部分依产品授权和现场要求处理。
- MiniMax 的真实试用既有成功候选，也有需求结构、证据校验与超时失败；不能把模拟轨迹或少量成功当整体可靠性。详细记录见 `2026-11-08-智能建造验证记录.md`。
- 养老社区不等于特定行动能力、固定活动方式或已合作；请以用户意图与场地方资料为准，不作医疗效果承诺。
- 本记录是工程盘点，不是正式规范意见、现场安全结论或上线保证。
