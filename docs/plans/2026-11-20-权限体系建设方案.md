# 权限体系建设方案：成熟产品对照与分期落地（2026-11-20）

> 定位：上游 [生成物可见性与权限分层研究](./2026-11-20-生成物可见性权限分层研究.md) 已盘点现状规则；本文回答三个问题——成熟产品怎么做权限分层、我们的目标模型长什么样、分几期落地。
> 边界：**P0 为前端/展示层，本轮可直接落地；P1/P2 涉及 migration 与 RPC 契约，只出设计，落卡前必须人 review**，本仓不擅自动迁移、不改 RPC/Edge 契约、不另起并行身份 schema。

## 一、成熟产品对照

选了四类与本仓（活动策划 + 3D 场景协作 + 素材库）最贴近的产品：协作设计工具 Figma、文档协作 Notion、设计模板平台 Canva、3D 室内设计 SaaS 酷家乐。

### 1.1 Figma：三级层级继承，显式授权可逐级覆盖

- 结构：**Team → Project → File**；权限沿层级继承，子级显式授权可以覆盖父级（项目覆盖团队，文件覆盖项目），显式优先于继承。
- 角色：每个资源有且仅有一个 **owner**；团队侧另有 **team admin**；成员默认 **can edit** 或 **can view** 两档。
- 项目对团队的访问三档：**Same as the team**（继承团队角色）/ **View-only**（全员只读不可新建文件）/ **Disable**（仅受邀人可见）。
- 团队库（Team Library）：editor 可把样式、组件发布进团队库；团队设置、默认库选择只有 admin 能管。
- 依据：Figma Help Center — Team permissions、File and folder permissions、File and project permissions（链接见 §八）。

### 1.2 Notion：工作区角色 + 页面访问级 + 通用访问三档

- 工作区成员类型：**workspace owner / member admin / member / guest**；guest 是组织外人员，只被邀请到具体页面，**不进入整个工作区**。
- 单页访问级：**Full access / Can edit / Can comment / Can view**，可对每个人、组、团队空间分别授予。
- 页面通用访问三档：**仅受邀人** / **工作区所有成员**（可再设「不在搜索结果中出现」）/ **互联网持链接任何人**；持链接访问可设过期时间；企业版可在安全策略里禁掉公开发布、禁止加 guest、禁止导出。
- 依据：Notion Help — Understanding Notion's sharing settings、Sharing & permissions（链接见 §八）。

### 1.3 Canva：设计与品牌模板分离，模板不做公开链接

- 普通设计可见性：**仅自己 / 团队全员 / 指定成员或组**；权限档 can edit / comment / view；可选择「对团队全员在搜索中可见」或「仅持链接可见」。
- Brand Kit 分**团队/组织 Kit**（admin、brand designer 管理，全员共享）与**个人 Kit**（创建者私有，admin 可在设置里开关是否允许建个人 Kit）。
- Brand Template 归属品牌而非个人；模板可见三档：**仅品牌设计师与管理员 / 指定团队成员 / 团队全员**。**品牌模板不支持公开链接分享**——要对外分享，只能从模板生成一份设计，再以 view-only 分享那份设计。
- 依据：Canva Help Center — Publish designs as Brand Templates、Set up Brand Kits、Share designs with your team（链接见 §八）。

### 1.4 酷家乐：素材四库分离，跨库提交走审核，库写权限按角色收窄

3D 设计 SaaS，素材分层与本仓最像。

- 素材四库：**个人库**（仅本人账号调用）/ **我的收藏** / **团队库（企业库）**（同企业全员可调）/ **公共商店**（品牌馆、公开模型）。
- 个人素材可**提交到团队库**：主账号提交自动入库；子账号提交进入「素材提交管理」，**主账号审核通过后才进团队库**。
- 角色对企业库的权限收窄：**主账号**上传/管理且唯一可「公开模型」；**库管理员角色**可上传管理但公开按钮置灰；**普通子账号**对企业库无上传/管理权，仅可取用。
- 场景模板：仅主账号/管理员可创建、管理；入库后同企业全部子账号可调用。
- 依据：酷家乐帮助中心 — 团队库上传、个人素材提交团队库（含审核）、棚拍管理员角色权限、多人协作出图素材复用（链接见 §八）。

## 二、收敛出的七条通用原则

1. **层级继承 + 显式覆盖**：团队 → 项目 → 资源，默认继承父级；单资源可显式收窄或放宽，显式优先。
2. **角色四档起步**：owner / admin / editor / viewer；外部协作者是「guest」，只进单资源，不进工作区成员表。
3. **资源可见性三档**：私有 / 团队内 / 公开；公开再拆「注册用户目录」与「持链接匿名」两条通道。
4. **素材库三库分离**：个人库 → 团队库 → 公共/策展库；跨库流动走**提交—审核**，不是一键直入公共。
5. **库写权限收窄**：普通成员只取用；入库、公开、库管理交给 admin / 策展角色。
6. **链接分享独立于库**：持链接可达；可过期、可吊销、可从检索隐藏；脱敏快照与库内原件不是同一授权。
7. **内部候选是中间态**：未达公开质量的试验件是「团队/管理员可见」的标记层，不构成独立公开层，也不进公共检索。

## 三、本仓目标模型（不另起身份 schema）

### 3.1 可见性层级 L0–L4

| 层级 | 含义 | 现状对应 | 目标 |
| --- | --- | --- | --- |
| **L0 本机草稿** | 本地存储，不联网 | localStorage / IndexedDB（本地项目备份） | 维持 |
| **L1 私有** | 仅物主本人 | `assets.owner_id`；`outdoor_plans.actor`；户外卡片历史；个人偏好；生成任务；Agent 运行记录 | 维持；绑定项目的任务/源图随项目进 L2（见 §5.2） |
| **L2 团队内** | 同工作室成员 | 项目、`project_assets` 引用件、成员、消息、工作室设置、重建源图 | 现状项目线保留；**补团队素材库**（P1） |
| **L3 注册公开目录** | 登录且有任意工作室身份可取用 | `published_assets`（物主发布）、`library_assets`（service_role 策展） | 维持；目录内再分「物主公开」与「策展精选」两组展示 |
| **L4 匿名链接** | 持 token 的访客，脱敏快照 | 分享快照 `publications`/`shares`（可吊销）；评审短链（180 天过期，物主可吊销，P1 已落地） | 评审短链吊销已补 |

> 静态随包物料库（`merged.json` + GLB + webp）是发版直链，无逐条鉴权，归 L4 匿名可达；内置 8 个基础件走鉴权接口，实际按 L3 口径取用。

### 3.2 角色目标态（分期扩，不一步到位）

| 角色 | 现状 | 目标职责 | 落地期 |
| --- | --- | --- | --- |
| **owner** | `members.role='owner'`，每工作室一人 | 全部编辑 + 成员管理 + 库管理 + 所有权转移 | 现状即此 |
| **admin** | 无；库管理只能 service_role 离线脚本 | 团队库审核与管理、成员角色调整、默认库选择；不能转移所有权 | P2 扩枚举 |
| **editor** | `members.role='editor'` | 内容编辑、可邀请 viewer、可提交素材进团队库（待审） | 现状 editor 代管，P1 起区分提交权 |
| **viewer** | 无 | 只读 + 评论，不可编辑、不可邀请他人 | P2 扩枚举 |
| **guest（匿名访客）** | 不进 members 表，持 L4 链接访问 | 维持：只拿到脱敏快照，无身份行 | 现状即此 |

一期不扩 `members.role` 枚举：admin 能力先由 owner 代管，避免迁移面铺开。

### 3.3 实体 × 角色 × 可见性矩阵（目标态）

| 实体 | 默认层 | 物主 | 同室 editor | 同室 viewer | 公共目录（L3） | 匿名链接（L4） |
| --- | --- | --- | --- | --- | --- | --- |
| 项目方案 | L2 | 编辑 | 编辑（持租约） | 只读 | 否 | 快照脱敏后可 |
| 项目引用物料 | L2 | — | 取用 | 取用 | 否 | 快照内带出已授权件 |
| 个人上传/生成物料 | L1 | 读写 | 否 | 否 | 物主可发布为 L3 | 否 |
| 团队库物料 | L2 | 提交者 | 取用 | 取用 | 否 | 否 |
| 策展目录物料 | L3 | 策展方 | 取用 | 取用 | 全员注册用户 | 否（静态随包件除外） |
| 分享快照 | L4 | 创建人/owner 可吊销 | — | — | — | 持链接，脱敏 |
| 评审短链 | L4 | 创建人可吊销（P1 已落地） | — | — | — | 持短码，过期 |
| 户外方案（独立） | L1 | 读写 | 否 | 否 | 否 | 否 |
| 重建源图/任务 | 随项目 L2 | — | 可见 | 只读 | 否 | 否 |
| 偏好/卡片历史 | L1 | 读写 | 否 | 否 | 否 | 否 |

### 3.4 素材库三库落点（对标酷家乐）

| 库 | 表/来源 | 写入主体 | 可见范围 | 对应前端分组 |
| --- | --- | --- | --- | --- |
| 个人库 | `assets` where `owner_id=me` | 物主上传/生成 | L1 | 「我的生成」 |
| 团队库（目标） | 新增 `studio_assets` 引用表（P1） | editor 提交 → owner/admin 审核 | L2 | 「团队」分组（P1 上线后出现） |
| 公共目录 | `published_assets` + `library_assets` | 物主发布 / 离线策展脚本 | L3 | 「公共」分组 |
| 静态随包库 | `frontend/public/showcase/assets/library/` | 发版构建脚本 | L4 直链 | 静态模型库页 |

## 四、分期路线

### P0 本轮：前端展示层与口径（不改后端契约）

- 物料面板把混排的「库」列表按现有字段拆成两段：**我的私有**（`owner_id === me`，未发布）与**公共目录**（`published_at` 有值）；项目引用件不在列表内，文案注明「打开对应项目时可见」。
- 界面文案对齐 L1 / L3 / L4 口径；不承诺尚不存在的「团队库」分组。
- 内部候选件先用 `metadata` / `catalog` 标记分组预留（如 `catalog='scendance-internal'`），不进公共检索。
- 依据字段均来自 `/assets` 现有返回（`owner_id`、`published_at`、`metadata`），不新增接口。

### P1 轻量后端（migration + RPC，**待人 review**）

1. **团队素材库**：新增 `studio_assets(studio_id, asset_id, submitted_by, submitted_at, reviewed_at, reviewer)`；editor 可提交，owner（未来 admin）审核通过后同室全员可取用；`can_use_asset` 补团队库分支。
2. **评审短链吊销**（✅ 已落地，待 review）：`review_share_links` 补 `revoked_at`，新增吊销 RPC（物主本人），`review_share_link_read` 过滤已吊销；前端分享菜单补「作废」入口，成功后清本机标记。落地：migration `20261120120000_review_share_link_revoke.sql`；后端测试 `tests/review-share-link-revoke.test.ts`；客户端 `review-link-cloud.ts` 的 `revokeReviewLink`；分享菜单 `share-menu.tsx` / `share-panel.tsx`。对标 Notion/Figma 链接均可吊销。
3. **项目级可见开关**：`projects` 加 `visibility` 字段，三档 `team`（默认，同室全员）/ `view-only`（同室只读）/ `private`（仅创建人 + 显式受邀）；对标 Figma 项目三档。`projects.list` 按档过滤。
4. **户外方案归属**：绑定到项目的户外方案与重建源图随项目升 L2；独立户外方案、卡片历史、偏好留 L1。

### P2 角色与策展体系（migration，**待人 review**）

1. `members.role` 枚举扩 `viewer`、`admin`；viewer 只读 + 评论；admin 管团队库、成员角色、默认库。
2. 公共目录策展前台入口：替代目前纯 service_role 离线脚本的策展登记，admin 可在界面上把团队库件提升到策展目录。
3. 权限矩阵落入 RLS/RPC 复核：每个实体的读、写、发布、吊销动作逐一对齐 §3.3。

### 明确不做

- **公共目录不对匿名开放**：L3 保持「登录且有工作室身份」；匿名只走 L4 快照。依据：Canva 品牌模板不做公开链接、酷家乐公共商店与企业库分离。
- 不另起并行权限表或身份 schema；复用现有 `studios` / `members` / `project_assets` / `published_assets` / `library_assets` 表达三态。
- 内部候选件不进公共检索、不进公共目录列表。

## 五、对原开放问题的建议答复（附对标依据）

承接研究文档 §五的 6 个待拍板问题，结合成熟产品证据给出建议：

1. **「开发者能看到的」指什么**：建议拆成两层——(b) 开发团队内部预览件（未达公开质量，L2 内用 catalog/metadata 标 `internal`，P0 轻量落地）；(a) 管理员策展视角（P2 admin 角色）。**不是** (c) 账主私有件。依据：Canva 模板分「仅设计师/管理员可见」与团队可见；酷家乐库管理员与普通成员分库权。
2. **户外方案 / 生成任务是否团队可见**：绑定项目的源图、重建任务随项目 L2；独立户外方案、生成任务记录、偏好留 L1。依据：Figma/酷家乐只共享产物，过程记录不进团队库。
3. **公共目录是否对匿名开放**：**不开放**。匿名体验只通过 L4 脱敏快照链接。依据：见 §四「明确不做」。
4. **14 个 Aholo 道具落哪层**：先挂 **L3b 内部候选**（`catalog='scendance-internal'`），完成缩略图、人工目检、中文标签门禁后，再决定进静态随包库（L4）还是公共目录（L3）；不直接公开。依据：酷家乐子账号提交先入待审，审核通过才进团队库。
5. **评审短链是否补吊销**：**补**（P1，已落地）。现状只有 180 天过期，无吊销入口；对标 Notion/Figma 链接均可主动吊销。
6. **项目级私有开关是否需要**：**需要**（P1 轻量三档）。现状工作室内所有项目对全体成员可见，没有逐项目收窄；对标 Figma 项目 Same as team / View-only / Disable。

## 六、风险与验收边界

- P0 前端分组只用既有返回字段；若 `/assets` 后续补 `catalog`、团队库标识，分组再扩，不改 P0 已落地口径。
- P1/P2 任何 migration、RPC、RLS 改动，落卡前先对照研究文档 §二的现状证据与本文 §3.3 矩阵；测试需覆盖：继承被显式覆盖、团队库审核前后可见性差异、吊销后短链不可读、private 项目对同室其他成员不可见。
- 14 个生成件的入库门禁不变：缩略图必须 RIFF/WEBP 实图（不能占位）、人工目检无悬浮碎片/畸形/残留文字、中文标签并入 `labels.zh.json`、`merged.json` 重建校验 sha256 + bytes。
- 工作树其余遗留改动保持原样；本轮不 `git add -A`，不推送 main。
