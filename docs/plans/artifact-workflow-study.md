# 从 Trooly 手册借鉴幕景的项目成果流程

2026-10-09。依据用户提供的37页企业手册，重点核对第16、17、24、25、29页的文字与第16、17页界面。以下是产品设计分析，尚未新增对应功能。手册中的效率、质量与客户覆盖数字是企业自述；案例页标注为模拟演示，不能当作已验证的市场证据。

## 手册中可以确认的设计

- 第16页以研究目标和背景资料组织对话，旁边呈现结构化的研究方案、受访对象和访谈大纲。聊天产生可继续操作的项目内容。
- 第17页展示洞察报告、访谈材料与分析助手并列。文字强调按研究目的生成报告，结论可追溯到访谈原文，并可继续提问、调取材料。
- 第24页用多轮概念测试说明迭代路径。第29页的模拟案例强调保存历史、稳定格式和便于分享的重要性。这些可作为产品设计启发，不能据此声称真实客户需求已验证。
- 手册没有展示完整的通用图表编辑器、图表数据计算规则或文件版本合并机制。借鉴时应自行定义并验证这些边界。
- 第25页模拟案例的背景写“东南亚五国”，执行方式却列美国、加拿大、英国、法国、德国；文字中的手表/手环与配图中的戒指也未充分对齐。不能由这处展示材料推断真实项目表现，但它提醒我们：自动生成的成品需要检查全文对象、范围、数量和版本是否一致，排版完整不等于内容可靠。

## 对幕景最有用的转化

用户输入目标、资料和约束，系统将已有项目数据组织成对应阶段的成果。每份成果应能回答：给谁看、帮助做什么决定、依据是什么、哪些仍未知、修改后哪些内容需重核。

| 阶段 | 幕景应交付的成果 | 主要用途与数据来源 |
| --- | --- | --- |
| 开场定题 | 活动简报与待确认清单 | 目标、观众、交付范围、场地与预算约束；保留用户原文和确认状态 |
| 方案讨论 | 原图、平面、三维及设计说明 | 同一项目与版本；注明示意/实测、采用情况和客户意见 |
| 执行准备 | 时间表、人员分工、物料与预算表 | 使用已保存活动任务、岗位计划、取得记录和人工估算 |
| 现场交接 | 到货/归还差额、异常及责任清单 | 使用独立点验账册和工作单，保留证据与更正历史 |
| 收尾 | 目标与实际结果对照、问题及下一步 | 有记录的实际发生情况；未收集的到场人数、反馈或费用保持未知 |

同一成果可有屏幕预览、内部HTML、客户HTML和可编辑备份等出口。客户版本选择公开范围，内部版本保留人员、供应与执行记录。原任务、物料及账册继续作为数据来源，成果视图无需重复维护台账。

## 当前已有与尚缺

当前已有客户方案评审、完整内部活动交接、CSV/场景导出和可选V4图片/对应表单备份。完整30人演练已从同一项目生成客户与内部文件，并核验原记录保留。客户画面逐张确认，修改来源会使旧内容失效；导出的文件明确为冻结版本。

仍值得补齐的部分：

1. 在现有工作台保留可持续访问的成果列表和草稿，能找到此前版本、对应材料和用途。
2. 对话能明确指出本次正在编辑哪份成果，并将修改映射回相应项目数据；重要状态变化继续由人确认。
3. 报告中的数字与结论能点回具体任务、物料或点验记录，而非只提供一段不可核查的总结。
4. 原数据变化时标明哪些成果需要更新。用户可重新生成新版本，保留旧冻结文件供追溯。

## 先做什么

优先统一已有“客户评审”和“内部交接”的成果入口、草稿保存与来源说明，复用现有评审快照、导出函数和项目存储。聊天保持独立，点选成果在工作区预览；未定的Figma功能标签仍保留为讨论内容。随后再从真实任务生成时间表，从点验账册生成数量差额图，并验证修改、保存、刷新和旧版本行为。

演练例子：规划30席；自有10把只是未清点的取得计划；租赁约定20、实收18、归还18。图表应清楚显示租赁仍未收2件、实收范围未退0件，不能推断当前可用库存为28、物料整体完成率为90%或合同已结清。预算同理：已知估算1000.50元、另1项金额未知、假设上限5000元，不能把相减所得当实际余额。

验收应使用同一真实项目数据：保存和重开不丢草稿；图表与原记录数值一致；未知不转成0；点击来源能定位；修改尺寸或点验后旧成果显示需更新；客户版本不自动带内部记录；分享或导出是用户明确执行的动作。实际图表生成、成果库和对话编辑能力尚待实施，不在本分析中宣称完成。
