## 2026-11-07 参考作品复核与路线纠偏（优先于早期方案）

用户否定卫星滤镜与挤出白模的视觉质量：目标是原帖那种细节丰富、真实城市结构可认的等距城市画风。可旋转和建筑数量不构成视觉验收通过。city3d.html 仅作坐标与体块技术验证，不视作参考效果交付。

本轮通过 Chrome 实际打开 Isometric SF，截图保存 D:/Scendance2026/hangzhou-map-lab/reference-site.png，并读取作者制作说明：https://www.justinchavez.com/blog/isometric-sf/ （2026-11-04）。作者说明以 Google 三维影像同视角渲染为基础，再做风格化绘制；45 张风格目标经 Qwen 编辑模型训练与蒸馏到 Klein，最终生成大量图块，并通过中心裁剪、边缘融合和邻块色彩校正拼接。这里的网页展示是等距绘制瓦片，不能因为画面立体就当成自由旋转的完整三维模型。早期文档没有充分核对真实三维输入，实施时误把 OSM 挤出当成最终画风。

杭州实施先完成一个小街区的视觉样板：
1. 选择西湖东岸一块可核验范围，保存原始卫星、建筑轮廓及固定斜视相机，记录输入来源。卫星图提供位置与屋顶纹理，不能单凭它恢复真实立面与高度。
2. 核查杭州可获得的真实三维、倾斜摄影或自采重建数据覆盖。不能假定 Google 在杭州有同等三维覆盖。已有 AHOLO 近景重建仅在确认位置、尺度与覆盖后作为局部来源。
3. 用真实结构输入制作同视角城市插画样板，要求屋顶/立面/窗格、树冠、道路、岸线、阴影和统一色板；真实缺失数据与艺术补全分开标注。不能再用降采样滤镜代替风格化。
4. 与参考作品和原始地理输入并排验收：风格与细节、真实道路/岸线/地标不漂移、遮挡关系合理。视觉样板通过前不扩地图范围、不宣布主产品接入完成。
5. 若用户需要自由旋转的 3D，另做真实几何+多面材质路线；单幅 AI 等距图不能充当这种交付。固定等距地图和自由旋转 3D 分别验收。

当前未完成：合格的风格样板、杭州真实三维覆盖核查、地标误差量测和拼缝验证。当前原型不达最终视觉要求。
## 参考项目与可行性

用户发的是 Justin Chavez 的 Isometric SF。作者介绍它是一张可探索的湾区等距像素地图，使用 Klein 图生图模型在 Modal 上生成。公开页面支持地点搜索和分享。页面加载 Leaflet 与独立瓦片服务，公开元数据包含自己的网格、512 像素瓦片、分级加载和版本信息，`art_bytes` 为 10,826,012,576。原作者完整素材来源和生产配置尚未核实。 [作者原帖](https://x.com/jus10chavez/status/2118061137736671383) · [项目](https://isometricsf.com/) · [项目元数据](https://isometricsf.com/data/meta.json) · [瓦片配置](https://isometricsf.com/config.js)

**初步判断：杭州版有可行路径，适合成为 Scendance 的可切换城市概览底图。** 城市图用可重复的地理数据构建道路、岸线和建筑轮廓，再把视觉风格作为独立渲染步骤。地标、场地范围和进入实景的点击位置来自真实矢量坐标。现场摆放、量距、碰撞与真实点云继续走 Scendance 的场地锚点和米制空间。西湖现有岸线和景区边界文件可用于本地原型，发布前核实数据出处和使用范围。 [场地锚点方案](../20-场地资产地理底图提案.md)

| 路线 | 具体做法 | 小样要回答的问题 |
| --- | --- | --- |
| 确定性等距渲染 | 用道路、水面、建筑轮廓生成固定机位的等距图。建筑按已知高度挤出，未知高度可使用显式标注的视觉默认值。批量渲染并切图，先得到稳定版。 | 相邻街区能否无缝拼起来，西湖岸线和道路是否可认，已有资产能否回到同一锚点。 |
| 参考 Isometric SF 的图生图 | 在确定性图上用 FLUX.2 Klein 4B 做风格试验。固定模型版本、提示词与色板，给相邻块保留上下文，瓦片切分前先检查拼缝。 | 能否保留桥、湖岸和主要道路。记录合格率、重跑次数和单块实际成本，再评估扩到杭州的量。 [FLUX.2 官方代码与模型许可](https://github.com/black-forest-labs/flux2) |
| 可交互的 2.5D 矢量底图 | 离线截取杭州数据，使用分级矢量瓦片，在 MapLibre 中按样式挤出建筑。数据量上来后再验证 PMTiles 按需加载。 | 这条路线能保留真实轮廓、缩放和点选，也可作为像素图缺块时的回退。实测与现有高德交互的切换成本。 [MapLibre 建筑示例](https://maplibre.org/maplibre-gl-js/docs/examples/display-buildings-in-3d/) · [Overture 的 MapLibre 与 PMTiles 示例](https://docs.overturemaps.org/examples/build-a-map/) |

数据试验先使用现有西湖文件，并评估 OSM/Geofabrik 在杭州的路网、水体、建筑覆盖率，量出建筑高度缺失比例。把来源、时间、坐标系、署名和许可写进数据清单。公开发布前分别核对原始数据、派生瓦片和底图服务的使用条件。国内高德坐标为 GCJ-02，外部地理数据接入时在既有边界做一次显式转换。 [Geofabrik 中国数据](https://download.geofabrik.de/asia/china.html) · [OSM 数据许可](https://www.openstreetmap.org/copyright) · [高德坐标说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/basetype)

## 独立仓库与主项目的接缝

- 实验仓放数据范围配置、来源清单、渲染脚本、瓦片构建、独立预览和验收用例。原始数据和大瓦片放独立数据目录。小样跑通并明确仓库归属与可见性后，再建 GitHub 仓库。
- 接入物先定义为一份有版本的 manifest，记录覆盖范围、坐标系、地图投影、瓦片矩阵、缩放级别、瓦片入口、署名和场地锚点索引。主项目用稳定的场地 ID 找现有 `sceneAnchor`，版本切换不改已有场地存档。
- 等距图有视角和遮挡，先接为城市概览视图。若要在现有 Three.js 场景地面直接铺图，另外输出北向正射、可按地理范围定位的图层。验证岸线与锚点能对上后接入场地。
- 高德继续承担地点检索和常规地图交互。切换像素图时保持搜索结果、选中地点和场地进入动作一致，超出样片范围时回到已覆盖的地图视图。

## 派给其他 AI 的验证顺序

| ID | 要交付的结果 | 通过条件 |
| --- | --- | --- |
| HZ-01 | 西湖东岸约 1–2 km² 样区输入清单，含至少一段岸线、一条主要道路和三个易辨地标。 | 能复现获取或裁剪步骤，能追溯许可和坐标系。抽查湖岸、道路、建筑、高度的覆盖缺口。 |
| HZ-02 | 独立预览中的确定性等距样片和两级缩放。 | 至少 2×2 相邻瓦片可平移和缩放，岸线道路不跳变。记录构建时间、瓦片大小和首屏实际请求量。依赖 HZ-01。 |
| HZ-03 | 对同一块样区做图生图 A/B。 | 对照三个地标和相邻块边缘，记录形变、接缝和重跑成本。若地标变形导致点位错读，保留确定性版继续接入。依赖 HZ-02。 |
| HZ-04 | Scendance 内部接入样片预览。 | 用 manifest 加载样片，核对三个地标的图面位置，报告误差。选中一个地点能进入已存在的场地锚点，返回概览后保留选中项。样片之外能回退。依赖 HZ-02 和 HANDOFF 的 MAP-04。 |
| HZ-05 | 扩展决策。 | 按实测瓦片密度和通过率估算西湖及杭州目标范围的生成时间、存储和流量，注明预算前提。达到 HZ-04 后再确定城市覆盖范围和独立仓库发布方式。 |

本轮完成资料核查和可执行方案。杭州瓦片、样区浏览器性能和 Scendance 接入还需要用 HZ-01 至 HZ-04 实测。
