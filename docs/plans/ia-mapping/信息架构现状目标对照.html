五个必须先拍板的风险点

1 · Binggo 命名与归属回归

现在 Binggo 挂着最成熟的 AI 链（DeepSeek 策划 + 腾讯 HY-3D 生成，经 proposals/apply 做租约 / 哈希 / 修订校验后回写画布）。把名字还给审校、主对话另立，须保住这条校验回写，回归成本不低。

2 · 审校闭环当前断裂

现评审是「制作者截图 → 导出只读 HTML 包」，客户只读页没有任何评论入口；全库无锚点钉点、意见线程、已解决状态与回流台账。这正是「能钉评」本意缺失的部分，是补回而非微调。

3 · 异层范畴不要平级人格化

活动是容器、审校是动作、空间 / 物料是两类资产。用面板 / 模式 / 库等不同 UI 原语区分，真正接 LLM 的才叫 agent，从根上避免为对称而生造聊天窗。

4 · 多智能体成熟度不足

后端现状是「一次 JSON 生成 + 最多一次修复，未接 Harness」。先把单 agent 的多步工具调用与状态机做扎实，等真出现并行 / 异步硬需求再上任务编排，不提前建调度台。

5 · 成员协作上层尚未建

成员面板目前是明确标注的虚构 demo；真实存在的是 Supabase 工作室 / 编辑权租约 / 只读分享这套权限底层。成员直达、在场、待办属于在底座上的新增，建议后置，勿当成已有功能。

技术名词先澄清，避免据错误前提排期

全库（含全部 git 分支与同级目录）大小写不敏感检索，以下词零命中：「总控 / 分派 / 左轨 / 门洞 / Aholo / Lux3d / MemberChat / 高斯」。它们来自尚未入库的设计稿，不是已实现模块。代码里真实的生成链路是 腾讯 HY-3D 单体 mesh 生成（generated-model-library），场地重建走的是 图纸 / 照片 floorplan（reconstruction-panel），并不存在高斯 / 世界模型管线。物料与场地在产品上可分库，但当前就同一条后端管线，无需先造第二套生成故事。
