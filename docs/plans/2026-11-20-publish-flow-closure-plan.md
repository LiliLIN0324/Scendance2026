## 2. 问题清单

「代码确认」表示实现中存在该缺口；「待复现风险」表示代码缺少保护，但本轮未观测到实际错误结果。

| 编号 | 级别／证据 | 断点与影响 | 改进要求 |
| --- | --- | --- | --- |
| PUB-01 | P1／代码确认 | 用户称入口为发布，实际按钮标为分享，默认进入评审分享；用途难辨 | 统一入口名称、提示和页内动作名称，明确评审、发布、案例与导出的用途 |
| PUB-02 | P0／代码确认 | 登录、关联项目、未保存、缺资源等多在点击后报错 | 打开发布页即预检，呈现可读状态与阻塞清单 |
| PUB-03 | P0／代码确认 | 错误要求用户自行去登录、保存或账户归档，没有直接恢复动作 | 阻塞项带处理入口，完成后回到原项目发布流程并重新核对 |
| PUB-04 | P1／代码确认 | 普通发布、完整只读链接与离线快照并列，内容和撤销语义不同 | 默认对客发布收敛为一个明确主路径，保留旧链接兼容；离线快照作为补充导出 |

| PUB-06 | P0／待复现风险 | 预检、归档、发布及离线快照多次读取可变状态 | 捕获项目与版本上下文；每个等待点后校验，确保交付来自同一快照 |
| PUB-07 | P1／代码确认 | 已发布页无发布当前新版入口，也不展示当前修改是否已发布 | 显示已发布版本与未发布修改；可发布新版，旧版保持独立 |
| PUB-08 | P1／代码确认 | 普通链接恢复依赖本机缓存；完整链接令牌仅存内存，缺统一记录管理 | 服务端记录为状态真源；刷新、换设备后可管理和撤销，不能假装能恢复令牌 |

| PUB-10 | P1／代码确认 | 多动作共用 busy 和 notice，页签切换可能误显示其他任务进度 | 状态按任务和项目隔离；展示具体阶段、失败原因与重试动作 |
| PUB-11 | P1／代码确认 | 完整页提供户外示意与资源链接，但归档文件存在不代表已在 3D 中还原；普通与完整页清单能力不同 | 发布摘要与客户实际呈现对齐，逐类核对场地、设施、模型、附件与缺失项 |
| PUB-12 | P1／代码确认 | 页签只有选中态与 tabIndex，缺方向键导航；弹层缺进入／返回焦点处理 | 补键盘导航、焦点恢复、关闭机制及屏幕阅读器关系；实测窄屏和短屏 |
| PUB-13 | P2／代码确认 | 导出动作触发即关闭，部分回调无结果反馈 | 导出有进行中、完成、失败和重试；选择导出范围时绑定明确版本 |
| PUB-14 | P2／待复现风险 | 评审权限开关与已生成链接并列；Bingo 行叫送到但动作是打开审校台 | 标明权限变更何时生效；核对并统一进入、送出、待评与回执语义 |

## 3. 目标流程与产品规则

### 3.1 标准路径

1. 打开发布：显示活动名、保存状态、最近发布版本及当前是否有新修改。
2. 执行预检：服务配置、登录、云项目、编辑权、保存进度、版本冲突、资源归档与场景转码。
3. 处理阻塞：提供登录、保存云项目、保存当前修改、补传资源、处理冲突或取回编辑权的明确入口。
4. 返回后重新检查：保留项目与发布意图；登录或上传完成不自动对外发布。
5. 展示发布摘要：场地、楼层、分区、路线、设施、模型、附件与对外可见范围；缺失项如实列出。
6. 用户点击发布：固定本次项目、版本与快照，按阶段反馈归档、创建发布、取得链接的进度。
7. 成功后交付：显示版本和时间，支持打开客户页、复制、二维码及管理发布记录。
8. 后续编辑：标记当前修改未发布；可创建新版，保留旧版内容与撤销能力。
9. 撤回：按具体 shareId 操作，明确影响范围；成功后同步记录、链接行和二维码状态。

### 3.2 发布方式与兼容

- 建议以完整受控分享作为默认主路径；实施前先核对普通发布与完整分享的内容、权限、清单、性能及撤销能力，补齐差异后再切换，不能只隐藏旧按钮。
- 已发普通链接继续按原语义读取和撤销；不静默改写为新类型。
- 离线快照不作为受控发布成功的替代品，生成失败不否定已经成功的云端发布。
- 官方案例继续使用平台管理权限，与普通用户对客发布区分；能力判断依据真实授权，不只依据是否传入 controller。
- 不新增并行 wire schema；后端契约以现有共享 domain、cloud-storage-contract 与 scene-client 为准。

### 3.3 内容与权限

- 明确发布的是当前方案、哪些楼层／设计版本以及哪些资料，不默认为所有可读资料都应公开。
- 当前 toPublishedManifest 会将依赖统一转为 published 可见性。实施时核对其是否符合发布摘要与用户选择；保留 sources 的既有私有边界。
- 受控撤回只阻止后续访问，无法收回已载入或下载的内容；离线副本不可远程撤回。
- 无法完整呈现真实扫描背景时，明确标为示意或提供受支持资源入口，不用占位背景冒充真实场地。

## 4. 状态、失败与一致性约束

| 状态 | 界面行为 | 继续方式 |
| --- | --- | --- |
| 检查中 | 显示正在检查保存与资源，不提前声称就绪 | 检查结束后显示就绪或阻塞清单 |
| 有阻塞 | 保留摘要，每条问题可操作 | 处理后原地重查 |
| 可发布 | 显示本次发布内容与版本 | 点击发布 |
| 发布中 | 显示具体阶段，避免重复提交 | 等待结果；不把关闭弹层当作服务端取消成功 |
| 已发布 | 显示版本、时间、链接与交付动作 | 复制、预览、管理记录 |
| 有新修改 | 区分当前草稿与已发布版本 | 保存后发布新版 |
| 结果待确认 | 请求超时但可能已经成功，不直接断言失败 | 读取服务端记录核对；按能力决定安全重试 |
| 发布失败 | 保留草稿与已知成功阶段，展示原因 | 从失败阶段恢复，避免重建已有发布 |
| 已撤回 | 隐去有效链接交付操作，保留历史状态 | 可创建新的发布 |

实现必须遵守：

1. 异步动作绑定 projectId、活动／会话身份和对应 revision；等待后重新核对。切换项目不得串状态、缓存、二维码或回执。
2. 归档清单、场景、户外规划和离线补充产物来自同一份明确快照；校验 gate 与当前项目、版本一致，不能只检查依赖 complete。
3. UI 防重复点击之外，还需核对接口幂等能力。一次请求的重试复用同一逻辑操作身份；新发布与恢复请求不能混为一谈。
4. 服务端成功、剪贴板失败应显示「发布成功，复制失败」，不能诱导重复发布。
5. 服务端 token 只返回一次时不能从哈希恢复原链接。跨设备仍可管理记录；丢失令牌时提供明确的新建／撤销路径。是否本机持久保存链接需统一策略。
6. 关闭、切页和刷新后的任务恢复以实际能力为准；不提供没有取消能力的“取消发布”假动作。

## 6. 验收矩阵

准备一份固定代表性方案：有项目身份、户外边界与分区、路线、设施、至少一个真实模型和一份附件；另准备室内多楼层方案。记录基线数量、尺寸与资源来源。合成模型只能验证传输，不算真实扫描还原证据。

| 用例 | 操作 | 必须观察到的结果 |
| --- | --- | --- |
| V01 | 未登录进入发布，完成登录后返回 | 回到原项目；重新预检；未自动发布 |
| V02 | 本地草稿首次保存云端后发布 | 关联真实云项目，版本可信，草稿保留 |
| V03 | 有未保存修改时发布 | 明确保存动作；保存完成后核对本次版本 |
| V04 | 存在本机模型、扫描或附件未归档 | 列出缺口、可补传；恢复后内容完整，无本机代理引用 |
| V05 | 上传中断、保存失败、配置缺失 | 不虚报成功，保留内容，错误有明确恢复方向 |
| V06 | 云端版本冲突或编辑权被收回 | 阻止错误发布；处理后重新检查授权与版本 |
| V07 | 预检／上传／发布中切项目或工作室 | 旧回执不出现在新项目，不写错缓存，不撤回错项目链接 |
| V08 | 发布等待中继续编辑户外或室内方案 | 发布固定捕获版本或明确中止；摘要与客户页不混版本 |
| V09 | 双击发布；超时但服务端已完成后重试 | 不产生非预期重复发布；可辨认既有成功记录 |
| V10 | 发布完成后修改并发布新版 | 版本差异清楚，旧链接仍为原版，新链接对应新版 |
| V11 | 拒绝剪贴板权限，令二维码生成失败 | 发布仍算成功，可手动取得完整地址，二维码错误可恢复 |
| V12 | 关闭面板、刷新、清理本机缓存、换设备 | 服务端记录仍可管理；令牌不可恢复时明确说明 |
| V13 | 手机匿名打开完整方案，核对室内／户外数据 | 数量、位置、尺寸、楼层范围、附件与发布摘要一致，无编辑控件 |
| V14 | 模型失败、资源授权到期，再刷新资源 | 明确缺失及重试；不会继续把失效资源标为可访问 |
| V15 | 撤回链接，再匿名重新访问；另打开离线副本 | 受控入口拒绝新访问，当前页清理内容；离线副本边界说明真实 |
| V16 | 调整评审权限后复制旧链接与生成新链接 | 生效规则与界面一致，意见／回执正确归属原方案版本 |
| V17 | 进入 Bingo 并完成评审反馈 | 进入与送出状态一致，客户反馈能返回对应方案 |
| V18 | 导出效果图、清单、几何文件、演示稿 | 有结果反馈；内容与所选版本一致；无回调或不支持时不伪造成功 |
| V19 | 键盘操作、390px 手机、短屏打开面板 | 页签可导航，焦点可进入／返回，操作与错误不被遮挡 |
| V20 | 普通成员、只读成员、平台管理员分别使用入口 | 权限说明与服务端结果一致；案例管理与普通发布不混淆 |

## 7. 验证与交付规则

- 先用 V07、V08、V10 各取一个代表性复现，定位第一失败步骤，再扩展相关回归；避免先跑全仓测试掩盖主链断点。
- 固定数据与模拟接口验证状态边界；真实浏览器验证交互；真实云端验证保存、内容覆盖、记录与撤销。报告分别标注，不互相替代。
- 实施期间运行相关测试；前端阶段收口执行 `npm --prefix frontend run typecheck`、`npm --prefix frontend run build`，按改动补 lint。涉及共享客户端或后端时补根 typecheck、相关测试与现有 edge 检查。
- 截图、日志与分享 URL 避免泄露令牌、签名资源地址或账号凭据；测试发布记录按获授权范围清理。
- 不改无关文件，不覆盖其他任务工作树；数据库、Edge 契约、根依赖与治理变更须按仓库约定提交人 review。本文不授权部署、tag 或 release。
- 第一阶段完成判据：P0-A、P0-B 与新版发布主路径通过；完整完成判据：本矩阵所有适用项有证据，不适用项说明原因，未覆盖项不得标为通过。
