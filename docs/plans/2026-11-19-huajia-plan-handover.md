## 一、这份东西是什么

一份**可直接在幕景里打开的户外规划起稿**：真实场地锚点、真实草坪边界、真实分区、真实动线、真实物料（含 37 件 aholo 生成的婚礼物料）。

- 规划数据本体：`frontend/public/huajia-plan.json`（126 KB，已过幕景自有契约 `sitePlanDataSchema` 校验）
- 物料清单与库内缺口：`docs/plans/2026-11-19-huajia-material-bom.md`
- 「零照片链路」文案与体验断点：`docs/plans/2026-11-19-zero-photo-lane.md`
- 一键载入页：`frontend/public/huajia-loader.html`

**读数**：11 个分区 / 188 件设施（其中 103 件是本轮生成件，85 件是物料库既有件）/ 4 条动线 / 4 个出入口 / 10 个岗位 / 4 块建筑禁区。

## 二、怎么打开（两条路）

### 路 A：幕景内「找回云端活动」（推荐，换设备也能用）

规划已经写进丽丽账号的云端活动表（`scene_private.outdoor_plans`）。在**这台设备还没有本机草稿**时打开幕景首页，会弹出「云端有你之前的活动」，点「打开」即可载入并直接进画布。

> 前提：这台设备的 localStorage 里没有 `scendance-outdoor-last-v1` 指针。
> 如果幕景已经在用中、没弹这个框，走路 B。

### 路 B：一键载入页（同一台设备上用）

正式站：`https://scendance.lilicoding.space/huajia-loader.html`

点「一键载入这份规划」→「打开规划」。它把规划写进本机 `scendance-outdoor-plan-v1:house-huajia-wedding-2026`，然后跳到 `/?project=house-huajia-wedding-2026&mode=outdoor`。

**已存在同名草稿时会先弹确认**，不会静默覆盖。

### 可核（有出处）

| 事实 | 出处 |

| 1 号楼（桂香园/仙子厅）局部坐标 (23.3, −52.3) | 高德 POI「杭州花家山庄」点位 + 局部 ENU 换算 |
| 大堂 (5.3, −50.6)、中餐厅 (16, −54.7)、会议厅 (7.5, −53.1) | 同上 |
| 宿舍楼 (90.5, −72.3)、杜鹃楼 (−81, −135.6)、水仙楼 (−148.5, −25.9) | 同上 |
| 停车场 (135.2, 86.1)、停车场出入口 (168.6, 163.2)、雅谷泉 (72.4, 140.5) | 同上 |
| 主草坪 1449 m²、其北侧草坪带 1951 m² | OSM `leisure=grass` 真实多边形（WGS-84 → GCJ-02 → 局部 ENU） |
| 滴翠湖 2574 m²、乌龟潭 1915 m² | OSM `natural=water` 真实多边形 |
| 仙子厅 26×18 m、层高 7.5 m、450 m²、无柱无窗、约 30 桌 | 两处公开来源一致 |
| 园区约 158 亩、绿地 95%+、「一湖三楼八景」 | 官方/媒体公开资料 |
| 游 2/游 5 线「赤山埠」站往回 20 m，前行 500 m 到场 | 官网交通指南 |
| 西湖景区单双号限行；停车免费 | 官方/媒体 |

### 待核实（**规划里已如实标注，没有编**）

1. **草坪面积三套口径冲突**：官方 1500 方 / 腾讯 1500 方 / 婚芭莎 600 方 / 2015 杭州网 1200 方。OSM 几何给的是 1449 m² 与 1951 m²，和哪一套都不严丝合缝。**规划里这两块标的是 `map-unverified`（地图来源、未核实），不是"已确认"。**
2. **两片草坪的归属关系**：哪一块真正做仪式区、哪一块做席位区，需要现场走一遍定。
3. **官方平面图**：查不到。建筑轮廓只能用高德 POI 点位摆占位矩形，**不是实测轮廓**。
4. **禁喷花 / 明火 / 雨天预案条款**：查不到。
5. **非合作婚庆入场费 5k、LED 屏 4k**：公开信息，需与场地方书面确认。

**建议 aholo 生成 2 条**：乐队台/DJ 台、草坪地插灯+追光灯+花球吊点横杆。
**aholo 已覆盖但静态库仍空缺 4 条**：白木椅、香槟塔/甜品台、桌花/席位卡/桌号牌/烛台、婚宴风签到背景墙/签到台。

**待补 1 条**：儿童餐椅。

### 5.3 尺寸偏差（18 条，备料前必须以 GLB 实测为准）

最影响排位的几条：

| 物件 | 提示词 | 实测 | 影响 |
|---|---|---|---|
| 婚礼圆桌 | 直径 1.8 m | **1.20 m** | 25 桌只能坐约 200 席，不是 250 |
| 婚礼落地花瓶 | 高 70 cm | **0.28 m** | 实为地面花器，不是落地瓶 |
| 婚礼餐盘 | 盘 | 高 **0.997 m** | 刀叉竖插，属几何缺陷，建议重生成后再公开 |
| 婚礼签到台 | 1.8×0.6×0.75 m | 1.80×0.92×1.15 m | 台面偏深偏高 |
| 婚礼白纱幔 | 2 m 宽 | 3.00×1.94×3.46 m | 尺寸大于提示词，摆放需重算 |

> 根因：aholo 产物**没有绝对尺寸**，尺寸是按 GLB 包围盒反推的，比例随参考图走。
> 图生 3D 的通道**根本不把提示词发给 aholo**（`supabase/functions/_shared/providers.ts:73` 只有文生通道传 prompt），所以改提示词对图生无效。

## 六、这一轮我做了什么 / 没做什么

### 做了什么（可核）

1. **37 件婚礼物料全部生成、公开、入库，并 37/37 带预览图**；其中「婚礼签到台」走**文生 3D** 一次成功（实测 1.80×0.92×1.15 m），因为图生通道两次失败。
2. **花家山庄规划起稿**：11 分区 / 188 设施 / 4 动线 / 10 岗位，过自有契约校验。
3. **规划同时写进丽丽账号云端** + 提供同源一键载入页。
4. **零照片链路的产品化文案**与 6 条体验断点清单（P0×3、P1×2、P2×1）。
5. **物料 BOM**：149 行清单 + 18 条缺口 + 18 条尺寸偏差。

### 没做（**刻意没做，不是忘了**）

1. **真实 DEM 地形**：本轮不做。第二档，需要接 AWS Terrain Tiles + 户外 3D 位移网格。起稿用的是平台自己的底图。
2. **不自动重派付费请求**：失败件不自动重试。aholo 失败仍是黑盒（`status:4`，零原因字段），失败 0 扣分。唯一一次重试是你点头的签到台换图，已用掉。
3. **不动数据库迁移 / Edge Function 契约 / 根依赖 / CI**：本轮只新增数据与文档，没有改契约。
4. **不做室内设计**：仙子厅只留作雨备退路。
5. **不编**：官方平面图、两片草坪准确边界、禁喷花/明火/雨天条款、精确经纬度权威来源 —— 查不到就写"未查到"。

### 还需要人拍板的

| 事项 | 谁定 |
|---|---|
| 两片草坪各做什么用 | 现场走查（丽丽 + 场地方） |
| 宾客席位数（按 250 席还是 300 席上限的 80%） | 丽丽 |
| 白绿系 + 金的具体色值与花材清单 | 丽丽 |
| 非合作婚庆入场费 5k / LED 屏 4k 是否适用 | 场地方书面确认 |
| 库内缺口 8 条采购 vs 生成 | 丽丽 + 终树 |
| 婚礼餐盘几何缺陷是否重生成（会再花 20 分） | 终树点头才做 |
