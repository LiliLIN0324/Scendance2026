# 圈画保存断点 · 根因与修复记录（P0-1）

2026-11-08 · 对应 [平湖秋月场地流程](../../HANDOFF.md#场地规划与实景采集) 的圈画保存。

## 断点现象

平湖秋月首轮实测（codex 现场截图见 `~/.codex/visualizations/2026/11/08/01a1ba55-325e-7e61-a367-a360d44b79c4/`）：

- `02b-boundary.png`：搜索「平湖秋月」出联想，能定位到孤山路一带；「圈画场地」「画主客流线」「生成户外场地」三个按钮中，后两个是灰的。
- `02c-close-attempt.png`：卫星图上多边形已经画出来了，但「生成户外场地」**仍是灰的**，边界没有保存。
- 计划原文记录：「本轮尝试闭合后『生成户外场地』仍是灰的，未保存边界。根因待复现。」

## 根因

`amap-venue-picker.tsx` 把「圈画是否完成」整个押在高德 `MouseTool` 的**隐式 `draw` 事件**上：

```ts
mouseTool.on('draw', (data) => { ... setBbox(...) ... });
```

这条链路有三个问题：

1. **完成动作不可见。** `MouseTool.polygon()` 只在「双击」或「回到起点闭合」时抛 `draw` 事件。用户看不到任何「完成」控件，只能靠试；一旦这次闭合没被 SDK 认下，事件不抛，`bbox` 一直是 `null`。
2. **失败无原因。** `bbox` 为 `null` 时「生成户外场地」只是灰着，界面不区分「还没点够」「闭合失败」「轮廓退化」——三者对用户是同一个表现。
3. **无法纠错。** 点错了没有撤销入口，只能清空重来；点得太近会产生重复顶点，把双击闭合的第二下也吃成一个点。

按钮的禁用条件是 `disabled={!bbox || busy}`，所以 `bbox` 不置位 → 按钮恒灰 → 无法保存。这是「闭合后仍灰」的直接机理。

## 修复

### 1. 圈画改为自收点 + 显式闭合

不再用 `MouseTool` 的绘制模式，改为在地图上监听 `click` 自己收顶点（`drawingRef` 记录当前在画边界还是流线）：

- 每次点击追加一个顶点；**离上一个点太近的点直接忽略**（`MIN_VERTEX_GAP_M = 0.5 m`），双击闭合的第二下因此不会多出一个点。
- 顶点数达到条件后，界面出现**常驻可见**的「完成圈画」按钮（不足 3 个点时禁用，同时进度行写明「至少 3 个」），不用用户去找完成入口。
- 「撤销上一点」随时回退最后一个顶点；「放弃」清空本次草稿。

### 2. 无效轮廓给具体原因

新增纯逻辑层 `frontend/components/room-organizer/lib/venue-drawing.ts`，判定不依赖地图 SDK，可脱图单测：

| 情况 | 判定 | 界面话术 |
| --- | --- | --- |
| 顶点 < 3 | `checkContour` | 「轮廓还没围住：至少要 3 个点，现在有 N 个。」 |
| 边与边交叉（自相交） | `polygonSelfIntersects` | 「轮廓自己穿模了（边和边交叉），圈画请按顺序描一圈。」 |
| 面积 < 4 m²（点挤在一起） | `polygonAreaMeters2` | 「轮廓围出的面积太小（约 N m²），点可能都点在了一起。」 |
| 顶点重合/过近 | `appendVertex` 拒绝 | 「这一点离上一个太近了，已忽略。」 |

### 3. 选址预览与保存分开

按 MAP-01「预览地点、取消搜索和确认写入锚点有明确区别」的要求：

- 搜索结果点击仍是**只挪图预览**，新增 `data-testid="venue-preview"` 行显式写明「选址预览：X · 尚未写入场地」。
- 真正写入锚点只发生在「生成户外场地」。
- 保存成功后该行追加「场地已保存」，预览态与已保存态在界面上可区分。
- 画到一半时「生成户外场地」禁用并提示「先把当前的圈画完成或放弃」——不让人存下半条边界。
