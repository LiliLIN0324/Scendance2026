## 0. 什么叫「值得托付」（而不是「画面合理」）

一个方案只满足「家具不重叠、通道能走人」远远不够。可托付要同时过四关：

1. **事实可信**：门在哪、尺寸多少、核定人数、固定障碍——每项事实都带来源和确认状态，推测的绝不冒充已确认。
2. **规则适用**：检查用的是哪本规范、哪个版本、适不适用这个地区/场地；不拿美国 ADA 数字当中国消防结论，不拿「研究论文能跑」当「现场安全」。
3. **活动真实**：不是静态家具堆砌，而是有人（观众/轮椅/工作人员）、有流程（签到排队、入场、观演、离场）、有时间（搭建/彩排/活动/撤场）、有资源（椅子库存、电源、装卸口、禁区）。
4. **责任可追**：谁确认的、改了什么会让哪些结论失效，交付包执行人员照着就能复述布置，出问题能定位到版本。

## 1. 成熟案例怎么用——不神化

| 来源 | 值得学 | 不能直接当结论 |
|---|---|---|
| FlairGPT | 功能区/物件/关系图、LLM→约束函数映射、分层优化 | 论文自报约束翻译错误、冲突、优化失败；**参数不匹配返回 0 会让约束凭空消失**，不能照搬到安全系统 |
| 多阶段生成/空间关系网络（arXiv 2506.22291） | 冲突感知、布局完整性 | 画面完整 ≠ 满足活动人流/消防/施工 |
| Co-Layout（arXiv 2511.12474） | 房+家具联合优化，避免先分区后摆不下 | 整数规划大场景算力/许可/时限必须先试验 |
| OpenAI grounded spatial reasoning | 机器可检查的布局描述、记录假设与修复点 | 示例能输出布局 ≠ 坐标可直接施工 |
| OptiScene / 偏好训练（2506.07570） | 用人工偏好改进排序 | 家居偏好不能迁移成活动现场安全判断 |
| Cvent 类活动 diagramming 商业产品 | 比例准确、座席图、协作、现场沟通 | 功能宣传 ≠ 它的每项自动化已被验证 |

**关键纪律**：研究系统证明「方法可行」，商业产品证明「交付形态」，现场反馈才证明「安全」。三者分开引用，不混为一谈。

## 2. 架构：一份可信事实 + 两个闭环（三层分工保留）

### 2.1 贯穿全流程的事实模型（Fact Record）

每项关键信息（门、尺寸、人数、固定障碍、电源、核定容量）都记录：

- **值与单位**：门宽 1.2m、位置与开启方向；
- **来源**：场地方图纸 / 现场测量 / 用户口述 / 模型推测；
- **状态**：`confirmed 已确认` / `pending 待确认` / `inferred 推测` / `unknown 未知`，必要时记测量误差；
- **版本与影响**：谁改的、何时改的、改动会使哪些检查失效。

铁律：**平面图识别出一扇门 ≠ 已确认出口**。它先是「图像推测」，场地方确认后才参与正式安全检查。信息不全时可以出探索草案讨论，但禁止据此给「动线通过」结论。

### 2.2 两个闭环

- **设计闭环**：理解需求 → 确认事实 → 编译约束 → 生成候选 → **独立验证** → 解释取舍 → 局部修改。
- **交付闭环**：冻结版本 → 场地方/执行方审阅 → 导出图纸与清单 → 现场核对 → 记录变更 → 回收实际结果。

**生成器与验证器职责独立**：生成器说「我找到方案」，验证器拿同一套事实和明确规则逐项复核。不能让生成过程给自己打分就当通过。

### 2.3 方案四态（每个方案必须落在一个状态上）

| 状态 | 含义 | 能否给客户 |
|---|---|---|
| 探索草案 | 允许缺场地信息，用于讨论，**所有假设显著可见** | 仅内部讨论 |
| 待核验 | 有布局，但关键事实或检查未完成 | 不可交付 |
| 已通过系统检查 | 列出实际通过的规则及版本，同时**列出未覆盖项** | 可内部执行 |
| 已由相关人员确认 | 记录场地方/负责人确认与对应版本 | 可交付 |

任何影响场地、安全、容量的修改，让相关确认**自动失效**，回落到待核验，而不是悄悄保留旧结论。

### 2.4 约束结果必须四值，不许「不匹配=通过」

每条约束检查返回 `pass / violated / unknown / not_applicable`：

- `unknown` 的关键安全项阻止进入「可交付」，并说明缺什么；
- 不匹配/无参数的约束绝不能静默返回 0 分（这是 FlairGPT 补充材料里的真实事故）；
- 对外永远说「已完成哪些自动检查」，不直接宣称「整体合规」；明确未检查项、适用地区、人工确认人。

## 3. 把「活动」真正放进模型（不止静态家具）

1. **人和流程**：区分观众、轮椅使用者、工作人员、供应商；建签到/入场/观演/休息/离场流程。签到台关键不是位置，而是**排队长度、队伍是否侵入通道、服务能力够不够**。初期用明确假设做容量估算，不假装精确人流仿真。
2. **时间**：搭建、彩排、入场、正式、撤场是不同状态。第一版先支持几个明确阶段及各阶段障碍物，后续再上动态模拟。
3. **施工与资源**：家具不是无限库存——有尺寸、数量、价格、供应商、供电、替代品；舞台/屏/灯/电缆/装卸口/禁区逐步纳入。生成时就提示「缺 12 把椅子」「需确认电源容量」，不是最后才发现摆不出来。

## 4. 阶段重排（v2）

| 阶段 | 交付目标 | 通过门槛 |
|---|---|---|
| **P0 可信底座** | 事实模型（值/来源/状态/版本）、规则版本管理、约束四值结果、方案四态 | 缺出口/比例尺时不能显示安全通过；未知规则不静默消失；推测门显著标注「门位置未确认」 |
| **P1 一个真实场景做通** | 选一个真实活动类型（如银发讲座），走完对话→场地确认→分组排布→方案解释 | 用真实场地+真实物料，从需求到可审阅方案；假设与不足全部可见 |
| **P2 可靠修改** | 对话修改、锁定对象、预览差异、撤销、独立复核 | 改动只在用户同意后应用；无解时说明冲突并给最小调整；改后相关检查自动重跑、旧确认失效 |
| **P3 交付版** | 版本冻结、平面图、尺寸、物料表、风险与待确认清单 | 没参与建模的执行人员仅凭交付包能复述布置；场地方能对特定版本确认 |
| **P4 活动流程** | 排队、人员路径、搭建/活动/撤场阶段、资源限制 | 在选定场景能识别静态图看不到的排队或阶段冲突 |
| **P5 优化与学习** | 求解性能、更多活动类型、偏好排序 | 先证明数据质量与人工基线；**偏好只影响排序，绝不覆盖硬规则** |

**近期最该做的不是更复杂求解器或 DPO，而是拿一场真实活动做纵向切片**：有图纸、明确人数和家具清单的银发讲座，从输入到场地方审阅走一遍，记录每一处需要人工补充的信息——先搞清楚缺的是算法、数据还是交付流程。

## 5. 验收：能证明「值得托付」的指标

保留 L1–L5（纯函数对抗 / 自由句理解 / 几何质量 / 端到端对话 / 线上行为），并补：

- **关键事实覆盖率**：入口/出口/尺寸/固定障碍多少已确认；不完整方案是否被正确标为待核验。
- **安全漏检率**：专业人员构造并标注的危险案例中漏多少；如实报样本量与置信区间——「测试集 100% 拦截」≠ 现实零风险。
- **无解解释质量**：人数/空间/通道冲突时，能否指出冲突并给用户可选调整，而不是悄悄删椅子。
- **局部修改可靠性**：锁定对象不动；差异与实际一致；撤销可恢复；过期确认被正确撤销。
- **现场可执行性**：让没参与建模的执行人员读交付包，检查能否找到物件、数量、尺寸、待确认项。
- **真实效果**：与人工方案比完成时间、现场返工、问题发现率、满意度；同时统计**放弃率与人工接管率**——不能只奖励「少说话、少移动」，用户因不可靠而放弃才是最大失败。

另外两条硬修正：
- 允许输出 **0/1/2 个方案**；场地太小时就说「实际只有一个可行方案」，无解时解释冲突并给最小调整建议，绝不硬凑三版假差异。
- 通行不是单一数字：通行净宽、转弯空间、会车空间是不同几何问题。1.5m 是保守设计目标，不替代完整无障碍规范判断；按中国规范/地方规定/场地要求建规则包，不套美国 ADA 数字；0.3m 网格 BFS 必须补「实体转弯能否通过」检查，并标注网格误差。
