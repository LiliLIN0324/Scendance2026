# 本地活动与场景服务连接

目的：同一活动在建立执行资料后，继续用助手规划空间、调整单件和处理图纸。本地活动编号不变，远端项目只用于场景处理；它不等于整场活动已经同步到云端。

## 数据与操作边界

- 本地保留需求表单、图纸表单及对应核对、任务、制作计划、物件工作单、方案历史与独立数量点验。发送给场景服务的是受现有契约校验的 Scene 和本次允许提交的需求上下文；图纸上传仍走单独确认的入口。
- 普通场景请求可能包含物件备注。单件材质处理不需要本地备注时清空请求中的备注，应用后保留本地原备注。任务、人员、供应方、估算和点验不会作为隐藏上下文提交。
- 绑定只保存版本、本地活动编号、远端场景项目编号、账号和服务地址，不保存令牌、编辑权或权限结论。重开后重新核对访问与编辑权；坏记录、失权或存储失败不会自动新建替代场景。
- 退出账号、连接失败或显式断开影响场景服务，本地草稿和执行资料保留。完整云项目打开/保存继续使用原有防丢失门禁。
- 本地任务与点验编辑不依赖远端场景编辑权。恢复备份或切换活动前先结束正在处理的助手任务，并释放当前场景连接；断开期间若有新输入则停止恢复。

## 候选与恢复

助手请求、图纸任务和材质候选用远端项目编号核对；应用结果仍合回原本地编号。场景、需求、身份、映射、编辑权或来源图片变化，旧候选必须失效。模型不得写入本地执行状态。

已有 Agent 或图纸任务在重开后只查询原任务，恢复连接不会重新付费生成。无法恢复原映射时明确停止，不把新项目伪装成原任务已恢复。

全局撤销继续按操作顺序撤销布局与任务编辑；数量事实不在布局历史中。AI删除物件后的一次撤销应恢复删除前布局和工作单。跨设计方案重新出现已删除物件时，工作单的最新记录恢复仍是单列问题，不能从任意旧方案回填并冒充最新事实。

## 验证状态

本切片已完成本地类型、单元/组件检查及独立浏览器联调。联调使用实际API处理器及PGlite、显式测试Auth/Storage和固定模型回复；不调用外部模型，不代表真实模型质量或真实云协作已经验收。


实际界面以30人假设活动为基线：固定候选把座椅右移0.1米，确认、撤销及备份读回均保持原活动编号、20条任务、需求、制作计划与20/18/18点验一致。准备连接和重新连接没有新增模型调用。原图选择及11×8×3米输入在重开后保留，原图仍是未完成对应核对的状态。

还通过实际参数化GLB和材质API制作并应用了独立材质版本。最终40件演练场景只改变1个模型资产引用，其实例编号、尺寸、位置、旋转、名称、图标、分组、备注及工作单均与应用前一致，其他活动资料未改。材质信息曾出现一次短暂读取失败，保留模型后手动重读恢复；服务保持运行，未通过重启掩盖结果。

实机发现并修复了人工创建矩形场地时重置物件名称/工作单/资产引用和地面样式的问题。11米宽场地、V2墙体与本地资料已通过实际备份读回核对。无材质槽的模型会明确提示并禁止创建无从修改的材质版本；有资产编号的物件属性指向材质工具，不再笼统声称不能改色。

场景连接恢复后，尚未载入的模型按资产编号重新授权并加载，不为加载模型发送整份活动或场景文字。换账号、换活动或断开连接期间返回的旧授权结果不用于当前场景。

验证批次包括11套443项整合检查，以及后续50项界面回归（有重叠，不累加）；完整类型检查和11页独立构建通过。构建来自明确暂存文件，不混入另一个后端Agent升级工作。正式云鉴权/存储、真实模型效果、双账号合作及真实活动仍需分别验收。
