## 可重现合成案例

案例 ID：`hall-d5-public-lecture-synthetic`。执行标记：`simulated`。没有联系场地方，没有现场执行。

构造活动是一场公开讲座，口述参加人数约 30。80 只出现在「我们有 80 把椅子」这句原话里。

| 账 | 身份 | 数量 | 来源 |
| --- | --- | ---: | --- |
| 口述 | `oral:unspecified-chair`，无规格 | 80 | 用户原话 |
| 场景模型 | `catalog:desk-chair-en`，0.49×0.57×0.90m | 100 | 目录模型，尺寸取官网英文页 |
| 场景模型 | `catalog:staff-chair`，0.45×0.45×0.90m | 26 | 另一椅型，用来阻止按总数轧差 |
| 核实库存 | 与课桌椅同身份、同规格 | 40 | 合成假定，证据写明不是现场盘点 |
| 核实库存 | 工作人员椅 | 无此行 | 可用数量保持未知 |

预期账本：课桌椅差 60 件；工作人员椅无法匹配，所以整本账是 `unknown`，不是通过。口述 80 不参与减法，也不变成人数。

平面与人工基线：

- 本版平面：19×15m，来源 `estimate`。
- 官网标称：16.5×17.2m、285㎡、层高 6.35m。16.5×17.2=283.8，与 285 不相等；这个差尚未向场地方核实，不能用来证明 19×15 更准确。
- 人工基线：官网课桌参考图 120 座，每桌 3 人，走道 1.2m，排距 1.4m，台前 5m。
- 既有摆放测试在估算矩形上的合成计数是 126 座，且没有舞台，也没有台前 5m。`compareSeatCounts` 记录相差 6，`calibration` 固定为否。

案例同时放入这些必须失败或保持未知的结论：

- 依据未知门宽写出的「疏散通过」变为未知或过期，不能留下通过。
- 讲台从 `podium-1` 换成 `podium-2` 时，即使仍有一件锁定讲台，保护核对也是违反。
- 交付记录含本版尺寸、官网标称、两类模型的身份和数量、假设、检查项、未核验清单和两条未执行任务。
- 调用方若把消防或现场库存写成通过，审核记录会改回未知。
- 清单含义固定为 `generated_not_procured_or_placed`。
- 冻结版本 1 后，只推进 `door_width` 的修订号，刷新结果为过期，过期键只有 `door_width`。

复现命令：

```bash
cd frontend && npx vitest run lib/facts/scenario-ledger.test.ts
```

既有摆放回归仍在 `frontend/lib/hall-d5-benchmark.e2e.test.ts`。本案例抄录它已经写明的 126，不重新摆放，也不把那次计数升级成实测。

## 缺口

1. 三本账还停在独立模块。对话里的口述库存仍是原话线索；场景清点在 `deliverable-inventory`；候选库存里的 `user_reported` 是用户填写的数量，不是核实库存。导出的场景 JSON 还没有这一份三列账。
2. `localPlan` 的脚本路径在未说明舞台时仍使用 `stage ?? true`。明确「不需要休息区」时，main 还没有旧补丁里的 `restNeed === false`：保留已有休息区并给出冲突，同时不自动删除。此项要和 03 一起改面板，本轮不动。
3. `raiseVenue` 在非首层、已有内墙或结构标记时仍会尝试换壳，地面颜色和图案也不随旧楼层保留。这是布置壳体行为，留待与场地交互一起改。
4. 冻结、刷新、恢复、撤销和过期分享已经各有路径，但没有共用一个事实版本令牌。可复用的现成路径是：评审包过期（`projectReviewIsStale`）、工作单和执行任务在场地变化后变为需复核（`review-fact-validity`）、审校钉评、活动执行表。资产签名 URL 过期只覆盖模型下载。分享链接本身尚未按事实修订失效。本轮纯函数只演示审核记录的冻结和刷新。
5. 门宽、开启方向、核定人数、消防、无障碍和真实库存仍待场地方与现场。公开网页、参考图和本案例都不能代替这些确认。
6. 椅子规格继续并存：英文页 0.49×0.57×0.9m，日文页 0.538×0.567×0.9m。目录尺寸不是现场型号。
7. 126 这个数字是从既有测试抄来的对照值。摆放算法若以后改变，本模块不会自动跟着变。
