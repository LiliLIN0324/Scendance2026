## 三、下一步任务拆解

### P0 · 跑通图生 3D 链路 + 精选婚礼道具（我方本轮主线）

**P0-1 先核额度与能力开关**

1. 登录云项目、拿到编辑权解除只读门禁；能力接口确认 `imageToModel` / `aholoImageToModel` 为真，并在平台侧核对剩余点数（用户口径约 **830 点**，以登录后实际显示为准）。
2. **计费口径（代码事实）**：内部账本 `reserved_cents/actual_cents`（分）只是幕景预留记账，生产 `limit_cents=NULL` 不限量，不挡生成；平台真实消耗走 `generation_jobs.provider_usage` 回填，`vendorError.no credits` 即服务商账号没额度。**代码内没有图生单件点数价目表，也没有余额查询接口**，单件扣多少点必须跑首件后从 `provider_usage` 回填读数，不能凭配置推断。
3. 未登录态面板能力表不加载，能力真假与额度不能凭配置文件推断，必须看接口返回。

**P0-2 精选道具清单与件数目标（按点数分批，不全量铺）**

> 件数不写死：先跑首件测出单件点数，再用剩余点数倒推后续批次；下方为优先级与分批框架。

- **基线批（先跑，跑通链路 + 每品类 1 件）**：仪式拱门/花架、路引花、桌花、手捧花、背景花艺，共 5 件；另起 1–2 件菊花/绿雕异形。
- **备选批（点数有余再追加）**：核心品类各补 1–2 个形态/配色；次选品类（签到台装饰、迎宾牌/合影框、椅背花与纱幔、甜品台摆件、指示牌花艺）择 2–3 类各 1 件。
- **止损线**：剩余点数低于预估两件成本时停止新提交；`failed/rejected` 且从未派发的不重跑，`submit_unknown` 响应丢失按代码现状不自动重派，先人工核对再决定是否重试。
- **先复用不生成**：植物、灯具、结构件、桌椅优先从现有 30 条 CC0 库挑（木椅/桌/签到台/展架/指示牌/盆栽/帐篷/遮阳伞/地毯）。
- 文生 3D 不跑；游戏风低模不选，口径要真实感。

**P0-3 图生产出与入库预检**

1. 参考图集按品类分文件夹（第七节映射表），图生模式：参考图 + 一句补充描述。
2. 产物异步任务：回执记任务号/请求号，完成后在历史模型面板取件。
3. 入库预检：kebab-case 文件名、中文标签与品类、占地宽深（米）、缩略图；GLB 2.0 头、原点接地、单位 +Y 上、无远程纹理/缓冲依赖；来源与许可按 `ASSET-SOURCES.md` 登记。
4. 不承诺实物颜色与价格；生成物件保留提示词备注。

**P0-4 批量工具增强（不阻塞手动跑件，产能不够再排）**：生成队列/一组多形态提交、入库预检脚本（复用现有 glb-validator / gltf-transform 工具链）。

### 生成过程可视化现状与增强（代码核对，2026-11-19）

**现状（事实）**

- 任务状态机 10 态：`queued 等待生成 / submitting 正在提交 / submitted 已提交 / processing 正在生成 / archiving 正在保存模型 / ready 模型已就绪 / added 已保存到场地 / failed 生成失败 / rejected 模型未通过检查 / submit_unknown 提交结果待核对`（`generated-model-library.tsx:13-18`）。
- 历史任务卡片：标题 + 一行中文状态 + 失败原因（供应商原话）+ 引擎与更新时间；`ready/added` 才出「加入场地预览」按钮。
- 活跃态任务每 **30 秒**自动轮询一次（`:109`）；提交中按钮显示「已提交，生成中…」并禁用。
- **没有**百分比进度条、预计剩余时间、阶段动画或骨架屏；`ready` 之前缩略图是空 `Box` 占位，不铺参考图。进度字段 `progress` 只在 Agent 任务契约（`agent-contract.ts:91`），模型生成 job 未接百分比。
- 线上 Pages.dev 旧构建比本地 main 落后：图生卡片无文字描述框（本地 `gs-field` 未同步上线）。

**可做的增强（建议，按「可视化卡片/可点控件、不堆文案」偏好；不阻塞本轮跑件）**

1. 卡片状态色态 + 图标：等待/生成中/保存中区分色与旋转指示，`ready` 亮缩略图，失败红条带原因；provider 不给阶段百分比时不造假数字。
2. 生成中卡片铺参考图缩略图（灰化 + 阶段标签），替代空占位 `Box`。
3. 活跃态轮询在 `processing/archiving` 阶段提速到 8–10 秒，并显示「上次更新 mm:ss」。
4. 提交卡片内联本次任务状态与任务号，不必翻到历史模型库才看到。
5. 若 provider 任务详情接口回阶段/进度，再接细粒度进度条；否则只展示状态枚举。

## 八、图生 3D 链路现状与阻塞（代码核对）

### 链路（事实）

1. 入口：创作面板「生成 3D → 图生 3D」tab；选参考图 + 一句补充描述 + 额度确认 checkbox。
2. 参考图上传：`accept="image/png,image/jpeg"`（`generation-sheet.tsx:467`、`generated-model-library.tsx:260`）；`mode=image` 必须带 `referenceId`，否则提示「先选一张参考图。」（`generation-sheet.tsx:197-199`）。
3. 能力探测：开面板后 `controller.getGenerationCapabilities()`；`anyConfigured` 取 `textToModel / imageToModel / aholoTextToModel / aholoImageToModel` 任一为真（`generation-sheet.tsx:168-169`）。
4. 门禁：未登录、能力未配置、只读项目三类都会挡住提交；只读文案「当前项目是只读状态，拿到编辑权后才能生成。」（`lib/model-generation.ts:126`，`writeBlocked`）。本轮截图底部橙字即只读提示。
5. 产物：异步任务，回执记任务号/请求号；完成后在历史模型面板取件，手动加入场地。

### 产品内闭环实操步骤（在 scendance 工作台内完成，不走 Aholo 手动跑）

目标：参考图 → 产品内图生 API → 回执取件 → 入物料库，整条链路在自己的工作台里闭环；Aholo 仅作场地/灵感参考，不在其 Studio 里手动生成。

1. **进项目拿编辑权**：账户中心选中自己的云项目 → 双击卡片取 lease；只读拦截文案消失即拿到写权限（已实测路径）。
2. **备参考图**：单主体、PNG/JPG、背景干净；现有小红书双拼/四宫格须先裁出单主体，带文字水印无法去除时在产物备注注明来源与非商用。
3. **提交首件测链路**：创作 → 图生 3D → 选图 + 一句补充描述（配色/材质/尺寸倾向）→ 勾「消耗额度」→ 提交。回执记录任务号/请求号/参考图 id；`submit_unknown` 不自动重派付费请求。
4. **读数与分批**：首件完成后从 `provider_usage` 回填读单件点数成本；按剩余约 830 点倒推可生成件数，分批提交；剩余点数低于预估两件成本即停新提交。
5. **取件**：历史模型面板轮询/刷新，任务完成后取件；核对预览、方位与主体。
6. **入库预检**：kebab-case 文件名、中文标签与品类、占地宽深（米）、缩略图；GLB 2.0 头、原点接地、单位 +Y 上、无远程纹理/缓冲依赖；来源与许可按 `ASSET-SOURCES.md` 登记。
7. **布进场地**：选件放入 `lawn` 预设，核对落地/轴向/尺寸；不承诺实物颜色与价格，保留提示词备注。
8. **状态分别汇报**：本地保存、mock 校验、真实云端验证分开记，不互相冒充；失败件与 unknown 单列，不记作通过。

### 13.3 只读门禁的真实成因（两条独立原因）

### 14.6 登录故障根因（**推翻此前判断**）

用户报错：「暂时无法连接登录服务」= `NETWORK_ERROR`（`frontend/components/intro/auth-card.tsx:67-68`）。

**此前记为「线上部署包内联 `http://localhost:9999` 导致 mixed-content 拦截」——这是错的，本章更正。**
`http://localhost:9999` 是 `@supabase/auth-js` 自带的默认常量
（`node_modules/@supabase/auth-js/src/lib/constants.ts:24` 的 `GOTRUE_URL`），只是未被覆盖的默认参数值。
线上包实际内联的是**正确的项目 URL**（`https://wkhfvnzgopjdzxlmycks.supabase.co`）与 **anon key**，配置本身没问题。

**真实根因是网络层：直连 `*.supabase.co` 被重置。** 分层实测：

| 层 | 读数 |
| --- | --- |
| DNS | `wkhfvnzgopjdzxlmycks.supabase.co` → `104.18.38.10` / `172.64.149.246`（Cloudflare） |
| TLS | 两个 IP 都 **ECONNRESET**（239 ms / 1225 ms），拿不到任何 HTTP 响应 |
| HTTP | `/`、`/auth/v1/health`、`/auth/v1/token`、`/functions/v1/scene-api/*` **全部 RST**（重试 3 次全失败） |
| 对照组（直连可达） | `supabase.com` 200、`api.supabase.com` 404（通）、`pages.dev` 200、`expo.dev` 200 |
| 对照组（直连不可达） | `cloudflare.com` 连接超时 |
| 走本机代理 `127.0.0.1:7897` | `/auth/v1/health` → **401**（= 服务健康，只是缺 apikey）、`scene-api/assets` → **401** |
| `curl --noproxy '*'`（强制直连） | `Recv failure: Connection was reset` |

**为什么浏览器也挂**：本机代理进程（`com.vortex.helper`，监听 `127.0.0.1:7897`）是活的，但
Windows 用户级 `ProxyEnable=0`（系统代理关着）→ 浏览器不读 `HTTP_PROXY`/`HTTPS_PROXY` 环境变量 → 浏览器直连 → 被重置 →
`signInWithPassword` 拿不到 HTTP 响应 → `NETWORK_ERROR` → 「暂时无法连接登录服务」。
（`curl` 之所以通，是因为它读环境变量代理；Node 的 `fetch` 默认也不读。）

**处置（本轮已做）**：打开用户级系统代理（`HKCU\...\Internet Settings: ProxyEnable=1`、`ProxyServer=127.0.0.1:7897`），
并广播 `InternetSetOption` 让运行中程序立即感知。**实测已恢复**：

- 线上编辑器重新加载后，`scene-api` 的 studios / assets / projects / outdoor-plans / members / sources / lease-acquire / lease-release **全部 200**；
- 6 张预览图被浏览器真实加载（`image/png`，200）；
- 应用自动弹出「打开云端版本会替换当前画布」确认框 —— 说明**云端会话已成功恢复**（此前拿不到这个状态）。

**回退方式**（若要关掉系统代理）：

```powershell
Set-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' -Name ProxyEnable -Value 0
```

> ⚠️ 代理软件一旦退出而系统代理仍开着，浏览器会连不上网。两者要一起开/关。

**治本方案（未做，需人决策）**：给 Supabase 项目挂**自定义域名**（不再走 `*.supabase.co` 共享域），
前端 `NEXT_PUBLIC_SUPABASE_URL` 改指自定义域。这能一次性解决「所有国内网络用户的登录/直连」问题，
但需要 Supabase 项目配置权限（Dashboard）＋一次前端重新构建部署。

### 14.11 「用户自己拍的照片能不能上传做图生 3D」——能做，但有四道闸

真正的卡点是四道闸门，全部有代码依据：

| 闸门 | 现状 | 依据 | 后果 |
| --- | --- | --- | --- |
| **HEIC 不收** | 只收 `png` / `jpeg`（`/assets/sources` 另收 `webp`），图生参考图只收 `png`/`jpeg` | `generation-input.ts:12`；`api.ts:747` | iPhone 默认 HEIC → **415 UNSUPPORTED_IMAGE** |

**16.6.1 为什么地形不能用 aholo 生成（尺寸实证）**

aholo 产物确实带 `bounds` / `sourceSize` / `groundOffset`（原点落在地面接触点，对定点摆放是对的），但**绝对尺度是按参考照里占的像素比例反推的**：

| 物料 | aholo 推算尺寸 | 实际 | 判定 |
| --- | --- | --- | --- |
| 婚礼香槟杯一对 | 0.156 × 0.230 × 0.074 m | ≈15.5 cm 宽 / 23 cm 高 | 对 |
| 婚礼刀叉组 | 0.23 × 0.355 m | 约 25 cm 宽 / 5 cm 高 | 高 3 倍 |
| 婚礼餐盘 | 0.27 × **0.997** m | 直径 27 cm，高约 3 cm | **高 33 倍** |

盘子在参考照里是斜拍的，包围盒把透视算了进去。**一个连餐盘高度都能差 30 倍的工具，不能拿来生成米级的地形起伏。**
产品文档里其实早有同口径：「Aholo 对我们是『道具工厂 + 人物动画外包』，不是『场景工厂』」（`docs/39:20`）；单图→3DGS 公开 API 2/2 失败（`docs/39:115-116`）。

**16.6.3 平台现状与接入点（代码取证）**

- 户外 3D 的地面与「地形」现状（**2026-11-19 子智能体复核后更正，原文把 `three/outdoor.ts` 当成户外地面是错的**）：
  - `three/outdoor.ts` 是**室内编辑器**的「郊区地块」（房子周围草地/人行道/沥青路/程序化树），只在**非**户外工作区建（`hooks/use-scene-effects.ts:1146` 的 `setOutdoorVisible(..., !outdoorWorkspace, …)`）。一进户外工作区，这一整层**根本不建**。
  - 真正的户外规划 3D 是 `components/outdoor-plan-3d.tsx`（接管态渲染），它的「地面」是**地图瓦片金字塔**（`three/plan-basemap-tiles.ts`，每级瓦片只差 4 mm 叠层）；没有地理锚点时才退化成一块 `PlaneGeometry` 纸面。
  - `three/terrain.ts` 的 `TerrainSpec { frontY, backY }` 是「房子挖山」的手工分段坡，**只在 `outdoor.ts` 里用**，与真实高程无关。
  - **结论：DEM 位移网格的落点是 `outdoor-plan-3d.tsx` + `plan-basemap-tiles.ts`**，不是 `outdoor.ts` / `terrain.ts`。
- **地理锚点换算已经现成**：`frontend/components/room-organizer/lib/scene-anchor.ts` 的 `anchorGeoToWorld(anchor, lng, lat)` 做地理→世界坐标（含 `orientationDeg` 旋转与 `metersPerUnit` 缩放），`sceneAnchorOf(layout)` 从布局取锚点。
- 户外 2D 侧坐标是 ENU 米（x 东 / y 北），见 `supabase/functions/_shared/site-plan.ts`；户外 3D 世界 = plan ENU 米制，**1 单位 = 1 米、不缩放**，`three.x = plan.x`、`three.z = −plan.y`。
- **DEM 落地的两个硬坑**（子智能体取证）：
  1. **坐标系必须先转**：Terrarium 是 **WGS-84**，而 `plan.anchor.crs` 固定 `'gcj-02'`（`site-plan.ts:28`）。杭州一带 GCJ 偏移实测 ≈ +0.0047° lng / −0.0023° lat ≈ **456 m 东 / 256 m 南**；不转则整块地形错位 500 m。转换用 `lib/geo-coords.ts:62` 的 `gcj02ToWgs84`。
  2. **规划层抬升只有毫米级**（`three/plan-footprint-builder.ts:31-47` 的 0.049–0.15 m，瓦片金字塔每级差 4 mm），DEM 起伏一旦超过几厘米就会与色块/物件/路线穿插 → **第一阶段只能做「视觉地形」，贴地联动是第二阶段**（要改 `ELEVATION`、`PLAN_LAYER_BASE_Y`、模型层与漫游眼高）。
