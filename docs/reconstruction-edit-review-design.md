# 重建候选人工修改：受控版本设计草案

状态：隔离实验，尚未接入应用，也没有数据库迁移。人工修改继续暂停。

每次修改创建独立版本，不复用计费任务记录。新表须保存项目、用户、父任务、项目修订与原始场景、父任务的候选和基线、来源快照、修改后的候选、完整修改前后值及确认状态。数据库事务必须锁定项目、父任务和版本，检查有效租约、成员权限、修订、来源和候选均未变化；由服务端生成差异，用户只能确认自己看到的确切版本。确认须一次性，重复请求可通过只读查询核对结果。修改结构后相关确认失效。

草稿创建和核对均不调用模型，也不创建或修改计费记录。后续生成必须通过新的受控事务将已确认版本绑定到计费任务；事务失败时不得留下一半绑定。旧接口须继续按原规则处理，不能通过旧确认路径绕过新版本核对。新增表、函数及权限须作为可审查的独立迁移，不能改动既有表结构。

`frontend/lib/reconstruction-edit-isolated-prototype.test.ts` 是实验代码，不是迁移或应用 RPC。PGlite 与独立 Docker PostgreSQL 17 实验已检查基线、父候选、差异和来源快照的部分变化被拒、确认重放被拒、预算表不变，以及 Docker 中并发确认互斥和中断回滚重试。Docker 使用本机镜像、无网络、无端口和持久卷，测试容器已清理。

开放前仍须补齐：真实来源资产存在性及所有权、完整 SceneV2 几何与结构状态验证、逐项可读差异及刷新恢复、可靠的确认结果只读查询、确认与计费任务创建的原子绑定、旧接口绕过、预算及日预算完整账务、真实并发与故障注入、权限/RLS 和部署兼容性。现有实验保存完整前后快照，并不等于已实现可读逐项差异，也未证明上述要求。

后续隔离实验增加了对真实 SceneV2 的无损解析和已实现的结构碰撞检查；候选编辑后将所有结构与尺寸状态降为推测，生成逐项中文标签及前后值。SQL 实验检查并锁定来源记录与资产归属，并允许重复只读查询版本。这些能力目前分别存在于纯函数和隔离 SQL，尚未形成不可绕过的服务端事务；完整几何正确性、生产权限、真实资产生命周期、可读差异刷新恢复及旧接口/计费任务的原子衔接仍未证明。这些验证结果还不能推断端到端可用。

最新实验在测试内组合了模拟认证服务端与 SQL：从数据库读取原候选，服务端执行 SceneV2 检查并生成候选与差异，SQL 仅授予 service_role，authenticated 不能直接执行；PGlite 用例覆盖畸形数据、身份拒绝与确认降级。更新后的 SQL 又在隔离 Docker PostgreSQL 验证普通客户端直调被拒、来源解绑被拒、并发确认互斥、中断回滚、重复查询和两类预算不变。Docker 测试直接验证了 SQL 原型；模拟认证服务端与 SceneV2 检查的组合目前仅在 PGlite 测试中运行。正式认证、service_role 密钥边界、旧 API 和确认至计费任务的原子绑定尚无实现；数据库本身并不验证完整 SceneV2。不得将此实验作为上线依据。

最新隔离原型另加入确认版本到原有计费任务创建的事务包装：只有确认版本且原场景、候选、来源等一致时调用原 RPC，随后同事务写入关联；重试必须匹配原请求。PGlite 与 Docker PostgreSQL 分别验证了未确认拒绝、事务中断回滚、并发同请求只创建一个任务且只预留一次、不同请求冲突。旧 HTTP 测试覆盖未绑定和擅改候选被拒。Docker 本次使用缩减模拟场景，只验证事务与计费原型，并非真实 SceneV2 端到端。实际服务认证及密钥、所有旧入口、版本确认和任务创建间的完整业务输入与失败恢复仍须证明，原型未接入应用。
