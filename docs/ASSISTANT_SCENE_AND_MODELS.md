# 助手中的场景与单件模型

右下角幕景助手共用一个聊天输入框，提供自动选择、场景方案、3D 物料三种模式。

- 场景方案：沿用 DeepSeek `/projects/:id/proposals` 和确认应用接口。已有 Scene v2 场地可基于当前确认结构提出布置修改，碰撞、锁定物件、版本、租约和旧结果校验继续生效。未核对的原始图纸/照片仍使用资料面板核对，不会借聊天跳过识别确认。
- 3D 物料：明确的单件生成要求调用混元 `/jobs`，状态和真实 GLB 归档结果显示在聊天里。发送前保留请求 ID；未知结果沿用原 ID 核对。换账号或项目后迟到结果不会加入新画布。加入场地前授权并下载真实模型，设定米制尺寸后加入，用户云端保存后才标记任务已加入。
- 现有预设：聊天可选择体育馆黑客松、香氛快闪；先展示现有预览图，确认才加载。载入前核对画布与账号没有变化，保留原草稿恢复点。预设仍为本地方案，暂不支持云保存和 AI 修改。

例句：

- “为 12 人设计交流沙龙，留出签到区和中心通道。”
- “使用体育馆黑客松预设。”
- “帮我生成一把绿色藤编椅。”

场景和模型混合的消息会要求选择能力，避免把整场布置发送给单件生成服务。问候、生成用法和否定生成请求不调用收费模型。场景对话没有填写需求表时，表单默认的活动类型和 24 人不会被当作用户已确认条件。

本次只调整前端路由和交互，复用已经配置的 DeepSeek、混元、私有存储和定时任务，不变更服务端密钥或预算。按用户安排，真实生成试用由用户操作；受控测试和浏览器预设检查不代表供应商真实生成成功。

验证：助手、生成任务、预设和客户端契约共 96 项前端测试，供应商、API、场景契约 34 项后端测试通过。TypeScript、改动文件 ESLint 和生产静态构建通过；既有 scene-preview.tsx import-order 警告未在本次改动范围内。
