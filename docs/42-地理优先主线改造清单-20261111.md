## 0. 目标链路（新主线）

```
/projects 新建  →  地图找场地（选点）  →  2D 平面规划（边界/分区/动线/设施/标注）

                                        →  〔后置〕再补墙 / 房间 / 精细结构
```

现状是反的：`/` 与 `/editor/` 默认落到**室内 3D 舞台**，户外只是室内壳里的一个开关。

## 墙体定位（2026-11-11 用户拍板）

**墙不是室内的专属构件，而是规划里的「隔断」——和围栏同构。** 所以它不该活在室内房间壳体里，而应该作为平面上的实体物件，落在 OnePlan 目录规则内：

- 主归属：**基础设施 → 屏障**。现有目录已有这一类，且 `BARRIER_SLUG = /barrier|fence|jersey|hoarding|bollard|stanchion|crowd-control/` 已把围栏/水马/围挡都归到「屏障」（`lib/oneplan-catalog.ts` L42-67）。
- 次归属（可选）：**区域、路线及交通**。若用户想按"动线隔断"理解，可在该段露出同一个物件；但语义上该段只放区域/入口/路线工具，建议不混实体。

结论：**墙 = 屏障类线性实体，与围栏共用一套数据与工具**；「画墙」不是室内能力，而是户外 2D 规划里的一个绘制工具。室内那套房间壳体（外墙/踢脚/屋顶）只剩"渲染表现"，不再是数据与交互的入口。

## 6. 新链路要补的缺口（不是删，但不补就成不了主线）

1. `/projects` 新建直接进「找场地」，而非 `/editor/?project=…`。
2. `/`（无参数）默认落点从室内舞台改为「找场地 / 最近场地」。
3. `workspace-shell` 判定改为**显式路由**（如 `mode=outdoor|indoor`），不再靠「有没有草稿」嗅探；室内改为显式入口。
4. 3D 视角按项目记忆：`outdoor-plan-workspace.tsx` L89 `useState<'2d'|'3d'>('2d')` 不落盘，重开回 2D；改为随项目记录上次视角。
5. **线性屏障实体**：`site-plan` 现有实体是「点/环/矩形设施」，隔断需要一条折线实体
   （`points[] + height + thickness + kind: 'wall' | 'fence'`），挂 `levelId`，进「基础设施 → 屏障」目录；
   2D 绘制沿用画墙手感（拖拽/多点），3D 由实体生成矮墙（现在 `outdoor-plan-3d.tsx` 只立 boundary 一圈）。
6. 室内壳体的后置位置：只在「有墙体数据」时渲染 `room-builder` 那套表现，不再给独立的画墙/改房入口。
7. 3D 侧"编辑"入口：3D 视角里把当前 2D 的布局/按钮/区域作为上下文交给顶部 Agent，产出智能活动布局方案（不是手画，手画全在 2D）。

## 8. 已拍板（2026-11-11）

1. **场地 : 项目 = 1:1**。一个项目只有一个场地；多方案留二期（届时才动草稿 key 与层级）。
2. **boundary 与屏障分开**：boundary 决定 3D 地面范围与规划坐标系；屏障是场内实体（可多段、可不闭合）。
3. **`/` 无参数**：有最近活动就续上次，没有就直接进「找场地」。
4. **旧链接兼容**：旧 `?project=` 仍走草稿嗅探；新入口一律带 `mode`；两个月后删嗅探，不长期双轨。
5. **室内能力不塞二级入口**：家具库、物料、漫游、拍场地重建户外本来也要用，全部留在主界面。
6. **3D 可编辑 = AI 布局**：手画都留在 2D；3D 里的"编辑"是带着 2D 的布局/按钮/区域去和顶部 Agent 对话，由 AI 给出智能活动布局方案。
7. **视角记忆**：按项目记住上次是 2D 还是 3D。
8. **屏障形态**：一个物件两个预设——`围栏`（通透、挡人）与 `墙`（有厚有高、挡视线），同一实体只差参数。
