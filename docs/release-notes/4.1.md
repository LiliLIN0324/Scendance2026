# 4.1 Door + Privacy + Furniture Catalog

> 这一版把「门」画进草案，并在打分时主动拦住「签到台顶门」「休息区放门口」这类反直觉布局；家具库也抽成了独立数据层，后续加家具只改一处。

## 新能力

### 1. door 节点 + 门弧遮挡检测
- `PlanAnnotation.geometry` 新增 `kind: 'door'`：`{ wall: 'north'|'south'|'east'|'west', position, widthM }`。
- `evaluateDoorSweep(placements, annotations)`：门宽 0.9 m、开门弧半径 0.45 m，扇区内若有家具 footprint → `DOOR_SWEEP_BLOCKED` hard，每条 -3。
- 人话举例：「签到台挡住了南边门的开门扇区」。

### 2. 隐私区前后排软约束
- `evaluatePrivacyOrder(zones, roomSize)`：签到区应在前排（zone 中心 z > 0）、休息区应在后排（zone 中心 z < 0）。
- 违反 → `PRIVACY_ORDER` soft violation（不扣分，只进 reasons）：
  - 休息区跑到前排 → 「休息区离门太近，建议往深处挪」
  - 签到区跑到后排 → 「签到区离门太远，建议往前排挪」

### 3. 家具库 catalog 数据层
- 新建 `frontend/lib/furniture-catalog.ts`：把原 `plan-approve.ts` 里硬编码的 SPEC 表抽成独立命名 `FURNITURE_CATALOG`，每条带 `type / name / category / width / depth / height / color / icon / zoneTypes`。
- `plan-approve.ts` 从 catalog 按 `(type, zoneType)` 取条目，`SPEC.roundtable.table` 访问形态保持向后兼容。
- 不增 UI 表，只是数据层可扩展；色板沿用既有 4 色。
