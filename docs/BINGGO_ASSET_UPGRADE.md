# Binggo 模型与材质升级

本轮依据用户的《HY3_3D模型与场景执行计划》推进现有产品；用户已明确保留 DeepSeek 策划。所有新增入口位于右下角 Binggo 的「3D 生成」内：新模型、材质调整、场景交付。没有改动小狗图片、其他主站页面或场景协议。

## 已实现

- DeepSeek 读取当前场景及真实资源目录，返回指定实例的材质建议；程序重新确认目标、锁定状态和源资产，不接受模型臆造的材质槽或文件链接。
- GLB 真实材质槽支持基础色、金属度、粗糙度和显式移除颜色贴图。每次变更创建不可变独立资产，原始 BIN、几何、UV 与其他非材质 JSON 保留。原/候选聚焦对比后，用户确认才更新指定实例的 assetId；同源其他实例、尺寸和位置保持不变。支持预览恢复父版本及画布撤销。
- HY3 保留已有文字生成，新增私有参考图生成输入与完整任务恢复。供应商及模型版本固定在任务记录里；未知提交只核对原请求，不自动重发。配置支持 3.1，但生产默认仍为已接入的 TokenHub 3.0。
- 接好受配置控制的纹理任务：输入授权、UV 预检、结果几何/UV 校验、独立版本和明确预览交接。未验证账号权限时保持关闭。
- 场景 GLB 从当前规范场景重新组装，不从编辑器选择框或幽灵预览复制。下载前真实重新加载，核对物件、完整三角连接/绕序、位置、UV、PBR 参数和纹理像素；导出副本改用 PNG 防止二次有损编码。另提供无签名 URL 的 JSON 与按版本/尺寸/颜色分组的 BOM CSV。

## 验证与边界

本地端到端使用真实 API、全迁移 PGlite、真实库模型和明确的 Auth/Storage/DeepSeek 测试替身：两把同源椅子只替换一把，预览未改变场景版本，确认后保存并重开，父版本恢复成功。浏览器另使用真实带两张 WebP 的讲台，GLB 导出完成重新加载复检，保存了 3 个物件及场地结构。详细样本见 [P0 检查](evidence/HY3_ASSET_P0.md)。

新材质建议未进行新的真实 DeepSeek 付费调用；此前的资源 Agent 已做过真实调用，本次验证不能替代新提示词的真实供应商验收。没有提高预算或调用收费 HY3。

本轮没有开放原生腾讯密钥接入、精确 Logo 印刷、UV 自动展开、未通过校验候选的人工复核、骨骼/动画交付和多层场景交付。多数库模型没有 UV；即使有 UV，当前纹理生成的严格模型验证仍可能拒绝 required extensions。不能将参数换色称为木纹重绘，或将供应商文档支持称为账号已授权。

[供应商配置与接口核查](HY3_PROVIDER_AUDIT.md) 和 [不可变版本契约](contracts/ASSET_CUSTOMIZATION.md) 记录这些边界。视觉材质与尺寸仍需实际采购确认。

自动回归：前端 132 个文件、1,707 项测试通过；后端 24 个文件、212 项测试通过。前端类型检查、Deno 三个函数检查与生产构建均通过。静态生产包在隔离 API 下实际下载 GLB、JSON、CSV，GLB 包含 3 个物件并完成复检。小狗图片 SHA256 仍为 `bc146412343ffe23a475ab63d0929e55139376b2962e613accc60a26a35664d2`。

真实云端验证：已认证能力接口显示 3.0 文字/图片入口可用、纹理关闭；未认证返回 401。实际库椅子的 5 个材质槽读取、创建不可变版本、同请求幂等复用、几何/UV 签名保持、仅一实例确认应用、保存重开、父版本恢复均通过。临时项目已删除；QA 账号保留一个独立验证材质资产，未覆盖源模型，付费调用为 0。

## 发布及回退

初始核查基线为 Pages `28d0c30c`（`9972522`）与 scene-api v11。发布期间发现并行任务已更新生产为 Pages `93a24b92-f1fd-4887-a2f1-0f870ff8b2c1`（`329b0d7`）与 scene-api v12；最终发布以此为基线，将该中文目录提交及发布记录 `96b099a` 合入本次专用分支。全部 529 项静态文件、528 项可用资源、中文映射及既有索引与生产提交逐字节一致。generation-worker 原为 v5，reconstruction-worker v2。

新增迁移仅 `20261003160000_material_variants` 与 `20261003161000_generation_inputs`。它们包裹当前 RPC 并委托旧路由，保留线上独有的 `20261003133000_studio_project_visibility` 与 `20261003140000_empty_studio_deletion`。不通过整库 push 覆盖迁移历史。两条迁移在同一事务执行，然后先发布 generation-worker，再发布 scene-api，最后发布 Pages；reconstruction-worker 不发布。先升级 worker，避免旧 worker 将新 API 的图片任务误作为文字任务提交。

数据库为增加性升级。回退优先恢复前端及旧函数发布，保留新资产、迁移记录和固定版本的任务字段；不要删除新表或资产。生成 worker 已有新类型任务时不得切回不识别其输入的旧 worker，应保留升级 worker 或停止该任务入口后处理剩余队列。
