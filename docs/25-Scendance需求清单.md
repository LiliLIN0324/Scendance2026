# Scendance 需求清单与分批执行计划

2026-11-06 · 工作基线 `9adbf7b`。任务开工前以实际分支、工作区和证据为准。

产品目标：让活动策划拿到场地和需求后，快速给甲方看两套有取舍的布置方案。甲方确认后，执行团队收到同一版的效果图、尺寸平面、物料清单和分享链接。首轮使用已有扫描或有尺寸的平面图，新增重建、支付和获客可以独立推进。

## 怎么排给其他 AI

- **P0**：影响首个项目能否交付。**P1**：提高方案可信度或减少后续返工。**P2**：扩展入口或提高规模化效率。
- 每次触发只领一张卡。先检查依赖的交付物是否存在、卡片是否已被认领、需求是否已实现。能用现有功能就复验。遇到阻塞时记录事实、复现步骤和恢复条件，然后按顺序选择下一张独立的卡。
- 认领表按任务 ID 记录 `执行者 | 状态 | 基线提交 | 分支或工作区 | 证据`。状态用 `待核对 / 进行中 / 待外部条件 / 待复核 / 已验收`。当前清单里的 36 张卡均为待核对，已知外部条件写在卡内。可在任务系统维护这张表，同一张卡只保留一个状态来源。
- 开工先读 [HANDOFF.md](../HANDOFF.md)、[COLLAB.md](../COLLAB.md) 和目标目录的 `AGENTS.md`。按协作约定处理渲染、导出和几何文件。多人或多个 AI 写代码时用隔离工作区，切分文件范围，使用各自的 `NEXT_DIST_DIR`。主分支关联自动构建，定时任务默认在本地或分支交付评审。
- 完成时回填验收用例、命令与结果、截图或产物路径。区分本地、模拟环境、线上实测。无数据时标记未知。客户确认、生产部署、收费和对外沟通按已有授权执行。
- **建议调度顺序**：第一轮派 SC-01；随后派 SC-02、SC-03、SC-04、SC-05。SC-06 至 SC-16 依赖产物逐步接通，验收后安排 SC-17 和 SC-18。SC-19 至 SC-23 可在方案链路上并行评审，SC-24 至 SC-36 按依赖挑选，重建和商业分支的阻塞不影响首单交付。
- **并行示例**：AI A 做 SC-02/03 的案例与验收记录，AI B 做 SC-04/05 的输入与存档复验，AI C 做 SC-24 的供应商对照。随后按文件所有权安排实现。两张卡会碰同一模块时串行。

## 可直接复制给定时 AI 的指令

> 先读 HANDOFF.md、COLLAB.md 和 docs/25-Scendance需求清单.md。按优先级与依赖只领一张未验收、未被认领的任务卡。先核对 Git 基线和已有实现，保护工作区里他人的改动。在独立分支或工作区执行能验证的最小改动，按卡片跑验收。回报任务 ID、基线、结果、证据、影响范围和下一步。如果卡住，写清阻塞原因和恢复条件，再选择一张不依赖该阻塞的卡。实测、模拟和未验证的情况分别写清。

推荐回填格式：

```text
任务 ID / 状态 / 执行者
基线提交与分支或工作区
完成的行为或核对结论
验收步骤、结果及证据路径
剩余阻塞与恢复条件
后续卡片及其依赖
```
