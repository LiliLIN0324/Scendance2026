## 用例 A（正常 · 容量内）：120 人公开讲座，课桌式

**输入**（与研究文档构造任务一致，模拟非真实活动）：东京国际论坛 Hall D5，120 人课桌式讲座；需要签到区、演讲区、观众席、两处休息位置；优先入场顺畅。画布输入参照已知答案测试：课桌区 zone 17m×9m 居中偏后（x=-8.5, z=-5.5），南缘留约 4m 给入口/通道，台前带由 zone 北缘内缩表达。

**期望**：
1. 出 1~3 个候选方案，至少 1 个 `feasible=true`（FEASIBLE），可进入推荐；
2. 在本模拟矩形和指定区域下，推荐版容量约 **126 座**（6 排 × 7 桌 × 3 椅/桌）；该结果不能与官网课桌 120 人作为同条件校准；
3. 物料判定：`capacitySeats` 必须等于画布上 desk-chair 实际数量；物料 CSV 行数与画布求和一致，缺规格/库存缺口要显式列出，区分「未填」与「数量为零」；
4. **降容不触发**：targetCapacity=120 时，推荐版容量 ≥ 108（=120×0.9 降容阈值），reasons 不出现「装不下 / 建议降到」。

**验收断言清单**（SC-03 走查逐项打勾；A2~A10 已由自动化测试背书，A1/A11/A12 走查时人工核对）：

- [ ] A1 候选方案 1~3 个，至少 1 个 feasible=true，状态 FEASIBLE
- [ ] A2 推荐版 capacitySeats 落在 96~144（约 126，容差 ±20%）
- [ ] A3 课桌排距 ≥ **1.4m**（对齐官方课桌图 1400mm，不是剧院的 0.9m）
- [ ] A4 块间走道 ≥ **1.2m**（官方 1200mm；block 内桌间隙 ≈0.04m 不算走道）
- [ ] A5 每桌 **3 椅**，每把讲座椅带 `ownerTableId` 链到所属课桌
- [ ] A6 家具 footprint 无 AABB 重叠
- [ ] A7 所有家具距墙 ≥ **0.3m**；desk-chair 椅背侧 ≥ **0.6m**（`71627ba` 校准）
- [ ] A8 南墙主入口门位 ±1.5m 带内无家具 footprint（不堵门）
- [ ] A9 西北角非常口 1.5m 半径内无家具（不堵应急口）
- [ ] A10 门弧因门宽/方向 unknown → violation status=**unknown**，不出现 status=pass；方案 assurance=**draft_unverified**（门是 fixture 推断的，不是用户真实画的）
- [ ] A11 targetCapacity=120 时 reasons 无降容提示；若实际容量 <108 导致提示出现，记为断点并核对提示文案与数字正确性
- [ ] A12 导出物料 CSV：desk-table / desk-chair 数量与画布求和一致，分组求和无出入

## 用例 B（超容量）：250 人（超官方剧院 200）

**输入**：同一场地 Hall D5，人数填 **250**（超过官方剧院 200、课桌 120）；画布输入参照已知答案测试：课桌区拉到最大 18m×14m（x=-9, z=-7），targetCapacity=250。

**期望**：**装不下时有解释性失败，不产出假通过，也不默默硬凑**。系统要指出冲突、给可达容量和人话调整建议，而不是静默减椅子假装排下了。

**验收断言清单**：

- [ ] B1 推荐版 capacitySeats **< 250**——没有为凑数虚增椅子
- [ ] B2 capacitySeats ≥ 100——量级对齐官方 120~200 区间，不是只摆几十把就交差
- [ ] B3 capacitySeats 严格等于 placements 中 desk-chair 实际数量（不凭空加椅）
- [ ] B4 targetCapacity=250 时，推荐版 reasons 必须出现「装不下 250」和「建议（把人数）降到 …」的人话；建议值取 10 的倍数（floor(容量/10)×10），或建议换更大场地（`71627ba` 引入）
- [ ] B5 无假通过：feasible=false 的硬冲突方案不被推荐选中；门弧不出现 status=pass；assurance=draft_unverified
- [ ] B6 人工拖拽家具堵住南墙门或非常口 → 旧结论失效、重跑报警（研究文档对抗检查 #6；走查时若产品未实现，如实记为断点）
