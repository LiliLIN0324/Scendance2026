## 一、计时口径

沿用规格文档口径，不因实测好看而放宽。

| 项 | 规定 |
|---|---|
| T0 | 用户打开工作台，**场景画布完成首次可交互渲染**（能看到场地，不包含登录页） |
| T5 | 另一台设备（未登录）打开分享链接，**看到方案首帧** |
| 计入用户耗时 | 生成等待、Agent 等待、上传/加载等待、失败后的重试 |
| 不计入（单独记「摩擦耗时」） | 登录、充值/购额度、等待人工审批；**不因此放宽 10 分钟** |
| 判定「10 分钟内」 | `T5 - T0 ≤ 600s`，且五步均达到各自验收条件；任一步需要下载/上传文件即判失败，不再计时间 |
| 计时方式 | 走查脚本按毫秒记录每一步 |

**一句话**：10 分钟是「从看到场地，到客户在手机上看到方案」的墙钟时间，含系统生成等待，不含登录与买额度。

### 本轮实测（当日点击）

| 段 | 实测 |
|---|---|
| ① 打开空间 → 看到场景 | ~10 s |
| ② 打开生成表单 → 填写 | ~6 s（未提交） |
| ③ 库件加入画布 → 工具条出现 | ~2 s |
| ④ 移动 + 确认；缩放/灯光各一轮 | ~20 s |
| ⑤ 打开发布 → 生成链接 → 客户页首帧 | ~18 s（首帧 5–12 s 波动） |
| 生成等待（Lux3D） | 3–5 min（文档口径，本轮未提交） |
| **合计（不含生成）** | **约 60–90 s**；加上生成约 **4–6 min** |
| 整轮自动走查 `elapsedSeconds` | **183 s**（含截图与脚本开销，不等于用户耗时） |

### 口径的两个边界

1. **10 分钟只在「已有扫描 + Lux3D 生成装置」这条路成立。** 若第 1 步走「真实场地重建」，Aholo 室内实测约 **15 分钟**出 SPZ/PLY/pano，单次等待就超过 10 分钟，口径不成立。
2. **数值达标不等于链路达标。** 第 1、2、5 步不可用，计时没有意义；当日实测走查脚本能在 4–6 分钟内跑完，是因为绕开了生成与真实场地。

### 本轮没测到的部分（不要当成已通过）

| 未覆盖项 | 原因 | 影响 |
|---|---|---|
| 真实提交一次 Lux3D 生成 | 会消耗真实额度，走查刻意未点「生成」 | 第 2 步「进度可见」「自动入库」只有代码证据，无实测 |
| 「生成完成 → 自动进场景」 | 无已完成任务，无生成物 | 第 3 步自动落位、贴地 ≤2 cm 全部未验证 |
| 标定后刷新保留 | 界面无标定入口 | G4 的「刷新后标定仍在」无法验证 |
| 真机 / 弱网首帧 | 走查在本机 3300 端口 | 第 5 步「客户首帧 ≤5 s」只有本机数据（实测 5–12 s） |
| 真实扫描的米制一致性 | 无带 meters 的已发布 `.spz` 可选 | G4 的「误差 ≤2%」仍是纸面标准 |

## 四、不可接受行为与降级矩阵

### 不可接受行为（任一出现即视为验收不通过）

1. 让用户下载 GLB 再手工上传，或要求手动换算单位/轴向。
2. 装置生成后悬空、埋地、比例明显失真，或刷新后位置丢失。
3. 场地尺寸与扫描不一致却不提示，仍宣称「可量尺寸」。
4. 生成按钮可点但在当前环境必失败；或错误文案要求用户运行终端脚本。
5. 生成/扣额度不告知，或失败后重复扣额度。
6. 分享链接需要客户登录、或打开后白屏/「链接不完整」而无替代说明。
7. 分享页只有 2D 平面却标注「3D 方案」；或宣称「真实场景」但背景不是现场。
8. 同一方案在 Agent、发布卡片、到场清单出现不同件数/不同品类。
9. 需要用户自己判断「用哪个链接/哪个导出」，且两种链接差异未说明。
10. 演示资产（宴会厅样例、干跑重建）被当作真实场地交付，无「演示」标记。

当日已命中的三条：**第 4 条**（错误文案要求运行 `tools/aholo/lux3d-dev-proxy.mjs`）、**第 6 条**（「分享链接不完整或已损坏」）、**第 8 条**（画布 6 件 / 分享页 5 件）。
