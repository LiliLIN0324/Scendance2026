## 现状盘点（积木都在，缺一根线）

已有能力：

| 积木 | 位置 | 现状 |
| --- | --- | --- |

| 卫星静态图 + 经纬度 bounds | `lib/amap-venue.ts`（`parseSatelliteImageBounds` 等） | 卫星贴地只作为 `geo/manual` 的场景地面层（历史称户外选址圈画） |
| 地名→坐标→铺 3D 底图 | Bingo「调研西湖」（`agent-panel.tsx` researchArea） | 已能按地名把参考底图铺进 3D 地面 |
| 场地资产注册表 | `lib/aholo-assets.ts`（localStorage `scendance:aholo-assets`） | `{assetId, kind, name, meters, savedAt, taskid}`，**没有地理字段** |
| 真实场地库 | `lib/venue-scans.ts` → 空间格「真实场地」 | 从注册表派生，**没有 `sceneAnchor` 字段与补录入口** |

缺口：**重建任务 ↔ `sceneAnchor`** 两份数据不通。底图知道经纬度，重建产物知道尺度，但资产上没有场景锚点；挂环境后 3D 地面也没有地理底图。

## 提案（P0 一条主线 + 两种补录方式）

### P0-A 数据模型：资产带可选 `sceneAnchor`

- `AholoAsset` / `ScannedVenue` 增加可选 `sceneAnchor`（落库字段沿用 `geo`，语义是场景锚点）：`{ mode: 'geo' | 'manual' | 'null'; lng?: number; lat?: number; headingDeg?: number; metersPerUnit?: number; radiusM?: number; source: 'picker' | 'manual' | 'lookup' }`。
- 注册表校验（`isValidAsset`）、`venue-scans` 描述行、schema（`venueScan`）同步放行；`sceneAnchor` 只作元数据，**不参与碰撞/落盘几何/重建素材**。
- `null` 是合法值，不是缺失错误：没有地点就是 `null`，显示 1m 网格地面。

### P0-B 来源：黄金路径自动带 + 存量手动补录

1. **自动（场景锚定 → 重建贯通）**：场景地面层的采集单已含场地中心与范围；创建重建任务时把 `sceneAnchor { mode:'geo', lng, lat, radiusM, source:'picker' }` 写进任务记录（历史/待处理凭据），成功挂载落盘时自动写进资产。
2. **存量两套西湖资产**：补录一次 `sceneAnchor`。西湖 0194 拍摄点坐标从拍摄记录取（DJI EXIF GPS 全 0 是已知坑，`docs/47`），必要时先用地名查坐标填 `sceneAnchor` 再微调。补录入口：真实场地卡上的「场景锚点」，未填时按 `null` 显示。

### P0-C 渲染：挂环境即铺场景地面层

- 环境预览开启且 `sceneAnchor.mode` 为 `geo/manual`：经代理拉 `/amap-static` 卫星图（中心 = 锚点，半径 = 资产 meters 对角线 ×2 左右），按 `amap-venue` 的 bounds 解析**贴在同一场景地面下方**作底图，北向对齐（`headingDeg` 默认 0，可后续用空间标定微调）。
- 复用卫星贴地纪律：底图仅观感，画布 chip 显示「底图 · 西湖 · 仅作参照」；观感抽屉加「场景地面层」开关（默认开）。
- `sceneAnchor.mode='null'` 或未填：只铺 1m 网格地面，不铺真实瓦片；不另起坐标系。

### P1（拍板可砍）

- 底图可切「卫星 / 路网矢量」两档（代理已有能力，UI 加一档）。
- 多楼层场地 geo 各自标注（当前先只做场地级）。

## 硬钉

- 卫星图/地图瓦片**永不进重建素材**（`RECON_MATERIAL_BAN` 既有红线）。
- geo 未标注时 UI 不得编造坐标；「调研西湖」查到的地名坐标只作参考底图，不冒充实测。
- 底图只作观感层：不进碰撞、不进落盘几何、不进台账尺寸。

## 验收线

1. 挂「西湖茶亭·标准档」→ 场景地面出现以真实坐标为中心的卫星底图，与高斯尺度对齐；关开关即回纯 splat。
2. 「西湖茶亭·极速档」补录一次 `sceneAnchor` → 两套切换时底图都在。
3. 场景锚定 → 采集单 → 重建 → 挂载全流程不手工填坐标，资产自动带 `sceneAnchor`。
4. `null` 态：无地点、无底图，1m 网格可摆物件；补地点后同一场景升级为 `manual`/`geo`，不重建场景。

- **P0 + P1 全做**（含卫星/路网矢量切换；`createResearchArea` 的 style 6/7 已原生支持，UI 补一档开关即可）。
- **西湖 0194 坐标来源**：地名只用于填 `sceneAnchor`（JSAPI PlaceSearch / 代理 `/amap-place`），铺底图后微调对齐 0194 亭；这不是独立地图入口或独立定位状态。
- 底图默认开（仅观感）。
- 实现要点（盘点更新）：`three/research-basemap.ts` 渲染器与 `createResearchArea` 已存在且支持卫星/路网；缺的只是 **资产的 `sceneAnchor` 字段** 与 **环境切换↔场景地面层的接线**。旧实现用 `mapGroundFrame` 时底图以画布原点为中心；新口径删除该框架，`geo/manual` 都挂同一场景地面，`null` 走 1m 网格。

## 二次拍板（同日）：场景地面层锚定改为画布左上角常驻输入

用户明确：3D 场景左上角放一个类似高德底图的地名输入，用来**写 `sceneAnchor`**；`geo/manual` 铺真实底图，**不输入就是 `null`（1m 网格，照常摆东西）**。底图要**真实比例 + 带道路信息 + 能铺整个西湖**（12km 级）。地名输入不是独立地图页、不是独立搜索流程、不是独立定位状态。

## 追加修复（同日，用户报「底图没铺上/怀疑比例不对」）

- **根因实锤**：布局残留了**第二套地面坐标**（`mapGroundFrame/mapLngLat/mapGroundPolygon` 指向北京 116.46,39.96 的旧演示壳），`researchBasemapPlacement` 按它算偏移 → 西湖底图被放到 ~350km 外，茶亭脚下空空如也。**旧修法（作废）**：以框架中心与底图中心相距 >3km 判定异地、连框架一起清掉；这是掩盖，不是修复。**现行修法**：删除 `mapGroundFrame`，`researchBasemapPlacement` 只读 `sceneAnchor`；`geo/manual` 铺同一场景地面，`null` 铺 1m 网格；不保留任何第二套坐标。
- **新增脚下高清贴片**：`ResearchArea.detailRadiusM/detailBounds/detailImageUrl`（±250m，z18 约 0.5m/px），`buildResearchBasemap` 同锚点叠一层（polygonOffset 防 z-fight，拉取失败整层隐掉）。大西湖全景做背景、贴片做脚下实景，**两层都是真实米制、无缩放**。
- **待修（新发现）**：有 12km 级底图在场时，放大按钮/滚轮/视角预设都推不回场地尺度（相机疑似被大场景撑大了活动范围）——临时替代：右轨「进入漫游」第一人称眼高直接走到茶亭。接力查 `use-camera-presets.ts` 的 `calculateRoomFraming` 与 controls 距离钳制。
