# 59 · Agent 评测集与打分口径（2026-11-18）

> 一句话：27 条样本考两件事——**该提的提得对不对**（layout），**该报的报没报、没问题的别乱报**（failure + 对照）。
> 数据：`data/agent-corpus/cases/eval-cases.json`；打分器：`frontend/lib/agent-corpus/eval-suite.ts`；守门：`tests/agent-corpus-eval-cases.test.ts`。

## 一、判分口径

| 样本类型 | 数量 | 考什么 | 怎么算过 | 明确不算的 |
|---|---:|---|---|---|
| `layout` | 10 | 方案「像不像一个真方案」 | 模板命中 + 四项计数落带 | 不校验具体坐标、物料型号 |
| `failure`（变异） | 13 | 布局有硬伤时能不能报出来 | 期望违规**一条不漏、一条不多** | 未实现判据不计分 |
| `failure`（事故） | 3 | 多故障叠加时能不能报全 | 同上（多故障） | 同上 |
| `failure`（对照） | 1 | 没硬伤时会不会乱报 | 硬违规必须为 0 | 不把它算进「召回」 |

两条底线照旧：参考带来自平台读数，不是标准答案；未实现判据不得计入得分。

## 二、负样本是怎么造的

**基准布局（1 份，对 11 条已实现判据全部合规）**：120×80 m 场地；西南舞台区 16×8 m，观演区 28×18 m 与舞台留 6 m 退距（台高 1.5 m 需 5 m）；南侧 6 个 3×3 m 展位成排、间距 7 m；餐饮车距最近展位 15 m；东侧两顶 3×3 m 帐篷相距 7 m、距餐饮车 28 m；东北角既有建筑距最近设施 12 m；配 2 具灭火器；1 个主出入口 + 1 个东侧出口；400 人。

**每条变异只改一处**，改完由执行器真跑，违规集合与期望逐条比对：

- 摊位贴建筑同时踩 GEN-07（临时设施退距）与 MKT-11（摊位退距）——后者是前者的子集。

为了证明联动不是「只能一起报」，各留了一条隔离样本：EV-NEG-11 让帐篷隔 3 m，CMP-02 通过、只报 CMP-03。

## 四、打分器

```ts
import { scoreLayoutSample, scoreFailureSample, summarizeResults } from '@/lib/agent-corpus/eval-suite';

scoreLayoutSample(sample, { templateId: 'MKT', zones: 9, objects: 60, routes: 4, entrances: 3 });
// → { pass: true, failures: [] }

scoreFailureSample(sample, rules);
// → { pass: true, failures: [], notes: ['本次共 69 条判据未实现，未计入得分'] }

scoreFailureSample(control, rules); // 对照样本
// 报出任何硬违规 → { pass: false, failures: ['误报：GEN-04（对照样本应报 0 条硬违规）'] }

summarizeResults(results);
// → { total, passed, failed, passRate, byKind: { layout: {...}, failure: {...} } }
```

对照样本的语义是这轮新增的：`expect.violations` 为空时，**报出任何硬违规都判错**。没有它，只有「漏报」会被抓，模型学会了「少说话」就能得高分。

## 五、覆盖情况（这轮的硬指标）

- **11 / 11** 已实现判据都有对应的负样本；测试里有一条「覆盖度」断言，缺一条就红。
- **17 / 17** 份夹具跑出来的违规集合与期望**完全相等**（多报一条也判错）。
- 对照布局的 11 条判据全部是 `pass`，**没有一条靠 `skipped` 混过去**——否则「合规」是假的。
- 剩下 **69 条判据做不了负样本**：它们缺的是栅格、水深、高程、树冠、传感器、路由拓扑等数据（`unsupported` 原因码已分类）。不是不想造，是执行器现在还测不出来。

## 六、三条使用纪律

1. **离线评测**，没接 CI 门禁，也没有真实 Agent 基线分数；不要拿「27/27 通过」当质量证明。
2. **平台读数不是标准答案**，同一场地换个人数口径就变；layout 样本只用来卡量级。
3. **未实现判据不能计分**，否则等于奖励「什么都不报」。11 条可算，是这套评测集的真实上限。

## 八、还缺什么

- **没有真实 Agent 基线**：10 条 layout prompt 还没真跑成 `LayoutProposal`，现在只有题面与判分，没有分数。
- **负样本只覆盖 11 条判据**，且都是「单点 + 三条事故」；真实工地更常见的是多规则耦合失效（通道 + 密度 + 出入口），耦合样本只有 3 条。
- **阈值本身没被拷问**：夹具按现行阈值造，阈值若错，样本会一起错；需要一份「阈值敏感性」检查（例如 MKT-02 的 1.5/2.0 m 换成 1.2 m 会漏掉哪些案例）。
