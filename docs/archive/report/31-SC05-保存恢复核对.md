### 验收点 2 · 无访问权的会话看不到私有内容 —— 服务端访问控制完备；卡上提到的套件口径需更正

**现状**：私有内容有两类——云端方案（登录 + 成员 + 资产授权三层门）与随分享链接出去的内容（出参剥私有字段）。本机演示链路则明确声明「换设备/无痕窗口打不开」。

**证据**：
- 数据库门：`scene_private` schema 对 public/anon/authenticated 全部 revoke，表全部启用 RLS，仅 service_role 可执行（`scene_core.sql:257-267`）；`scene_rpc` 无 actor 时除 `share.read` 一律 `UNAUTHENTICATED`（`:174`）；非成员访问项目一律 `PROJECT_NOT_FOUND`（不泄露存在性，`:201-202`）；发布/分享管理需创建者或 owner（`:238-239`）；工作室列表对非成员返回 `STUDIO_NOT_FOUND`（`20261003133000_studio_project_visibility.sql:26`）。
- 资产门：`can_use_asset` = 资产所有者，或被「自己所在工作室的项目」引用（`scene_core.sql:81-87`）；每次 `scene.save` 前跑 `check_assets`（`:88-104,148`）——无权资产根本写不进方案。

### 验收点 3 · 缺资产有定位信息 —— 名单 / 行级原因 / 占位体三层都有；集中台账面板未落地

**现状**：GLB 与 SPZ 的失败分支都带「哪个资产 + 下一步动作」；画布上以命名占位体呈现；分享页汇总名单；交付清单逐行写明缺失原因。docs/22 提议的「资产台账」面板在代码中尚无对应实现（仓库无 `asset-ledger` 代码文件），定位信息以分散形式存在。

**证据**：
- GLB 失败分支带原因：下载 HTTP 状态、>10MB、超时/取消、非 GLB 2.0、引用外部文件、无可显示网格，全部成为 `GlbAssetState.error`（`three/glb-assets.ts:70-83,85-110,120-154`）。
- 画布占位可定位：失败占位体红棕色、名字就叫「模型加载失败（占位）」，且占位体挂在**原物件的位置与标称尺寸**上（`three/furniture-builders.ts:107-117`）；顶栏通知 `模型加载失败，请重试。`（`room-organizer.tsx:2953`）。
- SPZ 缺失定位：`storedAholoSceneSource` 找不到登记时抛「本机已经没有这个场景，请重新生成。」；GLB 误当场景用会提示走「生成物件」入口（`lib/aholo-model-placement.ts:11-15,100-105`）；注册表写失败时注释明确「重开图纸时退回『模型未能加载』提示」（`aholo-assets.ts:119-126`）。
- 分享页名单：加载失败的资产按名汇总一行 alert「……未能加载，仅显示线框占位。请刷新模型资源重试。」（`components/business/scene-preview.tsx:127-145,181`）。
- 交付链路行级定位：`prepareDeliveryAssets` 抛 `"“<物料名>”模型尚未加载，请连接项目后重试。"`（`lib/scene-delivery.ts:182`）；导出时非 ready 物件拒绝出占位 `"“<物料名>”模型尚未就绪，未导出占位物件。"`（`:209-211`）；交付清单 CSV 每类写明可导出/不支持与原因（`:127-157`）；场景 JSON 明示 `assetVersionId` 为归档资产标识、私有资产重开仍需授权（`:98`）。
- 公共资产自愈：签名 URL 401/403 且字节身份可证时自动换 `/showcase/` 本站地址重试（`frontend/lib/public-asset-recovery.ts:43-69`）。

**测试覆盖**：`aholo-assets.test.ts` 12 例全过（含 `isValidAsset` 坏档过滤）；`scene-delivery.test.ts` / `scene-delivery-integrity.test.ts` 在全量基线中（SC-01 已核，37 项定性）。

### 验收点 4 · 保存失败后可重试或回到可编辑草稿 —— 重试是继续编辑即自动重试；回退有恢复点环 + 恢复副本 + 错误屏三路

**现状**：失败原因分三类（quota/blocked/unknown）如实上报 HUD；quota 时先逐出恢复点腾空间；原件保不住时压住 autosave；画布始终可编辑；历史面板与错误屏都提供回退。

**证据**：
- 分类：`lib/storage-errors.ts:12-20`（`QuotaExceededError`/code 22/1014 → quota；`SecurityError`/code 18 → blocked）。
- 上报：`saveLayout` 返回 `{ok:false,reason}`，HUD 不假显「已保存」（`lib/persistence.ts:294-310`、`use-layout-persistence.ts:296-301` 注释明说）；顶栏显示「保存失败 / 未保存」，title「保存失败，请导出备份」（`room-organizer.tsx:2641-2643,2807`）。
- 重试语义：失败后 `saving/pending` 保持为真，**下一次任意编辑会再次触发 autosave**（`use-layout-persistence.ts:269-303`），释放空间后自动恢复；`mainSaveHeld` 时每次编辑先尝试把原件复制出去，成功即恢复保存（`:271-279,143-151`）；pagehide flush 失败同样保持 pending。
- quota 纪律：`setItemEvictingSnapshots` 先逐出恢复点（最旧优先）再重试，其他错误不动环；单条 >5MiB 直接拒绝且**一个恢复点都不逐出**（`lib/version-history.ts:540-561`，#295/#332）。
- 回到可编辑草稿：
  - 恢复副本：`RecoveryEntry` 面板列出保留的副本，Restore（可撤销）/ Download（原始字节）/ Delete（`panels/recovery-entry.tsx:36-154`）；
  - 版本历史：`listSnapshots`/`getSnapshot` + History 面板回退到 5 分钟粒度的旧点（`lib/version-history.ts:427-465`）；
  - 错误屏：Reload 计 marker（2 分钟窗口识别「刷新没用」），start fresh 前必先 `resetStoredLayout` 复制原件、失败则拒并保留，另提供原始字节下载（`app/error.tsx:62-75`、`app/global-error.tsx:55,115`、`lib/persistence.ts:345-408,487-526`）；
  - 超上限载入：修剪载入并通知「原件已另存一份，不会被覆盖」（`lib/persistence.ts:42-50`）。

**测试覆盖**（本卡实跑）：`version-history.test.ts` 50 例（含 quota 逐出后仍报失败、超大值不清环 #332——运行日志里的 QuotaExceededError stderr 即这两个用例的**预期注入**，不是产品缺陷）；`persistence.test.ts` 45 例（保存失败原因 #472、无法复制的不可读存档保原件 #336）；`use-layout-persistence.react.test.ts` 63 例（含 #472/#336/#334 跨标签）。

**待 SC-03 实测**：真实浏览器塞满配额（如塞大平面图）后 HUD 的实际观感、继续编辑是否真恢复、恢复副本面板入口在 History 里的可达性。

## 三、缺口与风险清单

| # | 缺口 / 风险 | 影响 | 建议去向 |
| --- | --- | --- | --- |
| 1 | **「本地方案不跨设备」无主动提示**：主存档 / 恢复点 / 资产注册表 / 环境偏好 / SPZ 文件全在本机；跨设备只有登录后的云端项目链路（`scene.save` / `/view#token`）。换设备或清站点数据会丢本机草稿——review-share 有文字声明，但**主编辑器**对这一点没有等价的 onboarding/提示文案 | SC-05 卡面「换设备或账号」场景下，本机草稿默认丢失，需依赖手动导出备份（HUD title 有提示但只出现在失败时） | SC-03 走查确认观感后，考虑在「云面板未登录 / 本机活动工作区」状态加一行边界说明 |
| 2 | **缺资产缺集中台账**：定位信息分散在占位体（画布）、名单（分享页）、行级原因（交付清单），docs/22 提议的资产台账面板未落地；编辑器内没有一个页面能一眼列出「本方案缺哪些资产、各自在哪层哪个位置」 | 多资产缺失时用户要逐个找 | docs/22 台账提案落地前，可先在交付清单上补一列「缺失资产汇总」 |

## 四、对 SC-03 的交接注记

1. **保存走查建议**：改一桌 → 观察顶栏「正在保存…→已保存」（1500ms 防抖）→ 刷新 → 断言同版恢复（件数、位置、楼层、门标注一致）。再开第二个标签编辑，验证互踩提示可「采纳」（一次 Ctrl+Z 可退）。
2. **失败路径建议**：DevTools 里往 localStorage 塞满大值再编辑 → 确认 HUD「保存失败/未保存」且 title 提示导出备份 → 清出空间再编辑 → 确认自动恢复保存。刷新打断防抖窗口用 pagehide flush 兜底（隐藏标签页也会 flush）。
3. **无权会话建议**：匿名开 `/view#<伪造token>`（应为「分享链接不存在或已撤销」）；有 token 的确认版打开后核对**没有**平面底图与物件备注（服务端已剥）；非成员登录态打开他人项目深链应得「项目不存在」类提示。
4. **缺资产建议**：断开 lux3d 代理（127.0.0.1:3199）重开带真扫描场地的图纸 → 环境预览应报「本机已经没有这个场景，请重新生成。」且画布物料不受影响；带 GLB 资产的方案断网刷新 → 应见「模型加载失败（占位）」红棕占位与顶栏重试提示。
5. **输入卡**：SC-05 的验收输入沿用 [docs/27](27-首单需求卡-HallD5演练.md) 用例 A（正常）与用例 B（超容量）；已知答案测试 18/18 于同基线可复跑（`cd frontend && npx vitest run lib/hall-d5-benchmark.e2e.test.ts`）。
