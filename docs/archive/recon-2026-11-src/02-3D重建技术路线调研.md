## 0. 结论先行

### 0.0 前置结论：现有素材不能做重建

据同目录 [01-素材核查与采集缺口.md](file:///01-素材核查与采集缺口.md) 的核查：`scene-3d/` 是**同一晚、同一机位附近、以云台旋转为主的 24 张有效静态图 + 6 段 720p 视频**；0/32 文件有可用 GPS（`GpsStatus="Invalid"`、经纬度为 0），没有平移基线、没有 GCP/尺度，且是夜间拍摄、曝光从 1/6.25 s 到 1/100 s、ISO 210–4040 漂移、湖面反光 + 城市灯光逆光。**SfM 会在三角化阶段退化，3DGS 也没有可用视差**。

因此：

- 现有素材的交付上限是 **一张 360/180 全景氛围贴图 + 人工体块参考**，适合做“环境背景参考”，**不适合做可量化、可漫游的 3D 场景**。
- 下文所有路线、耗时与验收，**都以“重新采集”为前提**；不是对现有素材的“再加工方案”。

### 0.1 推荐路线：双轨混合，先样片后批量

**观感层用 3DGS，结构层用轻量 GLB；水面与天空在引擎里补，不指望重建。** 这是与本项目编辑器能力最匹配、也是户外大场景最稳的组合。

1. **样片阶段（先做 1 个 50–100 m 岸线段，必须重采）**：用现有 Aholo World 云重建链路跑一遍，产出 `SPZ + PLY + 全景图`；同一批样片并行跑一次本地 `COLMAP/GLOMAP + gsplat`，做 A/B。  
2. **量产阶段**：胜出的 3DGS 作为 `SPZ` 环境背景层；结构/落地基准用轻量 `GLB`（摄影测量粗模 + Blender 清理，或现有矢量壳体）。  
3. **若客户要求“可编辑几何/精确尺寸”**：以摄影测量 mesh 为主，3DGS 只做氛围参考，**不要让 3DGS 承担结构或落地基准**。

**最短可行链路**（只求“能进编辑器看”）：

```text
重采照片/视频 → Aholo World → SPZ/PLY → 本地 /asset/<uuid>.spz → 编辑器环境预览
```

结构先用现有矢量壳体即可；若需要真实结构，再加一步 `Metashape/COLMAP → Blender → GLB`。

### 0.2 为什么不是“单一路线”

| 判断 | 依据 |
|---|---|
| 编辑器已经支持 3DGS 背景层 + GLB 结构层，且点云**不参与拾取/落地** | 【C】[splat-preview.ts](file:///c:/Users/13266/.dsh/bot/workspace/Scendance2026/frontend/components/room-organizer/three/splat-preview.ts) 的两趟渲染与 `pickFootprint` 逻辑；[16-Aholo资产与3DGS预览.md](file:///c:/Users/13266/.dsh/bot/workspace/Scendance2026/docs/16-Aholo资产与3DGS预览.md) |
| 3DGS 的强项是“看起来真”，弱项是“没有可编辑几何” | 【A】3DGS 论文将场景表示为显式 3D 高斯集合；Nerfstudio 明确“目前不支持导出 mesh/pointcloud” |
| 摄影测量 mesh 的强项是“可编辑、可碰撞、可量尺寸”，弱项是水面/树木/天空 | 【A】COLMAP/Pix4D 文档；水面几乎不可重建 |
| 西湖是大型户外场景：水面占比高、游客多、树木风动、光照变化大 | 【A】Pix4D 对水面/植被/天气的说明；【D】对西湖场景的推断 |
| 西湖不在已公布的适飞空域（据官方反馈），许可比技术更前置 | 【A】杭州市交通运输局 2026-07-28 公开征求意见反馈；《无人驾驶航空器飞行管理暂行条例》；以最新通告为准 |

### 0.3 明确不建议

- **不要试图用现有 24 张原地旋转全景图跑 SfM/3DGS**：没有平移基线、GPS 全 0、无尺度，结果只会退化；现有素材只做氛围参考【C】。
- **不要用全景/等距柱状图直接训练 3DGS**：高斯光栅化假设透视相机，Nerfstudio 明确暂不支持 equirectangular/fisheye 渲染【A】。
- **不要指望 3DGS 输出可碰撞的 mesh**：它只能裁剪、变换、清理，不能当结构几何【A】【C】。
- **不要在正午硬光、大风、雨天拍**：阴影跳变、运动模糊、镜头水滴都会直接毁掉空三【A】。
- **不要在未审批的情况下在西湖飞无人机**：据官方反馈，西湖不在已公布的适飞空域，属管制空域；以最新通告为准【A】。
- **不要用普通 GPS 做 1:1 对齐**：普通无人机 GPS 的平面/高程误差是米级，RTK 才是厘米级【A】。

## 2. 四条技术路线对比

### 2.1 摄影测量：COLMAP / Meshroom / Metashape

**原理**：SfM 先恢复稀疏点云与相机位姿，再由 MVS 生成稠密点云/网格，最后做多视图纹理映射【A】[COLMAP Tutorial](https://colmap.github.io/tutorial)。

| 软件 | 定位 | 输入 | 输出 | 许可/成本 | 适合 |
|---|---|---|---|---|---|
| **COLMAP** | 研究级 SfM/MVS，命令行可编排 | 重叠透视/鱼眼图像 | 稀疏模型、`fused.ply`、`meshed-*.ply` | 开源免费【A】 | 需要自己控流程、批量脚本化 |
| **Meshroom / AliceVision** | 节点式桌面管线 | 一组照片 | 带纹理网格、点云 | MPL-2.0，免费【A】 | 不想写代码、快速出 mesh |
| **Agisoft Metashape** | 商业摄影测量 | 航拍/近景/卫星、多相机 | 点云、mesh、正射、纹理 | 标准版 $179 / 专业版 $3,499（官网节点锁定，税前）【B】 | 需要 GCP、正射、批处理、稳定商用 |

**输入要求（COLMAP 官方给的 capture 建议）**【A】：

- 纹理要好，避免白墙/空桌面这类无纹理面；
- 光照条件尽量一致，避免逆光、门窗透光、强高光；
- 高视觉重叠，每个物体至少出现在 3 张图里；
- 从不同视点拍，**不要只原地旋转相机**；视频输入要抽帧。

**几何可编辑性**：高。mesh 可进 Blender 重拓扑、补洞、分离结构/家具、UV 与烘焙；但原始重建网格通常脏、面数高，需要人工清理【D】。

**Web 可用性**：mesh 转 GLB 后 three.js 原生可用；但高面数 + 大纹理需要减面/压缩，否则首屏和移动端会崩【D】。

**耗时/算力**：没有官方“单场景固定耗时”；百张级通常小时级，千张级数小时到一天，取决于匹配策略、图像数与硬件【D】。Metashape 支持 GPU 加速，但具体随设置变化【B】。

**成本量级**：COLMAP/Meshroom 软件零成本，主要成本是 GPU/CPU 与人工；Metashape 是一次性许可证 + 人工【B】。

### 2.2 NeRF（nerfstudio / Instant-NGP 等）

**原理**：用神经网络隐式表示辐射场与密度，通过体积渲染合成新视角【A】[NeRF 论文](https://arxiv.org/abs/2003.08934)。

| 项 | 说明 |
|---|---|
| 输入 | 已标定位姿的图像（通常先跑 COLMAP）；静态场景；透视相机 |
| 输出 | 网络权重/checkpoint；可渲染图像；mesh 导出不是强项 |
| 几何可编辑性 | 基本没有；几何藏在网络里，不是 mesh |
| Web 可用性 | 差。需要专用 WebGL NeRF 渲染器，或转 mesh/点云；实时性不如 3DGS【A】【D】 |
| 耗时/算力 | 原版 NeRF 单场景约 **1–2 天 / 单张 V100**（论文）【A】；后续快速变体可到分钟级，但需按实现验证【D】 |
| 成本 | 开源实现免费；主要成本是 GPU 时间 |

**适用判断**：西湖这种大户外场景，NeRF 的“雾状/远景”问题与训练成本都不划算；除非要做“光照可编辑”的研究型演示，否则不建议作为主路线【D】。

### 2.3 3D Gaussian Splatting（3DGS / gsplat / nerfstudio Splatfacto）

**原理**：用一组带位置、协方差、不透明度、球谐颜色的 3D 高斯显式表示场景，GPU 光栅化实时渲染【A】[3DGS 论文](https://repo-sam.inria.fr/fungraph/3d-gaussian-splatting/)；Nerfstudio 的 Splatfacto 用 gsplat 作为光栅化后端【A】[Splatfacto](https://docs.nerf.studio/nerfology/methods/splat.html)。

| 项 | 说明 |
|---|---|
| 输入 | COLMAP/SfM 位姿 + 稀疏点初始化；透视图像；静态场景；全图训练 |
| 典型设备 | CUDA GPU；原版建议 24 GB VRAM 达论文质量【A】；Nerfstudio 默认 `splatfacto` 约 6 GB、`splatfacto-big` 约 12 GB【A】 |
| 单场景耗时 | gsplat 官方基准：Mip-NeRF 360、30k iter、**35m49s / 5.7 GB（单 GPU，A100 级）**；7k iter 约 5m35s【A】[gsplat Evaluation](https://docs.gsplat.studio/main/tests/eval.html) |
| 输出 | `.ply`（原始/压缩）；可转 `.spz`、`.sog`、`.splat` 等【A】【B】 |
| 几何可编辑性 | 低。可裁剪、缩放、旋转、删漂浮点，但**不是 mesh，不能布尔/碰撞/量尺寸**【A】【B】 |
| Web 可用性 | 好。Spark 是 three.js 的 MIT 3DGS 渲染器，WebGL2，支持桌面/移动/头显【B】[Spark](https://radiancefields.com/platforms/spark)；本项目已在用【C】 |
| 成本 | 开源训练免费；成本是 GPU 时间 + 人工清理；云服务按套餐/积分【B】 |

**关键限制（对西湖尤其重要）**：

- 水面/天空/远景是 SfM 初始化最稀疏的地方，3DGS 会“没东西可长”【A】[DomeGS](https://arxiv.org/pdf/2610.37172)；
- 动态游客/车辆会被“烤”进高斯，出现幽灵/拖影【A】[RobustSplat](https://arxiv.org/pdf/2506.02751v1)、[T-3DGS](https://arxiv.org/html/2412.00155)、[ForestSplats](https://arxiv.org/html/2503.06179)；
- 光照/曝光不一致需要外观建模（NeRF-W / GS-W / WildGaussians），但导出到 Web 后不一定保留【A】[NeRF-W](https://ar5iv.labs.arxiv.org/html/2008.02268)、[GS-W](https://arxiv.org/html/2403.15704)、[WildGaussians](https://wild-gaussians.github.io/)；
- 大面积场景单模型会过大，需要分块/层次 LOD【A】[Hierarchical 3DGS](https://repo-sam.inria.fr/fungraph/hierarchical-3d-gaussians/)。

### 2.4 混合路线：摄影测量粗模 + 人工精修 + 材质烘焙

**流程**：

```text
航拍/地面照片 → Metashape/COLMAP 空三 + 稠密重建 → 粗 mesh
→ Blender 重拓扑/补洞/分层 → UV + 纹理烘焙 → GLB
→（可选）3DGS 作为环境观感层
```

| 项 | 说明 |
|---|---|
| 输入 | 与摄影测量相同；最好有 GCP/RTK；需要现场尺寸复核 |
| 输出 | 可编辑 GLB（结构/家具/人物分层）+ 烘焙贴图；可选 SPZ 背景 |
| 几何可编辑性 | 最高；可碰撞、可量尺寸、可替换家具、可做 LOD |
| Web 可用性 | 最好；GLB + three.js，控制面数与纹理即可【A】 |
| 耗时/算力 | 重建小时级 + 人工清理/烘焙 **1–3 天/场景**（推断）【D】 |
| 成本 | 软件 + 人工最高；但资产可复用、可交付性最好 |

**烘焙依据**：Blender Cycles 支持把材质/光照/AO/法线烘到贴图，前提是 mesh 有 UV 和目标 Image Texture【A】[Blender Baking](https://docs.blender.org/manual/en/latest/render/cycles/baking.html)。

### 2.5 托管云重建（补充项：Aholo / Polycam / Luma 等）

| 项 | 说明 |
|---|---|
| 输入 | 照片或视频上传；通常要求环绕/多视角 |
| 输出 | 3DGS（PLY/SPZ/SOG）、mesh、全景；各家不同 |

| 成本 | 订阅制或按量；Aholo 定价未公开【C】；Polycam 订阅制（Business 约 $400/年/席位，Enterprise $1,200/年/席位起，官网口径）【B】[Polycam Pricing](https://poly.cam/pricing) |

## 3. 户外与景区场景的特殊问题

### 3.1 水面

**现象**：水面均匀、反射、波纹运动，SfM 找不到稳定特征；空三容易失败或在水中生成“坑/尖刺”【A】[Pix4D 水面说明](https://support.pix4d.com/hc/best-practices-for-image-acquisition-and-photogrammetry)、[Agisoft 论坛说明](https://www.agisoft.com/forum/index.php?topic=6976.0)。

**处理手段**：

1. **采集端**：每张图至少 3/4 画面是陆地/岸线等可识别特征；不要俯拍大面积开阔水面【A】。
2. **空三段**：对水面做掩膜，不参与特征匹配；必要时用“按参考坐标对齐”而不是纯特征匹配【B】。
3. **建模端**：水面单独做平面/网格 + 材质（反射、法线、颜色），不把照片纹理烘到水面【D】。
4. **3DGS 端**：水面高斯通常不稳定，建议裁剪掉，再用引擎水面替代【D】。

**对 Scendance**：西湖水面占比高，**不要承诺“重建水面”**；正确做法是“重建岸线 + 引擎水面”。这是本项目最应该提前和客户说清的一点。

### 3.2 天空

**现象**：天空无纹理、无几何；SfM 不生成点，3DGS 在远景/天顶稀疏，容易出现黑边、漂浮块【A】[DomeGS](https://arxiv.org/pdf/2610.37172)。

**处理手段**：

1. 裁剪掉高于场景包围盒/屋顶的高斯点（本项目已有 `roofCutoffY`）【C】。
2. 用天空渐变/HDRI/Skybox 补背景；本项目已有天空渐变兜底【C】。
3. 限制相机俯仰角，避免把“没有重建的天顶”暴露给客户【D】。
4. 全景图只做参考/环境贴图，不直接当训练输入【A】。

### 3.3 树木随风抖动

**现象**：叶片运动导致运动模糊、视角间不一致；植被纹理重复，匹配困难；3DGS 容易长出“雾状/毛刺”【A】[Pix4D 植被建议](https://support.pix4d.com/hc/best-practices-for-image-acquisition-and-photogrammetry)。

**处理手段**：

1. **选无风/微风时段**，风速大时直接改期【A】。
2. **短曝光**，减少叶尖拖影；Pix4D 的经验是如果超过 5% 图像有方向性模糊，就该提高快门【A】。
3. **提高重叠**：植被场景建议至少 85% 航向/旁向重叠【A】。
4. **分层**：近景树用 GLB 低模/卡片树，远景树接受 splat 的柔化；不要指望单棵树的枝条完全可编辑【D】。
5. 后期用 SuperSplat 删掉明显漂浮的叶片簇【B】。

### 3.4 游客与车辆

**现象**：人/车在曝光间隔内移动，重建出半透明人、拖影、幽灵车【A】[RobustSplat](https://arxiv.org/pdf/2506.02751v1)、[T-3DGS](https://arxiv.org/html/2412.00155)。

**处理手段**：

1. **采集端**：清晨/闭园后拍，减少人流；无法清场时，用长曝光? 不建议，反而更糊；应提高快门并接受后期清理【D】。
2. **掩膜**：用 SAM/语义分割把人物/车辆标为 transient，训练时降权或剔除【A】。
3. **算法端**：RobustSplat（延迟致密化）、T-3DGS（transient mask）、ForestSplats（可变形 transient field）都针对这个问题【A】。
4. **后期**：SuperSplat 框选删除、补洞；小面积残缺可接受【B】。

**对 Scendance**：基础场景应尽量“空场”；人物是布置资产，不该被烤进环境层。

### 3.5 逆光与光照不一致

**现象**：曝光跳变、阴影方向变化、颜色拼接；3DGS 会学到“每张图一套颜色”，换视角时闪烁【A】[NeRF-W](https://ar5iv.labs.arxiv.org/html/2008.02268)、[GS-W](https://arxiv.org/html/2403.15704)。

**处理手段**：

1. **锁定曝光/白平衡/ISO**，整场不自动跳【A】[Pix4D 相机设置](https://support.pix4d.com/hc/en-us/articles/202557419)。
2. **同一时段**拍完，避免太阳角度大幅变化；阴天/柔光最稳【A】。
3. **避免逆光**：逆光会让天空过曝、主体欠曝，空三直接掉点【A】。
4. **算法端**：NeRF-W 的外观嵌入、GS-W/WildGaussians 的外观建模可缓解，但工程复杂、Web 导出不一定保留【A】【D】。

## 4. 采集规范 checklist（可直接照着执行）

### 4.1 采集前

- [ ] 明确重建范围与边界（岸线、道路、建筑、树木），画出多边形。
- [ ] 查 UOM/适飞空域、临时管控通告；确认是否需要飞行申请。
- [ ] 向属地派出所/景区管理方报备；商业拍摄另办手续。
- [ ] 确认天气：**无雨、微风/无风、光照稳定**；避开正午硬光【A】。
- [ ] 设备：带 RTK 的行业无人机优先；地面用全画幅/手机主摄；备用电池与存储。
- [ ] 相机设置：**固定焦距、关防抖、手动对焦到无限远、ISO 最低、快门 1/300–1/800**【A】；整场锁定曝光/白平衡【D】。
- [ ] 记录：飞行日志、照片编号、控制点坐标、现场照片。

### 4.2 航线与重叠

| 场景 | 航向重叠 | 旁向重叠 | 说明 |
|---|---|---|---|
| 一般场景 | ≥75% | ≥60% | Pix4D 推荐下限【A】 |
| 可见光重建（DJI Terra 口径） | ≥80% | ≥70% | 适用于大部分场景【A】 |
| 森林/密集植被 | ≥85% | ≥85% | 还要提高航高、避开植被明显运动【A】 |
| 建筑/立面 | ≥80% | ≥70% | 环绕航线 2–3 圈，逐圈升高、逐圈降低俯仰；每 5°–10° 一张【A】 |
| 走廊（岸线/道路） | ≥85% | ≥60% | 至少 2 条航线，建议 3 条【A】 |

**高度层次**【A】【D】：

- 1 层：80–120 m 正射/倾斜，拿整体地形与岸线；
- 1 层：30–60 m 倾斜，拿建筑/树冠立面；
- 1 层：地面/低空环绕，拿近景纹理与遮挡区；
- 建筑/大树：2–3 圈环绕，每 5°–10° 一张【A】。

**张数估算**【D】：没有通用公式；按“航线数 × 每航线张数”估算。1–2 ha、2 cm GSD、80/70 重叠，通常是数百张量级；西湖岸线段建议先按 **200–400 张** 做样片，再按实测调整。此数字是推断，不是标准。

### 4.3 全景 vs 透视

| 类型 | 适合 | 不适合 | 说明 |
|---|---|---|---|
| 透视/鱼眼 | SfM、3DGS 训练、mesh 纹理 | 需要大范围天空/环境时不够 | 3DGS 光栅化假设透视相机【A】 |
| 全景/等距柱状 | 天空/环境参考、快速浏览、pano 展示 | 直接喂 3DGS/COLMAP | 需转 cubemap/多面透视，成本高【A】【D】 |
| 手机多摄 | 快速样片 | 混合不同镜头内参 | 固定主摄，不要中途切镜头【D】 |

### 4.4 曝光与色彩

- [ ] 整场锁定曝光、白平衡、ISO；不要用自动模式忽明忽暗【D】。
- [ ] 避免逆光、强烈高光、镜头眩光；水面反光要避开太阳角度【A】。
- [ ] 快门优先保证清晰：模糊图超过 5% 就提高快门【A】。
- [ ] 尽量 RAW+JPEG；保留原始文件，不改原图【D】。
- [ ] 同一天同一时段完成，避免阴影方向跳变【A】【D】。

### 4.5 地面控制点（GCP）与 GPS

| 项 | 建议 | 依据 |
|---|---|---|
| GCP 数量 | 最少 3 个，推荐 **5–10 个** | Pix4D【A】 |
| 分布 | 均匀覆盖，靠近重点对象，距边界至少一条航线 | Pix4D【A】 |
| 靶标尺寸 | GSD 的 **5–10 倍**（2 cm GSD → 10–20 cm 靶标） | Pix4D【A】 |
| 测量设备 | 全站仪（毫米级）或 GNSS（厘米级） | Pix4D【A】 |
| 普通无人机 GPS | 平面约 5 m、高程约 10 m | Pix4Dcloud【A】 |
| RTK/PPK | 约 1 cm + 2 ppm（平面/高程同量级） | Pix4Dcloud【A】 |
| 精度与 GSD | 平面约 1–2×GSD，高程约 2–3×GSD | Pix4D【A】 |

**对 Scendance**：编辑器按 scale=1 落位，**没有 GCP/RTK 就必须用已知基线（建筑边长、道路宽度）做尺度复核**；否则家具与点云比例会对不上【C】【D】。

### 4.6 拍摄时段

- 优先：**清晨/傍晚的柔光**，或**阴天均匀光**；阴影软、反差低【A】【D】。
- 避开：正午硬光（阴影短而硬、反差大）、逆光、太阳直射水面反光【A】。
- 避开：大风、降雨、雾霾严重时段；风会糊、雨会挂水珠、雾会丢特征【A】。
- 西湖实操：清晨游客少，利于“空场”；但要注意晨雾/逆光，先拍地面参考再飞【D】。

### 4.7 现场快速质检

- [ ] 抽查 20 张：清晰、曝光一致、无遮挡、无大面积水面；
- [ ] 确认相邻照片重叠足够（肉眼能看出同一物体在 3 张以上）；
- [ ] 确认 GCP 靶标在每个分区都可见；
- [ ] 确认没有漏拍岸线/建筑立面/树冠底部；
- [ ] 当天备份，原始卡不格式化。

### 4.8 素材入库

- [ ] 原始照片/视频只读备份；
- [ ] 导出 EXIF/GPS/飞行日志；
- [ ] 建立 `capture-YYYYMMDD/` 目录，记录航线、高度、重叠、相机参数、GCP；
- [ ] 生成一份 `capture-manifest.json`（后续 01 号文档可复用）。

## 5. 面向 Scendance 的推荐路径

### 5.1 目标资产

| 资产 | 格式 | 作用 | 验收 |
|---|---|---|---|
| 环境观感层 | `.spz`（优先）/ `.ply` | 实景背景、1:1 漫游 | 可加载、无黑洞、尺度正确 |
| 结构层 | `.glb` | 墙体/地面/固定结构、落地基准 | 与点云对齐、面数可控 |
| 家具/人物层 | `.glb` 或编辑器内资产 | 可编辑布置 | 与结构同尺度 |
| 参考全景 | `.jpg` | 天空/环境参考、发布卡 | 不参与训练 |

### 5.2 最短可行链路（推荐先跑）

| 步骤 | 工具 | 产出 | 验收 |
|---|---|---|---|
| 1. 重采 | 无人机 + 地面 | JPG/MP4 + GCP/尺度基线 | 覆盖、重叠、清晰 |
| 2. 云重建 | Aholo World（现有链路） | SPZ/PLY/pano | 任务成功、无大空洞 |
| 3. 落盘 | 本地资产代理 | `/asset/<uuid>.spz` | 可重复加载、地址稳定 |
| 4. 清理 | SuperSplat | 裁剪后的 SPZ | 无漂浮、无天空黑边 |
| 5. 结构 | 现有矢量壳，或 Metashape→Blender | GLB | 尺寸/朝向/层高正确 |
| 6. 进编辑器 | Scendance | 环境预览 + 布置 | 1:1、可漫游、可撤销 |
| 7. 发布 | 云端 | 只读链接/二维码 | 资产已上传（当前缺口） |

**工作量判断**：这条链路不追求 mesh，**最快能在 1 个样片周期内看到“像不像”**；但 Aholo 户外 Beta 是最大不确定性【C】。

### 5.3 可控链路（Aholo 不达标时）

| 步骤 | 工具 | 产出 |
|---|---|---|
| 1. 空三 | COLMAP / GLOMAP（视频先抽帧） | 相机位姿 + 稀疏点 |
| 2. 训练 | gsplat / nerfstudio Splatfacto | `.ply` |
| 3. 清理 | SuperSplat | 裁剪/去漂浮 |
| 4. 转格式 | SplatTransform | `.spz` / `.sog` |
| 5. 结构 | Metashape/COLMAP 稠密 | mesh → Blender → GLB |
| 6. 烘焙 | Blender Cycles | 贴图/法线/AO |
| 7. 验收 | 编辑器 + 量尺 | 资产契约 |

**优点**：参数可控、可复现、可批量；**缺点**：需要 GPU、需要人、链路长【D】。

### 5.4 混合交付链路（客户要“可编辑/可量尺寸”）

```text
摄影测量 mesh（结构/地形）
+ Blender 重拓扑/补洞/分层
+ 纹理烘焙 → GLB（结构层）
+ 3DGS（可选，仅观感层）
+ 编辑器内家具/人物资产
```

**判断标准**：如果客户要改墙、改地面、算面积、做结构分层，**必须走这条**；3DGS 只能当背景【A】【C】。

| 维度 | 权重 | 通过线（建议，需现场校准） |

### 5.6 验收标准（建议写入项目）

**硬性**：

- [ ] 尺度：两个已知点距离误差 ≤2%（建议值）。
- [ ] 覆盖：主要漫游区无大于 0.5 m 的洞/漂浮（建议值）。
- [ ] 天空：无黑色破洞；水面无“坑”。
- [ ] 资产：SPZ 可加载；首屏 ≤10 s（目标）；目标设备 ≥30 fps。

- [ ] 合规：有空域/报备/商拍记录。

- [ ] 无严重拖影/幽灵人；颜色连续；远景模糊可接受。
- [ ] 原始素材、工程文件、训练参数、GCP 记录齐全。

### 6.2 主要风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| 空域/报备不批 | 无法航拍，链路停摆 | 先办许可；改用地面+高处机位+摇臂；必要时换非管制点位 |
| 水面/天空重建失败 | 画面“坑/黑边” | 水面/天空引擎替代；裁剪高斯；限制机位 |
| 游客/车辆幽灵 | 观感差、不可用 | 清晨拍；掩膜；RobustSplat/T-3DGS；SuperSplat 清理 |
| 风/雨/雾 | 空三失败、模糊 | 改期；短曝光；提高重叠；现场质检 |
| Aholo 户外质量不达标 | 样片失败 | 本地 gsplat 兜底；或走摄影测量混合 |
| 单模型过大 | 加载慢/显存爆 | 50–100 m 分块；LOD/Streamed SOG；按需加载 |
| 尺度/对齐错误 | 家具与点云不匹配 | GCP/RTK；已知基线复核；编辑器内变换校准 |
| 云发布缺资产 | 客户扫码看不到 | 先补云端上传；发布前检查 |
| 隐私/肖像 | 合规风险 | 避开人群；掩膜；发布前审查 |
| 商业拍摄许可 | 被劝停/处罚 | 按景区经营服务规定办理；寺庙等点位单独确认 |

### 6.3 明确的未知项

1. **Aholo World 在西湖这类“大水面 + 远山 + 游客”场景的实际质量**：没有公开案例，必须样片验证【待核实】。
2. **Aholo 户外重建的计价/额度**：未公开【C】。
3. **西湖景区对无人机航拍的最新报备流程**：公开信息只有媒体口径，需向景区公安/管理方确认【待核实】。
4. **素材本身**：01 号文档已核查完毕，结论是**不能重建**（0/32 可用 GPS、24 张原地旋转全景、无尺度、夜间）；本报告不假设存在可用素材【C】。
5. **目标设备的性能基线**（桌面/移动/头显）：需要实测帧率与首屏【D】。

1. **接受 01 的结论**：现有素材只做全景氛围参考；不安排任何基于它的重建任务，避免浪费算力。
