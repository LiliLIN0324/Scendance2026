## 0. 结论先行

**六项能力没有一项是「从零开始」，真正的缺口是「同一件事有五套口径、五处入口」。**

| 能力 | 判断 | 一句话 |
|---|---|---|
| 多角度效果图 | 部分有 | 单张 PNG 可选整体/俯视/正面机位；没有批量、没有机位命名、没有图册 |
| 场景漫游 | 部分有 | 编辑器有第一人称漫游；客户侧只有轨道环绕；无导览、无录制 |
| 物料清单 | 部分有（且重复严重） | CSV/评审包/发布页/Agent/到场清单各算一套，口径与字段不一致 |
| 方案分享 | 已有 | 云端只读 `/view`（3D+物料+版本冻结）与免登录 `/review`（2D+钉）双轨 |
| 客户评审 | 部分有 | 画内钉 + 离线评审 HTML；**反馈只写本机 localStorage，不回传创作者** |
| 执行资料导出 | 已有（入口散） | 交接 HTML、时间表、活动安排/执行/物料 CSV、GLB、场景 JSON 七种；图纸能力写好未接线 |

**必须先解决的三个冲突**

1. **物料清单五套口径**：`file-io.ts` 的死代码按全楼层+价格导出；`scene-delivery.ts` 按资产版本聚合；`agent-panel.tsx` 只算当前层；`share-menu.tsx` 只给分类计数；`/view` 用服务端发布快照。同屏出现两个数字就会毁掉客户信任。
2. **导出入口五处**：画布导出圆钮、发布卡片四宫格、执行资料「导出」tab、评审包、Agent 对话文案。用户不知道该去哪。
3. **三条死链路仍在仓库里**：`handleScreenshot`、`downloadInventoryCsv`、`downloadSceneAsGlb`/`handleShareLink` 只有测试引用，维护者会误以为它们是现役能力。

**建议顺序（价值/成本比）**：多角度效果图 → 物料清单收口 → 分享卡片文案收敛 → 图纸接线+交付清单 → 客户评审回传 → 漫游导览。
前四项**都不需要后端**，可以先把「客户能直接看到、能带走」的东西做扎实；评审回执可先走无后端的导出/导入，只有「跨设备实时同步」才需要新后端。

**不要新建「交付中心」。** 客户版收进现有发布卡片，执行版收进现有执行资料「导出」tab，两项各加一张卡即可。

## 3. 设计（每项最小可行形态）

**总原则**：不新增一级导航；客户版放发布卡片，执行版放执行资料「导出」tab；每项一个卡片 + 一个主动作 + ⓘ 承担全部解释；不堆表单、不要求用户逐项勾选。

### 3.0 统一命名（所有导出共用）

```
<项目名slug>_v<revision>_<类别>[_<楼层或序号>].<ext>
类别 ∈ 效果图 | 效果图册 | 物料清单 | 执行清单 | 活动交接 | 执行时间表 | 平面 | 评审回执
```
例：`西湖共创_v3_效果图_01-整体.png`、`西湖共创_v3_物料清单.csv`、`西湖共创_v3_平面_1F.dxf`。
项目名去 `\\/:*?"<>|` 与空白（沿用 `plan-export/download.ts:9-24` 的 slug 规则）；未命名项目用 `未命名活动`；未发布用 `v0`。

### 3.1 多角度效果图 — 机位册（建议第一个做）

- **交互**：现有「导出效果图」弹层（`scendance-workspace.tsx:524-538`）里，视角那一行末尾加一个「机位册」图标钮（`View`/`GalleryVerticalEnd`，仅图标 + `aria-label`）。选中后 CTA 文案从「导出 PNG」变为「导出 5 张」；预览框显示当前机位缩略图，ⓘ 里写明「5 张：整体 / 俯视 / 正面 / 入口人视 / 主景人视，2×，PNG + 图册 HTML」。
- **机位集合**：沿用 `iso/top/front` 三个已有预设；新增 `entry`（`layout.entrance` 前方 1.6 m、朝向场内）与 `stage`（首个 zone 或最大物件质心、1.6 m 人眼高）。没有入口/分区时自动降级为 3 张，并在 ⓘ 说明。
- **产出**：N 张 PNG（命名见 3.0，序号 01..N）+ 1 份 `..._效果图册.html`（图 + 机位名 + 项目名 + 日期，`@page A4`，可打印为 PDF）。无水印、无内部字段。
- **复用**：`captureRenderImage`（`use-import-export.ts:87-129`）逐机位抓图；图册模板照 `projectReviewHtml` 的 CSP 与打印样式（`project-review.ts:485-506`）；下载用 `downloadTextFile`/`downloadDataUrlAsPng`（`plan-export/download.ts:26`、`file-io.ts:282`）。
- **新建**：`shot-list.ts`（机位定义 + 由 layout 推导 entry/stage）、批量调度与进度（顺序执行，避免同时抬 pixelRatio）、图册模板。
- **后端**：不需要。
- **不做**：全景图、视频、HDR/景深等渲染参数。

### 3.2 物料清单 — 一个口径，三种视图

- **唯一数据源**：`deliveryMaterials`（`scene-delivery.ts:38-55`），因为它带资产版本、来源、许可与采购状态，且与 GLB/场景 JSON 同源。
- **三种视图（同一份数据投影）**：
  - `summary`：品类×数量（发布卡片大纲、Agent 摘要），**必须带楼层范围**；
  - `customer`：名/规格/颜色/数量（评审包、发布页），隐藏采购状态与 SHA；
  - `execution`：全量字段（CSV、执行资料）。
- **交互**：不新建表单。执行资料「导出物料清单 CSV」保持不变；发布卡片大纲改为读同一投影；Agent「出物料清单」保留对话形态，但首行改为「物料清单 · 本层（1F）· N 件 / 全场地 M 件」，避免和左栏对不上；到场清单标题补楼层名。
- **产出**：`..._物料清单.csv`（执行版）；`..._物料清单.html`（客户版，打印 PDF）。
- **复用**：`sceneDeliveryCsv`、`renderMaterials`、`planOutline`。
- **新建/清理**：`material-inventory.ts` 三个投影函数；删除 `downloadInventoryCsv`（`file-io.ts:119-149`）与其中的 `Price` 列——`price` 目前只服务 2D 平面的「单件价格/面积」提示（`canvas-2d/render.ts:991-994`）与成就统计，交付类清单全都不读它，更不应出现在客户版。
- **后端**：不需要（`/view` 物料来自发布快照，保持现状）。

### 3.3 方案分享 — 双轨讲清楚，不合并

- **交互**：发布卡片（`share-menu.tsx:186-253`）保持一张卡；在两种链接旁各加一个 13px 图标 + 一行短标签，ⓘ 里放对照表：
  - 「云端方案页」`/view`：需登录发布，3D + 物料 + 版本冻结，适合正式发客户；
  - 「轻量评审页」`/review`：免登录，2D + 钉，适合快速收意见，**不含 3D/物料**。
- **产出**：链接（不落地文件）；复制时附带一行「项目名 v3 · 幕景」便于客户识别。
- **复用**：`publishVersion`、`issueReviewLink`、`QRCode.toString`（`share-menu.tsx:126-133`）。
- **新建**：无（文案与 ⓘ 结构调整）。
- **后端**：已有（发布态）。风险：签名资源 TTL ~300s（`app/view/page.tsx:29`），需在卡片 ⓘ 写明「长时间未打开请刷新一次」。
- **不做**：新的分享中心、密码保护、下载权限（P3）。

### 3.4 客户评审 — 先做「回执可带走」，再做「真同步」

- **V1（无后端，本周可做）**：`/review` 的「完成评审」旁加一个图标动作「导出评审回执」，产出 `..._评审回执_<planKey>.json`（钉文本/对象名/时间/完成态）；工作台议题卡加「导入回执」（粘贴或选文件），把钉并入现有 `reviewPins` 并标来源「客户」。
- **V2（需后端）**：发布 token 复用为评审 token，新增 `POST/GET /share/{token}/comments`（新表 + Edge Function），工作台在打开评审 Agent 时拉取；`/review` 页面把 localStorage 作为离线缓存。
- **复用**：`ReviewPin` 结构（`lib/review-pins.ts:39-88`）、议题卡、`ProjectReviewPanel` 的离线 HTML（作为无网兜底）。
- **产出（V1）**：回执 JSON；评审包 HTML（已有）。
- **新建（V1）**：回执 schema + 导出/导入动作；**（V2）**：评论表与接口、跨设备合并策略（按 pin id 去重）。
- **价值**：V1 只解决「能带回来」，V2 才解决「客户在自己手机上点完，创作者立刻看到」。

### 3.5 执行资料导出 — 交付清单 + 接线图纸

- **交互**：执行资料「导出」tab（`scene-delivery-panel.tsx:271-284`）顶部加一张「交付包」卡：6 行图标清单（平面 SVG / 平面 PDF（打印）/ DXF / 物料 CSV / 执行 CSV / 活动交接 HTML），一行状态（齐/缺 + 原因收进 ⓘ），一个主动作「按顺序导出」。不弹表单、不要求逐项确认。
- **产出**：上述文件（统一命名）+ `..._交付清单.csv`（文件名、类别、生成时间、件数、缺失原因）。无 ZIP 依赖时用顺序下载（浏览器会提示一次「允许多个下载」）。
- **复用**：`sceneExecutionCsv`、`sceneDeliveryCsv`、`eventOperationsCsv`（`scene-delivery.ts:113-139`）、活动交接与时间表 HTML（`scene-delivery-panel.tsx:273,275`）、`layoutToDxf`、`openPlanPrintWindow`。
- **新建**：导出清单卡 + manifest 生成；把 `print.ts`/`dxf.ts` 接到同一卡片（当前仅测试引用）。
- **后端**：不需要。
- **不做**：ZIP（需新依赖 jszip；先顺序下载）、模型资产打包（`/view` 已给客户）。

### 3.6 场景漫游 — 导览优先，录制延后

- **交互**：3D 工具栏现有漫游入口保留；新增「导览」= 按 3.1 的 5 个机位顺序飞行（每段 3 s、可空格暂停），复用 `flyDestination`/`lerpReviewCamera`（`lib/review-pins.ts:88-116`）与 `use-camera-fly`。漫游/导览激活时导出圆钮置灰，ⓘ 说明「先退出漫游再导出」。
- **产出（V1）**：无可下载文件（现场演示）；**V2**：`MediaRecorder` 录 `canvas.captureStream()` 15 s（WebM，Safari 降级为「不提供录制」）。
- **复用**：`use-walkthrough`、`flyDestination`、发布页 `ScenePreview` 的轨道控制（客户侧至少可环绕）。
- **新建**：导览状态机与机位序列；V2 录制器。
- **后端**：不需要。
- **风险**：3DGS 场景依赖 `walkBounds`（`room-organizer.tsx:1338`），缺失时导览只能走预设机位、不能自由行走；需要明确禁用文案而不是静默失效。

## 4. 优先级

评分：成本 1（低）–5（高）；客户评审价值 1–5；比值仅作排序参考。

| 序 | 能力项 | 成本 | 价值 | 比值 | 建议动作 | 验收标准 |
|---|---|---|---|---|---|---|
| 1 | 多角度效果图（机位册） | 2 | 5 | 2.5 | 弹层加一个图标 + 批量抓图 + 图册 HTML | 一次动作产出 5 张命名正确的 PNG + 1 份可打印图册；3 分钟内完成；无内部字段 |
| 2 | 物料清单收口 | 2 | 4 | 2.0 | 一个投影函数、三视图；删死代码与价格列；补楼层标注 | 同屏三处数字一致（左栏/Agent/CSV）；空场景是空态不是空表头 |
| 3 | 分享卡片讲清双轨 | 1 | 3 | 3.0 | 文案 + ⓘ 对照表；复制附带项目名与版本 | 新用户不看文档能说清两个链接的区别；客户手机扫码 5 分钟内可看 |
| 4 | 执行资料交付清单 + 图纸 | 2 | 3 | 1.5 | 一张清单卡 + 接线 print/DXF + manifest | 6 件产物命名一致、可离线打开；缺失项有原因 |
| 5 | 客户评审回执（V1） | 2 | 4 | 2.0 | `/review` 导出回执 + 议题卡导入 | 手机端 2 条钉 + 完成态可带回工作台并显示 |
| 6 | 客户评审同步（V2） | 4 | 5 | 1.25 | 评论表 + 接口 + 拉取合并 | 两台设备 60 s 内看到同一条钉；离线仍可写 |
| 7 | 漫游导览（V1） | 3 | 3 | 1.0 | 5 机位顺序飞行 + 暂停 | 演示中可完整走完 5 段；退出后相机可正常编辑 |
| 8 | 漫游录制（V2） | 4 | 3 | 0.75 | 15 s WebM | 文件可播放、时长/分辨率正确；不支持浏览器明确降级 |

**执行建议**：1→2→3 同一批做（都改导出/清单相关文件，回归面小）；4/5 第二批；6 单独排期（后端）；7/8 放最后，避免拖慢前四项。

## 5. 可执行验收场景

> 前置：`frontend` 独立端口 dev（不动 3000），mock 后端自动登录 `dev@mock.local`；每个场景跑完留截图。

**S1 · 多角度效果图**
1. 打开有 20+ 物件的 3D 场景，灯/天气为默认。
2. 点画布右上「导出效果图」→ 选「机位册」→ 2×。
3. 点「导出 5 张」，等待进度结束。
4. 预期：下载 5 张 `*_效果图_01-整体.png … 05-主景人视.png` + `*_效果图册.html`；每张无黑边、无 UI；HTML 离线打开图片齐全，打印预览 A4 不横溢。
5. 反例：无入口/无分区的场地只出 3 张，ⓘ 给出降级说明；2D 视图下机位册置灰。

**S2 · 物料清单一致性**
1. 两层场地，1F 放 80 套桌椅、2F 放 10 把椅子。
2. 左栏「到场清单」应显示「1F · 80 套」；Agent 问「出物料清单」应显示「本层 80 件 / 全场地 90 件」。
3. 执行资料导出物料清单 CSV：总数量 90，行含资产版本/来源/采购状态。
4. 评审包 HTML 物料概览：90，且无采购状态、无 SHA。
5. 发布 `/view`：物料表 90。
6. 反例：空场地导出应给「还没有物料」空态，不产生只有表头的 CSV。

**S3 · 分享双轨**
1. 保存并发布 v3 → 扫码打开 `/view`：3D 可旋转、物料表与大纲一致、链接显示「已发布 v3」。
2. 复制「轻量评审页」→ 无痕窗口打开 `/review#layout=…`：2D 平面 + 物件 + 可落钉，页面明确「不含 3D」。
3. 分享卡片 ⓘ 能回答：两种链接要不要登录、含不含 3D、客户能不能留言。

**S4 · 客户评审回执（V1）**
1. 手机打开评审页，落 2 条钉（一条物件、一条地面），点「完成评审」→「导出评审回执」。
2. 工作台议题卡「导入回执」→ 议题出现 2 条，标「客户」来源，可标记已解决/退回布置。
3. 刷新工作台后，导入的钉仍在（写入 layout 或持久化层，而非仅内存）。
4. 反例：回执 planKey 与当前方案不符 → 明确提示「不是这一版」，不静默丢弃。

**S5 · 执行资料交付包**
1. 完成需求、点验、活动任务后，打开执行资料「导出」。
2. 点「按顺序导出」：得到 `平面_1F.svg`、`平面_1F.dxf`、`物料清单.csv`、`执行清单.csv`、`活动交接.html`、`执行时间表.html`、`交付清单.csv`。
3. 全部离线打开：HTML 可打印；DXF 可被 CAD 打开且图层名可读；CSV 数量与 S2 一致。
4. 反例：点验未完成时主动作禁用，ⓘ 写明缺哪一项；场景含场馆预设时 GLB 行标「不支持，保留原文件」。

**S6 · 组合验收（P2-5 定义场景）**
> 「导出 3 个角度效果图 + 一份物料清单 PDF + 发一条分享链接」
1. 机位册降级为 3 张（整体/俯视/正面）→ 得 3 PNG + 图册。
2. 图册打印为 PDF，另存 `物料清单.html` 打印为 PDF。
3. 发布 v3，复制云端方案页链接发给客户；客户页面能看 3D 与物料。
4. 全程 ≤ 10 分钟，无需打开任何设置表单。

## 6. 风险与边界

| 风险 | 说明 | 处理 |
|---|---|---|
| 发布页资源 TTL | 签名 URL 约 300 s，超时显示「资源已到期」 | ⓘ 写明；必要时加「刷新资源」主提示（已有按钮） |
| 3DGS 场景导出 | 漫游/截图依赖 splat 就绪与 `walkBounds` | 未就绪时禁用并给具体原因，不静默失败 |
| GLB 交付限制 | 含场景预设/建筑入口扩展直接拒绝 | 清单行标注「不支持」，给「保留原文件」替代 |
| 跨源纹理 | 截图前若纹理未开 `crossOrigin` 会污染画布 | 沿用现有 `reviewSceneAssetsReady` 就绪门（`use-review-capture.ts:32-49`） |
| 评审同步一致性 | V1 回执可能重复导入 | 按 pin id 去重 + planKey 校验 |
| 多文件下载 | 浏览器可能拦截连续下载 | 首次提示「允许多个下载」；不做 ZIP |
| 定价字段 | `price` 只有 2D 平面/成就在用，交付清单不读，报价能力并不存在 | 物料 CSV 删除价格列，不假装有报价能力 |
