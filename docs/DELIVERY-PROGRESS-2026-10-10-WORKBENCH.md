# 幕景 · 工作台与执行资料版本更新

2026-10-10。开发分支 `codex/delivery-research-20261007`，前一上传基线 `3e65023`，包版本仍为 0.6.0。本批把活动任务建议、合同原件、场景与执行文件接入同一工作台；本文记录冻结代码与本机验证结果，不表示正式云或完整承办平台已经完成。

## 这次解决的问题

活动资料可以逐步整理，但生成建议不代表任务已经保存，保存失败也不能清掉原稿。现在用户在原“活动安排”里选择需求、任务和物件，查看发送摘要后请求建议，勾选并保存；完成保存读回后，任务进入原列表及执行时间表。网络结果未知时查询同一请求，避免再次生成或重复添加。

工具和素材采用常驻紧凑底栏、按需展开的素材架，给画布保留空间。顶栏和助手入口沿用户已确认的布局，资料分类、聊天及输入框设置各有固定位置。工具切换不重启助手请求或清除草稿。

“合同与约定”位于资料分类中，可以登记客户委托和供应外包资料、保留草稿与固定版、保存并下载原件、记录人工签署报告及更正、预检并恢复独立商务原件包。金额、时间和主体未定时保持未知；签署报告及收付款计划只是人工记录，不代替验签、付款或开票。

## Agent 与数据保存

- 活动任务建议使用独立请求和结果，只发送明确选择的摘要。不隐式读取合同原件、照片地址、人员承诺或内部费用；自由文本仍须用户核对。
- 建议只含任务标题、阶段、完成条件及已披露物件引用。确认后追加新的待办，既有记录保留；人员、时点、实际执行状态及证据仍由用户填写。
- 发送前保留请求编号，完整结果只准备一次稳定的本机任务编号。保存未核实时保留原稿和拟写结果，不提前显示成功。
- 运行中或一次异步操作期间的身份、租约及来源变化拒绝迟到结果。已完成建议可在同账号重新授权后重核并使用；90 秒运行截止不是另加的确认期限。首次保存前查询原运行，已取消或变化的结果不能确认。
- 场景修改的共享构建入口检查选中范围；checkpoint 保存异常会停止后续模型和工具，已有有效结果可查询找回。

隐藏页面时立即尝试保存当前布局，成功后更新状态并使旧计时器失效；失败保留待保存状态供重试。核对已提交任务时保留当前几何，随后修改的尺寸与角度继续正常保存。合同原件和执行事实保持自己的存储及历史，不随几何撤销删除。

## 公共模型与资源打包

公共模型仅从已核目录编号解析。合法大写 UUID 使用同一目录模型，存档与缓存标识保持原文。有自定义地址时先保留其成功加载；失效后只有精确目录别名，或当前可信来源下匹配同编号、同文件摘要的签名路径，才允许恢复。未知、私有和无法确认的地址保持原错误，交付拒绝占位模型。

标准构建必须执行 `npm run build`，包含现有资源打包步骤。直接执行 `next build` 的早期验收副本缺失模型文件，已保留为历史失败证据；新的完整打包副本包含模型库和模板资源。两份完整副本沿同一基线、1950 个源文件和 60 个冻结覆盖文件。

## 已有实际证据

- 合同资料：本机保存重开、PDF 原字节下载、固定历史、独立包预检恢复、两页面冲突保稿和退出保护已演练。原件与恢复 24 项核对通过。
- 空活动：从零任务查看摘要、发送、勾选保存、刷新后保持同一条待办。
- 30 人明确演练：原 20 项任务保持，新增后 21 项；刷新保持同一编号。CSV 21 行和原执行时间表均包含新任务，新任务人员、时点与证据仍为空。独立下载比较显示布局只增加这一任务。
- 恢复边界：隐藏保存三项及新页、同页核对已提交任务后继续修改几何两项，真实 Hook 独立检查由红转绿。
- 公共模型：完整打包后的实际浏览器冷开与刷新能显示真实折叠椅；原编号和原加载地址不被写回替换。实际导出 GLB、场景 JSON、交接 HTML 与原下载字节一致；GLB 含场地及源模型真实网格，导出文件并非源模型文件的逐字节复制。
- 已核受控签名失效的两次实际 403 后读取本地模型 200，目标原编号及原地址保持，实际输出场地与真实模型；该演练不代表真实账号到期已经验证。自定义 404 分支保留原地址且未产生占位 GLB 下载。另一个独立浏览器中，已知公共编号加自定义私有地址的受控 403 显示原错误、原标识和地址保留；两次私有请求后没有读取公共替代模型或导出占位文件。

测试数量分别按 API、客户端、领域模块、组件及真实浏览器记录，交叉覆盖不相加作为产品总分。越界主目录构建及根目录整套检查不计本候选验收。所有版本来源和原始下载位于本机 `development-evidence`，不会随代码发布原始资料。
