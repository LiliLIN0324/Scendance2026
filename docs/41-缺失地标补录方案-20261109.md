## 4. 与现有 4,961 条的衔接

### 4.1 ID 体系

现有 key 就是 OSM way id 字符串（如 `"4298707"`）。建议：

| 类型 | id 形如 | 说明 |
| --- | --- | --- |
| OSM way | `"159184108"` | 保持现状，不加前缀 |
| OSM 关系（multipolygon building） | `"r<relation_id>"` | 现有脚本不解析 relation，将来支持时加 `r` 前缀 |
| 手工描边 / 聚合地标 | `"x-baochu-ta"`、`"x-hangzhou-gate"` | `x-` 前缀，可直接看出非 OSM |

约束：**消费端必须把 key 当不透明字符串**。已知 `hangzhou-map-lab/iso.js` 用 `heightById[way.id]`（way.id 为数字），`x-`/`r` 条目它读不到；主仓当前无消费者。若将来要接渲染，先统一 schema。

### 4.2 高度来源等级

现有 `source_grade` 只有 A/B/C/D，`CONF` 只有 survey/osm_height/osm_levels/cnbh/typology。补录需沿用 `osm_height`，并**新增两类**：

| 新 source | grade | value_kind | 适用 |
| --- | --- | --- | --- |
| `osm_tag`（沿用 `osm_height`） | B | mapped | 六和塔 59.89、雷峰塔 71.7 这类 |
| `manual` | A* | measured | 保俶塔 45.3、环球中心 170、来福士 250、万象城 230、杭州之门 310（公开总高，非图纸实测）。**不建议**直接写 `survey`，否则违反 `OWNERSHIP.md`「measured 仅限现场实测」 |
| `manual_trace`（轮廓手工、高度无源） | C | derived | 净慈寺/岳庙聚合条（无公开总高），高度按同区 typology 或主殿檐高，`confidence` ≤0.5 |

> A* 的落法沿用 docs/40 §「A* 不等于 A」：`source_grade=A`、`confidence≈0.80`，`confidence_reason` 写「媒体口径总高」。这样不污染 A 级「现场实测」语义。

### 4.3 重跑不被覆盖（关键）

`build-building-heights.py` 是 `out[r["id"]] = rec` 全量重建，任何不在 OSM 输入里的记录都会消失。三种落法：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **S1 overlay 文件（推荐）** | 新增 `data/landmark-footprints.geojson`（手工轮廓 + 高度 + 来源），脚本加 `--landmarks` 参数，在 OSM 记录之后按 id 合并/覆盖 | 改脚本 1 处、加数据文件 1 个；重跑稳定 |
| S2 直接改 OSM 文件 | 把手描轮廓写成 way 追加进 `xihu-ring.osm` | 污染源数据、破坏 sha256 口径、map-lab 只读不能写 → **否决** |
| S3 只改 JSON | 手工编辑 `data/building-heights.json` | 违反 `OWNERSHIP.md`（唯一写入方是脚本）→ **否决** |

overlay 里需要 `id / name / footprint(GeoJSON Polygon) / height_m / height_source / source_grade / confidence / confidence_reason / anchor_osm_id`。脚本用解析 OSM 的同一套函数算面积，保证 `area_m2` 口径一致。

### 4.4 补丁 OSM 的收集方式

- 新建独立目录（建议 `D:\Scendance2026\scendance-map-data\`，与 map-lab 完全无关），存 `landmark-*.osm`；主仓只留脚本与 overlay geojson，原始 OSM 不进版本库（`.gitignore`）。
- 合并复用 `merge-osm.cjs` 的算法（读 `ring-*` → 去重 way → 写单文件），在主仓新写一份等价脚本，**不调用 map-lab 的脚本**（避免对其目录产生任何写副作用；只读引用 `xihu-ring.osm` 作基底）。
- 最终 `--osm` 指向「旧 xihu-ring.osm + 新补丁」的合并结果，`--sample-osm` 与 `--cnbh` 仍指 map-lab 原文件（只读）。

## 6. 风险

1. **重跑覆盖**（高）：不做 overlay，手工条目下次重跑必丢。这是本方案的第一优先级。
2. **OSM 漂移**（中）：同框重抓会让既有 4,961 条中部分 id/面积/高度变化；必须用「旧文件 + 补丁」而不是「新抓全量替换」。
3. **CNBH 对高层系统性低估**（中）：docs/40 已坐实（世贸 25.4 vs 72、城隍阁 25.1 vs 41.6）。200 m+ 塔若落到 CNBH 支路会被压到 40 m 上下甚至退回 D（6 m）。所有地标必须显式给 `osm_height`/`manual`，并在脚本里让显式高度优先于 CNBH。
4. **关系未解析**（中）：脚本只 `root.findall("way")`。扩大范围后商场/寺庙若是 multipolygon relation 会整条漏掉；本次实测九栋里未见 building relation，但范围内其他大建筑未查（800 系列查询两次遇 502，**未验证**）。
5. **轮廓语义错配**（中）：净慈寺 47,847 m²、岳庙 17,330 m² 是园区/宗教用地，不是楼体；整块挤出会出现「一块大板」。六和塔 way 845 m² 也可能不是塔体。
6. **六和塔定位存疑**（中）：OSM way 与公交站相距约 320 m；如果实际塔在西侧山坡则没问题，若不符需人工修正，否则塔会立在错误位置。
7. **地形高程**（中）：保俶塔在宝石山、六和塔在月轮山，塔基高度必须从 DSM/地形取，否则悬空或埋地；本轮未测这两处地形高。
8. **双轨数据**（低）：主仓 schema 2 与 lab 纯数字版互不兼容；补进主仓后渲染侧仍看不到，需要单独对接。
9. **许可**（低）：OSM 数据 ODbL-1.0，对外交付需署名；手工轮廓若描自卫星影像，注意影像版权，建议只做「几何近似」并在产源字段注明。
