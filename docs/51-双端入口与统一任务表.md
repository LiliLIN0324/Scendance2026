# 51 · 双端入口与统一任务表（2026-11-05）

> 结论先行：**一个账号、一张任务表、两个入口。**
> 小程序只收「现场 20–40 张照片」，网页收「整段视频 / SD 卡素材」。两端读写同一条 `recon_jobs`，不做两套状态。
> 上传通道是命门：**Aholo 只认自己资产库里的文件**。正确链路是「预签名/临时凭证直传 Aholo OUS → 拿资产记录（`obsTaskId` + `status.url`）→ 用资产记录建任务」；把外部 URL 直接塞给重建接口会被 502 拒掉。

## 0. 决策表

| 场景 | 入口 | 依据 |
| --- | --- | --- |
| 现场拍 20–40 张照片，一小时内看粗模 | **小程序** | `wx.uploadFile` 单文件上限 10MB、无断点续传；切后台 5 秒挂起，锁屏/来电必掉。只适合小体量、即时反馈 |
| 相机视频 / SD 卡导出的整段素材 | **网页** | 浏览器可分片直传（5MB/片）、可续传、有真实进度，可挂机跑几十分钟；单文件到 512MB |
| 结果查看、编辑、导出 | **两端都可达** | 同一张任务表、同一份产物；小程序看状态/预览/链接并转交网页编辑，网页做完整 3DGS 预览与导出 |

**小程序不做视频。** 不是「暂不支持」，是四条硬约束同时成立：录制最长 60 秒、单文件上传 10MB、后台 5 秒挂起、官方没有断点续传 API。

## 1. 地图是场景的地面层，不是独立模块

地图不是单独页面、单独坐标系，也不是叠加在 3D 上的一层贴图。它是**3D 场景里的一个层**，和场地几何共享同一个相机、同一个原点、同一套米制尺度。

- **投影规则**：有地理锚点时，地图瓦片按 `sceneAnchor`（原点经纬度 + 正北朝向 + 米制尺度）投影到 3D 地面，像高德一样铺在地面上；相机移动时底图跟着地面走。
- **三态不是三套系统**：`sceneAnchor` 有 `geo` / `manual` / `null` 三种数据源；它们共用同一个场景坐标、同一套锚点推导、同一条渲染路径。细节见 §11。
- **只有一套地面坐标**：场景里不允许存在第二套地面坐标。`mapGroundFrame` 就是第二套，它是「底图跑到 350km 外」这个 bug 的根因；用「差值超 3km 就清掉」来掩盖问题，本身就是错的。
- **关键澄清**：SfM 重建给的是**相对几何**，不是绝对位置。它知道相对距离与角度，不知道经纬度、正北、真实尺度。所以「重建自带地图信息」成立的前提，是有一个 `sceneAnchor` 把相对几何钉到地球上；`null` 态不做绝对定位，也不需要这个前提。
- **分类修正**：真实地图与真实场地不是两条独立能力。**场地是重建出来的那块几何，地图是它脚下铺开的那张底图**，它们共享同一个 `sceneAnchor`。拆成两条是多余的。

落地口径：

| 项 | 规则 |
| --- | --- |
| `sceneAnchor` | 三态：`geo`（经纬度 + 朝向 + 米制尺度）/ `manual`（人工原点、朝向、尺度）/ `null`（无地理锚点）；场景建立时写一次，之后任何时刻可改，不自动锁定 |
| 底图挂载 | `geo` / `manual` 铺真实瓦片；`null` 只铺 1m 网格地面；三态共用同一场景坐标，不再有独立 `mapGroundFrame` |
| 锚点缺失 | `null` 是默认入口，不是兜底：1m 网格地面、无底图；不退回第二套坐标 |
| 漂移判定 | 底图与场地偏差 **3km** 是错误，不是容差；只允许米级误差 |

## 2. Agent 的边界：不参与地图

Agent 只解决「场景内怎么摆、怎么活动」，不解决「场地在哪」。

- **输入永远只有三样**：已定位好的场景 + 场景内的物件 + 用户意图。
- **工具集里没有地图类能力**：不搜地点、不切城市、不算路线、不改 `sceneAnchor`。
- **职责是场景内的活动与布置**：摆家具、调布局、生成方案、解释场景；不是「帮用户找场地」。
- **三态一致**：不管 `sceneAnchor` 是 `geo`、`manual` 还是 `null`，Agent 都只看场景内物件与意图，不读 anchor。
- **视图层负责底图渲染与锚定**：底图铺不铺、铺在哪、朝哪，由视图层按 `sceneAnchor` 决定，不经过 Agent 决策。

一句话边界：**地图是场景的底座，Agent 是场景里的导演；底座不归导演管。**

## 3. 具体技术依据

### 3.1 小程序侧（能查到数字的都写数字）

| 约束 | 数字 / 事实 | 对产品的影响 |
| --- | --- | --- |
| 单文件上传 | `wx.uploadFile` 上限按 **10MB** 设计（微信社区答复口径；API 文档未写死，真机上线前复测） | 一张 3–8MB 照片可以；一段 1080p/60s 视频约 80–150MB，必超 |
| 网络并发 | `wx.request` / `wx.uploadFile` / `wx.downloadFile` 合计最大 **10 个** | 40 张照片不能一把并发；按 3–4 个一批，或顺序传 |
| 后台运行 | 进入后台 **5 秒**后 JS 线程挂起；5 秒内未结束的网络请求回调 `fail interrupted`；回前台前接口不可调用 | 用户锁屏、来电、切微信聊天，上传就断 |
| 断点续传 | 官方无断点续传 API；`wx.uploadFile` 是整文件一次性请求 | 中断的当前文件只能从 0 重传，已传完的文件不重传 |
| 本地文件 | 本地缓存 + 本地用户文件合计 **200MB** | 40 张 × 8MB = 320MB 会顶到上限；超限时先压到长边 2048 / q80（约 0.8–1.5MB/张） |
| 视频录制 | `wx.chooseMedia` 的 `maxDuration` 最大 **60 秒** | 只够小场景一圈；相机视频/SD 卡整段素材不在小程序 |
| 服务器域名 | 只支持 HTTPS，不支持 IP；域名需 ICP 备案，新备案 **24 小时**后可配置；每个小程序最多 **300 个**域名；普通账号每月 **5 次**修改（第三方平台代管 50 次） | 上传域名必须提前进白名单；不能中途换域名试错 |
| 文件选择 | `wx.chooseMessageFile` 单文件 **10MB**；不能读 SD 卡/外接盘路径 | 「从微信聊天拿素材」也只到 10MB |
| 打开网页 | `web-view` 需配置**业务域名**（ICP 备案 + 校验文件） | 小程序内不能随手嵌工作台；编辑入口走「带 ticket 跳浏览器」 |

补充：上传期间必须 `wx.setKeepScreenOn({ keepScreenOn: true })`，并在界面写一句「上传时请保持小程序在前台」。这是降低中断概率，不是解决中断。

### 3.2 Aholo 侧（真调实测）

| 事实 | 证据 |
| --- | --- |
| 只收资产库文件，外部 URL 一律拒 | ZCode **12 次**提交全报 `HTTP 502 … 文件链接不对，请使用 资产 模块相关接口上传文件`；同期视频创建另被拒 **16 次**，未受理不计费 |
| 图片运行时失败 | `3FO4K4RKJ4MW` / `3FO4K4RKJ1AV` 均 `FAILED progress=1`，`assets.splats.urls` 全 null，响应无失败原因 |
| 视频路线可成功 | `3FO4K4RKK337` 产出 `pavilion-0194-normal.spz` **23.2MB**；同批 0194 的 normal 任务耗时 **12.6 分钟**，low 档 **8.5 分钟** |
| 资产上传形态 | `POST /asset/v1/token` 取一次性 `ousToken`；单文件 ≤ `blockSize−256KB` 走 `ous/api/v2/single/upload`，否则按 `blockSize`（默认 **5MB**）走 `block/upload/init` + `block/upload/part`；同一个 token 轮询 `upload/status?md5=` 换 `status.url` |
| 凭证与索引 | `ousToken` **一次性**，跨文件复用报「Token已被使用」；上传完成到资产可查有 **0–12 分钟**不定的传播窗口，窗口内建任务报「文件链接不对」 |
| 建任务必填头 | `POST /world/v1/reconstructions` 必须带 `x-source: openapi`（未写进文档；缺头报误导性「文件链接不对」） |
| 素材规则 | 图片至少 **20 张**；图片与视频不可混传；视频 `mp4/mov/insv`，代理单文件上限 **512MB** |
| 失败与计费 | 创建即扣费、失败全额退（实测 2–11 分钟退回）；low/normal/high = **20/50/80** 积分；失败原因不通过 API 暴露 |

链路展开：

```text
后端 POST /asset/v1/token（国内网关 api.aholo3d.cn）
  → 返回 ousToken / globalDomain / blockSize
客户端直传 OUS（单文件或 5MB 分片，请求头 ous-token-v2）
  → 同一 token 轮询 /ous/api/v2/upload/status?md5=
  → 得 obsTaskId + status.url
后端写 recon_assets（asset_id = obsTaskId，asset_url = status.url）
  → POST /world/v1/reconstructions，带 x-source: openapi
  → resources[].url = asset_url（Aholo 目前只收 URL，没有单独的 assetId 参数）
```

**「用资产 ID 建任务」的落地口径**：Aholo 对外暴露的是资产记录 URL，不是 `assetId` 字段。任务表里同时存 `asset_id`（`obsTaskId`）和 `asset_url`（`status.url`）；建任务时传 `asset_url`。排查时用 `asset_id` 对账。

### 3.3 网页侧

| 能力 | 数字 / 事实 |
| --- | --- |
| 分片直传 | 按 OUS `blockSize`（默认 5MB）分片，浏览器逐片 PUT/POST；断点从「已完成片数」续，不从 0 |
| 单文件上限 | 代理 `/recon-upload` **512MB**；5 段西湖夜间视频实测最大 **488MB** |
| 挂机时长 | 单个任务上传 30–60 分钟可接受；页面前台需保持，系统睡眠/断网后靠分片续传 |
| 后端不中转 | Supabase Edge Functions 最大执行 **150s（Free）/ 400s（Paid）**、内存 **256MB**；几十 MB–GB 级上传不能走后端转发，只能签名后直传 |
| 结果编辑 | 现有 `:3000/editor` 工作台直接接 `jobId`，加载 `.spz` / `.ply`，可继续摆放、改方案、导出 |

不选的两种「对象存储」也在这里写清：

- Supabase Storage：Free 单文件全局上限 **50MB**，Pro 可到 **500GB**；标准上传最大 **5GB**，官方建议大于 **6MB** 用 TUS。它能传，但 Aholo 仍然不认这个 URL。
- Cloudflare R2：单 PUT **5GiB**，分片大小 **5MiB–5GiB**、最多 **10,000 片**、单对象 **5TiB**。同样解决不了「Aholo 只认自己资产库」。

## 4. 一个账号

账号本体是 `account_id`，不是「小程序 openid」或「网页 Supabase user」。两种登录方式都只是挂到同一个 `account_id` 上的入口。

| 表 | 关键字段 | 作用 |
| --- | --- | --- |
| `accounts` | `id / created_at` | 唯一账号；任务、订单、额度都挂它 |
| `account_links` | `account_id / provider / external_id` | `provider=wechat` 时 `external_id=openid`；`provider=supabase` 时是网页 user id；`(provider, external_id)` 唯一 |
| `handoff_tickets` | `id / account_id / direction / expires_at / used_at` | 一次性跨端交接，**5 分钟**失效，用后作废 |

两条绑定路径，都不需要用户填表：

1. **小程序 → 网页**：结果页点「在网页继续编辑」→ 后端签发 ticket → 打开 `https://<web>/auth/handoff?ticket=…` → 网页换出 session，并把当前 Supabase user 链到该 `account_id`。
2. **网页 → 小程序**：任务页显示二维码（内含 ticket）→ 小程序 `wx.scanCode` → `POST /auth/handoff/claim` → openid 链到该 `account_id`。

规则：

- 小程序首次启动 `wx.login` → `POST /session` 换 openid；没有 `account_links` 就静默建一个账号，无登录 UI。
- 绑定前免费额度用设备键 `owner_key` 兜底（沿用 `docs/45`）；绑定后一律按 `account_id` 计，避免双端各算 3 次。
- 绑定只迁移「未提交/未结算」的任务与订单；已成功的任务保持原 `account_id`，只做只读展示。

## 5. 任务表

### 5.1 主表 `recon_jobs`

一条任务 = 一次重建计费单位，不是一张照片。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | uuid PK | 是 | 两端共用的任务号 |
| `account_id` | uuid | 是 | 账号主体 |
| `source` | text | 是 | `miniprogram` / `web`；记录发起端 |
| `media_type` | text | 是 | `image` / `video` |
| `asset_count` | int | 是 | 图片张数或视频段数 |
| `frame_count` | int | 否 | 视频抽帧数；图片任务等于 `asset_count` |
| `duration_seconds` | numeric | 否 | 视频总时长；图片为 null |
| `capture_meta` | jsonb | 否 | 层数、覆盖度、评分、GPS 覆盖；小程序现场快检结果 |
| `scale_source` | text | 是 | `manual`（用户填已知长度）/ `reference`（参照物，后续）/ `none` |
| `scale_meters` | numeric | 否 | `manual` / `reference` 时有值；`none` 为 null |
| `scene` | text | 是 | `space` / `model` |
| `quality` | text | 是 | `low` / `normal` / `high` |
| `status` | text | 是 | 见 5.3 状态机 |
| `progress` | numeric | 否 | 仅服务端进度，0–1；拿不到就 null，不造数 |
| `provider` | text | 是 | 固定 `aholo` |
| `provider_job_id` | text | 否 | Aholo `worldId` |
| `error_code` | text | 否 | `UPLOAD_INTERRUPTED` / `PROVIDER_FAILED` / `QUOTA_EXHAUSTED` / `TIMEOUT` / `EXPIRED` |
| `error_message` | text | 否 | 一句中文；Aholo 不给原因时固定为「重建服务未返回原因」 |
| `up_axis` | text | 否 | `X` / `Y` / `Z` / `unknown`；产物坐标轴，来自 `semanticsMetadata.upAxis`，缺省按 `Z` 处理 |
| `outputs` | jsonb | 否 | `{ spz, ply, lod, pano, glb, raw }`；Aholo 原始产物 + 我们归一化的 GLB |
| `size` | jsonb | 否 | `{ w, d, h, unit: 'm' }`；归一化后的场地尺寸 |
| `normalized` | boolean | 否 | GLB 是否已按 Y-up、底面贴 y=0、水平居中处理 |
| `upload_state` | jsonb | 是 | `{ file_name, file_size, part_size, parts_total, parts_done, upload_id, md5, last_error }` |
| `consumption_id` | uuid | 否 | 对应 `scan_consumptions`，用于失败返还 |
| `idempotency_key` | text unique | 是 | `job:{account_id}:{client_ref}`；防双端重复建任务 |
| `client_ref` | text | 是 | 端本地 id；离线重放/上传恢复用 |
| `created_at` / `updated_at` | timestamptz | 是 | 两端都按 `updated_at` 判断是否要重拉 |
| `finished_at` | timestamptz | 否 | 终态时间 |
| `expires_at` | timestamptz | 是 | 未提交素材 **24 小时**过期；过期后 `status=expired` |

### 5.2 子表 `recon_assets`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | text PK | Aholo `obsTaskId`（对外称资产 ID） |
| `job_id` | uuid | 归属任务 |
| `kind` | text | `image` / `video` / `insv` |
| `name` | text | 原文件名 |
| `bytes` | int | 文件字节数；用于对账和 512MB 上限 |
| `sha256` | text | 去重；同一账号重复素材不重复上传 |
| `asset_url` | text | OUS `status.url`；建任务时传给 `resources[].url` |
| `uploaded_at` | timestamptz | 上传完成时间 |
| `status` | text | `uploaded` / `missing` / `expired` |

约束：`(job_id, sha256)` 唯一；`asset_url` 只在 `status=uploaded` 时可空转。

### 5.3 状态机与进度

```text
draft → uploading → uploaded → submitted → queued → processing → succeeded
                                     ↘ failed / cancelled
draft / uploading / uploaded → expired（24h 未提交）
```

| 状态 | 谁写 | UI 文案 |
| --- | --- | --- |
| `draft` | 客户端建任务 | 「准备上传」 |
| `uploading` | 客户端 + 后端片进度 | 「已传 12/30」；中断时附「继续上传」 |
| `uploaded` | 后端校验资产 | 「素材已就绪，待提交」 |
| `submitted` | 后端 | 「正在创建任务」；通常 <1 秒 |
| `queued` | 后端 | 「排队中」；Aholo `QUEUED/PENDING/INITIALIZING` |
| `processing` | 后端 | 「重建中 · 约 X 分」；Aholo `RUNNING/PROCESSING` |
| `succeeded` | 后端 | 「已完成」；挂 `outputs/size/up_axis` |
| `failed` | 后端 | 「失败 · 次数已退回」；挂 `error_code` |
| `cancelled` | 客户端 | 「已取消」 |
| `expired` | 定时任务 | 「素材已过期，重新上传」 |

进度规则：

- `progress` 只放 Aholo 的 0–1 进度，不做前端平滑假进度。
- 上传进度单独放 `upload_state.parts_done / parts_total`，不和重建进度混成一根条。
- Aholo 失败固定回 `progress=1` 且无原因；UI 直接进失败态，不停在 99%。

### 5.4 两端怎么共享同一条记录

| 规则 | 做法 |
| --- | --- |
| 同一任务号 | 两端 URL 都带 `jobId`：网页 `/jobs/:id`，小程序 `pages/result?jobId=` |
| 同一份读写 | 只有 7 个最小接口，两端调同一套 |
| 谁写什么 | 客户端只写 `source/media_type/asset_count/frame_count/duration_seconds/capture_meta/scale_*`；`status/progress/provider_job_id/outputs/error_*` 只由后端写 |
| 上传归属 | 上传中的任务只有**发起端**能续传（文件在本机）；另一端只读进度，不接管文件 |
| 提交幂等 | `POST /jobs/:id/submit` 带 `idempotency_key`；一端提交后另一端再点只返回既有 `worldId` |
| 轮询 | 小程序前台 15 秒一次，网页 10 秒一次；进终态即停；重新打开先 `GET /jobs/:id` |
| 切换设备 | 素材已在 Aholo 资产库，换设备不需要原文件；只能继续查看/提交/导出 |

最小接口：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/v1/jobs` | 建 `draft`，返回 `jobId` 与上传计划 |
| POST | `/v1/jobs/:id/assets/sign` | 取该文件的一次性 `ousToken/domain/blockSize` |
| POST | `/v1/jobs/:id/assets/complete` | 回写 `asset_id/asset_url/sha256/bytes` |
| POST | `/v1/jobs/:id/submit` | 预扣额度 + 建 Aholo 任务（带 `x-source: openapi`） |
| GET | `/v1/jobs/:id` | 状态、进度、产物、错误 |
| POST | `/v1/jobs/:id/retry` | 复用资产重试；受重试规则约束 |
| POST | `/v1/jobs/:id/cancel` | 取消未终态任务 |

## 6. 两端职责边界

| 能力 | 小程序 | 网页 | 为什么 |
| --- | --- | --- | --- |
| 现场拍照 / 相册选图 | ✅ 20–40 张 | ✅ 也可以 | 小程序原生相机、就地快检、微信分享；网页是补充 |
| 视频 / SD 卡整段素材 | ❌ | ✅ | 视频 60s 上限、单文件 10MB、后台 5s 挂起、无续传；整段素材动辄 100–500MB |
| 上传方式 | `wx.uploadFile` 逐文件 | 5MB 分片直传 | 小程序无分片 API；网页按 OUS `blockSize` 分片 |
| 断点续传 | ❌ 只能整文件重传 | ✅ 从已完成片数续 | 官方无续传 API；浏览器可记录 `parts_done` |
| 切后台 / 锁屏继续传 | ❌ 5 秒挂起 | ✅ 前台可挂机 | 微信运行机制；浏览器页面在前台即可 |
| 现场快检（模糊/覆盖/尺度） | ✅ 完整 | ✅ 部分 | 两端共用 `capture-guide` 阈值；小程序已有离线快检 |
| 建任务 / 查进度 | ✅ 前台可 | ✅ | 同一套接口 |
| 看结果 | ✅ 状态 + 4 张预览 + 链接 | ✅ 完整 3DGS 预览 | 小程序不内置 3DGS 渲染器；`web-view` 还要业务域名 |
| 编辑 | ⚠️ 转交网页 | ✅ 完整工作台 | 小程序没有 3D 编辑器；编辑入口用 ticket 跳浏览器 |
| 导出 | ⚠️ 分享链接 / 预览图 / 文件卡片 | ✅ GLB / SPZ / PLY | 小程序下载到本地后受 200MB 与分享形态限制；原文件以网页下载为准 |
| 支付 | 微信虚拟支付（待开通）+ 广告 | 支付宝 | 两套通道都挂同一 `account_id` 与同一额度账本 |
| 分享 | ✅ 微信会话 / 朋友圈 | ✅ 链接 | 小程序天然在微信内 |
| 直传外部 URL 给 Aholo | ❌ | ❌ | 两边都不行；必须先进 Aholo 资产库 |

**「结果查看、编辑、导出两端都通」的准确定义**：

- 「查看」两端都能看到同一条任务与同一份产物，网页多看完整 3DGS。
- 「编辑」两端都有入口；小程序不重写编辑器，只把 `jobId` 和 ticket 交给网页工作台。
- 「导出」网页直接下载原文件；小程序给分享链接、预览图和文件卡片，重产物以网页为准。

## 7. 失败与重试

| 情况 | 触发 | 后端动作 | 用户看到 | 重试规则 | 计费 |
| --- | --- | --- | --- | --- | --- |
| 上传中断 | 小程序切后台/锁屏/来电；网页断网/睡眠 | 保留已完成的 `recon_assets`，写 `upload_state.parts_done`，任务停在 `uploading` | 「上传中断：已传 12/30 · 继续上传（不扣次数）」 | 小程序从下一个文件继续，当前文件从 0；网页从已完成片数继续，重选同一文件按 `sha256` 对齐 | 未提交，不扣 |
| 任务 FAILED | Aholo 返回 `FAILED progress=1`，无原因 | 置 `failed`，写 `provider_job_id`；调 `/scan/release` 返还 | 「重建失败（服务端未返回原因）· 任务号 3FO4… · 1 次已退回」 | 图片任务：不自动重试（当前图片通道是 Aholo 侧 bug，重试=白烧调用），只给「改拍视频」/「仍要重试」；视频任务：自动 1 次同资产重试，再失败就提示按 70% 重合度重拍 | 失败自动返还，净消耗 0 |
| 额度用尽 | `POST /submit` 返回 402 `INSUFFICIENT_CREDITS` | 任务保持 `uploaded`，不删素材，不建 Aholo 任务 | 「今日免费 0/3 · 明日 00:00 恢复 · 看广告 +2 · 4.9 元 1 次 / 9.9 元 3 次 / 29.9 元 10 次」 | 看广告或购买后对同一 `jobId` 再提交，不重传 | 未建任务，不扣 |

补充规则：

1. **先查额度再上传**。入口先 `GET /quota`；额度为 0 时直接出三栏，不让用户白传 300MB。最终裁决仍在 `submit` 的 402，防并发。
2. **中断不自动重试**。上传中断只恢复游标；重建失败才谈重试。
3. **超时也返还**。任务 30 分钟无终态 → `failed / TIMEOUT` + `/scan/release`，与 `docs/45` 的 `pay_release_stale` 同一条规则。
4. **素材 24 小时过期**。`expires_at` 到点置 `expired`；再传重新建任务，不复用过期资产。
5. **失败必须可对账**。失败页永远显示 `worldId`；Aholo 不给原因就写「服务端未返回原因」，不猜、不编。
6. **不在失败后无限重试**。图片通道在官方修复前禁止自动重试；视频自动最多 1 次。

## 8. 决策记录

### ADR-01 为什么是两个入口，不是一个端全包

- **问题**：能不能只做网页，或只做小程序？
- **结论**：双端，共用一张任务表。
- **否决 A「只做网页」**：现场拍照要开浏览器、登录、处理相机权限；弱网下首屏与上传都重，微信里分享不出结果。
- **否决 B「只做小程序」**：小程序传不了整段视频（10MB/5s/无续传），相机与 SD 卡素材没有入口。
- **代价**：两端都要维护入口 UI；用统一任务表与统一接口把分叉压到最小。

### ADR-02 为什么小程序不做视频

- **问题**：小程序也能 `chooseMedia` 录 60 秒视频，为什么不做？
- **结论**：不做，视频只走网页。
- **否决「60 秒够用」**：单文件 10MB 上限，1080p/60s 约 80–150MB，`wx.uploadFile` 直接失败。
- **否决「分片传」**：官方没有分片/断点 API；后台 5 秒挂起会让分片状态半途而废，自己拼分片仍躲不过挂起。
- **否决「压到 10MB」**：压到 10MB 要降分辨率/帧率，Aholo 视频通道靠抽帧配准，压完大概率重建失败；压缩本身还发热、耗时。
- **证据**：`docs/22` 已把 `maxDuration:60` 接进小程序，但 S5 直传仍卡在后端；`docs/49` 的视频成功样本是 26 秒/整段，不是压缩片段。

### ADR-03 为什么必须是「直传 Aholo 资产库」，不是「给个公网 URL」

- **问题**：把 Supabase Storage / R2 的公网 URL 直接传给 Aholo，不就行了？
- **结论**：不行。Aholo 只认它资产库里的文件。
- **证据**：12 次提交全报 502「文件链接不对，请使用 资产 模块相关接口上传文件」；文件公网可达性 98/98 正常，content-type 正确，重编码新对象也一样。
- **否决「Supabase 中转」**：Free 单文件上限 50MB，且 Aholo 仍不认它的 URL；多一跳只多一个失败点。
- **否决「R2 中转」**：R2 能传 5GiB/10,000 片，但同样过不了 Aholo 的资产库校验。
- **否决「后端转发」**：Supabase Edge Functions 150s/400s、256MB，512MB 视频与几十分钟上传不现实；后端只签名，不搬字节。
- **采用**：`/asset/v1/token` → OUS 直传 → `status.url` → 建任务。

### ADR-04 为什么只有一张任务表

- **问题**：小程序、网页各建一张表，不是更解耦？
- **结论**：一张 `recon_jobs`，用 `source` 区分发起端。
- **否决「两张表」**：双写必然分叉：一端 `processing`、另一端 `failed`；重复提交会重复扣次；用户切换端看到两个状态。
- **代价**：字段要容得下两种素材；用 `media_type/frame_count/duration_seconds` 三个字段覆盖，不另开表。

### ADR-05 为什么小程序不内置编辑器，只做转交

- **问题**：结果查看、编辑、导出都说「两端都通」，为什么不干脆在小程序里做编辑器？
- **结论**：查看与导出在小程序做轻量版；编辑转交网页。
- **否决「内置 3DGS 编辑器」**：小程序主包 2MB、现有包已 1.42MB；3DGS 渲染器 + 工作台塞不进去，真机 WebGL 也未验证。
- **否决「web-view 直接嵌」**：`web-view` 需要业务域名（ICP 备案 + 校验文件），当前结果页已明确降级为「复制链接到浏览器」。
- **采用**：结果页「在网页继续编辑」用一次性 ticket 拉起网页，账号与任务不断。

## 11. 无 GPS 与真空世界：`sceneAnchor` 三态

`sceneAnchor` 不是「有」或「没有」的布尔值，而是三种数据源。**这是一条渲染路径的三种数据源，不是三套系统。**

| 状态 | 底图 | 适用 |
| --- | --- | --- |
| `geo` | 真实地图瓦片，按经纬度锚定 | 户外、素材带 GPS |
| `manual` | 真实瓦片，原点经纬度/朝向/尺度由人指定 | 室内、商场、地下、GPS 漂移 |
| `null` | 1m 网格地面，无地理底图 | 还没有场地，纯概念推敲 |

**禁令：不允许为「真空世界」另起一套坐标系或另一套渲染管线。** 那会退回到「两套坐标打架」的老病。三种状态共用同一个场景坐标与同一套锚点推导；只换数据源，不换世界。

五条判断：

1. **`null` 是默认入口，不是兜底。** 首个使用场景就是「没素材、没场地，先摆一摆」。硬要求先选地点是门槛，不符合默认路径。
2. **渐进增强**：`null` → 摆东西 → 想落地 → 补一个地点 → 变成 `manual` 或 `geo`。地点任何时刻都可（改）编辑，不能自动锁定。
3. **尺度来源**：`null` 态用 **1m 网格**（可切 **0.5m / 2m**）作为尺度参照；用户在格子上摆放即自洽，不需要先知道真实尺寸。
4. **Agent 三态行为一致**：它只看场景内，不看 anchor。`geo/manual/null` 都只影响视图层的底图与锚点推导，不进入 Agent 的输入或工具集。
5. **离线能力**：`null` 态不依赖瓦片、GPS、网络；断网也能新建、摆放、保存草稿。

状态迁移只允许这几种，且不自动发生：

```text
null ──补地点──→ manual ──有可信 GPS──→ geo
  ↑                 │                    │
  └────清空地点─────┴────清空地点────────┘
geo ──GPS 漂移/改地点──→ manual
```

不允许的反向操作：`geo/manual` 不能自动降级为 `null`；清空地点必须由用户明确触发。`null` 也不是「未锚定错误」，它就是一个合法的最终状态。
