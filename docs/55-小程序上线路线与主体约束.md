## 2. 个人主体：能做什么、什么时候必须换公司

微信 2026-08-31 起向**个人主体**开放了小程序虚拟支付，「必须先注册公司才能收钱」这条旧口径已经过时。
以下是 2026-11 核对的官方口径：

| 能力 | 个人主体 | 什么时候必须换企业 |
| --- | --- | --- |
| 小程序上线、发布 | ✅ | — |
| **虚拟支付**（卖重建次数，正是我们的形态） | ✅ 硬条件：**服务类目含「工具」** + 已认证 + 已备案；月限额 **¥10 万** | 月流水 > 10 万；要做实物/电信资质类目 |
| 费率与账期 | Android 1% T+3；**iOS 12%（Apple 佣金），结算 45–60 天** | 需要更低费率/更快回款 |
| 流量主广告 | ✅ 门槛 **累计 UV ≥ 100**（2026-11 从 500 下调到 100） | — |
| 赞赏（用户打赏开发者） | ✅ 平台 **0 抽成** | — |
| 普通微信支付（卖实物） | ❌ | 要卖实物时 |
| 微信开放平台**移动应用 / 多端框架**（`project.miniapp.json` 已配鸿蒙/Android/iOS，`app.miniapp.json` 绑了开放平台账号 `gh_5945d22ed79a`） | ⚠️ 个人主体可注册开放平台账号，但**高级能力受限**；移动应用上架应用市场需企业资质认证（¥300/年） | 要发布成独立 App / 上架 |
| 对公结算、合同、发票、团队协作 | ❌ | 公司要签 B 端合同 |

**判断：个人主体够用。** 现在做的是「验证有没有人愿意为一次重建付 ¥9.99」，个人主体的月限额、
0 抽成赞赏、100 UV 的广告门槛都远够这个阶段。真到需要的时候再开公司主体、迁移数据，
成本远低于现在卡在这里等。

> 主体迁移不是「以后再说」就零成本：主体从个人变企业/个体户，小程序 AppID 本身可以保留
> （同一主体下换），但**类目、备案、支付商户要重新走一遍**。所以现在按工具类目做，
> 以后换主体时改动最小。

## 3. 关键路径（阻塞依赖图）

```
① 小程序 ICP 备案 + 个人认证（¥30/年，企业 ¥300）   ← 必须账号本人扫码，审核中
        ↓
② 已 ICP 备案 + 境内接入的 HTTPS 域名  ← ★ 最容易被低估的一步
   （不能用 Supabase 境外域名，不能用 Cloudflare Pages 的 *.space）
        ↓
③ 小程序后台配 request / uploadFile / downloadFile 合法域名 + 校验文件
        ↓
④ 后端：把 web 端已跑通的 /recon-upload → /world-recon 暴露成
   匿名 + 限流 + 一次性任务 token 的入口（README「重建服务契约」那张表）
   —— 额度侧（/scan/consume、/scan/release）已经有了，不用重写
        ↓
⑤ miniprogram/config.js 填 API_BASE → services/recon.js 自动切 real
        ↓
⑥ 类目选「工具」→ 后台开虚拟支付 → 拿 OfferID / 现网 AppKey → 道具管理发布道具
   （后端还要补一条 /pay/virtual/order 签单路由）
        ↓
⑦ UV 破 100 → 开流量主（广告做独立收入，不换次数）
```

**② 与 ④ 是关键路径上唯二的技术活，①③⑥⑦ 是账号本人操作。**
本轮已经把 ⑤ 的接线做完（填上域名即生效），把 ⑥ 的前端接线做完（见 `docs/46` §5），
把额度侧的前后端契约对齐（A-7）。
