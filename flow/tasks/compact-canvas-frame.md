# 素材架、工具轨道与助手共享画布空间

2026-10-10，来自用户五张 PetitMaker 参考截图及直接反馈。优先于上一段示例文案清理；已完成的关闭资料与草稿保护保留。

## 现状实测

导演独立 Chrome 使用当前 3157 已发布固定包，未操作用户浏览器存档。1280×720：工作区高644px，素材架300px，画布仅264px；打开助手后画布896×264，助手340px。561×720：素材架仍300px；助手打开后同尺寸浮层覆盖工作区，底层虽有545×324画布，却不可见。这些是布局问题，旧的按钮避让检查不足以证明完整地图可见。

## 学习依据

固定上游 Stry233/PetitMaker 4e120e50c844198649454eec6069ac65a062a732。FrameLayoutProvider 按 dock-inset 剩余空间统一提供 plan；ObjectShelf 分类与搜索同一行，卡片固定单排；railClearanceFor 只避让与工具相交的带。借鉴空间计算和交互结构，不复制其美术与资产。

本地3D ResizeObserver 只改变 aspect，原 fitToRoom 只按场地标量确定距离；窄画布可能继续裁切。因此真正减少画布与按新比例取景都要验，不能仅CSS移动按钮。2D已有按viewWidth/viewHeight计算transform，独立核其实际边界。

## 改动与所有权

原“幕景 · 前端交付流程”独占共享UI、必要视图连接；导演不并行改这些源文件，只做参考核对、真实浏览器验收和交接记录。保现有米白/绿色、原素材添加/拖放/历史和隐私门禁，不重写引擎或新建导航平台。

- 素材按需展开为紧凑单横排，桌面目标160–190px，低屏更紧；分类搜索不堆多行，文件大小等次要信息按需。
- 长横工具条改画布侧边分组图标，保视图/缩放/适应场地/撤销/重做/截图/网格等原动作和可访问名称。
- 助手打开预留宽度，画布、工具与素材架消费同一剩余空间；窄屏用明确可用的分区或切换，不能留下不可操作的细条或隐形叠层。
- 面板切换不修改活动数据，不变聊天模式，不覆盖草稿；相机布局适应不在输入或每个动画帧重置用户视角。
