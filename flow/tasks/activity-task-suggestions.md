# 活动上下文与任务建议：先接同一业务真源

2026-10-10。AIHOT源码候选2来自用户“学习优化幕景”与既有活动策划执行目标；不是把资讯评分搬成现场事实。当前Agent只读Scene/brief，活动任务只有人工/演练模板入口，缺口已在aihot-code-adoption-20261010.md指出。

## 本段范围

原后端对话独占新增frontend/lib/activity-task-suggestions.ts与activity-task-suggestions.test.ts。实现可供现有任务面板组合的纯领域函数，root审定下列边界；前端继续独占UI与存储接线。不得改共享EventOperations schema、其他owner文件、导航、模型/API、数据库、依赖或运行服务。该模块完成不称真实Agent生成/完整UI流程完成。

1. 当前持久layout.id、资料性质、用户明确选择的活动需求文本和任务/场景物件白名单形成可预览的只读上下文。没有明确编号拒绝，不用公共local回退。资料来自当前真源，不创建第二份任务库；任务有效状态可用operationReview派生。联系人/承接团队、合同、原件、证据地址、图纸照片、私有资产URL、内部费用不隐式纳入摘要；选定自由文本仍可能含个人信息，须让UI显示发送前预览，模块不能声称自动脱敏。
2. 来源指纹绑定本段相关输入与项目，提示过期在本机判断。指纹用途是检测输入变化，不是事实核验或权限凭证；无需含每次镜头/主题/选择状态。白名单摘要的界限清楚，与本机一致性依据分开。
3. 建议仅允许标题、阶段、完成条件，以及可明确对应当前已披露物件的引用；不允许模型写任务ID、完成状态、实际时间、证据、付款/金额/人员承诺。当前不自动填计划时间或负责人，确认后可沿原界面人工补。字符串、数量和重复/失联引用按已有limits/schema拒绝，资料性质保当前类型。
4. 建立待确认建议时使用现有createOperation等能力一次生成稳定的新任务ID；未确认不产生任何业务写入。来源说明保在提案元数据，不把技术hash串塞进用户的完成条件，不扩正式task schema。
5. 人工勾选后仅返回追加的新todo草稿与当前EventOperations合并结果，保全部原任务/ID/人工修改，不改场景或工作单。项目或相关输入变化拒绝旧建议。一次接纳后提案由UI关闭；重复同批确认不追加重复ID，不用同名任务去覆盖已有任务。已经追加后用户手改该新任务，重复接纳不改回；部分接纳后的剩余建议可失效重生成，不为支持无限分批引入复杂重基机制。
6. 模块不执行持久保存或外部请求。UI后续需把结果走现有更新/保存/flush与身份守卫；失败保提案与原记录，原ID重试不重复追加。必须明确数据调用与实际业务保存的责任，不能只在内存返回成功就说活动已保存。

异步接线边界：纯函数同步冻结输入后可能等待有效状态/指纹计算，不能观察调用后的UI编辑。前端应在调用前保存当前活动/相关资料基线，await返回后、写入前再检查最新身份和相关资料是否仍等于基线；不把返回的accepted解释为已保存。复用现有immutable layout/ref与scope epoch守卫，不新建全局事件总线。随后真实保存核实，才闭合receipt。

## 采用依据及验收

接口确认补充：buildActivityTaskContext/prepareActivityTaskSuggestions/acceptActivityTaskSuggestions三函数可组合。一次生成proposal与稳定草稿IDs；accept只返回拟写operations和极小闭合receipt，caller真实保存核实后才持有receipt并关闭。保存失败不能预先关闭。重复携正确project/proposal/acceptedIDs receipt仅返回当前记录，不复活用户已删任务、不回卷人工改动；无receipt撞已存ID明确拒绝。没有EventOperations的新项目也应能使用，由caller显式提供资料性质（包括未指定），不猜actual/rehearsal；已有性质或实际参与制作/点验依据不一致则拒绝。模块不新增receipt存储库或后台。

已读AIHOT当前输入revision围栏、人工更正优先及业务/结果共用读取层；活动输出的可执行步骤用项目已审runbook方法，专业内容按professional-skill-basis.md，不编造安全/成本/法规阈值。

用同一30人演练输入与明确标示“合成建议”的响应验证：未确认不修改；白名单没有隐藏资料；有效状态不同于原accepted记录；跨项目/改需求/原任务/关联物件后过期；非法字段/重复引用拒绝；确认仅追加todo且原记录不变；重复确认及手改后的再次确认不覆盖。金额、实际时间、验收/收付等未知继续未知。只跑本模块与真实依赖必要检查，不把本地合成响应叫真实模型效果。

模块交付后root核代码/回归，再交前端单独接入任务入口与实际保存重开/时间表导出。模型白名单摘要发送须由用户在产品中明确选定并确认；没有模型调用层不做“假生成”生产按钮，合成输入仅用于演练。
