# 执行时间表接入验收

用户已明确要求继续完成；样稿数据和视觉核对通过后进入生产实现。本段服务录音A执行与外包交接、录音B执行者看得懂的结果要求，不新增业务模块。

## 所有权

- 幕景 · 本地备份与恢复：仅新增frontend/lib/execution-timetable-export.ts及对应test，负责静态HTML生成与单元测试。
- 幕景 · 前端交付流程：结束评审库实机验收后，负责已有scene-delivery-panel.tsx及对应tests集成、独立build与浏览器下载。
- 导演：协调接口、核对文件来源及可读性、汇总版本；不覆盖执行者源码或操作其浏览器。

## 必须交付

1. 从当前活动的现有执行入口生成时间表，不依赖样稿路径或固定示例编号。空任务有清楚提示；未知日期/时间保留未知，不默认今天或零时。
2. 与现有完整活动交接共用准备与快照保护；资料未读成功、项目不匹配、未保存表单阻止、生成期间源变化时不能下载伪成功文件。
3. 每项源任务包括文字工作均保留，计划与实际、原记录状态与核对后有效状态可区分。日期及负责人索引有对应任务，顺序稳定。
4. 静态HTML转义所有源文本，无执行脚本或主动外部加载；有文件编号、冻结时间和资料性质。任务无日期、同名负责人、含特殊字符以及跨日任务不丢失。
5. 关联数量只使用既有点验投影与约定：20约定、18收取、18归还应表达未收2、已收部分无未还；不能推断损耗/结清/库存或把点验录入日期代替任务实际日期。
6. 生成前同步冻结业务数据，后续修改不能让同一输出混用前后版本；原HTML不随当前任务修改。重新生成取得当前已保存内容及新文件编号。

## 验证层次

- 纯模块：边界/转义/未知/原状态与有效状态/异步冻结/项目账册一致性，用真实合同验证，不自建镜像业务规则。
- 面板：入口到prepareBackup到函数到下载；失败及变化不能下载，忙碌恢复后可重试，不让新入口破坏完整交接/CSV。
- 实机：现有20任务39物料演练直接生成实际HTML，下载回读检查20任务保留及撤场需复核；任务修改保存后再次生成，与第一份冻结文件并存。首次及窄屏可读。
- 源码副本独立build，不修改正在运行的3157构建目录。当前候选完成前不stage/commit/push。

## 边界

这是给内部执行者的项目派生成果，包含负责人和任务信息，不自动发布为客户文件或上传飞书。客户评审本机历史库仍只接既有评审HTML，本段不混入新的成果类型。云同步、真实活动和模型质量另验；不重建任何定时任务。
