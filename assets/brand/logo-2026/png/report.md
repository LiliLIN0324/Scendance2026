# Logo render report — measured, not eyeballed

Generated by `.scratch/logo-v2/render/logo-render.mjs` · sharp 0.35.4.
Every number below is computed from the rendered pixels (alpha > 128, 4-connected).
Geometry is measured on a transparent render, so background colour cannot skew it.

## How to read the gate numbers

All geometry comes from the alpha mask at `alpha > 128`, so it is a *lower bound*:
the outermost half-covered pixel is dropped. Expect +-1 px of quantisation per edge,
which is why a 39 and a 41 can be the same design measured at two sizes.

| column | meaning | gate |
| --- | --- | --- |
| `bbox W/48 H/48` | ink extent on the 48-unit design grid | should sit inside 4..44, symmetric about the centre |
| `pad L/R` | background pixels left / right of the ink, at that raster size | unequal padding = the mark leans |
| `centre x/y /48` | ink optical centre minus canvas centre, in 48-grid units | non-zero = not optically centred |
| `wall px` | thinnest / median wall thickness from the medial axis | < 1.5 px at 16px = the wall greys out |
| `doorway px` | width of a *bounded* opening in the wall, in px | < 2 px at 16px = the doorway closes up |
| `clearance px` | min distance between the green dot and the wall | <= 1 px = the dot merges with the wall |
| `person Ø/48` | diameter of the person (green accent, else largest enclosed hole) | < 10 = the figure blurs into a dot |
| `green %` | green pixels / foreground pixels | < 3% = the accent has effectively vanished |

### Why the verdict is computed at 48px and not at 16px

At a 16px raster one pixel spans 48/16 = **3 grid units**. The clearance threshold is
0.08 x 40 = **3.2 units**, i.e. 1.07 px — *finer than a single pixel*. A 16px render can
therefore only ever report 0, 3, 6, ... units of clearance, so it cannot decide the gate.
The verdict is computed on the 48px render, where 1 px = 1 unit and the numbers are the
designer's own arithmetic. The 16px column answers the question it *can* answer: after
the mark is a 16x16 image, does the feature still exist at all (>= 1 px of doorway gap,
>= 1 px of clearance, a person >= 2 px across)? That is the `16px survival` column.

## Known traps this report is designed to expose

1. `--backgrounds paper` means `#F4F5F7`, but the CSS token `--wk-paper` is `#FFFFFF`
   (`frontend/app/globals.css:752-765`). Same word, opposite value.
2. Green `#4A7C59` on ink `#141416` is 3.81:1 — it clears the 3:1 non-text bar but
   fails 4.5:1. That is why `reverse` neutralises the accent to white.
3. A 16px render is a 16px render: sharp rasterises the vector at the target size
   (measured byte-identical to an SVG whose width/height were rewritten), so these
   numbers are what the browser tab/UI actually shows.
